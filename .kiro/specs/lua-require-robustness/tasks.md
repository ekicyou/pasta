# Implementation Plan

実装順序は要件どおり B（可視化）→ A（モジュール解決）とする。B が先に入ることで、A の実装中に起きるロード失敗が 500 とログで可視化された状態で作業できる。

- [x] 1. テスト基盤の整備とベースライン固定
  - 両クレートのテスト共通ヘルパに、どの単一 ANSI コードページでも表現できない複数文字体系混在のディレクトリ名定数、絶対パス長が指定長を超える深いディレクトリを掘るヘルパ、フィクスチャを任意の宛先へコピーするヘルパを追加する
  - 深いディレクトリは設置ルート自体が 300 文字超になるよう構築し、`canonicalize` を使わず絶対化のみで形を保つ（CI の 8.3 短縮名対策）。後始末は一時ディレクトリの drop に任せる
  - `PASTA_DEBUG` を中和するコンストラクタガードは両クレートの共通モジュールに既存であるため新設しない。本仕様で追加・更新する独立テストバイナリが共通モジュールを宣言して既存ガードが効く形にする
  - 着手前のベースラインとして、チャンク識別子の往復検証テストと応答バイト不変テストを実行し、成功を記録する
  - 完了状態: 両クレートのテストから新ヘルパが呼び出せ、深いパス・非 ANSI パスの一時ゴーストがテスト内で構築・破棄できる。ベースラインの 2 テストが緑であることが記録されている
  - _Requirements: 6.4, 6.6, 6.7_
  - _Boundary: TestPathHelpers_

- [ ] 2. 欠陥 B: ロード失敗とリクエスト処理エラーの可視化
- [ ] 2.1 エラー応答ヘッダ値の単一行化
  - `X-ERROR-REASON` の値を組み立てる際、スタックトレース以降を捨て、残りの行を trim して空行を除き、半角スペース 1 個で連結する非公開ヘルパを追加する
  - 改行を含まない入力は無変換で返し、既存応答をバイト不変に保つ。候補パス列は落とさず、長さの上限も設けない。非 ASCII 文字は変換しない
  - 500 応答と 400 応答の両方がこのヘルパを通るようにする。応答の行構成・ヘッダ名・文字コード指定は変更しない
  - 完了状態: CR / LF / CRLF / タブ字下げ・スタックトレース付き・改行なしの各入力に対する単体テストが緑で、既存の応答不変テストも緑
  - _Requirements: 2.3, 3.5, 4.6, 4.11_

- [ ] 2.2 リクエスト処理エラーを 500 応答として返す
  - アクタースレッドの GET 処理でリクエスト処理がエラーを返した場合、応答チャネルを drop するのではなく、エラーから生成した 500 応答文字列を返すよう変更する
  - 観測ログを「応答を返した（エラーあり）」として出し、「応答を返さなかった」ことを示す既存のログ点はそのケースに限定する
  - 応答を送れない異常（スレッド消滅・panic・タイムアウト・mailbox 不在）および NOTIFY の即時 204 は変更しない。マーシャリング側はコード無変更とし、旧契約を書いたコメントのみ新契約へ更新する
  - 完了状態: GET に対してアクタースレッドが生存している限り応答が必ず 1 回値で送られ、既存のマーシャリング・安全網・トレースの各テストが緑のまま
  - _Requirements: 4.3, 4.4, 4.8, 4.10_

- [ ] 2.3 本番起動シーケンスの致命分類
  - 起動モジュールを require し、失敗時にモジュール名と致命フラグを構造化フィールドに持つ error ログを出し、起動モジュール名の文脈を付けたエラーを返す共通ヘルパを追加する
  - 利用者初期化スクリプト・SHIORI 応答モジュール・シーン辞書モジュールの 3 種すべてをこのヘルパ経由にし、失敗を致命として伝搬する（利用者初期化スクリプトの致命化は意図的な挙動変更）
  - ログのエラーフィールドには複数行・スタックトレース込みの全文を欠落なく出す。成功時の既存 debug ログは残す。起動シーケンスのコメントを新分類へ更新する
  - 本番経路の既存ローダテストを棚卸しし、利用者初期化スクリプトまたは応答モジュールのロード失敗が警告止まりであることを前提にしていたものがあれば期待値を更新する
  - 完了状態: 利用者初期化スクリプトが構文エラー／上書きした応答モジュールが実行時エラー／応答モジュールが存在しないモジュールを require、の各ケースでロードがエラーを返し、その表示文字列に起動モジュール名と根本原因の両方が含まれることを検証する統合テストが緑
  - _Requirements: 4.1, 4.5, 4.7, 4.9, 5.1, 5.2, 5.3, 5.5_

- [ ] 2.4 旧経路の無言化の是正
  - SHIORI 応答モジュールを直接読み込む旧経路について、ファイルが存在するのに読み取り・実行に失敗した場合を致命として伝搬するよう変更する
  - ファイルが存在しない場合は従来どおりスキップする（旧経路は応答モジュールを任意とする軽量構築経路であるため）
  - 失敗ログは本番経路と同一の構造化フィールド構成・同一の文脈文言を用い、ファイル読み取り失敗も同じ経路で伝搬させる
  - 完了状態: 旧経路の既存テストを、応答モジュールの実行失敗でエラーを返し不在では成功する期待へ更新し、緑になる
  - _Requirements: 5.3, 5.5, 5.6_

- [ ] 2.5 UTF-8 の設置パスを受け取る初期化入口の追加
  - DLL 共通仕様の UTF-8 版初期化入口を追加する。所有権規約（受け取ったハンドルを全経路で解放）と panic 封じ込めは従来の入口と同一とし、差はパスのデコード方式のみとする
  - 「UTF-8 入口で初期化済み」をプロセス全域のフラグで保持し、アクター起動へ到達した時点で立てる（ロード失敗時も立てる）。終了処理で下ろす
  - フラグが立っているとき従来の初期化入口は、受け取ったハンドルを解放したうえで何もせず成功を返す。フラグが無ければ従来どおり ANSI デコードでロードする
  - 既存のリクエスト処理・終了処理のロジックは変更しない。冒頭コメントの旧契約の記述を新契約へ更新する
  - 完了状態: 32bit / 64bit の両ビルドで新旧 2 つの入口がエクスポートされ、UTF-8 入口で初期化済みのとき従来の入口が再ロードせず成功を返す

  - 完了状態: 候補パス生成の単体テストが緑で、設置関数がレイアウト違反の VM に対してエラーを返す
