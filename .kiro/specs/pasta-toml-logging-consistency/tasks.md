- [x] 4. ログの出力先の決定とロガーの作成
- [x] 4.1 (P) ログファイルのパスの判定を「`profile/` ディレクトリの下」に厳密化する

  - 設置ディレクトリの外・絶対パス・`..` を含むパスを不正とする現行の判定は保つ

  - _Requirements: 5.5_
  - _Boundary: LogFilePathValidation_

- [x] 4.2 (P) ログ 1 件の出力先を決める規則を、文脈なしでも唯一のロガーへ書く形に改める
  - 文脈あり→その設置パスのロガー（未登録なら捨てる）、文脈なし→登録がちょうど 1 つならそれ、それ以外は捨てる、の 3 規則を出力先の決定に入れる
  - 登録簿のロックを持つのは表を引く間だけにし、置き換えや登録解除で外したロガーの破棄（フラッシュ）はロックの外で行う
  - モジュールの説明を新しい規則に合わせる
  - 単体テスト（プロセス全域でない登録簿で）: 文脈なしで 0 個・1 個・2 個、文脈ありで登録済み・未登録（他に 1 個登録）の各場合の結果と、ロガーが無いときの書き込みとフラッシュが成功を返すことを検証する
  - プロセス全域の登録簿を使う既存の単体テスト（文脈なしで捨てることを見るテスト、登録・取得・解除、置き換え）は、新しい規則の下で並列実行と競合するため、private な登録簿を使う形に書き換える。文脈なしで捨てる場合は「0 個」の検証が引き継ぐ
  - `pasta_lua` のテストを並列実行で繰り返しても、登録簿の単体テストが安定して通る
  - _Requirements: 4.1, 4.6, 4.7, 7.5_
  - _Boundary: LogRouting_
