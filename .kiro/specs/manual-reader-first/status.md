## 承認された方針（2026-11-19。開発者が議題 1〜5・8 を承認。議題 4 はト書きの範囲を広げた）

1. **規約を読む人の側へ改める** — 入門の「台詞に書いた事実を、台詞以外にも必ず書く」をやめ、事実は 1 回だけ書く。全章に「今の動きだけを書く・Windows 11 で自明なことを書かない・抽象の規則には実物の例を 1 つ」を足す。章の並びを縛る検査は新しい構成に合わせて直す。
2. **入門の構成** — 「まず会ってみる（hello-pasta を入れて、1 行書き換えて ▶ で鳴らす）」を先頭に足し、前提環境と準備の解説は付録へ下げる。自分のゴーストの器は、入門用の nar（スターター）を SSP に入れて始める。確かめ方は「SSP の再起動」から、エディタの「▶ シーンを実行」に替える。代償: hello-pasta の `pasta.toml` に `[debug] enabled = true` を入れる。スターターはリリースの配布物が 1 つ増える（リリース CI に手が入る。次のリリースまでリンクが切れるので、この波はリリースの直前に main へ入れる）。
3. **見本ゴーストの台詞** — 「パスタ屋の見習い 2 人」の設定を笑いの足場にして、13 枚を書き直す。書く前に emo2 開発のセッションへ掛け合いのコツを相談する。絵 16 枚は撮り直す。
4. **文法の部** — 概要を「Pasta DSL は台本である」の全体像（通しの作例 1 本と対応の表）に書き直し、目次を 概要 → マーカー → 行とブロック → アクション行 → アクター辞書 → さくらスクリプト → 単語 → 変数 → リテラル → Call の順に並べ替える。語の決め:
   - **台本** — 辞書（`.pasta`）に書くもの全体。
   - **柱** — 場面の見出し。グローバルシーン `＊`・ローカルシーン `・` と、それに付く属性 `＆`・アクター指定行 `％`。
   - **台詞** — アクション行（`アクター：台詞`）。
   - **ト書き** — シーンの中の、台詞以外のほとんど全部。`＞`（呼び出し）と選択肢 `＠？` も、台本の流れを制御するト書きの一種である。`！` 行・変数の代入 `＄`・台詞の中の表情もここに入る（開発者: 「ト書きはセリフ以外ほとんど全部」）。
   - **登場人物** — アクター辞書 `％名前`。
   - 今「台本」と呼んでいる出力（ゴーストが返したさくらスクリプト）は「スクリプト」に言い換える。エディタの出力の文言（`editors/shared/runSceneAtCursor.ts` の `台本:` ほか 3 つ）も同じ変更で直す。
5. **デバッグの部** — 部の題を「編集ツールとデバッグ」に、章を「pasta-recipe で書く」「VS Code で書く」に改める（pasta-recipe を先に）。WebView2・ポート番号・前の版からの移行・設定の置き場のパスは消す。本体にも Claudia を出し、入門と同じ気軽さで書く。ファイル名は変えない。
6. **リファレンス 3 章**・7. **内部設計** — 着手済み。プレビューで確かめてもらう。
8. **シェルの章の絵** — 表情の一覧に顔の切り抜き（2 人 × 9 表情）を並べ、当たり判定の枠を重ねた図を 1 枚足す。

範囲の前提（異論なし）: 雑記は触らない。Lua の部は、ほかの直しに伴うリンクと語の直しだけ。

### 文法の部

- マニュアルの本文に、台本・脚本・柱・ト書きの説明は 1 行も無い。プロジェクトの中では roadmap と `cue-command-runtime` の brief が「柱＝`＊` と `＆属性`、ト書き＝`！` 行、台詞＝アクション行」と言っている。
- 通しの作例（アクター辞書＋シーン＋`％` 行＋表情の単語）が最初に出るのは、最後の章 `actor-dictionary.md`。概要の唯一の作例は算術式。
- `？` 単独のジャンプは無い。章題「Call / Jump」の Jump は本文に無い。
- `！` 行で今働くのは `!select` だけ。
- 語「台本」は、デバッグと Lua の章で「ゴーストが返したさくらスクリプト」の意味に使われている（5 章・25 か所）。エディタの出力にも `台本:` がある（`editors/shared/`）。
- スキルは目次の順を見ない（`SKILL.md` が自前のマーカー表を持つ）。目次の並べ替えはスキルに響かない。目次の順を縛る検査は無い。
