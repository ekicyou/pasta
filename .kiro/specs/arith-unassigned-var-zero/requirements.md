# Requirements Document

## Project Description (Input)

入門ガイドの 10 段目「覚えていてほしい（変数の保存）」で、読者が `＄＊回数＝＄＊回数＋１` の 1 行だけで回数を数えられるようにしたい。現行の pasta では、未代入の変数を算術の被演算子にするとその演算が値なしになり（`act:arith - operand is not a number` の警告）、値なしを代入した変数は未代入のままなので、`＄＊回数` は永久に数え始めない。DSL には条件分岐も既定値の構文も無く、回避には Lua 関数が要る。「この程度の表現で Lua を出させるなら、それは DSL の問題」として、算術の被演算子が未代入の変数なら 0 とみなす。値を返さない関数呼び出し・数字でない文字列・真偽値などは従来どおり警告＋値なしとし、「書き間違いを 500 にしない」方針は保つ。マニュアル 3 ページとスキル references を同じ PR で直す（`hello-pasta-tutorial-stages` の設計ディスカッション #1 の決定。コミット `0e1f53a0`）。

## Introduction

本仕様は、Pasta DSL の算術式（`＋`・`－`・`＊`・`／`・`％`）の被演算子が**未代入の変数**であるときの扱いを、「警告＋値なし」から「0 とみなして演算を成立させる」に変える。対象は被演算子の出どころが変数（ローカル `＄x`・グローバル `＄＊x`・シーン引数 `＄０`…）である場合だけで、関数呼び出しが値を返さない場合や、数値にできない文字列・真偽値などの失敗は変えない。

本仕様の決定の正本は `hello-pasta-tutorial-stages` の `design.md` Q1 と `requirements.md` Requirement 3.6（コミット `0e1f53a0`）、および本 spec の `brief.md` である。brief が要件フェーズに残した 6 つの論点は、各要件に **【仮定】** として既定案を書き、`research.md` の「要件ディスカッションへの持ち越し」に事実と一緒に列挙した。

### 用語

- **未代入の変数**: 値を一度も代入していない変数、または値なしを代入した結果として「値を代入していない状態」になった変数（`dsl-codegen-runtime-safety` R3.4 の規則。アクション行で参照すると空文字に展開されて警告が出る状態）。
- **値なし**: 演算の失敗の結果。代入すると変数は未代入の状態になる（`string-concat-operator` の用語と同じ）。
- **被演算子の出どころ**: 算術の被演算子が、変数参照（ローカル・グローバル・シーン引数）、関数呼び出し（`＠f（）`・`＠＊g（）`・`＠＄x（）`）、リテラル、括弧式、入れ子の演算のどれとして書かれたか。現行の警告ログの `operand=`（変数の場所・関数名）が示すもの。
- **0 とみなす**: 被演算子の値として数値 0 を使って演算を続けること。変数そのものに 0 を代入することではない（`＄＊回数＋１` を評価しても `＄＊回数` は代入しない限り未代入のまま）。

## Boundary Context

- **In scope**:
  - 算術式を書けるすべての位置（変数代入の右辺・式文・関数呼び出しの引数・Call の引数・動的コールのターゲット・プロパティ代入の右辺）で、被演算子が未代入の変数のときに 0 とみなすこと。
  - 0 とみなさない失敗（値を返さない関数呼び出し・数字でない文字列・真偽値・表など）が従来どおり警告＋値なしであること。
  - 新しい挙動を固定する回帰テスト（ランタイムの確認・トランスパイル→実行の確認）と、現行挙動を固定している既存テストの更新。
  - マニュアル 3 ページ（`grammar/variables.md`「算術の評価」「連結の評価」、`lua/script-api.md` の `act:arith`、`internals/internal-modules.md`「生成コード用のメソッド」）の更新と、スキル `pasta-ghost-authoring` の算術の 1 行および `references/` の再生成。
- **Out of scope**:
  - 連結 `＆` で未代入の変数を空文字とみなすこと（動機が無いため入れない。Requirement 4 で「変えない」と明記）。
  - アクション行で未代入の変数を参照したときの空文字展開と警告（`act:talk - undefined variable`）。
  - 「値なしを代入した変数は未代入になる」規則の変更。
  - 数字でない文字列・空文字列・真偽値・表などの被演算子の扱いの変更。
  - DSL の文法変更（条件分岐・複合代入 `＋＝`・既定値の構文 `＄x？？０` など）。
  - 警告の文言・出口の一本化（`failure-output-unification` の持ち場）。本仕様は新しい警告文を増やさず、既存の警告文も変えない。
  - 0 による除算・剰余の数値の規則そのもの（Lua の数値演算どおり。`dsl-codegen-runtime-safety` が範囲外とした点を引き継ぐ）。
- **Adjacent expectations**:
  - `dsl-codegen-runtime-safety`（完了）: 「書き間違いを 500 にしない」「数値にできない被演算子は警告＋値なし」「内側の失敗は外側で黙って伝播」の規則を前提とし、本仕様はそのうち「未代入の変数」の 1 分岐だけを変える。
  - `string-concat-operator`（完了）: 連結の失敗の規則と、被演算子の説明（変数の場所・関数名）の形を前提とする。連結の結果と警告は変えない。
  - `hello-pasta-tutorial-stages`（下流）: 10 段目の作例 `＄＊回数＝＄＊回数＋１` が、初期化行も Lua も無しに初回から 1・2・3… と数えることを本仕様が保証する。同 spec の実装着手は本仕様が main に入ることをゲートとする。
  - `getting-started-story-guide`（下流）: 10 段目の章の説明が本仕様の規則（未代入は 0）に依拠する。
  - `failure-output-unification`（未着手・隣接）: `act.lua` の警告の出口を一本化する。本仕様は同じ関数の数値化の分岐だけを触り、警告の文言・出口は触らない。同じウェーブに置くなら本仕様を先に入れ、同 spec が rebase する。
  - `manual-ssot-authority`: マニュアルが文法・API の唯一の権威であり、スキル `references/` はマニュアル章からの生成物である。生成物の鮮度照合（`--check`）とリンク検証が通ることを完了条件とする。

## Requirements

### Requirement 1: 未代入の変数を被演算子にした算術

**Objective:** ゴースト作者として、回数・得点・好感度のような「増やしていく値」を `＄＊回数＝＄＊回数＋１` の 1 行で書きたい。初期化の行や Lua を書かなくても、初回から数え始めてほしい。

#### Acceptance Criteria

1. When 算術式（`＋`・`－`・`＊`・`／`・`％`）の被演算子が未代入のローカル変数（`＄x`）またはグローバル変数（`＄＊x`）であるとき, the pasta shall その被演算子を 0 とみなして演算を成立させ、他方の被演算子が数値にできれば数値の結果を返す（`＄＊回数＝＄＊回数＋１` は `＄＊回数` が未代入なら 1 になる）。
2. When 算術式の被演算子が、値の渡されていないシーン引数（`＄０`・`＄１`…。Call の引数が足りない場合やイベントの Reference が無い場合）であるとき, the pasta shall 1 と同じく 0 とみなす。（**【仮定】** brief の論点 2。変数の 3 スコープをすべて対象とする案を既定とした。プロパティ参照 `＄％…` は式の中に書けずトランスパイルエラーになるため、本要件の対象に含まれない）
3. The pasta shall 1・2 を 5 つの算術演算子（`＋`・`－`・`＊`・`／`・`％`）のすべてと、左右どちらの被演算子にも同じく適用する（`１－＄未代入` は 1、`＄未代入＊２` は 0）。（**【仮定】** brief の論点 1。`＋` だけに限る案は採らず、演算子で区別しない案を既定とした）
4. When 0 とみなした被演算子が除数（`／`・`％` の右の被演算子）であるとき, the pasta shall 0 を除数にした既存の数値の規則どおりの結果（`１／＄未代入` は `inf`、`１％＄未代入` は非数）を返し、実行時エラーにしない。（**【仮定】** brief の論点 1 の除数の扱い。「除数だけは従来どおり警告＋値なし」とする案との二者択一で、規則を 1 つに保つ案を既定とした。要件ディスカッションで確定する）
5. The pasta shall 1〜4 を、算術式を書けるすべての位置（変数代入の右辺・式文・関数呼び出しの引数・Call の引数・動的コールのターゲット・プロパティ代入の右辺）に同じく適用する。
6. When 未代入の変数を含む算術が括弧や優先順位で入れ子になっているとき, the pasta shall 内側の演算で 0 とみなした結果を外側の演算にそのまま使う（`（＄未代入＋１）＊２` は 2、`「合計」＆（＄未代入＋１）` は `合計1`）。
7. When 値なしを代入した結果として未代入の状態になった変数（`＄y＝「abc」＊２` のあとの `＄y`、`＄z＝＠＊未定義関数（）` のあとの `＄z`）を算術の被演算子にしたとき, the pasta shall 1 と同じく 0 とみなす。（「値なしを代入した変数は未代入になる」規則は変えないため、その帰結として確定。失敗した値がその後の算術で 0 として通ることの是非は要件ディスカッションで確認する）
8. When グローバル変数に 1 の結果を代入してゴーストを終了・再起動したとき, the pasta shall 保存された値から数え続ける（`＄＊回数＝＄＊回数＋１` が起動のたびに 1・2・3… と増える）。
9. The pasta shall 被演算子がすべて数値にできる算術式の結果と、警告を出さないことを従来から変えない。

### Requirement 2: 0 とみなさない被演算子（従来の失敗の維持）

**Objective:** ゴースト作者として、関数の書き間違いや数字でない文字列の算術は、今までどおりログで気づけるようにしてほしい。「0 とみなす」が書き間違いを隠さないでほしい。

#### Acceptance Criteria

1. If 算術式の被演算子が値を返さない関数呼び出し（ローカル `＠f（）`・グローバル `＠＊g（）`・動的 `＠＄x（）`。見つからない関数の呼び出しを含む）であるとき, the pasta shall 従来どおり実行時エラーにせず、その演算の結果を値なしとし、演算子と関数名を含む警告ログ（`act:arith - operand is not a number`）を出す。
2. If 動的関数呼び出し `＠＄x（）` の変数 `＄x` が未代入であるとき, the pasta shall 関数呼び出しの失敗として扱い（1 と同じ）、変数の 0 扱いを適用しない。
3. If 算術式の被演算子が数字でない文字列（`「abc」`・全角数字だけの `「１２」`）、空文字列（`「」`）、または空文字列・数字でない文字列を代入した変数であるとき, the pasta shall 従来どおりその演算の結果を値なしとし、警告ログを出す。（空文字列の変数は「未代入」ではないため 0 とみなさない。brief の論点 5 の境界で、現行どおりで確定し Requirement 5 でマニュアルに書く）
4. If 算術式の被演算子が真偽値・表・関数など、数値にも数字の文字列にもできない値であるとき, the pasta shall 従来どおりその演算の結果を値なしとし、警告ログを出す。
5. When 1・3・4 で値なしになった演算の結果が、さらに外側の演算（算術・連結）の被演算子になったとき, the pasta shall 従来どおり外側も値なしとし、外側では警告ログを追加で出さない。
6. The pasta shall 既存の警告ログの文言・含まれる情報（演算子・被演算子の場所または関数名・値とその種類）・出口を変えない。

### Requirement 3: 0 とみなしたときのログ

**Objective:** 入門ガイドの読者として、作例どおりに書いて初めて起動したときに、ログに警告が並んで戸惑うことのないようにしてほしい。

#### Acceptance Criteria

1. When 未代入の変数を 0 とみなして算術を成立させたとき, the pasta shall 警告ログ（`warn`）を出さない。（**【仮定】** brief の論点 3。「黙る」案を既定とした。出すなら `warn` ではなく `debug` 程度、という代替案と合わせて要件ディスカッションで確定する）
2. The pasta shall 0 とみなした被演算子について、作者が辞書の挙動を追うための新しい警告の種類や出口を増やさない。（`failure-output-unification` の持ち場を侵さない）

### Requirement 4: 変えない隣接の挙動（連結・アクション行）

**Objective:** ゴースト作者として、算術以外の未代入の変数の扱い（連結・台詞での参照）が本仕様で黙って変わらないことを、マニュアルで確認できるようにしてほしい。

#### Acceptance Criteria

1. The pasta shall 連結 `＆` の被演算子が未代入の変数であるときの扱い（値なし＋警告 `act:concat - operand is not a string or number`）を変えない（`「合計」＆＄未代入＆「個」` は従来どおり値なし。brief の論点 6）。
2. When 連結の被演算子として書いた括弧内の算術に未代入の変数があるとき, the pasta shall 算術側の規則（Requirement 1）で 0 とみなした結果を連結する（`「合計」＆（＄未代入＋１）` は `合計1` になり、`「合計」＆＄未代入` が値なしのままであることと対照をなす）。
3. The pasta shall アクション行で未代入の変数を参照したときの扱い（空文字として展開し、警告 `act:talk - undefined variable` を出す）を変えない。
4. The pasta shall 「値なしを代入した変数は未代入になる」規則、および動的参照（`＠＄名前`・`＠＄名前（…）`）で未代入の変数を使ったときの扱いを変えない。
5. When 手書きの Lua から生成コードと同じ形で算術のメソッドを呼んだとき（被演算子の値が無く、説明として変数の場所を渡したとき）, the pasta shall 生成コードと同じ規則で 0 とみなす。（**【仮定】** brief の論点 4。「被演算子の説明（変数の場所 `var.x`／`save.x`／`args[n]` と関数名 `@f()`）で見分ける」案を既定とした。トランスパイラーが被演算子の種類を別の引数で渡す案を採る場合は、本項の手書き Lua からの呼び方が変わる）

### Requirement 5: マニュアルとスキルの同期

**Objective:** ゴースト作者と入門ガイドの読者として、マニュアルを読めば「未代入の変数は算術で 0 とみなされる」ことと、その境界（0 にならないもの）が分かるようにしてほしい。

#### Acceptance Criteria

1. The pasta manual（`grammar/variables.md`「算術の評価」） shall 未代入の変数（ローカル・グローバル・シーン引数）が算術の被演算子になったとき 0 とみなされ警告が出ないこと、および数値にできない被演算子（数字でない文字列・空文字列・値を返さない関数呼び出し・真偽値など）は従来どおり値なし＋警告であることを書き、作例 `＄x＝＄未代入＋1`（結果が 1 になる）と、数値にできない例（`「abc」` など）を新しい挙動に合わせて書き直す。
2. The pasta manual（`grammar/variables.md`「算術の評価」） shall 空文字列を代入した変数は未代入ではなく 0 とみなされないこと、値なしを代入して未代入になった変数は次の算術で 0 とみなされること、除数が未代入のときの結果（Requirement 1.4 の確定内容）を書く。
3. The pasta manual（`grammar/variables.md`「連結の評価」） shall `＆` の未代入の扱いが変わらないことと、作例 `＄y＝「合計」＆（＄未代入＋1）` の結果が `合計1` になることを新しい挙動に合わせて書き直す。
4. The pasta manual（`lua/script-api.md` の `act:arith` の節、`internals/internal-modules.md`「生成コード用のメソッド」） shall 未代入の変数を 0 とみなす規則と、関数呼び出し・数値にできない値との区別の仕方を、確定した仕組み（Requirement 4.5）に合わせて書く。
5. The pasta skill（`pasta-ghost-authoring/SKILL.md` の算術の 1 行と `references/variables.md`） shall マニュアルと同じ内容になる（`references/` は再生成し、鮮度照合とリンク検証が通る）。
6. When 入門ガイド 10 段目の作例（`＊会話` の中で `＄＊回数＝＄＊回数＋１` に続けて `＄＊回数` を台詞に使う）を初期化行も Lua も無しに実行したとき, the pasta shall 1 回目に「1」、2 回目に「2」と数えた台詞を出し、`hello-pasta-tutorial-stages` がこの作例をそのまま段階辞書に使える。

### Requirement 6: 挙動を固定する検証

**Objective:** 開発者として、新しい規則と変えない規則の両方がテストで固定され、現行挙動を固定している既存テストが新しい挙動に揃っていてほしい。

#### Acceptance Criteria

1. The pasta test suite shall 未代入の変数（ローカル・グローバル・シーン引数）を 0 とみなす結果（Requirement 1.1〜1.7）と警告の有無（Requirement 3）を、ランタイム（Lua のテスト）と、DSL をトランスパイルして実ランタイムで実行するテストの両方で固定する。
2. The pasta test suite shall 0 とみなさない被演算子（Requirement 2）と連結の不変（Requirement 4.1・4.2）を固定する。
3. The pasta test suite shall 現行の「未代入の変数は警告＋値なし」を期待している既存のテスト（ランタイムの Lua テスト・トランスパイル→実行のテストとその期待警告）を新しい挙動に更新し、新しい挙動と矛盾する期待を残さない。
4. While 生成コードの形（算術 1 演算が被演算子の説明付きの 1 呼び出しになる形）を変えない案（Requirement 4.5 の既定）を採るとき, the pasta shall 生成コードのスナップショットと `internals/transpiler.md` の生成形の記述を変えない。
5. The pasta shall 本仕様の変更後も、既存のテスト（ワークスペース全体）とマニュアルの検証（鮮度照合・リンク検証）がすべて通る。
