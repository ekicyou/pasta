# Requirements Document

## Project Description (Input)

入門ガイドの 10 段目「覚えていてほしい（変数の保存）」で、読者が `＄＊回数＝＄＊回数＋１` の 1 行だけで回数を数えられるようにしたい。現行の pasta では、未代入の変数を算術の被演算子にするとその演算が値なしになり（`act:arith - operand is not a number` の警告）、値なしを代入した変数は未代入のままなので、`＄＊回数` は永久に数え始めない。DSL には条件分岐も既定値の構文も無く、回避には Lua 関数が要る。「この程度の表現で Lua を出させるなら、それは DSL の問題」として、算術の被演算子が未代入の変数なら 0 とみなす。値を返さない関数呼び出し・数字でない文字列・真偽値などは従来どおり警告＋値なしとし、「書き間違いを 500 にしない」方針は保つ。マニュアル 3 ページとスキル references を同じ PR で直す（`hello-pasta-tutorial-stages` の設計ディスカッション #1 の決定。コミット `0e1f53a0`）。

## Introduction

本仕様は、Pasta DSL の式の中で **nil**（値が無いこと）を見つけたときの扱いを変える。算術（`＋`・`－`・`＊`・`／`・`％`）の文脈では 0、連結（`＆`）の文脈では空文字列 `""` とみなし、ログを出さずに評価を続ける。これにより、`＄＊回数＝＄＊回数＋１` が初期化の行も Lua も無しに初回から数え始める。

当初の brief は「未代入の**変数**だけを 0 とみなし、値を返さない関数呼び出しは従来どおり失敗、連結は範囲外」としていた。要件ディスカッション（2026-10-08）で、開発者の判断により「nil の出どころを問わず、文脈で 0 か `""` にする」規則に組み替えた（下の「方針の組み替え」）。nil の出どころ（変数か関数か）を見分ける仕組みは不要になった。

### 方針の組み替え（要件ディスカッション、2026-10-08）

- 開発者の言葉: 「nil を数式演算の文脈で見つけたときに 0 にせよ、だけ。同様に文字連結の文脈で見つけたときは "" であってほしい」。
- これにより、brief の論点 4（区別の仕組み）・論点 6（連結は範囲外）と、要件ディスカッションの議題 3（値なしを代入した変数の扱い）は消えた。値なしを代入した変数も nil なので、次の算術で 0、次の連結で `""` になる。
- 議題 #1（除数も 0 とみなす）・#2（シーン引数も対象）の決定は、この規則の一部としてそのまま有効である。
- 実装の形について、開発者から「num 関数・str 関数を作り、被演算子をすべてそこへ通すようにトランスパイルする」案が出た。設計への申し送りとして `research.md` 5.3 に記録した。
- 議題 #4 で、nil 以外の変換できない値（`「abc」`・真偽値など）も、警告を出したうえで 0・`""` とみなすと決めた。これにより、算術の文脈の値は必ず数値、連結の文脈の値は必ず文字列になり、式の演算が「値なし」を作ることは無くなった。式の結果が nil になるのは、値を返さない関数呼び出しを演算子なしで書いた場合（`＄x＝＠f（）`）だけである。

### 用語

- **nil**: 値が無いこと。未代入の変数（値を一度も代入していない変数、値なしを代入して未代入に戻った変数）、渡されていないシーン引数、値を返さない関数呼び出しが、式の中では nil として現れる。
- **値なし**: 代入の右辺の値が nil であること。代入すると変数は未代入の状態になる（`dsl-codegen-runtime-safety` の規則。変えない）。本仕様の後は、算術・連結の演算が値なしを作ることは無い（議題 #4）。
- **算術の文脈**: 算術演算子 `＋`・`－`・`＊`・`／`・`％` の被演算子の位置。
- **連結の文脈**: 連結演算子 `＆` の被演算子の位置。
- **0 とみなす／`""` とみなす**: その被演算子の値として 0 または空文字列を使って演算を続けること。変数そのものに代入することではない。

## Boundary Context

- **In scope**:
  - 算術の文脈の nil を 0、連結の文脈の nil を `""` とみなし、ログを出さないこと。式を書けるすべての位置（変数代入の右辺・式文・関数呼び出しの引数・Call の引数・動的コールのターゲット・プロパティ代入の右辺）で同じに扱う。
  - nil 以外の、数値にも文字列にもできない値（数字でない文字列・真偽値・表など）を、警告を出したうえで 0・`""` とみなすこと（Requirement 4。議題 #4 で確定）。
  - 新しい挙動を固定する回帰テストと、現行挙動を固定している既存テストの更新。
  - マニュアル（`grammar/variables.md`「算術の評価」「連結の評価」、`grammar/call-jump.md` の Call の失敗の表、`lua/script-api.md` の `act:arith`・`act:concat`、`internals/internal-modules.md`「生成コード用のメソッド」、生成形を変えるなら `internals/transpiler.md`）と、スキル `pasta-ghost-authoring` の算術・連結の行、`references/` の再生成。
- **Out of scope**:
  - 演算子の被演算子でない位置での nil の扱い（関数呼び出しの引数に `＄未代入` を 1 つだけ渡す、Call のターゲットが変数 1 つだけ、動的参照 `＠＄名前` など）。文脈が無いので変えない。
  - 「値なしを代入した変数は未代入になる」規則の変更。
  - DSL の文法変更（条件分岐・複合代入 `＋＝`・既定値の構文 `＄x？？０` など）。
  - 警告の文言・出口の一本化（`failure-output-unification` の持ち場）。本仕様は新しい警告文を増やさない。
  - 0 による除算・剰余の数値の規則そのもの（Lua の数値演算どおり）。
- **Adjacent expectations**:
  - `dsl-codegen-runtime-safety`（完了）: 「書き間違いを 500 にしない」を前提とする。同 spec が「0 は失敗を隠す」として採らなかった既定値 0 を、nil に限って採る。関数が見つからないときの警告（`act:expr_fn - handler not found`・`act:global_fn - function not found`・動的呼び出しの `undefined variable`）は呼び出しの時点で出るので、書き間違いはログに残る。
  - `string-concat-operator`（完了）: 連結の規則のうち、nil の扱いだけを変える。
  - `call-execution-correctness`（完了）: Call のターゲットの失敗表記（`【Call失敗：…】`）。ターゲットが連結・算術の式のときの nil の扱いが変わる（Requirement 5 と要件ディスカッションの議題）。
  - `hello-pasta-tutorial-stages`（下流）: 10 段目の作例が初期化行も Lua も無しに数えることを本仕様が保証する。同 spec の実装着手は本仕様が main に入ることをゲートとする。
  - `getting-started-story-guide`（下流）: 10 段目の章の説明が本仕様の規則に依拠する。
  - `failure-output-unification`（未着手・隣接）: `act.lua` の警告の出口を一本化する。本仕様を先に入れ、同 spec が rebase する。
  - `manual-ssot-authority`: スキル `references/` はマニュアル章からの生成物。鮮度照合（`--check`）とリンク検証が通ることを完了条件とする。

## Requirements

### Requirement 1: 算術の文脈の nil は 0

**Objective:** ゴースト作者として、回数・得点・好感度のような「増やしていく値」を `＄＊回数＝＄＊回数＋１` の 1 行で書きたい。初期化の行や Lua を書かなくても、初回から数え始めてほしい。

#### Acceptance Criteria

1. When 算術演算子の被演算子の値が nil であるとき, the pasta shall その被演算子を 0 とみなして演算を続ける。nil の出どころ（未代入のローカル変数 `＄x`・グローバル変数 `＄＊x`・リクエスト変数 `＄ｒ０`…、渡されていないシーン引数 `＄０`…、値を返さない関数呼び出し `＠f（）`・`＠＊g（）`・`＠＄x（）`）は問わない（`＄＊回数＝＄＊回数＋１` は `＄＊回数` が未代入なら 1 になる。議題 #2 でシーン引数を対象と確定）。
2. The pasta shall 1 を 5 つの算術演算子のすべてと、左右どちらの被演算子にも同じく適用する（`１－＄未代入` は 1、`＄未代入＊２` は 0）。
3. When 0 とみなした被演算子が除数（`／`・`％` の右）であるとき, the pasta shall 0 による除算・剰余と同じ結果（`１／＄未代入` は `inf`、`１％＄未代入` は非数）を返し、実行時エラーにしない（議題 #1 で確定。リテラルの `１／０` と同じ振る舞い）。
4. The pasta shall 1〜3 を、算術式を書けるすべての位置に同じく適用する。
5. When 内側の演算に nil や変換できない値があったとき, the pasta shall 内側の演算を Requirement 1〜4 どおりに数値として計算し、その結果を外側の演算に使う（`（「abc」＊２）＋１` は内側の警告 1 行と結果 1。従来の「外側も値なし」の伝播は無くなる）。
6. When 値なしを代入して未代入になった変数を算術の被演算子にしたとき, the pasta shall 1 と同じく 0 とみなす。
7. When グローバル変数に 1 の結果を代入してゴーストを終了・再起動したとき, the pasta shall 保存された値から数え続ける（`＄＊回数＝＄＊回数＋１` が起動のたびに 1・2・3… と増える）。
8. The pasta shall 被演算子がすべて数値・数字だけの文字列である算術式の結果を、従来から変えない。

### Requirement 2: 連結の文脈の nil は空文字列

**Objective:** ゴースト作者として、未代入の変数を `＆` でつないでも、その部分が空になるだけで文全体が消えないようにしてほしい。

#### Acceptance Criteria

1. When 連結演算子 `＆` の被演算子の値が nil であるとき, the pasta shall その被演算子を空文字列とみなして連結を続ける。nil の出どころは Requirement 1.1 と同じく問わない（`「合計」＆＄未代入＆「個」` は `合計個`）。
2. When 括弧内の算術が連結の被演算子になったとき, the pasta shall 算術側の規則（Requirement 1）で計算した結果を連結する（`「合計」＆（＄未代入＋１）` は `合計1`）。
3. When 内側の演算に nil や変換できない値があったとき, the pasta shall 内側の演算を Requirement 1〜4 どおりに計算し、その結果を外側の連結に使う（`「a」＆（true＆「b」）` は内側の警告 1 行と結果 `ab`）。
4. The pasta shall 1〜3 を、連結を書けるすべての位置に同じく適用する。
5. The pasta shall 被演算子がすべて文字列・数値である連結の結果（数値の表記を含む）を、従来から変えない。

### Requirement 3: nil を 0・空文字列とみなしたときのログ

**Objective:** 入門ガイドの読者として、作例どおりに書いて初めて起動したときに、ログに警告が並んで戸惑うことのないようにしてほしい。書き間違いは、今までどおりログで気づけるようにしてほしい。

#### Acceptance Criteria

1. When nil を 0 または空文字列とみなしたとき, the pasta shall ログ（`warn`・`debug` のいずれも）を出さない。
2. The pasta shall nil の扱いについて、新しい警告の種類や出口を増やさない。
3. The pasta shall 関数が見つからないとき・動的関数呼び出しの変数が未代入のときに、呼び出しの時点で出している既存の警告（`act:expr_fn - handler not found`・`act:global_fn - function not found`・`undefined variable`）を変えない。

### Requirement 4: nil 以外の、数値・文字列にできない値

**Objective:** ゴースト作者として、数字でない文字列の計算や、真偽値の連結のような書き間違いは、ログで気づけるようにしてほしい。そのうえで、式はいつも値を返してほしい。

#### Acceptance Criteria

1. If 算術演算子の被演算子が、nil 以外で数値にできない値（数字でない文字列 `「abc」`・全角数字だけの `「１２」`・空文字列 `「」`・真偽値・表・関数）であるとき, the pasta shall 実行時エラーにせず、演算子とその値を含む警告ログを 1 行出し、その被演算子を 0 とみなして演算を続ける（`「abc」＋１` は警告 1 行と結果 1。議題 #4 で確定）。
2. If 連結演算子の被演算子が、nil 以外で文字列にできない値（真偽値・表・関数）であるとき, the pasta shall 実行時エラーにせず、その値を含む警告ログを 1 行出し、その被演算子を空文字列とみなして連結を続ける（`true＆「x」` は警告 1 行と結果 `x`。議題 #4 で確定）。
3. The pasta shall 1・2 の警告の文言と含まれる情報（演算子・被演算子の場所または関数名・値とその種類）を、従来から変えない。
4. The pasta shall 空文字列を代入した変数を nil（未代入）として扱わず、1 の変換できない値として扱う（`＄x＝「」` のあとの `＄x＋１` は警告 1 行と結果 1）。
5. The pasta shall 算術の文脈の値を必ず数値に、連結の文脈の値を必ず文字列にしてから演算する。演算子に数値・文字列以外が届いて実行時エラーになることは無い（表のメタメソッドも呼ばれない）。

### Requirement 5: 式の外の nil と Call のターゲット

**Objective:** ゴースト作者として、演算子の無い場所での nil の扱い（台詞での参照・Call のターゲット）がどうなるかを、マニュアルで確認できるようにしてほしい。

#### Acceptance Criteria

1. The pasta shall アクション行で未代入の変数を参照したときの扱い（空文字として展開し、警告 `act:talk - undefined variable` を出す）を変えない。（**【仮定】** 要件ディスカッションの議題で確定する）
2. The pasta shall Call のターゲットが変数 1 つ・関数呼び出し 1 つ（`＞＄未代入`・`＞＠f（）`）で nil のときの扱い（警告と失敗表記 `【Call失敗：…】`）を変えない。演算子が無いので文脈が無い。
3. When Call のターゲットが連結・算術の式で、被演算子に nil があるとき, the pasta shall Requirement 1・2 どおりに評価した結果をターゲットにする（`＞＄時間帯＆「の挨拶」` で `＄時間帯` が未代入なら `の挨拶` を探す）。（議題 #5 で確定: Call が失敗するのは、受け取った値が nil・空文字列・文字列と数値以外のとき、という規則は変えない。連結・算術の結果は nil にならないので、この規則のまま検索に進む。検索して見つからなければ、既存の「見つからない」の失敗表記になる）
4. When Call のターゲットの連結の結果が空文字列になったとき（`＞＄未代入＆＄未代入２`）, the pasta shall 従来どおり空文字列の値として Call を失敗させる（`【Call失敗：値が空文字列】`）。
5. The pasta shall 「値なしを代入した変数は未代入になる」規則、関数呼び出しの引数に nil をそのまま渡すこと、動的参照（`＠＄名前`・`＠＄名前（…）`）の扱いを変えない。

### Requirement 6: マニュアルとスキルの同期

**Objective:** ゴースト作者と入門ガイドの読者として、マニュアルを読めば「式の中の nil は、算術なら 0、連結なら空文字列」という規則と、その境界が分かるようにしてほしい。

#### Acceptance Criteria

1. The pasta manual（`grammar/variables.md`「算術の評価」「連結の評価」） shall Requirement 1〜4 の規則を書き、作例（`＄x＝＄未代入＋1`・`＄y＝「合計」＆（＄未代入＋1）`・`＄x＝「合計」＆＄未代入＆「個」` など）を新しい結果に合わせて書き直す。除数が nil のとき（`inf`・非数）、変換できない値は警告を出して 0・`""` とみなすこと、空文字列は nil ではなく変換できない値であること、演算が値なしを作らなくなったこと（値なしの伝播が無くなったこと）を書く。
2. The pasta manual（`grammar/call-jump.md` の Call の失敗の表） shall Requirement 5.2〜5.4 の確定内容に合わせて、連結・算術のターゲットの行を書き直す（「それ以外の式」が値なしになる行と、`＞＄未代入＆「_挨拶」` の補足は、演算が値なしを作らなくなったので消すか書き換える）。
3. The pasta manual（`lua/script-api.md` の `act:arith`・`act:concat`、`internals/internal-modules.md`「生成コード用のメソッド」、生成形を変えるなら `internals/transpiler.md`） shall 確定した実装の形に合わせて書く。
4. The pasta skill（`pasta-ghost-authoring/SKILL.md` の算術・連結の行と `references/`） shall マニュアルと同じ内容になる（`references/` は再生成し、鮮度照合とリンク検証が通る）。
5. When 入門ガイド 10 段目の作例（`＊会話` の中で `＄＊回数＝＄＊回数＋１` に続けて `＄＊回数` を台詞に使う）を初期化行も Lua も無しに実行したとき, the pasta shall 1 回目に「1」、2 回目に「2」と数えた台詞を出し、ログに警告を出さない。

### Requirement 7: 挙動を固定する検証

**Objective:** 開発者として、新しい規則と変えない規則の両方がテストで固定され、現行挙動を固定している既存テストが新しい挙動に揃っていてほしい。

#### Acceptance Criteria

1. The pasta test suite shall Requirement 1〜3 を、ランタイムのテストと、DSL をトランスパイルして実ランタイムで実行するテストの両方で固定する。nil の出どころ（ローカル・グローバル・シーン引数・値を返さない関数・値なしの内側の演算）ごとのケースを含む。
2. The pasta test suite shall Requirement 4・5 の確定内容を固定する。
3. The pasta test suite shall 現行の「nil・変換できない値は警告＋値なし」「外側も値なし」を期待している既存のテスト（ランタイムの Lua テスト・トランスパイル→実行のテストとその期待警告・生成形を変えるならスナップショット）を新しい挙動に更新し、矛盾する期待を残さない。
4. The pasta shall 本仕様の変更後も、既存のテスト（ワークスペース全体）とマニュアルの検証（鮮度照合・リンク検証）がすべて通る。
