# Implementation Plan

## 1. 基盤: SHIORI デフォルトの SSOT 定義

- [ ] 1.1 `[ghost]` の SHIORI デフォルト値を単一供給源（SSOT）として定義する
  - 既存の `Default` ＋ `default_*()` 関数規約に従い、`[ghost]` の SHIORI デフォルト値（`talk_interval_min=180` / `talk_interval_max=300` / `hour_margin=30` / `spot_newlines=1.5`）を保持する不変のデフォルト供給源を新設する
  - この供給源は値の供給のみを担い、`[ghost]` を設定テーブルから型抽出する経路には転用しない（Lua 公開経路は不変に保つ）
  - 観測可能な完了条件: デフォルト供給源のデフォルト値を取得すると `180 / 300 / 30 / 1.5` がそのまま返る単体テストが通る
  - _Requirements: 1.2, 1.3, 3.3_
  - _Boundary: GhostConfig_

- [ ] 1.2 慣例 dic 配置を網羅する既定 glob へ拡張する
  - 辞書探索パターンの既定値を一階層のみのものから、任意深さ（直下・一階層・多階層）を網羅する再帰形へ変更する
  - 明示的に探索パターンを指定済みの既存ゴーストには既定が適用されない（加算的・非破壊）ことを設計どおりに維持する
  - 観測可能な完了条件: 既定の探索パターンを取得すると再帰形（任意深さ）の値が返る単体テストが通る
  - _Requirements: 2.5_
  - _Boundary: default_pasta_patterns_

## 2. コア: 単一補完チョークポイントと actor 判別

- [ ] 2.1 ロード後のデフォルト補完チョークポイントを実装する
  - 設定ロード後に、SHIORI プロファイルのデフォルト供給源（SSOT）に基づき、省略された `[ghost]` のフィールドのみをフィールド単位で補完する単一ステップを新設する
  - 明示的に記述された値は上書きしない（フィールド単位の欠落補完のみ）こと、および再適用しても結果が変わらない（冪等）ことを保証する
  - エンジンプロファイル専用セクション（`[package]`）は補完対象としない
  - 観測可能な完了条件: `[ghost]` を一部だけ書いた設定を補完すると欠落キーのみ既定で埋まり、明示値（例: `talk_interval_min=120`）は不変であること、および二重適用で値が変わらないことを検証する単体テストが通る
  - _Requirements: 2.1, 2.2, 2.4, 3.1, 3.2, 3.4_
  - _Boundary: apply_shiori_defaults_

- [ ] 2.2 `[actor]` 不在の軽量警告を追加する
  - 補完ステップ内で `[actor]` セクションが存在しない場合に、起動を停止せず利用者が判別可能な軽量警告（ロギング）を1回発する
  - 警告メッセージはパスや機密を含まない一般的な文言に留める
  - 観測可能な完了条件: `[actor]` を含まない設定の補完時に警告が発火し、かつ補完処理が正常終了する（起動を妨げない）ことを検証するテストが通る
  - _Requirements: 2.3_
  - _Boundary: apply_shiori_defaults_

- [ ] 2.3 補完チョークポイントをロード経路へ結線する
  - 設定生成の唯一の地点（パース処理の戻り直前）で補完ステップをちょうど1回呼び出し、Rust 消費側と Lua 公開側の双方が補完後の同一状態を見るようにする
  - 補完後は `[ghost]` セクションが常に実体化され、`@pasta_config.ghost.*` が常に存在する状態になることを設計どおりに確定する
  - 観測可能な完了条件: `[ghost]` を一切書かない設定をパースしても、結果の設定に `ghost` セクションが実体化され既定値が入っていることを検証する単体テストが通る
  - _Requirements: 3.1, 3.3_
  - _Depends: 1.1, 2.1, 2.2_
  - _Boundary: apply_shiori_defaults, PastaConfig::parse_

  - リファレンスに記載する SHIORI デフォルト値は SSOT 由来の値とする
  - 観測可能な完了条件: 設定リファレンスに3分類表・最小テンプレート・フルリファレンステンプレート・`[package]` 予約注記がすべて含まれる
  - _Requirements: 1.1, 1.4, 1.5, 4.1, 4.2, 5.1, 5.2, 5.3, 7.1, 7.3_

- [ ] 3.2 (P) README と入門章へ最小構成を反映する
  - ライブラリ README の設定ファイル章に分類と最小構成を反映する
  - 入門章に最小構成の `pasta.toml` 例（必須の `[actor]` のみ）を提示し、利用者がフル記述のコピーを強制されないようにする
  - 観測可能な完了条件: README と入門章の双方に `[actor]` のみの最小構成例が掲載され、最小テンプレートと整合する
