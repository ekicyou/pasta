# 実装計画

- [x] 1. 基盤: 設定の既定値
- [x] 1.1 `[ghost] line_newlines` の既定値を設定の正本に足す
  - ゴースト設定の正本に、行の改行の幅（浮動小数・既定 `0.0`）と既定値の関数を足し、他の既定値と同じく公開する
  - SHIORI の既定値の補いで、書かれていない `line_newlines` を `0.0` で補う。型・範囲の検査は足さない（`spot_newlines` と同じ）
  - `[ghost]` を省いた設定を読み込むと、Lua の設定の `ghost.line_newlines` が `0.0` で読めるテストが通る
  - _Requirements: 1.2, 1.6_

- [ ] 2. 台詞の継ぎ目（act）
- [ ] 2.1 行の頭の印を受け取り、次に積む台詞に継ぎ目を付ける
  - act に行の頭の印のメソッドを足す。行の改行の値が `nil` でも `0` でもないときだけ「次の台詞に継ぎ目」を立て、自分を返す
  - 台詞とさくらスクリプトのトークンに、立っていれば行の頭の継ぎ目（位置 1）を付けて印を消す。`raw_script` には付けない。`talk(nil)`（積まない）は印を消さず次の台詞へ持ち越す
  - 新しい Lua のテストのスイートを作り、Lua のテストの一覧に登録する
  - `pasta_check` の act のメソッドの一覧に印のメソッドを同時に足し、数の検査を 27 から 28 に直す（一覧と act の実際のメソッドを照合するテストがあるため、act と同じ作業で直す）
  - 値が `0`・`nil` のとき、印の後のトークンに継ぎ目の欄が現れない（トークンの表が今と同じ）テストと、持ち越しのテストが通り、`pasta_check` のテストも通る
  - _Requirements: 2.1, 6.1, 6.4_
- [ ] 2.2 同じアクターの台詞の結合で継ぎ目の位置を残す
  - 結合を始める台詞は継ぎ目を写して持ち、元のトークンの表を書き換えない
  - 続けて結合する台詞の継ぎ目に、結合前のテキストの長さを足して加える（位置は 1 始まり・昇順・`#text + 1` 以下）
  - 3 つの台詞を結合したとき、継ぎ目が結合後のテキストで各台詞の始まりのバイト位置を指すテストが通る
  - _Requirements: 2.1, 2.5_

- [ ] 3. 行の改行の判定と差し込み（組み立て）
- [ ] 3.1 列の動きの分類（Rust の写し）と改行のタグの換算を足す
  - 組み立てに、単位の名前と引数から「次」「最初」「飛ぶ」「動かない」を返す局所関数を足し、内部の口に出す（Rust の分類と片方だけ直さない旨を 1 行の注で残す）
  - 行の改行の幅から改行のタグを作る局所関数を足す（`N` が 0 以下なら空、100 なら `\n`、他は `\n[N]`。既存の換算を使う）
  - Rust の分類のテストと同じ単位の並びで、写しの分類が `talk_to_script` の列の動きと一致するテストと、換算（`1.8`・`1.0`・`0.5`・`0.009`・`-1`）のテストが通る
  - _Requirements: 1.3, 1.4, 4.1, 4.2_
- [ ] 3.2 行の状態を列の状態に持ち、入れる継ぎ目で改行を差し込む
  - 列の状態に Lua だけの 2 つの欄（続けられる・保留）を持ち、列を進める・最初の列へ戻す所でどちらも捨てる（行の機能を使わないときの列の表は今と同じ）
  - 台詞を単位ごとに読み、継ぎ目・見える字・列を動かす単位で設計の行の状態のとおりに動かし、保留のまま見える字に来たらその字の直前に改行のタグを差し込む。字の無い行の保留は次の継ぎ目の位置に出し、保留を立てたままにする
  - 行の改行の値が `nil`・`0` なら台詞を読まずに元のテキストを返す。組み立ての設定に `line_newlines` を足し、台詞を変換に渡す 4 か所を差し込みの関数に通す。組み立て本体には状態変数も分岐も足さず、新しい関数は複雑度 15 以下に分ける
  - 同じ話し手の継ぎ目で 1 つ・字の無い行の後の空の列（`なら。\s[5]\n[180]\n[180]次の話。`）・結合した台詞の途中・さくらスクリプトの頭・Call 先の後の継ぎ目・話し手の切り替えの後・選択肢の前後・`\c` の後・出力の最初・スポットの割り当てを消した後・差し込み後に列が 1 つ進み幅が 0 から数え直されること、のテストが通る
  - _Depends: 2.2_
  - _Requirements: 1.3, 1.7, 2.1, 2.2, 2.4, 2.5, 2.6, 3.1, 3.2, 3.3, 3.4, 3.5, 5.1, 5.2_
- [ ] 3.3 手書きの位置の指定を尊重する規則を確かめる
  - 行の頭の位置を決めるタグ（`\n[180]\_u[0x3000]`・`\![bind,…]\n[180]`・`\_w[2000]\c`・`\_l[-283,0]`）では入れない
  - 前の出力の末尾の改行・`\_l[…]`・`\c` が同じ台詞・別のさくらスクリプト・改行のトークンにあるときは入れない。行の末尾の `\_l[-253,0]` はその行自身の頭を止めない
  - `raw_script` をはさんでも判定が変わらない。エスケープ・囲みの中の `\n` を位置のタグにしない
  - 入れなかった継ぎ目の出力が `line_newlines` なしとバイトまで同じ（budoux のあるアクター・句読点のウェイトを含む）、手書きの `＠改行` を消して設定した出力が手書きの出力と同じ、話し手が戻った直後の表情だけの台詞で `spot_newlines` だけが出る、のテストが通る
  - _Depends: 3.2_
  - _Requirements: 3.1, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 6.3_

- [ ] 4. 行の頭の印の生成（トランスパイラ）
- [ ] 4.1 アクション行と継続行の頭に印の 1 行を出す
  - アクション行と継続行の生成で、アクションの前に値によらない印の 1 行を書き、その行の span で行の対応に記録する。継続行ではアクターの確認（`InvalidContinuation`）の後に書く
  - 変数代入・Call・選択肢・空行・コメントには出さない
  - アクション行・継続行の生成の単体テスト（アクション行の要素の生成のテスト）の期待値を印つきに直し、印がアクション行と継続行だけに出る・局所シーンの頭の継続行が今のエラーのまま・印の行が継続行の span に記録される、のテストが通る
  - ソースマップと行の対応のテストをこの作業で回し、印の行で行番号がずれても食い違わないことを確かめる
  - _Depends: 2.1_
  - _Requirements: 2.2, 2.3, 6.4_
- [ ] 4.2 生成した Lua の比較の期待値を作り直す
  - 4.1 で直した単体テスト以外の、生成物を文字列で比べるテスト（サンプルの期待値・トランスパイラの比較とスナップショット・他の生成の単体テスト）の期待値に印の行を入れて作り直す
  - サンプルの生成物に残る改行コードだけの差分はコミットに入れない
  - `pasta_lua` のテストがすべて通り、印つきの生成物を `pasta_check` で検査しても未知のメソッドの指摘が出ない

- [ ] 5. 統合: 設定から出力まで
- [ ] 5.1 SHIORI の act で値を読み、act と組み立てに渡す
  - SHIORI の act を作るときに `[ghost] line_newlines` を既定 `0.0` で読み（リテラルは正本の表記と同じ）、印の要否と組み立ての設定に渡す。型の検査はしない
  - アクターごとの同名のキーは読まない
  - 値を設定した act の出力に行の改行が入り、数でない値は改行を作る所で Lua のエラーになる（`spot_newlines` と同じ）ことのテストが通る
  - _Depends: 1.1, 2.2, 3.2_
  - _Requirements: 1.1, 1.5, 1.7_
- [ ] 5.2 一時ゴーストで設定の有無と出力を比べる E2E テストを足す
  - 一時ゴーストを読み込み、SHIORI の要求で出力を比べるテストを新しく作る（既存の連鎖トークの割り込みのテストと同じ作り）
  - `line_newlines = 1.8` で、継続行の前と書き直した行の前に `\n[180]` が入り、`ぱすた：＠左` の前には入らない。Call 先の最初の同じ話し手の行に入る
  - ぱすたの実例（`　　：＠改行` → `ぱすた：＠左` → `＞系統` の先の `ぱすた：＠目閉じ`、`ぱすた：\c` → Call 先の頭の行）には入らない。相手役の継続行 `　　：＠改行　…` の出力が設定の前後で同じ
  - 同じ辞書を設定なし・`0` で読み込んだ出力が今の版と同じ。`[actor."ぱすた"] line_newlines` だけでは入らない
  - 新しい E2E テストが通る
  - _Requirements: 1.1, 1.2, 1.7, 2.1, 2.2, 2.5, 4.1, 4.2, 4.5, 6.1_
