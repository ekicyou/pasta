# Requirements Document

## Project Description (Input)
**誰が困っているか**: Pasta DSL でゴーストを書く作者と、デバッガ（DAP）でカーソル位置からシーンをキックする作者。

**現状**: グローバルシーンのランタイム名は「サニタイズした名前＋通し番号」を区切り無しでつないで作る（`メイン` の 1 つ目は `メイン1`）。そのため末尾が数字のシーン名で内部名が別のシーンと重なる。`＞A1` が `A` の 1 つ目を選び、内部名が完全一致する場合（`A1` の 1 つ目と `A` の 11 個目がどちらも `A11`）はシーン表が上書きされてシーンが消える。デバッガの `split_runtime_global` は名前末尾の数字まで通し番号とみなし（`章11` を (`章`, 11) と読む）、カーソル位置のキックが別のシーンを選ぶ。さらに位置からのキックは前方一致で引くため、`会話1` に対して `会話10` が再生されうる。

**何を変えるか**: どんなシーン名でもランタイム名が一意で、名前と通し番号に曖昧さなく分けられる形式に変える（区切りの導入。推奨は `_`。キック・DAP の番兵 `:` を含まず、`scene-search-key-normalization` のサニタイズ規則と両立する）。デバッガのシーン identity 索引と位置からのキックが正しいシーンを選び、キックは完全一致で引く。形式を作る・分ける処理を Rust と Lua それぞれ 1 か所にまとめる。マニュアル（`lua/modules/pasta-search.md`・`lua/patterns.md`・`lua/script-api.md`・`internals/internal-modules.md`・`internals/debug.md`）を新形式に更新し、スキル `references/` を再生成する。サニタイズ規則とシーン検索アルゴリズム（前方一致・シャッフル）は対象外。

## Introduction

Pasta は、グローバルシーンを実行時に「登録名」で区別する。現行の登録名は、シーン名の照合用の名前に同名シーンの通し番号を **区切り無しで** つないだもの（1 つ目の `＊メイン` は `メイン1`）である。このため、末尾が数字のシーン名では登録名が別のシーンの登録名と重なったり（`＊A1` の 1 つ目と `＊A` の 11 個目がどちらも `A11`）、別のシーンの登録名の先頭部分になったり（`＞A1` が `＊A` の 1 つ目 `A1` に前方一致する）する。前者ではシーン表の上書きでシーンが消え、後者では Call が別のシーンを選ぶ（U21）。

同じ曖昧さはデバッガにも及ぶ。デバッガのシーン索引は登録名の末尾の数字をすべて通し番号とみなすため、`＊章11` を `＊章` の 11 個目と取り違え、カーソル位置からのキックが別のシーンを再生する。さらに位置からのキックは、デバッガが確定した登録名を前方一致の検索で引き直すため、`会話1` に対して `会話10` が再生されうる。

本仕様は、取り違えの根本原因である「シーンを 1 つに特定する名前（登録名）を、作者が書いた名前で探すときの照合相手にも使っていること」を解消する。登録名を「照合用の名前・区切り `_`・通し番号」の形にして、どんなシーン名でも登録名が一意で、名前と通し番号に曖昧さなく分けられるようにする。シーン検索は、通し番号を除いた照合用の名前だけと前方一致させ、検索キーが通し番号の部分に一致しないようにする。あわせて、デバッガのシーン索引と位置からのキックが正しいシーンを選ぶようにし（キックは完全一致で引く）、登録名を作る規則と分ける規則を一か所にまとめ、マニュアル（API・内部設計の唯一の権威）と生成スキルの `references/` を新しい形式に揃える。

本書で使う用語:

- **照合用の名前**: 名前のうち、Unicode の英字・数字と `_` 以外の文字を `_` に置き換えた名前（`scene-search-key-normalization` が決めた規則。本仕様では変えない）。例: `会話・朝` → `会話_朝`。
- **通し番号**: 照合用の名前が同じグローバルシーンに、定義順に 1 から振る番号（現行と同じ。本仕様では振り方を変えない）。
- **区切り**: 登録名の中で、照合用の名前と通し番号の間に置く文字。`_` とする。
- **登録名**: 実行時にグローバルシーンを 1 つに特定する名前。`@pasta_search` の `search_scene` が返し、`search_scene`・`search_word` の第 2 引数や `WORD.create_local` の第 1 引数に渡す名前である。本仕様の変更後は「照合用の名前＋`_`＋通し番号」になる（1 つ目の `＊メイン` は `メイン_1`、1 つ目の `＊会話・朝` は `会話_朝_1`）。登録名は特定するための名前であり、名前で探すときの照合相手にはしない。
- **ローカルシーンの登録名**: ローカルシーンの照合用の名前に `_` と通し番号を付けた名前（例: `選択肢_1`）。形式は現行のまま変えない。グローバルシーンと同じく、名前で探すときの照合相手にはしない。
- **シーン identity**: デバッガがカーソル位置から確定する、実行時のシーンの名前の組（グローバルシーンなら登録名、ローカルシーンなら親の登録名とローカルシーンの登録名）。

> **決定（議題 1）**: 区切りは `_` とする。`_` は照合規則で置き換わらない（単語のスコープに渡しても変わらない）、キック・DAP の番兵 `:` を含まない、通し番号が数字だけなので「最後の `_` の後ろが数字だけ」で一意に分けられる。シーン検索は通し番号を除いた照合用の名前と前方一致させるので、区切りが `_` でも、検索キーが通し番号の部分に一致することは無い。

## Boundary Context

- **In scope**:
  - グローバルシーンの登録名の形式（区切りの導入）と、その形式を作る規則・分ける規則を一か所にまとめること。
  - シーン検索の照合相手を、登録名から「通し番号を除いた照合用の名前」に変えること（グローバルシーンとローカルシーンの両方。前方一致・シャッフル＆順次消費の規則は変えない）。
  - 形式の変更に伴う、Call・シーン単位の単語（ローカル単語）の、登録名を介した振る舞いの維持。
  - デバッガのシーン identity 索引が、どんなシーン名でも正しいシーンへ解決すること。
  - 位置からのキックを、デバッガが確定したシーン identity の完全一致で引くこと（グローバル・ローカルとも）。
  - 修正を固定するテスト、既存テスト・スナップショットの期待値の更新。
  - マニュアルの該当章の更新とスキル `references/` の再生成。
- **Out of scope**:
  - 照合規則（サニタイズ規則）の変更（`scene-search-key-normalization` が持つ。完了済み）。
  - シーン検索の選び方（前方一致・シャッフル＆順次消費・Call の 5 段の探索順）の変更。照合相手を登録名から照合用の名前に変えることは In scope。
  - ローカルシーンの登録名の形式の変更（既に `名前_通し番号` の形。変えるのは検索の照合相手だけ）。
  - 通し番号の振り方（1 始まり・照合用の名前ごと・定義順）の変更。
  - 旧形式の登録名（`メイン1` の形）を新形式の別名として受け付けること（受け付けない。登録名を Lua に直接書いて使い込んでいるゴーストはまだ無いと見て、告知だけで移行する）。
  - 存在しないシーンの登録名を渡したときの警告（旧形式の登録名を含む。告知だけで足りると判断した）。
  - 照合用の名前が重なる名前・登録名の先頭部分が重なる名前の検出・警告（読み込み時の警告や検査ツールでの検出）。
  - `act.lua`（Wave 2 では `act-token-grouping-fix` が持つ）・`actor.lua`（Wave 2 では `actor-proxy-act-delegation` が持つ）の振る舞いの変更。
- **Adjacent expectations**:
  - `scene-search-key-normalization`（完了）の要件 3.2 は「登録名を検索する名前として渡したときの結果を変えない」と決めた。本仕様はこれを意図して改める。`search_scene` の第 1 引数は作者が書くシーン名であり、登録名を渡しても、その登録名のシーンを指す結果にはならない（要件 2.5）。同 spec のほかの要件（照合規則・第 2 引数の扱い）は保つ。
  - Wave 2 で並走する `search-selector-indices` が `pasta_core` のシーン表のシャッフル部分に触れる場合、本仕様の索引の変更と重ならないことを設計で確かめる。
  - `dsl-codegen-runtime-safety`（完了）の後に着手する。トランスパイラのスナップショットを広く更新するのは Wave 2 では本仕様だけである。
  - 後続の `call-execution-correctness`（スナップショットを本仕様の後に変える）・`scene-attribute-store`（`scene.lua` を本仕様の後に触る）は、本仕様が決めた登録名の形式と、形式を作る・分ける一か所の規則を前提にする。
  - キックの完全一致化とデバッガ索引の修正は、形式の変更と独立して先に出せる小さな単位である（ただし登録名が完全に重なる場合は形式の変更でしか直らない）。出す順序は設計・タスクで決める。

## Requirements

### Requirement 1: 一意で曖昧さなく分けられるグローバルシーンの登録名

**Objective:** As a ゴースト作者, I want どんな名前のグローバルシーンも、ほかのシーンと重ならない登録名を持つこと, so that 名前の付け方（末尾が数字かどうか）によってシーンが消えたり取り違えられたりしない。

#### Acceptance Criteria

1. The Pasta runtime shall グローバルシーンの登録名を、照合用の名前・区切り `_`・通し番号をこの順につないだ名前にする（1 つ目の `＊メイン` は `メイン_1`、2 つ目は `メイン_2`、1 つ目の `＊会話・朝` は `会話_朝_1`）。
2. When 照合用の名前または通し番号の異なる 2 つのグローバルシーンがあるとき, the Pasta runtime shall 2 つに異なる登録名を与える（例: `＊A1` の 1 つ目は `A1_1`、`＊A` の 11 個目は `A_11` になり、重ならない）。
3. When `＊A1` を 1 つと `＊A` を 11 個定義したゴーストを読み込んだとき, the Pasta runtime shall 12 個すべてのグローバルシーンを実行可能な状態で保持し、どのシーンの登録内容もほかのシーンの登録内容で上書きしない。
4. The Pasta runtime shall 任意の登録名から、元の照合用の名前と通し番号を一通りに復元できる形式にする（最後の `_` の後ろの数字だけの部分を通し番号、その手前を照合用の名前とする。`章_1_1` は（`章_1`, 1）、`章_11` は（`章`, 11））。
5. The Pasta runtime shall 登録名に、キック・DAP の番兵 `:` を含めない。
6. The Pasta runtime shall 通し番号の振り方（照合用の名前ごとに、定義順に 1 から）と、ローカルシーンの登録名の形式（`選択肢_1` の形）を変えない。

### Requirement 2: 名前どおりのシーンを選ぶ Call とシーン検索

**Objective:** As a ゴースト作者, I want Call とシーン検索が、書いた名前で始まる名前のシーンだけを候補にすること, so that `＞A1` と書いたときに `＊A` が実行されることが無い。

#### Acceptance Criteria

1. The Pasta runtime shall グローバルシーンとローカルシーンの Call とシーン検索で、検索する名前の照合用の名前を、各シーンの通し番号を除いた照合用の名前と前方一致させて候補を決め、登録名の通し番号・区切りの部分には一致させない。
2. When `＊A` と `＊A1` があるゴーストで `＞A1` を Call したとき, the Pasta runtime shall 照合用の名前が `A1` で始まるグローバルシーンだけを候補にし、`＊A` を候補にしない。
3. When Lua から `SCENE.search("A1")` または `@pasta_search` の `search_scene("A1")`（第 2 引数なし）を呼んだとき, the Pasta runtime shall 照合用の名前が `A1` で始まるグローバルシーンだけを候補にし、`＊A` を返さない。
4. When `＊章` と `＊章・1` があるゴーストで `＞章・1` を Call したとき, the Pasta runtime shall 照合用の名前が `章_1` で始まるグローバルシーンだけを候補にし、`＊章` を何個目であっても候補にしない。
5. When 登録名の形の名前（例: `メイン_1`）を `search_scene` の第 1 引数に渡したとき, the Pasta runtime shall それを作者が書いたシーン名として扱い、照合用の名前が `メイン_1` で始まるグローバルシーンだけを候補にする（`＊メイン` の 1 つ目を指す結果にしない）。
6. When 検索する名前が、本仕様の変更前にどの登録名の通し番号の部分にも一致していなかったとき, the Pasta runtime shall 本仕様の変更前と同じシーンの集合を候補にし、同じ前方一致・シャッフル＆順次消費の規則で 1 つを選ぶ（返る登録名の形だけが新しい形式になる）。
7. When `search_scene` がグローバルシーンを返すとき, the Pasta runtime shall 新しい形式の登録名を返し、その登録名を第 2 引数に渡したローカルシーンの検索で、そのグローバルシーンのローカルシーンを返す。
8. When 動的ターゲット（`＞＄変数`・`＞＠関数（）`・`＞「文字列」` など）や SHIORI イベントからグローバルシーンを Call したとき, the Pasta runtime shall `＞シーン名` で書いた場合と同じ候補から 1 つを選び、その出力を返す。
9. While `set_scene_selector` に整数を渡して決まった順に選ぶ設定であるとき, the Pasta runtime shall 照合用の名前が同じグローバルシーンを通し番号の小さい順に並べる（`メイン_2` は `メイン_10` より先）。
10. When 同じグローバルシーンの中に `・挨拶` と `・挨拶・1` があり、そのシーンの中で `＞挨拶・1` を Call したとき（`search_scene("挨拶・1", 登録名)` も同じ）, the Pasta runtime shall 照合用の名前が `挨拶_1` で始まるローカルシーンだけを候補にし、`・挨拶` を何個目であっても候補にしない。
11. When Lua で直接定義したシーン関数（通し番号を持たない名前。例: Lua ブロックの `function SCENE.加算ループ`）を Call・シーン検索するとき, the Pasta runtime shall その関数名の全体を照合相手にして前方一致させる。名前が `_` と数字で終わる関数（例: `SCENE.step_2`）を、生成されたローカルシーンと見分けられる場合は名前の全体を、見分けられない場合は最後の `_` と数字を除いた部分を照合相手にし、どちらであるかをマニュアルに書く（見分ける方法は設計で決める）。
12. While シーン辞書の確定前（`main.lua`・`entry.lua` の実行中）であるとき, the Pasta runtime shall 確定後と同じ形式の登録名を返し、同じ照合相手で候補を決める。

### Requirement 3: 登録名を受け取る Lua API（シーン単位の単語・単語検索）

**Objective:** As a Lua でゴーストを拡張する作者, I want 登録名を渡す Lua API が新しい形式の登録名で動くこと, so that シーン単位の単語（ローカル単語）を Lua から登録・検索できる。

#### Acceptance Criteria

1. When DSL のシーンに単語を定義した（生成コードが `scene:create_word(キー)` で登録した）とき, the Pasta runtime shall 本仕様の変更前と同じく、そのシーンを実行中の単語参照でその単語を返す。
2. When Lua から `WORD.create_local(登録名, キー)` に新しい形式の登録名（例: `メイン_1`）を渡して単語を登録したとき, the Pasta runtime shall その登録名のグローバルシーンを実行中の単語参照で、登録した単語を返す。
3. When Lua から `@pasta_search` の `search_word(キー, 登録名)` に新しい形式の登録名を渡したとき, the Pasta runtime shall その登録名のグローバルシーンのローカル単語から探す。
4. If Lua から旧形式の登録名（例: `メイン1`）を、登録名を受け取る引数（`WORD.create_local` の第 1 引数・`search_scene` と `search_word` の第 2 引数）に渡したとき, the Pasta runtime shall それを新しい形式の登録名の別名として扱わず、該当する登録名が無い場合と同じ結果（登録した単語がどのシーンを実行中でも参照されない・検索結果なし）にし、エラーで停止しない。
5. The 本仕様の変更を入れるプルリクエストの件名と本文 shall 登録名の形式の変更（`メイン1` → `メイン_1`）と、`search_scene` の第 1 引数に登録名を渡す使い方の廃止を、Lua コードの書き換えが必要になる破壊的変更として、書き換え方とともに書く（リリースノートはコミット履歴から作られるため、ここが告知の出どころになる）。

### Requirement 4: デバッガのシーン identity 索引

**Objective:** As a デバッガを使う作者, I want カーソル位置のシーンが、名前にかかわらず正しいシーン identity に解決されること, so that カーソル位置からのキックやシーンの表示が別のシーンを指さない。

#### Acceptance Criteria

1. When `＊章` を 11 個以上と `＊章11` を定義したゴーストで、カーソルが `＊章11` の範囲にあるとき, the Pasta debugger shall シーン identity を `＊章11` の登録名に解決し、`＊章` の 11 個目に解決しない。
2. When カーソルがグローバルシーンまたは名前付きローカルシーンの範囲にあるとき, the Pasta debugger shall シーン名が末尾が数字・`_` と数字で終わる・記号を含むのいずれであっても、そのシーンのシーン identity（ローカルシーンなら親の登録名を含む）に解決する。
3. If `.pasta` のシーン定義に対応する実行時のシーンが無いとき, the Pasta debugger shall 本仕様の変更前と同じく、そのシーンを索引に入れない（別のシーンに解決しない）。
4. The Pasta debugger shall `.pasta` 行と生成 Lua 行の対応（ソースマップ）、ブレークポイント、シーン範囲（開始行・終了行・入れ子）の振る舞いを、本仕様の変更前と同じに保つ。

### Requirement 5: 位置からのキックの完全一致

**Objective:** As a デバッガを使う作者, I want 位置からのキックが、デバッガが確定したシーンそのものを再生すること, so that 名前が接頭辞になる別のシーンや、同じ名前のシーン以外の関数が再生されない。

#### Acceptance Criteria

1. When 位置からのキックの対象がグローバルシーンのシーン identity であるとき, the Pasta runtime shall その登録名と完全に一致するグローバルシーンの本体を再生し、その登録名を先頭部分に持つ別の登録名のシーン（`会話_1` に対する `会話_10` など）を再生しない。
2. When 位置からのキックの対象がグローバルシーンのシーン identity であるとき, the Pasta runtime shall 登録名と同じ名前のシーン以外の関数（Lua で登録した同名の関数など）を再生せず、グローバルシーンの表から引いたシーンだけを再生する。
3. When 位置からのキックの対象がローカルシーンのシーン identity であるとき, the Pasta runtime shall 指定された親のグローバルシーンの中で、ローカルシーンの登録名と完全に一致するローカルシーンを再生し、その登録名を先頭部分に持つ別のローカルシーン（`挨拶_1` に対する `挨拶_10` など）を再生しない。
4. If キックの対象のシーン identity と完全に一致するシーンが無いとき, the Pasta runtime shall 本仕様の変更前と同じく、キックを破棄して診断ログを残し、進行中の会話を保持する。
5. The Pasta runtime shall キックの対象を通常のトーク再生と同じ手順で再生し（出力の合成・継続・割り込みの扱いを変えない）、SHIORI リロードの予約文字列によるキックの振る舞いを変えない。

### Requirement 6: 登録名を作る規則と分ける規則の一元化

**Objective:** As a Pasta の開発者, I want 登録名を作る規則と分ける規則が一か所で定義されていること, so that トランスパイラ・ランタイム・デバッガの間で登録名の形式が二度と食い違わない。

#### Acceptance Criteria

1. The Pasta codebase shall 登録名を作る規則と分ける規則を、Rust 側とランタイム（Lua）側でそれぞれ一か所に定義し、登録名を作る・分ける箇所（シーンの登録、トランスパイル時のローカル単語の登録、デバッガの索引）はすべてその定義を使う。
2. The Pasta debugger shall 実行時の登録名を末尾の文字の並びから推測して分けるのではなく、記録されたシーン定義ごとに一か所の規則で登録名を組み立てて、実行時の登録名と突き合わせる。
3. If Rust 側とランタイム側の登録名の形式が食い違ったとき, the Pasta test suite shall 少なくとも 1 つのテストで失敗する。

### Requirement 7: マニュアルと生成スキルの更新

**Objective:** As a ゴースト作者・Pasta の開発者, I want マニュアルが新しい登録名の形式と、デバッガの索引・キックの扱いを正しく書いていること, so that マニュアルを読めば登録名の形と、それを渡す API の使い方が分かる。

#### Acceptance Criteria

1. The Pasta manual shall `lua/modules/pasta-search.md`・`lua/patterns.md`・`lua/script-api.md` の登録名の説明と例を新しい形式にする（例: `"メイン_1"`・`"会話_朝_1"`・`WORD.create_local("メイン_1", …)`）。
2. The Pasta manual shall `internals/internal-modules.md` に、登録名が照合用の名前・区切り・通し番号からなることと、登録名を分ける規則を書き、「区切り無し」の記述を残さない。
3. The Pasta manual shall `internals/debug.md` に、デバッガの索引が新しい形式の登録名で突き合わせることと、位置からのキックがシーン identity の完全一致で引くことを書く。
4. The Pasta manual shall シーン検索が通し番号を除いた照合用の名前と前方一致させること、`search_scene` の第 1 引数に登録名を渡してもその登録名のシーンを指さないこと、決まった順に選ぶときの同名シーンの並びが通し番号順であること、Lua で直接定義したシーン関数の名前の照合相手（要件 2.11）を書く。
5. The Pasta manual shall 旧形式の登録名（区切り無しの `メイン1` の形）を、現行の登録名の説明・例として残さない。
6. When マニュアルを更新したとき, the 生成スキルの `references/` shall マニュアルから再生成され、鮮度の検査とリンク検査に通る。

### Requirement 8: 修正を固定するテスト

**Objective:** As a Pasta の開発者, I want 登録名の一意性・デバッガの索引・キックの完全一致をテストで固定すること, so that 登録名の曖昧さが再発したらすぐに気づける。

#### Acceptance Criteria

1. The Pasta test suite shall `＊A1` の 1 つ目と `＊A` の 11 個目が別々の登録名を持ち、どちらのシーンも実行できることを確かめるテストを含む。
2. The Pasta test suite shall `＊A` と `＊A1` があるときに `＞A1`（および `search_scene("A1")`）が `＊A` を選ばないことを確かめるテストを含む。`＊章` と `＊章・1` があるときに `＞章・1` が `＊章` を選ばないこと、同じシーンの中の `・挨拶` と `・挨拶・1` で `＞挨拶・1` が `・挨拶` を選ばないことも確かめる。
3. The Pasta test suite shall 末尾が数字のシーン名（`＊章11` など）のシーン identity が正しく索引されることを確かめるテストを含む。
4. The Pasta test suite shall 位置からのキックが、登録名を先頭部分に持つ別のシーン（グローバル `会話_10`・ローカル `挨拶_10` など）を再生しないことを確かめるテストを含む。
5. The Pasta test suite shall 登録名を作る規則と分ける規則が、末尾が数字・`_` と数字で終わる・記号を含む名前で往復一致することを確かめるテストを含む。
6. When 本仕様の変更を入れたとき, the Pasta test suite shall 既存のテスト・スナップショットを、登録名の形の変更に伴う期待値の更新だけで通す（ソースマップとデバッガの既存テストを含む）。
