- [ ] 2. ステップA: サーフェスの観測と復旧ロジック
- [ ] 2.1 外見モジュールを新設し、出力文字列のタグ走査とサーフェス観測を実装する
  - 空の外見状態を生成でき、状態は引数で受け取ってその場で変更する（モジュール自身は状態を持たない）
  - `\s[ID]`・`\sN` をサーフェス変更として ID を文字列のまま記録し、1発話内で最後のものを発話アクターとそのスポットへ反映する。`\\` に続く `s` は検出しない
  - スコープ切替タグ（`\0` `\1` `\h` `\u` `\p[N]` `\pN`）で全スポットを不明化し、その文字列の残りはアクターへ記録しない。直前発話アクター・前回発話スポットは消さない
  - アクター未指定の生さくらスクリプトでは、サーフェス変更・bind・スコープ切替のいずれかを含むときだけ全スポットを不明化し、アクター状態は変えない
  - 他タグの引数内の入れ子タグは読み飛ばし、バックスラッシュを含まない文字列は即座に戻る
  - 新しい単体テストファイルを Lua テスト一覧へ登録し、上記の観測規則がすべてグリーンになる
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.7, 1.8_
- [ ] 2.2 アクター切替時のサーフェス復旧判定を実装する

  - 既知サーフェス（無ければアクター設定の既定サーフェス）がスポットの表示中サーフェスと異なる・不明のとき `\s[ID]` を返して表示中サーフェスを更新し、一致・既知なしなら空文字列を返す
  - 切替先グループの先頭タグ列（最初の一般文字・スコープ切替タグ・生スクリプトトークンまで）にサーフェス変更があれば復旧しない
  - A がスポット0→スポット1→スポット0と戻ったとき、スポット0で A の既知サーフェスが復旧されることを単体テストで確認できる
  - 一致・不一致・不明・既知なし・既定フォールバック・既定未設定・先頭抑止・一般文字列後の変更・継続の各ケースが単体テストでグリーンになる

- [ ] 4. ステップB: 着せ替えの観測と復旧
- [ ] 4.1 着せ替え指定の観測と記録を実装する
  - 数値0/1とパーツ名が明示された bind（作者が書いた bind-noevent を含む）を発話アクターとスポットへ記録し、アクター側はカテゴリごとの記録順を保つ（再記録で末尾へ移動）
  - 数値1の明示 bind では、スポット側の同カテゴリ他パーツを不明にする（全脱衣で脱衣済みの分は残す）。アクター側の他パーツ記録は保持する
  - パーツ名空・数値0（カテゴリ全脱衣）は、スポットと発話アクターの当該カテゴリを「全パーツ脱衣」に置き換え、後続の明示パーツはその上に記録する
  - パーツ名ありのトグルは、スポット側の当該パーツの実効値が既知なら反転値の明示 bind として記録する。不明なトグル、またはパーツ名空・数値0以外の bind では、スポットの当該カテゴリを不明、発話アクターの当該カテゴリを「不明（既定も使わない）」にし、他アクターは変えない
  - 引数に `"`・`\` を含む bind は、発話スポットの着せ替えのみ全カテゴリ不明にし、アクター既知状態と他スポットは変えない
  - 上記の各規則と、スコープ切替後・生スクリプト中の bind が記録されないことが単体テストでグリーンになる
  - _Requirements: 3.1, 3.4, 3.11, 3.12, 3.13_
- [ ] 4.2 アクター切替時の着せ替え復旧を実装する
  - 既知着せ替え = アクター設定の既定着せ替えを記録で上書きした集合とする。アクター側で全脱衣済み、または不明（既定も使わない）のカテゴリでは既定を使わない。既定の型が想定外なら当該項目を無視する
  - カテゴリごとに、いずれかのパーツ（または全脱衣）がスポット側の実効値と不一致・不明なら、そのカテゴリを丸ごと「全脱衣 → 既定パーツ（パーツ名昇順）→ 記録パーツ（記録順）」の順に `\![bind-noevent,カテゴリ,パーツ,値]` で返し、スポット側を観測と同じ規則で更新する。不一致の無いカテゴリは返さない
  - カテゴリはカテゴリ名のバイト昇順で並べ、サーフェス復旧の後に置く。スポット側にのみあるパーツには触れない
  - 先頭タグ列に同一（カテゴリ, パーツ）の明示 bind があるパーツのみ出力せず、先頭のトグル・カテゴリ単位 bind では抑止しない
  - 複数選択不可カテゴリで A が麦わら→B がリボン→A が戻ると、A の記録順に再出力されて麦わらが残る出力になることを単体テストで確認できる
  - 差分カテゴリの丸ごと再出力・全一致で無出力・既定フォールバック・既定未設定・全脱衣の先行出力・スポットが既に全脱衣なら無出力・先頭抑止・継続時無出力の各ケースが単体テストでグリーンになる
  - _Requirements: 3.2, 3.3, 3.5, 3.7, 3.8, 3.9, 3.10, 3.11, 2.11_
- [ ] 4.3 ビルダー経由で着せ替え復旧を検証する
