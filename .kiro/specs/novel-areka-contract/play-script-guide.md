# 演劇の台本の書き方（骨子の写し。2026-11-19）

`/kiro-discovery`（ノベルゲームの深掘り）で決まった骨子を、台本を書く人の目線で 1 か所にまとめた。骨子の全体は `final-model-2026-11-19.md`（承認待ちの整理は、その 4 章。暫定設計の議論の決定は、その 8 章で、2026-11-20 にこの手引きへも織り込んだ）、spec ごとの決定は各 brief の「決定（2026-11-19。最終形）」の節、議論の経緯は `discovery-2026-11-19.md` に在る。**命令の名前は、どれも仮である**（取り決めの文書を作る `novel-areka-contract` の要件定義で確定する）。まだ実装は無い。

## 1. 再生モード（走り方）

- 走り方は、柱 `＆再生モード`（仮）で書く。値は、トーク・演劇・設定の 3 つである。

| 値 | 走り方 |
| -- | ------ |
| トーク | シーンをまとめて、さくらスクリプト 1 本で返す（今までのゴースト） |
| 演劇 | アクション行ごとに 1 本返して待つ。記録する（目印・バックログ・セーブ） |
| 設定 | アクション行ごとに 1 本返して待つ。記録しない。物語の再生位置を動かさない |

- 柱は上書きで、書いていなければ前のモードが続く。物語のファイルは、頭のファイル属性の行に `＆再生モード：演劇` を 1 行書けば済む（ファイル属性は、必ず 1 行にまとめて書く）。
- ふつうのゴーストの途中から始められる。演劇のモードのシーンへ飛べば、着いた時に演劇になる。シーンの途中では、切り替えられない。
- 演劇と設定のモードの間は、どのシーンも 1 行ずつ進み、時報とランダムトークは出ない。
- 舞台の窓を開くことは、別の制御である（4 章）。舞台を開かない演劇は、デスクトップのゴーストのまま、1 行ずつ進む。
- 設定やセーブの画面は、`＆再生モード：設定` のシーンで書く。物語へ単に戻る所に `＞演劇再開`、ロードで戻る所に `＞スロット読込` を書く。

```pasta
＆再生モード：演劇

＊第一章
    さくら：むかしむかし。
    うにゅう：ほう。
    ＞エンディング

＊エンディング
    さくら：おしまい。
    ＞あとがき

＊あとがき　＆再生モード：トーク
    さくら：また読みたくなったら言ってね。

＊OnMouseClick　＆＄ｒ４＝「設定」　＆再生モード：設定
    さくら：どうする？
    ＠？セーブする「セーブ」
    ＠？ロードする「ロード」
    ＠？もどる「物語へ戻る」

    ・セーブする
        ＞スロット保存（１）
        さくら：保存したよ。
        ＞演劇再開

    ・ロードする
        ＞スロット読込（１）

    ・もどる
        ＞演劇再開
```

## 2. 区切り（さくらスクリプト 1 本に入る物）

- 1 本は「前の区切りの次から、次のアクション行（と、その継続行）の末尾まで」。字の無いアクション行（表情だけ）も、1 本になり、末尾でクリックを待つ。
- 間のト書き（`！` 行）・柱・アクター指定行は、その 1 本に、書いた順で入る。**ト書きは、直後のアクション行を修飾する。**
- **待たせたくない表情は、単語に印を書く。** 「待たずに、次を並べて再生する」は、その表情の単語が展開されるさくらスクリプトの持つ機能である（開発者の決定）。pasta が勝手に「字の無い行は待たない」とは決めない。印は、pasta が読む疑似のさくらスクリプトでよい（pasta が、その 1 本の末尾で待たず、次のアクション行を続けて返す）。印（仮 `\![parallel]`）から、その単語の終わりまでが、並走の区間になる。areka では、区間が別の流れとして始まり、次の行は待たずに始まる（見た目と音だけ。字は並走しない）。SSP では並走できないので、順に再生される。作者が書く印は `\![parallel]` の 1 つで、ベースウェアへは、pasta が `\![parallel,1]`・`\![parallel,0]` の対に直して出す。
- 並走は、届いた順に、そのまま当たる（後から始まった流れが勝つ、という決まりは無い）。続いてほしくない並走は、短く作るか、終わりの絵を決めておく。

```pasta
％教室
    ＠雨：\s[10]\![parallel]
    ＠稲光：\![parallel]\s[12]\_w[200]\s[10]\_w[200]\s[12]

＊嵐の教室　＆曲：雨音
    ％教室、さくら
    教室：＠雨
    さくら：降ってきたね。
    ！効果音（雷）
    ！揺らす（強く）
    教室：＠稲光
    さくら：＠驚き　きゃっ！
```

1 本目は、柱・並び・教室の雨と「降ってきたね。」（雨の単語に印が在るので、教室の行では待たない）。2 本目は、雷・揺れ・稲光と「きゃっ！」（稲光の並びが続いたまま、字が出る）。印の無い表情だけの行は、その行でクリックを待つ。

## 3. ト書きと柱

- `！名前＠対象（引数…）` は、`\![名前,対象,引数…]` になる。対象はアクターの名前。日本語の名前は、`pasta.toml` の別名表でタグに置き換わる。
- 柱には、値を並べて書ける（`＆環境音：空調、遠い街`）。ト書きの引数と同じに読まれる。
- 柱（`＆名前：値`）は、シーンに入ったときに自動で打たれるト書きである。曲のように、場面の間ずっと成り立つことは柱に書く。柱は上書きで、書いていない物には触らない（前の音が続く）。同じ値なら何も起きない。止めたいときは「なし」と書く（`＆曲：なし`）。
- ローカルシーンでは、親のグローバルシーンの柱に、自分の柱を重ねた物が打たれる。物語を通して同じ物（環境の音・舞台を開く）は、ファイル属性に 1 行書ける。
- 柱として打たれるのは、pasta が意味を知る 10 個（舞台・曲・環境の音・効果音・待つ・時間で次へ・位置・透明度・大きさ・転換）・別名表の名前・登録された柱だけである。ほかの属性（`＆見出し` など）は、打たれない。
- シーンの頭に `！転換` を書くと、着いた時の柱の変化も、その転換に包まれる。
- 柱が打たれるのは、イベントか、最後の行の `＞` で、シーンに着いた時だけである。途中の行の `＞` で呼んだシーンの柱は、打たれない（ト書きの束や共通のシーンを呼んでも、曲も走り方も変わらない）。
- **状況が変わるのは、シーンに到達した時だけ**（開発者の決定）。シーンに到達すると、そのシーンの柱で状況が変わる。呼んだシーンから戻っても、状況は変わらない。状況を変えたいときは、ローカルでもグローバルでもよいので、シーンへ飛ばす。
- **曲を変えたいときは、シーンを分ける**（開発者: 「曲を変えたければローカルで良いからシーンを分ければいいんですよ」）。ローカルシーンでよい。曲は、分けたシーンの柱に書く。こう書いておけば、ロードやバックログの巻き戻しでも、再生位置から曲が決まる。

```pasta
＊教室　＆曲：昼のテーマ
    さくら：そろそろ帰ろうか。
    ＞夕方

    ・夕方　＆曲：夕方のテーマ
        さくら：もう、こんな時間。
```

- 命令には「残る」と「瞬間」が在る。
  - **残る**: 値を置く命令。アクターに付く物（並び・表情・位置・重ね順・大きさ・透明度）は、pasta が最後の値を覚え、巻き戻し・ロード・出し直しのときに、覚えた値で画面を作り直す。アクターに付かない物（曲など）は覚えず、戻った先のシーンの階層の柱で決まる（5 章のセーブとロード）。
  - **瞬間**: その行が再生されるときだけ起きる。
- 引数の決まり: 数字で始まる文字は「」で囲む。対象と引数には、変数を書ける（下の「ト書きの束」）。**時間は、どれもミリ秒で書く**（`！待つ（３０００）`・`！select（２００００、時間切れ）`）。
- 式（呼び出しの引数・代入の右辺）にも、「」なしの文字列を書ける（文法に足す）。空白・区切り・演算子の字を含む時だけ「」で囲む（`＞消えて現れる（さくら、いちばん前）`・`＄＊スロット今の席＝いちばん前`）。
- 残る命令を切るときは、引数なしで書く（`！曲（）`・`！色調（）`）。

| 区分 | ト書き（仮） | 値 | フェーズ（6 章） |
| ---- | ------------ | -- | ---------------- |
| 残る | `！舞台（開く）`・`！舞台（閉じる）` | 開く・閉じる。形（ウィンドウ・全画面・ボーダーレス）は遊ぶ人の設定。書けばそれが勝つ | 3 の前半 |
| 残る | アクター指定行 `％教室、さくら` | 並び。舞台では、並びに無いアクターは消える | 1（舞台の並びは 3 の前半） |
| 残る | `！位置＠さくら（窓際）` | 数値。舞台の立ち位置は、スポットごとの座標で決まる（4 章） | 数値は 1。スポットの立ち位置は 3 の前半 |
| 残る | `！大きさ＠`・`！透明度＠` | 数 | 1 |
| 残る | `！重ね順＠` | 数 | 3 の前半 |
| 残る | 表情（`さくら：＠驚き`） | サーフェスと着せ替え | 1 |
| 残る | `＆曲：雨音`・`！曲（雨音）`・`！曲（）` | 曲の名前。引数なしで止める | 1 |
| 残る | `＆環境音：雨`・`！環境音（雨）` | 音の名前 | 1 |
| 残る | `！色調（琥珀）` | 色の名前 | 3 の後半 |
| 残る | `！カメラ（窓へ寄る）` | 寄り・位置 | 3 の後半 |
| 瞬間 | `！転換（１０００）`・`！転換（１０００、待つ）` | この後の変更を、直前の絵から新しい絵へ、時間（ミリ秒）をかけて替える | 3 の前半 |
| 瞬間 | `！効果音（雷）`・声 | 音の名前 | 1 |
| 瞬間 | `！揺らす（強く）`・`！フラッシュ` | 強さ | 3 の前半 |
| 瞬間 | `！待つ（３０００）` | 字の前に間を置く（ミリ秒） | 1 |
| 瞬間 | `！時間で次へ（１０００）` | この行は、クリックを待たずに次へ進む（ミリ秒） | 1 |

- **転換**（開発者の決定）: 転換は、直前の絵から、新しい絵へ替わる。直前の絵が、常にフェードの出発点である。黒を挟む形（暗転・明転）と、ルール画像は入れない。種類は書かず、時間だけ書く。表情は溶け、透明度は濃淡が動き、位置と大きさは動き、並びに入る・出るアクターは溶けて現れる・消える。重ね順だけは、その瞬間に替わる。字は転換を待たない。待たせたいときだけ `！転換（１０００、待つ）` と書く。まとめる範囲は、転換のト書きから「次の字・次の待ち・次の転換・1 本の終わり」のどれか早い所まで。時間を付けるのは転換だけ。黒くしたい場面は、黒い背景のアクターへ替える。

```pasta
    ！転換（１０００、待つ）
    教室：＠夜
    さくら：もう夜だ。
```

- **ト書きの束**（開発者の承認）: よく使う動きは、シーンにまとめて、引数つきの呼び出しで呼ぶ。ト書きの対象と引数に、変数（`＄０`・`＄１`）を書ける。

```pasta
＊消えて現れる
    ！転換（３００、待つ）
    ！透明度＠＄０（０）
    ！転換（０）
    ！位置＠＄０（＄１）
    ！転換（３００、待つ）
    ！透明度＠＄０（１００）

＊席替え
    ＞消えて現れる（さくら、いちばん前）
    さくら：いちばん前、だよ。
```

- `！転換（０）` は「ここからは一瞬で替える」の意味で、前の転換の組を終わらせる。

## 4. 舞台と箱

- 舞台が開いている間、デスクトップの窓とバルーンは隠れる。閉じると戻る。
- 画面の部品は、全部アクターである（人物・背景・小道具・台詞の箱・ボタンを載せた「システム」）。役や種別は無い。
- 台詞は、ふつうに話者の行で書く。舞台に「字を受ける」印の在るアクター（台詞の箱）が居れば、字はその箱に出る。話者の名前は、並びの名前が出る。
- 箱のアクター自身の行で書いた字は、その箱に出る（地の文・チャット）。縦書きか横書きかは、箱の定義で決まる。
- 字を受けるアクターが居ないときは、話者自身のシェルの箱に出る（キャラのそばのふきだし）。
- 立ち位置は、スポット（`pasta.toml` の `[actor."名前"]` の `spot`）ごとの座標で決まる。座標は pasta の側に書き、pasta が、並びを打つ時に、位置を渡す。座標の置き場（`pasta.toml` か、台本か）は、要件定義で決める。

```pasta
    さくら：＠横目　‥‥今日は、窓が大きいでしょう。
    地の文：ビルの隙間に、ひとつ。
```

## 5. 遊ぶ人の操作

- **進める**: 台詞の箱を押す。どのシーンも拾わない所を押す。選択肢が出ている間は、選ぶまで進まない。
- **小道具を押す**: イベントのシーンを書く。**台詞だけ書く。** 演劇の間は、どのシーンも 1 行ずつ進む。
  - その場面だけの反応は、その場面のローカルシーンで書く（`・OnMouseClick`）。演劇の間、イベントのシーンは、今のシーンのグローバルシーンのローカルシーンを先に探し、無ければグローバルシーン（`＊OnMouseClick`）を探す。
  - イベントでシーンが選ばれると、再生位置はそのシーンへ移る（選択肢で選んだ先と同じ、分岐である）。元の場面を読ませ直したいときは、最後の行に `＞` を書いて、そのシーンへ飛ぶ。シーンは頭から走る。
  - 最後の行に `＞` が無ければ、物語はそこで止まり、次のイベントを待つ。
  - **反応を置くのは、戻ってきても困らない「待つ場面」にする。** 一本道の場面の途中で反応へ移ると、元の行の続きへは戻れない（飛ぶ先は、シーンの頭だけである）。
  - **記録の要らない反応は、設定のモードのローカルシーンで書き、最後に `＞演劇再開` を書く。** その反応はバックログにもセーブにも残らず、終わると、待っていた行がもう一度出る。

```pasta
＊教室　＆曲：昼のテーマ
    さくら：気になる所を押してみて。
    さくら：もういいなら、先へ進もう。
    ＞廊下

    ・OnMouseClick　＆＄ｒ４＝「ドア」
        さくら：鍵がかかってる。
        うにゅう：開かへんな。
        ＞教室

    ・OnMouseClick　＆＄ｒ４＝「時計」　＆再生モード：設定
        うにゅう：まだ昼やな。
        ＞演劇再開
```

- **選択肢**: `＠？飛び先「表示」`。条件を付けられる（文法に足す）。時間切れの飛び先も書ける（`！select` の 2 つ目の引数。足す）。

```pasta
    ！select（２００００、時間切れ）
    ＠？明かりを消す「明かりを消す」
    ＠？手を振る「手を振ってみる」　＆＄＊スロット訪ねた数≧３
```

- 選択肢の行と `！select` は、直前のアクション行の 1 本に入る。その 1 本は、クリックでなく、選ばれるのを待つ。
- **いつもの反応との書き分け**: 何も書かなくてよい。演劇と設定の間は、`＆再生モード` に演劇か設定を書いたシーンだけが、イベントで選ばれる。いつもの辞書のシーン（つつき・撫で・時報・ランダムトーク）は、選ばれない。物語のファイルの頭に、ファイル属性 `＆再生モード：演劇` を書いておけば、そのファイルのイベントのシーンは選ばれる。今の場面のローカルシーン（`・OnMouseClick`）は、いつも先に探される。
- **途中で出すアクター**: アクター指定行は、シーンの頭にだけ書ける。途中で出したいアクターは、最初から並びに入れて、表情で隠しておく。
- **セーブとロード**: `＞スロット保存（１）`・`＞スロット読込（１）`。ロードすると、セーブした時の、変数と、再生位置と、アクター状態が戻る（開発者の決定）。状態が元へ戻るのは、ロードした時と、バックログの行を選んだ時だけである。
  - シーンの頭に書いた保存は、そのシーンの頭から続く。行が待っている間の保存（設定の画面から）は、待っている行から続く。
  - 曲・環境の音・舞台は、保存されない。ロードした時に、その行のシーンの階層（グローバル → ローカル）の柱が打たれる。だから、音の変わる場面のグローバルシーンには柱を書き、舞台を開くことも柱で書く（`＆舞台：開く`）。前のシーンから引き継いだだけの音と、ト書きで途中に変えた音は、ロードでは戻らず、止まる（階層に書いていない残る物は、止まる）。
  - ロードとバックログで戻った先の走り方は、いつも演劇である。
  - 台本を直した後のロードは、同じ所へ戻るとは約束しない。
  - 戻る時、pasta は今のシーンを頭から早回しする。早回しは、抽選も引き直す。途中の `＞` で、行の数の違う同名のシーンを抽選すると、着く行がずれうる（そう書くのは作者の選択である）。
  - **セーブの見出し**は、シーンの属性 `＆見出し`（仮）で書く。書いていなければ、シーンの名前である。保存した再生位置のシーンの階層から引かれる。セーブの画面では、`＠スロット見出し（１）`（仮）で出す。「スロットにセーブが在るか」も、スロットを読む関数の仲間で答える。

```pasta
＊第二章　＆見出し：放課後の教室
    さくら：もう、みんな帰ったね。
```

- **設定やセーブの画面**: `＆再生モード：設定` のシーンで書く（1 章）。その行は、バックログに残らず、セーブの対象にもならない。`＞演劇再開` で単に戻ると、何も戻らず、待っていた行がもう一度出る。`＞スロット読込` で戻ると、セーブした時の状態になる。
- **覚える所**: セーブと一緒に戻る物は `＄＊スロット〜`。ロードしても消えない物（見た結末）は、ふつうの `＄＊〜`。後者は、デスクトップのトークの条件にも使える。
- **バックログ**: 行を選ぶと、その行へ戻る。行は、ト書きごと再生される（雷が鳴り、揺れる）。
- **オートと高速再生**: 遊ぶ人の設定。台本には書かない。高速再生は、選択肢と、まだ読んでいない行で止まる。
- **設定の画面への入口**: 常に出ているボタンとキーボードの 2 つである。ボタンは、シェルの絵（アクター）と当たり判定で出す。右クリックは、ベースウェアのいつものメニューのままである（差し替えない）。

## 6. フェーズの分け方（開発者の決定）

開発者: 「pasta 側のゴール設定も分けてください。現在の SSP でも実現可能なもの、SSP が対応すれば可能なもの、areka がないと実現できないもの、この 3 つでフェーズを分けます。」「ゴールを分けてよい。最低限実現に必要なもの → 実装が重いが後回しでもよいもの、は分けるべきですね。」

| フェーズ | ベースウェア | 台本に書ける物 |
| -------- | ------------ | -------------- |
| **1** | 今の SSP | 柱 `＆再生モード`（1 行ずつ進む演劇・設定の画面）。ト書きと柱。曲・環境の音・効果音・待つ。表情と着せ替え。その場面だけのクリックの反応（ローカルシーン）。選択肢の条件と時間切れ。セーブとロード（行単位の再開）。高速再生。オート。その行だけ時間で次へ進む。当たり判定のクリック。アクターの窓の位置・透明度・大きさ（数値）。バックログは SSP の窓で読むだけ |
| **2** | SSP が対応すれば | バックログの行へ戻る。話者の名前。曲のフェード。ウインドウモードの切り替え。セーブの画面の縮小 |
| **3 の前半（最低限）** | areka（合成した舞台） | 舞台の窓（ウィンドウと全画面）・並び・スポットごとの立ち位置（座標と重ね順）・転換（アクターごとのフェードと移動）・揺れとフラッシュ・台詞の箱（縦書きと横書き）・並走 |
| **3 の後半（重い。後回しでよい）** | areka | 色調・カメラ・舞台の外（画面いっぱいの透明の舞台・デスクトップ全体を暗くする・枠の外へはみ出す絵・窓が広がる）・カーソル（付いて動く絵・目で追う・視差）・掴んで動かせるアクター・全画面に文を流す形・動画 |

- ト書きの書き方は、どのフェーズでも 1 つである。pasta が、ベースウェアが areka かどうかと、areka の版を見て、タグへ直す（areka はセマンティックバージョンを返す）。直せない物は、そのベースウェアでは何も出さない。舞台を使う台本を、SSP で遊べるとは約束しない。
- フェーズ 1 は、areka を待たずに作れて、SSP の実機で測れる。**フェーズ 1 の芯（1 行ずつ進む・待ちの間のクリックで別のシーンへ移る・貯めない区間・透明度と大きさ・時間で次へ）は、SSP 2.9.34 の実機で確かめた**（`research-ssp-capabilities.md` の D 節）。オートと「時間で次へ」は、実機の結果を受けて、フェーズ 2 から 1 へ移した（開発者の決定）。
- 色調は、フェーズ 3 の前半の間、半透明の色のアクターを重ねて代えられる。

企画の段で挙がって、まだ語彙に無い物: ぼかし・ピント・ビネット／選択肢をボールの周りに輪で出す／下から積み上がるチャットの吹き出し／字が震える・字の音／音の向き。台本の検証で、足りない物の一覧に入れる。

## 7. 確かめていないこと

- ベースウェアの側の見立て（areka）は、読むだけの調査である。SSP の仕訳のうち、実機で確かめていないのは、ウインドウモード・音のタグ・早送りキーを有効にした設定での動きである（確かめた分は `research-ssp-capabilities.md` の D 節）。
- 継続行の前にト書きを挟む書き方が、今の検査を通るか。
- 式に「」なしの文字列を書けるようにした時、今の台本の読まれ方が変わらないか。
- 高速再生で `\x` を出さないと、行が画面に出る前に次の行で置き換わるおそれ（areka の指摘。起きるなら、pasta が行の末尾に短い待ちを入れる）。
