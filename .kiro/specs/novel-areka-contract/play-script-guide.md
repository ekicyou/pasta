# 演劇の台本の書き方（骨子の写し。2026-11-19）

`/kiro-discovery`（ノベルゲームの深掘り）で決まった骨子を、台本を書く人の目線で 1 か所にまとめた。決定の本文は各 brief の「決定（2026-11-19）」の節に、議論の経緯は `discovery-2026-11-19.md` に在る。**命令の名前は、どれも仮である**（取り決めの文書を作る `novel-areka-contract` の要件定義で確定する）。まだ実装は無い。

## 1. 演劇の始めと終わり

- `＞演劇開始` を呼ぶと、その流れは「字を出すアクション行ごとに、さくらスクリプト 1 本を返して、クリックを待つ」走り方になる。`＞トーク開始` で、ふつうのゴーストの走り方に戻る。
- 演劇は、さくらスクリプトの切り方の状態である。シーンに種類は無い。ふつうのゴーストの途中から始められる。
- 舞台の窓を開くことは、別の制御である（4 章）。舞台を開かない演劇は、デスクトップのゴーストのまま、1 行ずつ進む。

```pasta
＊物語の入口
    ＞演劇開始
    ＞第一章
```

## 2. 区切り（さくらスクリプト 1 本に入る物）

- 1 本は「前の区切りの次から、次のアクション行（と、その継続行）の末尾まで」。字の無いアクション行（表情だけ）も、1 本になり、末尾でクリックを待つ。
- 間のト書き（`！` 行）・柱・アクター指定行は、その 1 本に、書いた順で入る。**ト書きは、直後のアクション行を修飾する。**
- **待たせたくない表情は、単語に印を書く。** 「待たずに、次を並べて再生する」は、その表情の単語が展開されるさくらスクリプトの持つ機能である（開発者の決定）。pasta が勝手に「字の無い行は待たない」とは決めない。印は、pasta が読む疑似のさくらスクリプトでよい（pasta が、その 1 本の末尾に `\x` を付けず、次のアクション行を続けて返す）。印（仮 `\![parallel]`）から、その単語の終わりまでが、並走の区間になる。areka では、区間が別の流れとして始まり、次の行は待たずに始まる（見た目と音だけ。字は並走しない）。SSP では並走できないので、順に再生される。印の名前は、areka の並走の brief と 1 つにそろえる。

```pasta
％教室
    ＠雨：\s[10]\![parallel]
    ＠稲光：\![parallel]\s[12]\_w[200]\s[10]\_w[200]\s[12]

＊嵐の教室　＆曲：雨音
    ％教室、さくら
    教室：＠雨
    さくら：降ってきたね。
    ！効果音（雷）
    ！揺らす（強く）
    教室：＠稲光
    さくら：＠驚き　きゃっ！
```

1 本目は、柱・並び・教室の雨と「降ってきたね。」（雨の単語に印が在るので、教室の行では待たない）。2 本目は、雷・揺れ・稲光と「きゃっ！」（稲光の並びが続いたまま、字が出る）。印の無い表情だけの行は、その行でクリックを待つ。

## 3. ト書きと柱

- `！名前＠対象（引数…）` は、`\![名前,対象,引数…]` になる。対象はアクターの名前。日本語の名前は、`pasta.toml` の別名表でタグに置き換わる。
- 柱には、値を並べて書ける（`＆環境音：空調、遠い街`）。ト書きの引数と同じに読まれる。
- 柱（`＆名前：値`）は、シーンに入ったときに自動で打たれるト書きである。曲のように、場面の間ずっと成り立つことは柱に書く。同じ値なら何も起きない。
- **状況が変わるのは、シーンに到達した時だけ**（開発者の決定）。シーンに到達すると、そのシーンの柱で状況が変わる。呼んだシーンや寄り道から戻っても、状況は変わらない。状況を変えたいときは、ローカルでもグローバルでもよいので、シーンへ飛ばす。
- **曲を変えたいときは、シーンを分ける**（開発者: 「曲を変えたければローカルで良いからシーンを分ければいいんですよ」）。ローカルシーンでよい。曲は、分けたシーンの柱に書く。こう書いておけば、ロードやバックログの巻き戻しでも、再生位置から曲が決まる。

```pasta
＊教室　＆曲：昼のテーマ
    さくら：そろそろ帰ろうか。
    ＞夕方

    ・夕方　＆曲：夕方のテーマ
        さくら：もう、こんな時間。
```

- 命令には「残る」と「瞬間」が在る。
  - **残る**: 値を置く命令。pasta が最後の値を覚え、巻き戻し・ロード・出し直しのときに、覚えた値で画面を作り直す。
  - **瞬間**: その行が再生されるときだけ起きる。
- 引数の決まり: 数字で始まる文字は「」で囲む。対象と引数には、変数を書ける（下の「ト書きの束」）。**時間は、どれもミリ秒で書く**（`！待つ（３０００）`）。
- 残る命令を切るときは、引数なしで書く（`！曲（）`・`！色調（）`）。

| 区分 | ト書き（仮） | 値 | フェーズ（6 章） |
| ---- | ------------ | -- | ---------------- |
| 残る | `！舞台（開く）`・`！舞台（閉じる）` | 開く・閉じる。形（ウィンドウ・全画面・ボーダーレス）は遊ぶ人の設定。書けばそれが勝つ | 3 の前半 |
| 残る | アクター指定行 `％教室、さくら` | 並び。舞台では、並びに無いアクターは消える | 1（舞台の並びは 3 の前半） |
| 残る | `！位置＠さくら（窓際）` | 席の名前か数値。席の名前は舞台の定義に書く | 数値は 1。席の名前は 3 の前半 |
| 残る | `！重ね順＠`・`！大きさ＠`・`！透明度＠` | 数 | 1 |
| 残る | 表情（`さくら：＠驚き`） | サーフェスと着せ替え | 1 |
| 残る | `＆曲：雨音`・`！曲（雨音）`・`！曲（）` | 曲の名前。引数なしで止める | 1 |
| 残る | `＆環境音：雨`・`！環境音（雨）` | 音の名前 | 1 |
| 残る | `！色調（琥珀）` | 色の名前 | 3 の後半 |
| 残る | `！カメラ（窓へ寄る）` | 寄り・位置 | 3 の後半 |
| 瞬間 | `！転換（１０００）`・`！転換（１０００、待つ）` | この後の変更を、直前の絵から新しい絵へ、時間（ミリ秒）をかけて替える | 3 の前半 |
| 瞬間 | `！効果音（雷）`・声 | 音の名前 | 1 |
| 瞬間 | `！揺らす（強く）`・`！フラッシュ` | 強さ | 3 の前半 |
| 瞬間 | `！待つ（３０００）` | 字の前に間を置く（ミリ秒） | 1 |
| 瞬間 | `！時間で次へ（１０００）` | この行は、クリックを待たずに次へ進む（ミリ秒） | 1 |

- **転換**（開発者の決定）: 転換は、直前の絵から、新しい絵へ替わる。直前の絵が、常にフェードの出発点である。黒を挟む形（暗転・明転）と、ルール画像は入れない。種類は書かず、時間だけ書く。表情は溶け、透明度は濃淡が動き、位置と大きさは動き、並びに入る・出るアクターは溶けて現れる・消える。重ね順だけは、その瞬間に替わる。字は転換を待たない。待たせたいときだけ `！転換（１０００、待つ）` と書く。まとめる範囲は、転換のト書きから「次の字・次の待ち・次の転換・1 本の終わり」のどれか早い所まで。時間を付けるのは転換だけ。黒くしたい場面は、黒い背景のアクターへ替える。

```pasta
    ！転換（１０００、待つ）
    教室：＠夜
    さくら：もう夜だ。
```

- **ト書きの束**（開発者の承認）: よく使う動きは、シーンにまとめて、引数つきの呼び出しで呼ぶ。ト書きの対象と引数に、変数（`＄０`・`＄１`）を書ける。

```pasta
＊消えて現れる
    ！転換（３００、待つ）
    ！透明度＠＄０（０）
    ！転換（０）
    ！移動＠＄０（＄１）
    ！転換（３００、待つ）
    ！透明度＠＄０（１００）

＊席替え
    ＞消えて現れる（さくら、いちばん前）
    さくら：いちばん前、だよ。
```

- `！転換（０）` は「ここからは一瞬で替える」の意味で、前の転換の組を終わらせる。

## 4. 舞台と箱

- 舞台が開いている間、デスクトップの窓とバルーンは隠れる。閉じると戻る。
- 画面の部品は、全部アクターである（人物・背景・小道具・台詞の箱・ボタンを載せた「システム」）。
- 台詞は、ふつうに話者の行で書く。舞台に「トークの場所」の役のアクター（台詞の箱）が居れば、字はその箱に出る。話者の名前は、並びの名前が出る。
- 箱のアクター自身の行で書いた字は、その箱に出る（地の文・チャット）。縦書きか横書きかは、箱の定義で決まる。
- トークの場所が居ないときは、話者自身のシェルの箱に出る（キャラのそばのふきだし）。

```pasta
    ぱすた：＠横目　‥‥今日は、窓が大きいでしょう。
    地の文：ビルの隙間に、ひとつ。
```

## 5. 遊ぶ人の操作

- **進める**: 台詞の箱を押す。当たり判定の無い所を押す。
- **小道具を押す（寄り道）**: 条件の属性で書いたシーンが走る。**本筋と同じに、台詞だけ書く。** 演劇の間は、寄り道のシーンも 1 行ずつ進み、読み終えると、その場で元の行に戻る。寄り道のために足して書く物は無い（開発者: 「面倒な書き方はしたくない。この書き方じゃないとダメ」）。

```pasta
＊OnMouseClick　＆＄ｒ４＝「ドア」
    さくら：鍵がかかってる。
    うにゅう：開かへんな。
```

- 寄り道の途中に別の小道具を押したら、前の寄り道は捨てて、新しい寄り道に替わる。本筋は残る。寄り道の中で選択肢を出して、選んだ先を訪ねて戻る形（ハブ）も、同じ決まりで書ける。

- **選択肢**: `＠？飛び先「表示」`。条件を付けられる（文法に足す）。時間切れの飛び先も書ける（`！select` の 2 つ目の引数。足す）。

```pasta
    ！select（２００００、時間切れ）
    ＠？明かりを消す「明かりを消す」
    ＠？手を振る「手を振ってみる」　＆＄＊スロット訪ねた数≧３
```

- 選択肢の行と `！select` は、直前のアクション行の 1 本に入る。その 1 本は、クリックでなく、選ばれるのを待つ。
- **いつもの反応との書き分け**: イベントで走るシーンでは、今の演劇のシーンの名前が、ローカル変数（仮 `＄演劇`。演劇でなければ空）に入っている。条件に書いて、いつもの雑談と、演劇の間だけの寄り道を分ける（`＊OnMouseClick　＆＄ｒ４＝「ボール」　＆＄演劇＝「くじ」`）。この名前も、シーンに到達した時にだけ変わる。寄り道のシーンに到達すれば、寄り道のシーンの名前になる。何度も寄り道させる場面では、作者が自分の変数で場面を覚えるか、寄り道の終わりでシーンへ飛ばす。
- **途中で出すアクター**: アクター指定行は、シーンの頭にだけ書ける。途中で出したいアクターは、最初から並びに入れて、表情で隠しておく。
- **セーブとロード**: `＞スロット保存（１）`・`＞スロット読込（１）`。続きの場所は、シーンの名前と行の番号。ロードすると、セーブした時の、変数と、再生位置と、アクター状態が戻る（開発者の決定）。状態が元へ戻るのは、ロードした時と、バックログの行を選んだ時だけである。曲など、アクターに付かない物は、戻った先のシーンの柱から拾い直される。
- **覚える所**: セーブと一緒に戻る物は `＄＊スロット〜`。ロードしても消えない物（見た結末）は、ふつうの `＄＊〜`。後者は、デスクトップのトークの条件にも使える。
- **バックログ**: 行を選ぶと、その行へ戻る。行は、ト書きごと再生される（雷が鳴り、揺れる）。
- **オートと高速再生**: 遊ぶ人の設定。台本には書かない。

## 6. フェーズの分け方（開発者の決定）

開発者: 「pasta 側のゴール設定も分けてください。現在の SSP でも実現可能なもの、SSP が対応すれば可能なもの、areka がないと実現できないもの、この 3 つでフェーズを分けます。」「ゴールを分けてよい。最低限実現に必要なもの → 実装が重いが後回しでもよいもの、は分けるべきですね。」

| フェーズ | ベースウェア | 台本に書ける物 |
| -------- | ------------ | -------------- |
| **1** | 今の SSP | `＞演劇開始`・`＞トーク開始`（1 行ずつ進む）。ト書きと柱。曲・環境の音・効果音・待つ。表情と着せ替え。寄り道と出し直し。選択肢の条件と時間切れ。セーブとロード（行単位の再開）。高速再生。オート。その行だけ時間で次へ進む。当たり判定のクリック。アクターの窓の位置・透明度・大きさ（数値）。バックログは SSP の窓で読むだけ |
| **2** | SSP が対応すれば | バックログの行へ戻る。話者の名前。曲のフェード。ウインドウモードの切り替え。セーブの画面の縮小 |
| **3 の前半（最低限）** | areka（合成した舞台） | 舞台の窓（ウィンドウと全画面）・並び・席の名前・重ね順の自動・転換（アクターごとのフェードと移動）・揺れとフラッシュ・台詞の箱（縦書きと横書き） |
| **3 の後半（重い。後回しでよい）** | areka | 色調・舞台の全体を溶かす転換とルール画像・カメラ・舞台の外（画面いっぱいの透明の舞台・デスクトップ全体を暗くする・枠の外へはみ出す絵・窓が広がる）・カーソル（付いて動く絵・目で追う・視差）・掴んで動かせるアクター・全画面に文を流す形・動画 |

- ト書きの書き方は、どのフェーズでも 1 つである。pasta が、ベースウェアが areka かどうかと、areka の版を見て、タグへ直す（areka はセマンティックバージョンを返す）。直せない物は、そのベースウェアでは何も出さない。
- フェーズ 1 は、areka を待たずに作れて、SSP の実機で測れる。**フェーズ 1 の芯（1 行ずつ進む・寄り道・貯めない区間・透明度と大きさ・時間で次へ）は、SSP 2.9.34 の実機で確かめた**（`research-ssp-capabilities.md` の D 節）。オートと「時間で次へ」は、実機の結果を受けて、フェーズ 2 から 1 へ移した（開発者の決定）。
- 色調は、フェーズ 3 の前半の間、半透明の色のアクターを重ねて代えられる。

企画の段で挙がって、まだ語彙に無い物: ぼかし・ピント・ビネット／選択肢をボールの周りに輪で出す／下から積み上がるチャットの吹き出し／字が震える・字の音／音の向き。台本の検証で、足りない物の一覧に入れる。

## 7. 確かめていないこと

- ベースウェアの側の見立て（areka）は、読むだけの調査である。SSP の仕訳のうち、実機で確かめていないのは、ウインドウモード・音のタグ・早送りキーを有効にした設定での動きである（確かめた分は `research-ssp-capabilities.md` の D 節）。
- 継続行の前にト書きを挟む書き方が、今の検査を通るか。
- 高速再生で `\x` を出さないと、行が画面に出る前に次の行で置き換わるおそれ（areka の指摘。起きるなら、pasta が行の末尾に短い待ちを入れる）。
