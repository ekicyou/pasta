# Brief: novel-areka-contract

`/kiro-discovery` で起票（2026-10-10・main `88c4bc0e`）。0.5.0「areka でノベルゲームが作れる」の道筋の 1 番目で、**areka に依頼を出すための spec** である。コードは書かない。

## Problem

0.5.0 の目標は、別リポジトリで開発中の areka で、市販品の体裁のノベルゲームが作れるようになることである。画面と音を出すのは areka で、pasta は台本を返すだけである。ところが、pasta が台本に何を載せ、areka がそれをどう受け取るかの取り決めが、どこにも無い。

- areka には、音の層・複数のシェルを 1 つの窓に並べる仕組み・場面転換の演出・スクリプトへ届くキーボード入力が無い。どれも brief すら無い。
- areka には、ほかのプロジェクトからの依頼を受ける窓口が無い。areka の新しい作業は、areka のリポジトリでの `/kiro-discovery` から始まる。
- pasta の側の spec（`cue-command-runtime` ほか 6 本）は、語彙の名前とイベントの名前が決まらないと、既定値と見本を書けない。

areka の側の作業が一番重い。依頼が遅れるほど、0.5.0 が遅れる。

## Current State

### 決まっていること（2026-10-10 の discovery での開発者の決定）

- **合格ライン**: 市販品の体裁。遊ぶ人は、クリック送り・セーブとロード・バックログと巻き戻し・既読スキップ・オート・設定・タイトル画面を使える。
- **通り道**: SHIORI/3.0 とさくらスクリプトのまま。演出は `\![名前,引数…]` に載せる。pasta 専用の通り道（`pasta_novel` アダプタ、SHIORI4）は作らない。
- **画面**: 複数のシェルの組み合わせで作る。背景・登場人物・トークの出る場所が、それぞれシェルである。普通の窓と全画面の両方を areka に依頼する。
- **アクター**: 背景もトークの場所も、キャラと同じく pasta のアクターとして扱う。状態はサーフェスで表す（例: アクター「教室と窓」に `＠稲光` を引かせると、雷の絵に替わる）。
- **システム画面**: areka が出すのは部品だけである（エレメント単位のクリック、シェルの中のバルーン、サーフェスの階層）。タイトル・セーブ・ロード・設定の画面は、シェルとして組み、pasta の場面が動かす。
- **バックログ**: 一覧（顔・話者・文）は areka が持つ。pasta は台本に目印の ID を埋める。バックログの行が選ばれたら、areka はその行の直近の ID をイベントで知らせる。ID の中身は pasta だけが知る。
- **表示の進み具合に関わる機能**（クリック送り・早送り・オート・既読とスキップ）は areka が持つ。どこまで表示したかを知っているのは areka だけだからである。

### areka の現在地（2026-10-10・areka main `b3650b68`・v0.0.2 を読み取りで調べた）

- 伺か互換のベースウェア。描画は Windows.UI.Composition と Direct2D・DirectWrite。1 スコープに 1 枚の透明な窓で、2 体まで。areka の土台（`wintf`）は普通の窓も作れるが、areka の本体は使っていない。
- pasta は、32 ビットの `pasta.dll` を別プロセス（`shiori-host32-helper.exe`）で動かして使っている。本番の通り道はこれだけである。
- さくらスクリプトは、areka の中で台本（`CueSheet`）に直されて再生される。`\![名前,引数…]` は、すべて `Custom{command, params}` の 1 本で運ぶ決まりで、命令ごとの型は増やさない。areka 独自の拡張は `\![…]` の中に置く。
- **もうある物**: サーフェスの階層（エレメントが別のサーフェスを呼べる）、シェルの中のバルーン、縦書き、1 字ずつの表示、選択肢、アンカー、`\_w` の待ち。
- **brief だけある物**: クリック待ち `\x` と早送り（`areka-P0-talk-fast-forward`）、ルビ、禁則、フェードで現れる文字、3 体目以降（`areka-P0-extra-character-windows`）、`OnMouseClick`（`areka-P0-mouse-click-wheel-events`）、文字入力。
- **何も無い物**: 音（BGM・効果音・声）、動画、複数のシェルを 1 つの窓に並べること、場面転換の演出、キーボード入力、ボタンなどの部品。
- areka が SHIORI へ送るイベントは、許可した名前だけである（`areka-kanade` の `ALLOWED_EVENT_IDS`）。新しいイベントは、ここへ足してもらう必要がある。
- areka は「自動の改ページ待ち」を採らない方針である（デスクトップマスコットは勝手に喋るもの、という理由）。クリック待ちは、台本に書いた `\x` だけで起きる。
- areka の作業の進め方: Kiro の spec 駆動。`/kiro-discovery` が `.kiro/specs/areka-P0-<名前>/brief.md` を書く。1 spec は 20 タスクまで。spec をまとめて量産しない決まりがある。文書は日本語。`.kiro/MEMO.md` は人間専用で、LLM は読まない。

### pasta の現在地（2026-10-10 に確かめたこと）

- 知らない `\![…]` は、日本語の引数を含めて、そのまま台本に残る。待ちも改行も挟まれない。
- NOTIFY のイベントに、pasta は台本を返せない（DLL が Lua を走らせる前に 204 を返す。`crates/pasta_shiori/src/actor/marshaling.rs` 232 行付近）。**ノベル用のイベントは、すべて GET で送ってもらう必要がある。**
- GET の応答が 5 秒を超えると、DLL は 204 を返す（同ファイル 71 行）。

### 調査ノート（このフォルダ）

- `research-jp-engines.md` — 国産エンジン 10 系統（KAG3・NScripter・TyranoScript・Artemis・Suika2・宴ほか）のスクリプト仕様。共通コア 30 項目、セーブと実行位置の方式、スクリプトとエンジンの役割分担。
- `research-western-engines.md` — 欧米 9 系統（Ren'Py・Ink・Yarn Spinner・Naninovel ほか）。ホストとの取り決めの 3 つの型、コルーチン実行でのセーブと巻き戻し、ホストに前提される最小の演出語彙。

どちらも、記述ごとに「取得したページで確かめた／記憶」の印がある。記憶の印の記述は、根拠にする前に原典で確かめる。

## Desired Outcome

- pasta と areka の取り決めが、1 つの文書になっている。版の番号を持つ。
- その文書から起こした areka への依頼書が、areka のセッションへ渡っている。areka の側でどの brief になったかの対応表が、pasta の側に残っている。
- 0.5.0 に要る物と、後へ回す物の線引きが、依頼ごとに書いてある。
- 後続の spec が、語彙の名前・イベントの名前・設定の値の名前を、この文書から引ける。

## Approach

### 取り決めの文書に書くこと

何が出来てほしいかだけを書く。作り方は書かない。areka の言葉（シェル・サーフェス・スコープ・バルーン・エレメント・台本）で書く。下は、discovery の時点での要求の一覧（要件定義のたたき台）である。

**画面**

- 複数のシェルを、1 つの窓の中に組み合わせて出す（背景・登場人物・トークの場所・上に重ねる画面）。
- 普通の窓と全画面。その切り替え。画面の大きさが違う環境での拡縮。
- シェルごとの位置（名前の付いた席と数値）、重ね順、出す・消す。3 体以上。

**映像**

- サーフェスの替わり方。瞬間・クロスフェード・ルール画像によるワイプ。時間の指定。複数の変更をまとめて 1 回で替える。
- 位置・大きさ・不透明度を、時間をかけて変える。
- 画面の揺れ、フラッシュ、色調（暗転・セピアなど）。
- 動画は、要るかどうかから決める。

**文章**

- トークの出る場所は、シェルの中のバルーン。話者名の欄。名前を指定してバルーンへ書く。
- クリック待ち（`\x`）と早送り。行末の待ちと改ページの待ち。窓を出す・隠す。
- 文字の速度、色、大きさ、ルビ。下に窓を置く形と、全画面に文を流す形。

**音**

- 曲: 再生・停止・ループ・フェード・曲から曲への移り変わり。同じ曲は鳴らし直さない。
- 効果音: 重ねて鳴らす。ループ。
- 声: 台詞に結び付ける。次の台詞で止める。バックログから聞き直す。
- 区分ごとの音量。演出のための音量と、遊ぶ人の設定の音量を分ける。再生の終わりを待つ。

**時間と入力**

- 時間の待ち（飛ばせる・飛ばせない）。演出が終わるまでの待ち。
- クリック送り。キーボード（送り・スキップ・画面を開く）。
- エレメント単位のクリックを、名前つきで知らせる。
- オート（声が終わるのを待つ）。スキップ（既読だけ・全部）。

**目印・バックログ・既読**

- 目印の ID を台本に書ける。areka は、通り過ぎた ID を、バックログの行に結び付けて覚える。
- 目印を通り過ぎた時点の画面と音を控え、ID を指定されたら、演出なしで即時に再現する。
- バックログの行が選ばれたら、その行の直近の ID をイベントで知らせる。
- 「ここは記録しない」の印（タイトル画面など）。
- 既読は、台本を直さない限り変わらない ID で覚える。全セーブ共通。

**セーブ**

- スロットごとに、areka の側の控え（画面と音・直近の ID）を持つ。
- 画面を画像に撮る（縮小画像）。エレメントの絵を差し替える。

**設定の値**

- 文字の速度、区分ごとの音量、全画面か窓か、オートの待ち時間、スキップの対象。これらを、スクリプトから読み書きできる値として出す。

**イベント**

- 巻き戻し、エレメントのクリック、「読み終えたので次の場面へ」、セーブとロード。名前を決め、areka の許可した一覧へ足してもらう。**すべて GET で送る。**

**配布**

- ノベルを 1 本の配布物として起動する形（ゴーストとして入れるのか、専用の起動か）は、決めていない。

### 依頼の出し方（開発者の指示・2026-10-10）

- この spec の最後のタスクで、areka のリポジトリ（`C:\home\maz\git\areka`）のセッションへ依頼書を渡す。areka の側の `/kiro-discovery` が、それを areka の brief にする。
- pasta のセッションから、areka のリポジトリを直接書き換えない。
- 依頼は、areka の決まり（1 spec は 20 タスクまで・まとめて量産しない）に合う大きさの束に分けて出す。0.5.0 に要る束と、後でよい束を分ける。
- 後続の spec が、要件定義や実装の途中で依頼を足す・変えるときも、同じ手順を踏む（取り決めの文書を直す → areka のセッションへ知らせる）。そのとき、areka のセッションを立てて、同時に説明してもよい。各 brief の「areka への依頼」の節が、その入口である。

### 依頼に添える訂正

- areka の `doc/PASTA_PROFILE.md` §5 は、「pasta が出す `\w[N]` は上流の欠陥」と書いている。2026-10-10 に確かめた所、pasta のエンジンは `\w[` を出していない（出す待ちは `\_w[ミリ秒]`）。出どころは、同じ文書の作例にある手書きの `\w[500]` である。作例を `\_w[500]` に直してもらう。

### 要件定義で最初に決めること

1. 取り決めの文書をどこに置くか（マニュアルの内部設計の部か、リポジトリの `doc/` か）。
2. 語彙の名前の付け方。areka の拡張は SSP の流儀（英語）である。日本語の名前は、pasta の別名表（`cue-command-runtime`）で足す見込み。
3. 依頼の束の分け方と、0.5.0 に要る物の線引き。
4. 動画・配布の形のように、要るかどうかから決める項目の扱い。

## 決定（2026-11-19 の discovery「ノベルゲームの深掘り」）

決まった順に書き足す。areka のセッション（2026-11-19）の現状報告と見立ては、この discovery の材料にした。

### 決定の続き（2026-11-19）

- **原則**（開発者の言葉）: 全ての画面はシーンであり、さくらスクリプトである。areka から見たら、イベント起動が付いたさくらスクリプトを延々と再生しているに過ぎない。シーンによって状態を管理する責務は、SHIORI の側にある。取り決めに「画面」「システム画面」という言葉を入れない。areka が知るのは、台本の中の命令だけである。
- **バックログに貯める・貯めないは、トグルで切り替える**（開発者の案。areka も異論なし）: `\![play,backlog,1]`／`\![play,backlog,0]`。値は 1／0（ukadoc の `\![bind,…,数値]`・`\f[bold,1]` と同じ流儀。`on`／`off` の形は ukadoc に見当たらない）。既定は 1。
  - pasta は、返す台本の頭に毎回 1 か 0 を打つ（戻し忘れを防ぐ。areka の勧め）。演劇のシーンの台本は 1、`On` で始まるシーンの台本は 0（`novel-talk-flow` の「状態はシーンで決まる」）。
  - areka は、起動・ゴーストの切り替え・SHIORI の読み直しで 1 に戻す。1／0 と true／false の 4 つを受ける。切り替わったときはログに 1 行残す。
  - 0 の間は、ほかの出どころの台本（マウスの小さな返事・外からの SSTP）も貯まらない。
- **出し直しの印は、その台本 1 本だけに効く**（areka も異論なし）: `\![play,again]`。areka は、バックログに貯めず、字を一度に出し、単発の音と転換を飛ばす。末尾の `\x` はふつうに待つ。トグルにしない（戻し忘れると、以後の全部の行で音と転換が飛ぶ）。
  - 使う所: `On` のシーンが終わって演劇へ戻るとき、pasta が最後に返した行を出し直す。出し直しのためのイベント（仮 `OnPlayResume`）は作らない。areka は、台本がどのイベントへの返事かで扱いを変えない。
- **areka の側の事実（2026-11-19。areka のセッションがコードで確かめた）**:
  - 再生中に届いた GET の返事の台本は、`OnSecondChange` と倍率（`OnShellScaling`・`OnBalloonScaling`）を除いて、全部が今のトークを置き換える。
  - 置き換えられたトークの残りは配られない。だから、割り込まれた行の末尾の `\![raise,…]` は出ない。
  - バルーンの左ダブルクリックは、台本を止めてバルーンを消す（中断）。末尾の `\![raise,…]` が出ないので、避け方を決める必要がある（`novel-talk-flow` の「まだ決まっていないこと」）。
- オートと高速再生の命令も同じ形にそろえる見込み（仮 `\![play,auto,1]`・`\![play,skip,1]`）。入切の状態の持ち主は、まだ決めていない。

### 設定のシーンへの入口（2026-11-19。開発者の決定）

- 開発者の言葉: 「本質的に特殊な扱いが必要なシーンは『設定画面』と、そこから呼ばれるセーブロードくらい。設定画面はどのシーンからでも呼び出される可能性がある」。
- **0.7.0 の入口は 3 つ**: 右クリック・常に出ているボタン・キーボード。**キーボードも必須**（開発者の決定）。コントローラーは 0.7.0 の取り決めに入れない（areka に予定が無い。足すなら、別のイベントを作らず、キーと同じ道へ寄せる）。
- pasta の側は、どの入口でも「イベントが届いて、`On` で始まるシーンが走る」だけである（`novel-talk-flow` の「状態はシーンで決まる」）。受け口は、今の条件の属性で分ける（`＊OnMouseClick　＆＄ｒ４＝「設定」`・`＊OnMouseClick　＆＄ｒ５＝１`・`＊OnKeyPress　＆＄ｒ０＝「…」`）。入口が複数でも、同じ設定のシーンへ飛ばす。
- **areka へ頼むもの**（2026-11-19 に areka のセッションへ見立てを聞いた。実機は未確認）:
  - **キーボード**: 正典の `OnKeyPress` を送る。今の areka には無く、持ち主の brief も無い（下の層の受け口は在る。重さは軽い〜中）。
  - **ボタン**: キャラクターとは別の、ボタン用の席を 1 つ（areka の brief `shell-multi-compose` の上）。そこにボタンのシェルと名前つきの当たり判定を置く。名前つきの当たり判定のクリックが `OnMouseClick` の Reference4 で届くのは、今の areka に在る。
  - **右クリック**: 頼むものは無い。areka は右ボタンを離すたびに、正典のリソース `sakura.popupmenu.visible`（スコープ 0）・`kero.popupmenu.visible`（スコープ 1）を照会する。pasta が演劇の間だけ「出さない」と答えると、右クリックが `OnMouseClick`（Reference5＝1）で届く。3 つ目からのスコープと席の窓で照会する名前は、areka でまだ決まっていない。
- 右クリックのメニューを止めている間は、ベースウェアのメニュー（終了・ゴーストの切り替え）へ行けない。設定のシーンに終了の道（`\-`）を置くことを、見本とマニュアルに書く。
- **まだ決まっていないこと**: 待っている間の入力の切り分け（物語を進める入力と、イベントで届く入力）。pasta がリソースの照会に答える口の書き方。メニューを止めたときに右クリックのイベントが届く順と回数（areka がコードを最後まで追っていない）。

### 画面の部品はアクター（2026-11-19。開発者の決定）

- 開発者の言葉: 「アクターに、紙芝居の背景の役割も持たせたい。『教室』アクターで、窓の外が雨、たまに雷が鳴るなどの『表情』があるかんじ」「システムという名前のアクターを定義すればよい。『教室』アクターなどと同じように、画面上の部品を『アクター』として管理する」。
- **画面上の部品は、アクターとして管理する**。背景（教室）も、画面の中の帯やメニューやボタンを載せた絵（システム）も、作者が名前を付けて定義する、ただのアクターである。「背景」「ボタン」「システム」という役や種別を、pasta にも取り決めにも作らない。
- 状態は表情（サーフェス）で表す。教室の「晴れ・雨・雷」も、メニューの「開いた・閉じた」も表情である。「たまに雷が光る」は、surfaces.txt のアニメーションで書ける（areka に在る）。
- 押せる所は、アクターの表情ごとの当たり判定（正典の `collision*`・`collisionex*`）。ボタンは、アクターの絵の中の「絵の部品＋名前つきの当たり判定」の組である。押すと `OnMouseClick`（Reference3＝どのアクターか・Reference4＝当たり判定の名前）で届き、pasta のシーンが拾う。さくらスクリプトで当たり判定を作るタグは正典に無く、足さない。
- areka の文書（`doc/ideas/novel-platform.md`）にも、背景もトークの場所もシェルでありアクター、と書いてある。
- OS の窓の枠（ウィンドウのモードのタイトルバー）は、この話とは別である。混ぜない。
- **まだ決まっていないこと**: 舞台の大きさ（areka のどこにも決まっていない）。Reference3 の番号とアクターの名前の対応の持ち方。雷の音を絵に合わせて鳴らす口（正典にも areka の予定にも無い）。ボタンに乗せたとき・押したときの見た目。つかんで窓を動かせる場所の決まり（areka の側）。

### 待ちの解き方（2026-11-19。開発者の決定）

- 待つのは areka（前の決定のまま）。pasta は行の末尾に `\x\![raise,OnPlayNext]` を付ける。正典の `\x` は、バルーンのクリックで解ける（ukadoc「バルーンをクリック待ちにする」）。
- **背景のクリックでも進める**（開発者の決定）。絵の上のクリックは、待っている間も `OnMouseClick` で pasta へ届く（正典に、状態で送らない条件は無い。areka も分けずに送っている）。pasta が背景のクリックを拾い、字が出ている途中かどうか（`talking`）を見ずに、次の行を返す。返した台本は待っているトークを置き換え、残っていた `\![raise,…]` は実行されない（areka のコードの事実）ので、二重には進まない。areka に頼むものは無い。pasta の中でどう背景を見分けるかは、pasta の側で決める。
- **`\x` が自動で解けるまでの時間を、台本で指す**（開発者の案。areka も異論なし）。「ふつう」と「オート」は、この時間 1 つで表す。
  - 命令は `play` の並びに置く（仮 `\![play,xtimeout,時間]`）。形は正典の `\![set,choicetimeout,時間]` にそろえる。正典の `\![set,…]` の並びには足さない（後から SSP が同じ名前を足すとぶつかる）。
  - 単位はミリ秒。数え始めは `\x` に着いた時（字が出終わった後）。**-1 は無限に待つ**（ふつう）。正の値は、その時間で自動に解ける（オート）。0 と負の値は「解かない」（正典の `choicetimeout`・`balloontimeout` と同じ読み）。読めない値は「解かない」として警告を残す。
  - 有効な範囲は、その台本の中だけ（正典の前例と同じ。discovery と areka の推奨）。pasta が、返す台本の頭に毎回打つ。オートの入切と時間は pasta が覚え、areka は状態を持たない。指定の無い台本（ふつうのゴースト）は、今までどおり押すまで待つ。
  - 時間で解けたときも、クリックで解けたときと同じに、続きの `\![raise,…]` へ進む。専用のイベントは送らない。時間切れとクリックが重なっても、解けるのは 1 回だけ。
  - 待っている途中でオートを切り替えたときは、pasta が今の行を `\![play,again]` 付きで、新しい時間を付けて返す（切り替えは次の台本から効くため）。
  - 上の「決定（2026-11-19）」の「待ちの解き方は 3 通り」と、「決定の続き」の「オートの命令（仮 `\![play,auto,1]`）」は、これで読み替える。
- **高速再生は、この時間とは別の口にする**（開発者「高速再生は多分別途さくらスクリプトのコマンドを使ってトグル切り替えするしかないのでは」）。形はまだ決めていない。
  - ukadoc と SSP のヘルプを確かめた（2026-11-19）。**さくらスクリプトに、高速再生を操るタグは無い。** 近いのは、字を一度に出す `\_q`・`\![quicksection,true]`（1／0 でも可）と、字の速さの `\![set,balloonwait,倍率]`（0 で即時表示）だけで、どれもウェイトのタグは実行される。
  - SSP では、高速再生は本体の設定である。「早送りキーを有効にする」（設定したキーを押している間、ウェイトを無視して早送りする）と、「クリック待ちタイムアウト（標準＝しない）」（クリック待ちで、どれだけ経てば待たずに読み進めるか）が、本体設定の「喋り/バルーン」に在る。
  - areka の `\![set,balloonwait,倍率]` は、まだ動かない（持ち主は areka の brief `sakura-time-directives`）。

### 高速再生のトグル（2026-11-19。開発者の決定）

- **高速再生は、バックログと同じ 1／0 のトグルにする**（開発者の決定）: `\![play,skip,1]`／`\![play,skip,0]`（名前は仮）。値は 1／0。
- 1 の台本は、字を一度に出して、`\x` で待たずに次へ進む。
- 入切は pasta が覚え、返す台本の頭に毎回 1 か 0 を打つ（バックログのトグルと同じ。戻し忘れを防ぐ）。areka は覚えない。
- 高速再生を止めるのも pasta である。入力のイベント（クリック・キー）はいつも届くので、届いたら次の行から 0 を打つ。
- **まだ決まっていないこと**: 行の中の `\w`・単発の音・転換を、高速再生で飛ばすか。未読の行で止めるか（未読かどうかを知るのは pasta だけ）。選択肢で止めること。

### 「演劇のシーン」「`On` で始まるシーン」の読み替え（2026-11-19）

- 上の節に出てくる「演劇のシーン」「`On` で始まるシーン」は、名前の決まりを取り下げたので読み替える（`novel-talk-flow` の「演劇は『台本の切り方』の状態」）。「演劇のシーン」は「演劇の状態で走っている流れ」、「`On` で始まるシーン」は「イベントで新しく走る、トークの状態の流れ」。
- 演劇の入切は、pasta の組み込みの呼び出しの対（`＞演劇開始`＝`play_start`・`＞トーク開始`）で、pasta の中だけの話である。areka は、演劇かどうかを知らない。areka が受けるのは、台本の中の命令だけである。
