# Brief: novel-areka-contract

`/kiro-discovery` で起票（2026-10-10・main `88c4bc0e`）。0.5.0「areka でノベルゲームが作れる」の道筋の 1 番目で、**areka に依頼を出すための spec** である。コードは書かない。

## Problem

0.5.0 の目標は、別リポジトリで開発中の areka で、市販品の体裁のノベルゲームが作れるようになることである。画面と音を出すのは areka で、pasta はさくらスクリプトを返すだけである。ところが、pasta がさくらスクリプトに何を載せ、areka がそれをどう受け取るかの取り決めが、どこにも無い。

- areka には、音の層・複数のシェルを 1 つの窓に並べる仕組み・場面転換の演出・スクリプトへ届くキーボード入力が無い。どれも brief すら無い。
- areka には、ほかのプロジェクトからの依頼を受ける窓口が無い。areka の新しい作業は、areka のリポジトリでの `/kiro-discovery` から始まる。
- pasta の側の spec（`cue-command-runtime` ほか 6 本）は、語彙の名前とイベントの名前が決まらないと、既定値と見本を書けない。

areka の側の作業が一番重い。依頼が遅れるほど、0.5.0 が遅れる。

## Current State

### 決まっていること（2026-10-10 の discovery での開発者の決定）

- **合格ライン**: 市販品の体裁。遊ぶ人は、クリック送り・セーブとロード・バックログと巻き戻し・既読スキップ・オート・設定・タイトル画面を使える。
- **通り道**: SHIORI/3.0 とさくらスクリプトのまま。演出は `\![名前,引数…]` に載せる。pasta 専用の通り道（`pasta_novel` アダプタ、SHIORI4）は作らない。
- **画面**: 複数のシェルの組み合わせで作る。背景・登場人物・トークの出る場所が、それぞれシェルである。普通の窓と全画面の両方を areka に依頼する。
- **アクター**: 背景もトークの場所も、キャラと同じく pasta のアクターとして扱う。状態はサーフェスで表す（例: アクター「教室と窓」に `＠稲光` を引かせると、雷の絵に替わる）。
- **システム画面**: areka が出すのは部品だけである（エレメント単位のクリック、シェルの中のバルーン、サーフェスの階層）。タイトル・セーブ・ロード・設定の画面は、シェルとして組み、pasta の場面が動かす。
- **バックログ**: 一覧（顔・話者・文）は areka が持つ。pasta はさくらスクリプトに目印の ID を埋める。バックログの行が選ばれたら、areka はその行の直近の ID をイベントで知らせる。ID の中身は pasta だけが知る。
- **表示の進み具合に関わる機能**（クリック送り・早送り・オート・既読とスキップ）は areka が持つ。どこまで表示したかを知っているのは areka だけだからである。

### areka の現在地（2026-10-10・areka main `b3650b68`・v0.0.2 を読み取りで調べた）

- 伺か互換のベースウェア。描画は Windows.UI.Composition と Direct2D・DirectWrite。1 スコープに 1 枚の透明な窓で、2 体まで。areka の土台（`wintf`）は普通の窓も作れるが、areka の本体は使っていない。
- pasta は、32 ビットの `pasta.dll` を別プロセス（`shiori-host32-helper.exe`）で動かして使っている。本番の通り道はこれだけである。
- さくらスクリプトは、areka の中で台本（`CueSheet`）に直されて再生される。`\![名前,引数…]` は、すべて `Custom{command, params}` の 1 本で運ぶ決まりで、命令ごとの型は増やさない。areka 独自の拡張は `\![…]` の中に置く。
- **もうある物**: サーフェスの階層（エレメントが別のサーフェスを呼べる）、シェルの中のバルーン、縦書き、1 字ずつの表示、選択肢、アンカー、`\_w` の待ち。
- **brief だけある物**: クリック待ち `\x` と早送り（`areka-P0-talk-fast-forward`）、ルビ、禁則、フェードで現れる文字、3 体目以降（`areka-P0-extra-character-windows`）、`OnMouseClick`（`areka-P0-mouse-click-wheel-events`）、文字入力。
- **何も無い物**: 音（BGM・効果音・声）、動画、複数のシェルを 1 つの窓に並べること、場面転換の演出、キーボード入力、ボタンなどの部品。
- areka が SHIORI へ送るイベントは、許可した名前だけである（`areka-kanade` の `ALLOWED_EVENT_IDS`）。新しいイベントは、ここへ足してもらう必要がある。
- areka は「自動の改ページ待ち」を採らない方針である（デスクトップマスコットは勝手に喋るもの、という理由）。クリック待ちは、さくらスクリプトに書いた `\x` だけで起きる。
- areka の作業の進め方: Kiro の spec 駆動。`/kiro-discovery` が `.kiro/specs/areka-P0-<名前>/brief.md` を書く。1 spec は 20 タスクまで。spec をまとめて量産しない決まりがある。文書は日本語。`.kiro/MEMO.md` は人間専用で、LLM は読まない。

### pasta の現在地（2026-10-10 に確かめたこと）

- 知らない `\![…]` は、日本語の引数を含めて、そのままさくらスクリプトに残る。待ちも改行も挟まれない。
- NOTIFY のイベントに、pasta はさくらスクリプトを返せない（DLL が Lua を走らせる前に 204 を返す。`crates/pasta_shiori/src/actor/marshaling.rs` 232 行付近）。**ノベル用のイベントは、すべて GET で送ってもらう必要がある。**
- GET の応答が 5 秒を超えると、DLL は 204 を返す（同ファイル 71 行）。

### 調査ノート（このフォルダ）

- `research-jp-engines.md` — 国産エンジン 10 系統（KAG3・NScripter・TyranoScript・Artemis・Suika2・宴ほか）のスクリプト仕様。共通コア 30 項目、セーブと実行位置の方式、スクリプトとエンジンの役割分担。
- `research-western-engines.md` — 欧米 9 系統（Ren'Py・Ink・Yarn Spinner・Naninovel ほか）。ホストとの取り決めの 3 つの型、コルーチン実行でのセーブと巻き戻し、ホストに前提される最小の演出語彙。

どちらも、記述ごとに「取得したページで確かめた／記憶」の印がある。記憶の印の記述は、根拠にする前に原典で確かめる。

## Desired Outcome

- pasta と areka の取り決めが、1 つの文書になっている。版の番号を持つ。
- その文書から起こした areka への依頼書が、areka のセッションへ渡っている。areka の側でどの brief になったかの対応表が、pasta の側に残っている。
- 0.5.0 に要る物と、後へ回す物の線引きが、依頼ごとに書いてある。
- 後続の spec が、語彙の名前・イベントの名前・設定の値の名前を、この文書から引ける。

## Approach

### 取り決めの文書に書くこと

何が出来てほしいかだけを書く。作り方は書かない。areka の言葉（シェル・サーフェス・スコープ・バルーン・エレメント・台本）で書く。下は、discovery の時点での要求の一覧（要件定義のたたき台）である。

**画面**

- 複数のシェルを、1 つの窓の中に組み合わせて出す（背景・登場人物・トークの場所・上に重ねる画面）。
- 普通の窓と全画面。その切り替え。画面の大きさが違う環境での拡縮。
- シェルごとの位置（名前の付いた席と数値）、重ね順、出す・消す。3 体以上。

**映像**

- サーフェスの替わり方。瞬間・クロスフェード・ルール画像によるワイプ。時間の指定。複数の変更をまとめて 1 回で替える。
- 位置・大きさ・不透明度を、時間をかけて変える。
- 画面の揺れ、フラッシュ、色調（暗転・セピアなど）。
- 動画は、要るかどうかから決める。

**文章**

- トークの出る場所は、シェルの中のバルーン。話者名の欄。名前を指定してバルーンへ書く。
- クリック待ち（`\x`）と早送り。行末の待ちと改ページの待ち。窓を出す・隠す。
- 文字の速度、色、大きさ、ルビ。下に窓を置く形と、全画面に文を流す形。

**音**

- 曲: 再生・停止・ループ・フェード・曲から曲への移り変わり。同じ曲は鳴らし直さない。
- 効果音: 重ねて鳴らす。ループ。
- 声: 台詞に結び付ける。次の台詞で止める。バックログから聞き直す。
- 区分ごとの音量。演出のための音量と、遊ぶ人の設定の音量を分ける。再生の終わりを待つ。

**時間と入力**

- 時間の待ち（飛ばせる・飛ばせない）。演出が終わるまでの待ち。
- クリック送り。キーボード（送り・スキップ・画面を開く）。
- エレメント単位のクリックを、名前つきで知らせる。
- オート（声が終わるのを待つ）。スキップ（既読だけ・全部）。

**目印・バックログ・既読**

- 目印の ID をさくらスクリプトに書ける。areka は、通り過ぎた ID を、バックログの行に結び付けて覚える。
- 目印を通り過ぎた時点の画面と音を控え、ID を指定されたら、演出なしで即時に再現する。
- バックログの行が選ばれたら、その行の直近の ID をイベントで知らせる。
- 「ここは記録しない」の印（タイトル画面など）。
- 既読は、台本を直さない限り変わらない ID で覚える。全セーブ共通。

**セーブ**

- スロットごとに、areka の側の控え（画面と音・直近の ID）を持つ。
- 画面を画像に撮る（縮小画像）。エレメントの絵を差し替える。

**設定の値**

- 文字の速度、区分ごとの音量、全画面か窓か、オートの待ち時間、スキップの対象。これらを、スクリプトから読み書きできる値として出す。

**イベント**

- 巻き戻し、エレメントのクリック、「読み終えたので次の場面へ」、セーブとロード。名前を決め、areka の許可した一覧へ足してもらう。**すべて GET で送る。**

**配布**

- ノベルを 1 本の配布物として起動する形（ゴーストとして入れるのか、専用の起動か）は、決めていない。

### 依頼の出し方（開発者の指示・2026-10-10）

- この spec の最後のタスクで、areka のリポジトリ（`C:\home\maz\git\areka`）のセッションへ依頼書を渡す。areka の側の `/kiro-discovery` が、それを areka の brief にする。
- pasta のセッションから、areka のリポジトリを直接書き換えない。
- 依頼は、areka の決まり（1 spec は 20 タスクまで・まとめて量産しない）に合う大きさの束に分けて出す。0.5.0 に要る束と、後でよい束を分ける。
- 後続の spec が、要件定義や実装の途中で依頼を足す・変えるときも、同じ手順を踏む（取り決めの文書を直す → areka のセッションへ知らせる）。そのとき、areka のセッションを立てて、同時に説明してもよい。各 brief の「areka への依頼」の節が、その入口である。

### 依頼に添える訂正

- areka の `doc/PASTA_PROFILE.md` §5 は、「pasta が出す `\w[N]` は上流の欠陥」と書いている。2026-10-10 に確かめた所、pasta のエンジンは `\w[` を出していない（出す待ちは `\_w[ミリ秒]`）。出どころは、同じ文書の作例にある手書きの `\w[500]` である。作例を `\_w[500]` に直してもらう。

### 要件定義で最初に決めること

1. 取り決めの文書をどこに置くか（マニュアルの内部設計の部か、リポジトリの `doc/` か）。
2. 語彙の名前の付け方。areka の拡張は SSP の流儀（英語）である。日本語の名前は、pasta の別名表（`cue-command-runtime`）で足す見込み。
3. 依頼の束の分け方と、0.5.0 に要る物の線引き。
4. 動画・配布の形のように、要るかどうかから決める項目の扱い。

## 決定（2026-11-19 の discovery「ノベルゲームの深掘り」。最終形）

**この節が正である。** 上の「Current State」「Approach」と、2026-11-19 より前の申し送りのうち、この節と食い違う所は、この節で読み替える。骨子の全体は、このフォルダの `final-model-2026-11-19.md`（以下「骨子」）、台本を書く人の目線のまとめは `play-script-guide.md`、議論の経緯は `discovery-2026-11-19.md`、調査は `research-display-patterns.md`・`research-ssp-capabilities.md` に在る。この節は、2026-11-19 の最後の洗い直しで、決まった順に書き足してきた節を 1 つにまとめ直した物である（前の形は git の履歴に在る）。命令の名前は、どれも仮で、この spec の要件定義で確定する。ベースウェアの動きに関わる所は、areka のセッションと協議して、食い違いを無くした（areka の側は、読むだけの調査の見立てである）。

### 原則

- **全ての画面はシーンであり、さくらスクリプトである**（開発者）。ベースウェアから見たら、イベントの起動が付いたさくらスクリプトを、延々と再生しているに過ぎない。状態を管理するのは、SHIORI（pasta）の側である。
- 取り決めに、「画面」「システム画面」「演劇」「シーン」という言葉を入れない。ベースウェアが知るのは、さくらスクリプトの中の命令だけである。走り方（柱 `＆再生モード`。トーク・演劇・設定）は、pasta の中だけの話である。
- **命令の名前の頭は `play`**。ukadoc に `\![play,…]` というタグは無い。SSP 2.9.34 は、知らない `\![play,…]` を読み飛ばす（実機で確かめた）。
- **正典を先に使う**（開発者の承認）。正典に在る物は正典のタグで出し、`play` の命令は、正典に無い物だけにする。
- **バックログは、ベースウェアの機能である**（開発者の決定）。pasta.dll に依らない。取り決めの名前に `pasta` を入れず、ほかの SHIORI でも、同じ印を埋めれば同じことができる形にする。
- **セーブデータは pasta だけが持つ。** ベースウェアの側の控えは作らない。

### さくらスクリプト 1 本の形

- pasta は、演劇の間、アクション行ごとに、さくらスクリプトを 1 本返す。末尾は、正典の `\x` と `\![raise,イベント名]` である。選択肢の在る 1 本は、`\x` を付けず、選ばれるのを待つ。
- イベントの名前（`OnPlayNext`・`OnPlayRollback`）は、pasta の中の名前である。pasta が `\![raise,…]` と目印の引数で渡すだけで、ベースウェアは名前を知らない。
- ベースウェアは、`\x` で待つ間と、`\![raise]` を打ったさくらスクリプトが終わってから返事が届くまで、Status の talking を立てたままにする。`\x` で待つ間、台詞の箱を閉じない。
- 例: `\![play,mark,OnPlayRollback,12]\p[1]それほどでもない。\x\![raise,OnPlayNext]`

### 命令の表

| 用途 | 形 | 効く範囲 |
| ---- | -- | -------- |
| 待ち・続き | 正典の `\x`・`\![raise,イベント名]` | — |
| 貯めない | 正典の `\__v[disable]` の区間（SSP は、この区間をバックログに記録しない。実機で確かめた） | その区間 |
| 字を一度に出す（高速再生） | 正典の `\_q`。pasta が `\x` と瞬間の命令を出さない | その 1 本 |
| 曲・環境の音・効果音・声 | 正典の `\![sound,loop／play／stop,名前]`。同じ曲は pasta が打たない。止めるときは名前を付ける | — |
| 字の前の間 | 正典の `\_w` | — |
| 目印 | `\![play,mark,イベント名,ID]`。バックログのこの行に目印を付ける。遊ぶ人がこの行を選んだら、そのイベントを GET で送り、Reference0 に ID を載せる。字の無い 1 本には付けない | その 1 本 |
| 出し直しの印 | `\![play,again]`。貯めない。字を一度に出す。`\w`・`\_w` を飛ばす。`\x` はふつうに待つ。頭で、鳴っている途中の単発の音と声を止め、並走を全部止める。残る命令の値を全部既定へ戻してから、続く命令を当てる（pasta は、いつも状態を全部書く） | その 1 本 |
| `\x` の時間 | `\![play,xtimeout,ミリ秒]`。`\x` が自動で解けるまでの時間。数え始めは `\x` に着いた時。-1 は解かない。0 と負の値・読めない値は「解かない」。時間で解けたときも、クリックで解けたときと同じに、続きの `\![raise,…]` へ進む | その 1 本 |
| 話者の名前 | `\![play,speaker,名前]`。既定は並びの名前で、替えたいときだけ打つ | その 1 本 |
| 並走の区間 | `\![parallel,1]`・`\![parallel,0]`（下の「並走」） | その区間 |
| 舞台・並び・位置・重ね順・大きさ・透明度・転換・揺れ・フラッシュ・色調・カメラ | `play` の命令（名前は要件定義で確定） | 残る命令は、窓に残る |

- 値のフラグは 1／0 にする（ukadoc の `\![bind,…,数値]`・`\f[bold,1]` と同じ流儀）。
- 残る命令の表を、取り決めに 1 つ持つ。表の命令は、同じ値をもう一度受けたら何もしない。「無い」の打ち方は、引数なし（サーフェスは `\s[-1]`）。
- 待ちを挟まずに続けて書いた命令は、同じフレームで見える。ベースウェアは、その 1 本の同じ時刻の命令を全部当ててから、最初の絵を出す（作りかけの舞台を見せない）。
- SSP へは、`\x` の時間を `\![timerraise,ミリ秒,1,OnPlayNext]\x\![timerraise,0,1,OnPlayNext]\![raise,OnPlayNext]` の形で出す（pasta が直す。`\![set,balloontimeout]` は `\x` に効かない。実機で確かめた）。

### バックログと目印

- どの SHIORI のゴーストでも、さくらスクリプトを再生すれば、バックログに行が貯まる。目印は、SHIORI が任意で埋める印である。
- 目印の無い行は、選べない（選んでも何も起きない）。
- 字の無い 1 本は、バックログに行を作らない。
- 戻るとき、pasta は 2 本返す。1 本目は、出し直しの印付きで、画面の状態だけ（字も `\x` も無く、末尾で `\![raise]`）。2 本目は、選ばれた行を、同じ目印の ID で、ふつうに再生する。
- 結果として、選ばれた行を含めて後ろのバックログは消え、選ばれた行が貯め直る（開発者の承認）。
- 捨てるのは、行を選ばれた時である（今のまま）。
- ID は英数字だけにする。`\![raise,OnPlayNext,ID]` の引数は、正典どおり Reference0 に載る。

### 待ちの解き方

- 待つのは、ベースウェアである。正典の `\x` は、台詞の箱（吹き出し）のクリックで解ける。
- 絵の上のクリックは、待っている間も `OnMouseClick` で pasta へ届く。pasta が拾って、次の 1 本を返す。返したさくらスクリプトは、待っている 1 本を置き換え、残っていた `\![raise,…]` は実行されない（SSP の実機と、areka のコードで確かめた）。
- オートは、`\x` の時間で表す。入切と時間は pasta が覚え、ベースウェアは状態を持たない。
- 高速再生も、入切は pasta が覚える。キーを押している間だけの早送り（SSP の本体の設定）は、取り決めに入れない。

### 設定の画面への入口（開発者の決定）

- 入口は 3 つ: 右クリック・常に出ているボタン・キーボード。**キーボードも必須。** コントローラーは入れない。
- pasta の側は、どの入口でも「イベントが届いて、シーンが走る」だけである。受け口は、今の条件の属性で分ける（`＊OnMouseClick　＆＄ｒ４＝「設定」`・`＊OnMouseClick　＆＄ｒ５＝１`・`＊OnKeyPress　＆＄ｒ０＝「…」`）。
- ベースウェアへ頼むもの:
  - キーボード: 正典の `OnKeyPress` を送る（今の areka には無い）。Alt+Enter も、ベースウェアは自分で切り替えず、`OnKeyPress` で送る。
  - ボタン: アクターの絵の中の、名前つきの当たり判定（下の「画面の部品はアクター」）。
  - 右クリック: 頼むものは無い。pasta が、正典のリソース（`sakura.popupmenu.visible` など）に「出さない」と答えると、右クリックが `OnMouseClick`（Reference5＝1）で届く。
- 右クリックのメニューを止めている間は、ベースウェアのメニュー（終了・ゴーストの切り替え）へ行けない。設定のシーンに終了の道（`\-`）を置くことを、見本とマニュアルに書く。

### 画面の部品はアクター（開発者の決定）

- 画面上の部品は、全部アクターとして管理する。背景（教室）も、帯やメニューやボタンを載せた絵（システム）も、作者が名前を付けて定義する、ただのアクターである。「背景」「ボタン」「システム」という役や種別を、pasta にも取り決めにも作らない。
- 状態は表情（サーフェス）で表す。「たまに雷が光る」は、surfaces.txt のアニメーションで書ける。
- 押せる所は、アクターの表情ごとの当たり判定（正典の `collision*`・`collisionex*`）。押すと `OnMouseClick`（Reference3＝どのアクターか・Reference4＝当たり判定の名前）で届く。さくらスクリプトで当たり判定を作るタグは、足さない。

### 舞台の窓と箱

- **舞台の開け閉めは、作者が書く**（開発者: 「＞演劇開始と舞台スクリーン窓の開始は別の制御。！コマンドで別途定義すべき」。この言葉の後、走り方は柱 `＆再生モード` で書く形になった）。pasta は自動で打たない。舞台を開かない演劇は、デスクトップのゴーストのまま、1 行ずつ進む。ロードで戻したい舞台は、柱で書く（`＆舞台：開く`）。
- 窓の形は 3 つ（ウィンドウ・全画面・ボーダーレス）。遊ぶ人の設定で、pasta が保存して打つ。既定はウィンドウ。作者がト書きで形を指したときだけ、それが勝つ。ベースウェアは保存しない。
- **基準の大きさは 1920×1080**（96DPI の論理の大きさ）。絵と座標は基準の大きさで作り、ベースウェアが、窓の大きさに合わせて拡大縮小する。比が合わないときは、比を保って中央に置き、余りは黒にする。マウスのイベントの座標は、基準の大きさの値で届く。黒い余白の上のクリックは送らない。窓の大きさは覚えない。最大化のボタンは押せなくする。
- 舞台が開いている間、デスクトップの窓とバルーンは隠す。閉じると、隠す前の位置と絵のまま戻す。閉じるとき、ベースウェアは、残る命令を全部「無い」に戻し、バックログの目印を外す。窓の × と Alt+F4 は `OnClose` へ流す。
- 並び（仮 `\![play,cast,…]`）は窓に残る。並びに無いアクターは消える。スコープの番号は並びの順で、同じ 1 本の中でも、並びの命令の位置で意味が切り替わる。位置を明示しないアクターは、並びと役（背景 → 役者 → トークの場所）から自動で置く。位置を明示したアクターは、自動の並べ方に数えない。席の名前と位置の対応は、舞台の定義（`descript.txt` の areka の独自キー）に書く。（**2026-11-20 に改めた**: 自動で置く決まりと、席の対応を舞台の定義に書く決まりは、外した。座標は、pasta が命令で渡す。末尾の「立ち位置と並走」の節）
- 台詞の字は、pasta が話者のスコープに打ち、ベースウェアが「トークの場所」の役のアクターの箱へ出す。箱のアクター自身のスコープで打った字は、その箱に出る（地の文・チャット）。トークの場所が並びに居ないときは、話者自身のシェルの箱へ出す。舞台の中に、ふつうのバルーンは出さない。縦書きか横書きかは、箱の定義で決まり、同じ舞台に両方を置ける。
- 話者の名前は、台詞の箱のシェルの中の、決まった名前の小さい箱に出す。箱が無ければ、名前は出さない。
- シェルの切り替えのメニューは、areka が役で隠す。配布はゴースト（`.nar`）のまま。

### 並走（開発者の承認。areka 独自）

開発者: 「1 が終わらないまま、1 のアニメーションが継続しつつ、2 の再生が『上書きされずに』開始される。」

- 1 本のさくらスクリプトの中に、並走の区間を書く（開く印と閉じる印）。ベースウェアは、区間を別の流れとして始める。主の流れは、区間のぶんの時刻を進めず、待たずに先へ進む。
- 区間に書ける物は、見た目（サーフェス・着せ替え・アニメーション）と、音と、待ち。字・選択肢・`\x` は読み捨てて記録する。
- 後から始まった流れが、あるアクターの表情を置いたら、前から走っている並走は、そのアクターへはもう書かない。（**取り下げ。2026-11-20**。末尾の「立ち位置と並走」の節）
- 並走は、自分の末尾まで走って終わる。クリックの早送りは効かせない。出し直しの頭と、舞台を閉じるときは、全部止める。
- 閉じる印が無ければ、1 本の終わりまでを区間とする。入れ子は効かせずに記録する。閉じる印で、スコープは開く印の前の値へ戻る。
- areka の brief `parallel-visual-script`（1 本の冒頭に印を置く形）の要件に、区間の形を足してもらう。印の名前は 1 つにそろえる。
- 頼みごとに足す物: 正典の `\i[ID]`（アニメーションを名指しで始める）。

### 転換（開発者の決定）

- 転換は、直前の絵から、新しい絵へ替わる。今、画面に出ている絵（転換の途中なら、途中の絵）が出発点になる。黒を挟む形と、ルール画像は入れない。
- 替わったアクターごとに溶かす。サーフェスが替わったアクターは、前の絵から次の絵へ溶ける。透明度は濃淡が動く。位置と大きさは動く。並びに入る・出るアクターは、溶けて現れる・消える。重ね順は、その瞬間に替わる。
- 転換は始めるだけで、後ろの字を待たせない。待つのは正典の待ちのタグで、pasta が打つ。
- 命令の形（仮）: `\![play,trans,ミリ秒]`。まとめの終わりは「次の字・次の待ち・次の転換・1 本の終わり」。時間 0 は、前の転換の組を終わらせる。
- クリックで字を早送りしたら、走っている転換も、新しい絵へ飛ぶ。

### フェーズ（開発者の決定）

開発者: 「現在の SSP でも実現可能なもの、SSP が対応すれば可能なもの、areka がないと実現できないもの、この 3 つでフェーズを分けます。」「最低限実現に必要なもの → 実装が重いが後回しでもよいもの、は分けるべきですね。」

- 同じ台本を、SSP でも areka でも動かす。pasta が、ベースウェアが areka かどうかと areka の版を見て、タグへ直す（`cue-command-runtime`）。
- 取り決めの文書は、マニュアルの内部設計の部に 1 章として置き、3 つのフェーズを通して 1 本で持つ。合格の測り方: 正典だけで動く層は SSP の実機で、`play` の命令の層は areka の実機で測る。
- **実施の時期**: フェーズ 1 は、areka を待たずに作れる。フェーズ 2・3 は、ベースウェアの準備を待つ（areka のノベルゲーム基盤は v0.4.0 の後ろ。areka の並びは動かさない）。この spec（取り決めの文書）は、先に始められる。

### areka の現状（2026-11-19。areka のセッションの報告）

- ノベル向けの部品は、ほぼ全部がまだ無い。在るのは、シェルの中のバルーン・名前つきの当たり判定のクリックを `OnMouseClick` の Reference4 で送ること・知らない `\![名前,…]` を運ぶ入れ物・`\![get,property,…]`・`\![set,choicetimeout]` と `OnChoiceTimeout`。

### 作らないもの

- キーを押している間だけの早送り。
- 絵のアニメーションに合わせて音を鳴らす口（作者がト書きで鳴らす）。
- ボタンに乗せたとき・押したときの絵（areka の brief `shell-hover-animation` を待つ）。
- コントローラー。

### 要件定義へ送ること

- 命令の名前の確定。遊ぶ人の設定（文字の速さ・音量・窓の形）を伝える命令。SSP に入れられたときの知らせ方。数値の位置の基準と、アクターのどこを合わせるか。
- areka の勧め（どれも、読むだけの調査の見立て）:
  - 隠したアクター（`\s[-1]`）は、当たり判定・名前の欄・箱が出ない。隠したアクターのスコープで、字を打たない。
  - 字の箱を持つアクターは、役を「トークの場所」にする。人物の字は、並びで最初の、出ているトークの場所へ回す（台詞の箱を、チャットの窓より先に並べる）。
  - 選ばれるのを待つ間も、並走は走り続ける。選ばれた後の最初の 1 本で、並走の区間が書いていたアクターの表情を置く。
  - サーフェスのアニメーションは、`\x` や選択肢で待つ間も進み、同じサーフェスの置き直しでは頭から始まらない。
  - ロードの 1 本目に、「バックログを空にする」合図を足す（正典に無い。足さないなら、pasta は ID をロードをまたいで重ねない）。
  - 止まった舞台から、遊ぶ人が必ず出られる道（メニュー・閉じるキー）を、ベースウェアが持つ（areka の `shell-multi-compose` の要件に足す）。
  - 舞台が開いている間に talking が落ちると、`OnSecondChange` が「トークを再生できる」で届く。pasta は、演劇の間、ランダムトークを返さない（`novel-talk-flow`）。演劇でなく、舞台だけが開いている間をどうするか。
- 選択肢の行と、選んだ答えを、バックログにどう並べるか。

## areka の作り直した設計からの見立て（2026-11-20。**決定ではない**。取り決めの要件定義の材料）

2. 出し直しの印は、1 本の先頭（最初の字と待ちより前）に書く。先頭でなければ、効かせずに記録する。
3. 並びの命令・舞台の開け閉め・字を受ける印は、主の流れに書く。並走の流れに書かれた物は、読み捨てて記録する。
