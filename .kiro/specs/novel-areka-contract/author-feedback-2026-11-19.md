# 台本を書いた側の困りごと（2026-11-19）

固まった文法（`final-model-2026-11-19.md`）で、ゴースト作者のセッション（「ぱすた開発」）が、台本 2 本を頭から書き直した。1 本は areka の舞台を使う長い物（場面 6 つ・結末 3 つ）、もう 1 本は今の SSP だけで遊べる短い物である。その時に「文法で困った所」として返ってきた一覧を、設計の材料として控える。

- 台本そのもの（台詞・設定）は、作者のリポジトリに在り、ここへは写さない。ここに書くのは、書き方の要点だけである。
- 2 本とも、discovery が全文を骨子と照らした。**骨子と食い違う書き方は、無かった。** 下の一覧は、どれも「決まりどおりに書けたが、書きにくかった・書けなかった」所である。
- 各項目の「見立て」は discovery の物で、決定ではない。暫定設計の問題点と合わせて、開発者と議論する。

## A. 書きたい演出が書けなかった・形を変えた所

| 番号 | 困りごと | 見立て |
| -- | -------- | ------ |
| A1 | 台詞の途中で、別のアクターの絵を替えたい（前の字を吹き出しに残したまま、背景を替えて、続きの字を足す）。1 本はアクション行の末尾で切れ、継続行は別のアクターの行をまたげないので、2 本に分けて `！時間で次へ` でつないだ。前の字は、2 本目で消える | 1 本の切り方（骨子 2.2）の帰結。前の字を消さずに続ける口が要るかどうか。SSP には、前のスクリプトの吹き出しに書き足すタグ（`\C`）が在る（areka では未確認） |
| A2 | 場面の途中で変わる演出は、ロードで戻らない。戻るのは柱だけなので、状況が変わるたびにシーンを分けた（台詞 1 行だけのシーンも出来た）。分けなかった所は、戻らない | 骨子 2.5 のとおり（「ロードで戻したい物は、柱に書く」）。作者は、承知で書き分けている |
| A3 | 柱の変化が、シーンの頭の転換に入らない。着いた時に柱が先に打たれるので、頭の `！転換（２０００）` で溶かしたい色の変化が、先に替わってしまう | **設計で決める所。** 1 本の中の、柱とシーンの頭のト書きの並び順。頭の転換が、着いた時の柱の変化も包むかどうか |
| A4 | 対象つきの残る命令（`！名前＠対象（値）`）を、柱に書く形が無い。ト書きのままなので、ロードで戻らない | 柱は `＆名前：値` で、対象を書く所が無い。アクターに付く物（位置・透明度・大きさ）はアクター状態として戻るが、語彙の外の「対象つきの残る命令」は戻らない |
| A5 | 席の名前（フェーズ 1）。今の SSP で決まっているのは数値の位置だけである。画面の大きさは人で違うので、数値では書けない。画面の端・まんなか・始めたときの位置を、名前で指したい | `cue-command-runtime` の「要件定義で決めること」に在る（席の名前を、正典の移動の引数へ直す表。窓の今の位置を覚えて、元へ戻す形）。フェーズ 1 の必須の物として扱うかどうか |
| A6 | 選択肢の見た目。選択肢を出す場所を変えるために、台詞の末尾に、さくらスクリプト入りの単語を手で書いた（4 か所） | 選択肢の出力の形は、`choice-line-layout`（完了）と `novel-talk-flow` の境目。語彙の外 |
| A7 | 残り時間の絵と、時間切れ（`！select（ミリ秒、飛び先）`）が、別々である。絵の長さと時間を、手で合わせる | 語彙の外。今は、作者が合わせる |
| A8 | トークのモードへ戻すシーンは、まとめて 1 本で出るので、終わりの台詞が 1 つの吹き出しに並ぶ。1 行ずつ出したければ、もう 1 つシーンを分ける | 骨子 2.1 のとおり（シーンの途中では、走り方を切り替えられない） |

## B. 同じ事を何度も書いた所

| 番号 | 困りごと | 見立て |
| -- | -------- | ------ |
| B1 | ファイル属性に、残る演出の「なし」を 10 個並べた。ロードや巻き戻しで、前の場面の残り物を消すためである。新しい演出を 1 つ使うたびに、ここへ足すことになる | **骨子へ諮る候補。** ロードと巻き戻しで、その行の階層に書いていない「残る物」を、どうするか。今の文面は「階層の柱を打つ」だけで、書いていない物には触らない（ロードする前の音や色が、そのまま残る） |
| B2 | 待たない印を、背景と小道具の表情の単語の全部（30 語ほど）に付けた。付け忘れると、その行でクリックを待つ | 印を、単語ごとでなく、アクターごと（役が背景・小道具なら既定で待たない）に付ける口が要るかどうか |
| B3 | 似た場面 3 つの頭と終わり（代入・通知・転換・表情）を、3 回書いた。変数の名前を引数から作れないので、束にできなかった | 語彙の外。束（シーンと引数つきの呼び出し）の限界 |
| B4 | `＆再生モード：演劇` を 2 か所に書いた（舞台を開く前の入口の宣言行と、その後ろのファイル属性） | ファイル属性は「その行より後ろ」に付くので、こうなる。今のまま |
| B5 | 途中から出すアクターを、最初に隠す行を書いた（3 行） | 並び（`％`）に入れたアクターは、表情を指定するまで出さない、という既定が要るかどうか（areka の側の話） |
| B6 | 同じ値を 2 か所に書いた（台詞の途中で落とすト書きと、次のシーンの柱）。途中で替えるのはト書き、ロードで戻すのは柱、と 2 度書く | A2 と同じ根 |

## 読んで気づいたこと（discovery）

- 選択肢と `！select` が、途中の `＞` で呼んだローカルシーン（口上）の台詞の後に続く書き方が在る。「選択肢は、直前のアクション行の 1 本に入る」を、呼んだ先から戻った後にも効かせる必要がある（`novel-talk-flow` の設計で確かめる）。
- 同じ飛び先の選択肢を 3 つ並べ、飛び先を、条件つきの同名のローカルシーン 3 つにする書き方が在る（くじ引き）。今のコードでは通る: 選択肢の行は ID と見出しだけを見る（`grammar.pest` の `choice_line`）。選ばれた ID は、選択肢を出したグローバルシーンのローカルから、条件で絞って探す（`shiori/event/choice_select.lua` の `SCENE.search(choice_id, scope, act)`。シャッフルして順に使うのは、その中）。辞書の検査に、同じ飛び先の選択肢を止める検査は無い。選択肢の行の条件（`＆`）は、今の文法に無く、Phase 13 で足す物である。
- 途中の `＞` で、同名のシーンの抽選を呼ぶ書き方（条件つきの口上）が在る。巻き戻しとロードは「今のシーンを頭から早回しする」ので、早回しの中の抽選が、前と違うシーンを選ぶと、区切りの通し番号がずれる。条件が互いに重ならなければ起きないが、重なる書き方も書ける。`novel-checkpoint-rollback` の設計で確かめる。
- 題の画面を、設定のモードで書いている（題字と選択肢は、バックログに残らず、巻き戻しの戻り先にならない）。物語の再生位置は、入口の 1 行のままである。
- 語彙の外の名前（色の調子など）を、柱に書いている。作者の読み: 「pasta が意味を知らないト書きも、柱に書けば、着いた時に打たれる。柱の『なし』は、引数なしのト書きになる」。骨子と `cue-command-runtime` の brief の文面どおりなら、そうなる。pasta が意味を知らない名前の「今の値」を覚えるかどうか（同じ値なら打たない、の扱い）は、設計で決める。
- 手引きと `cue-command-runtime` の brief の、ト書きの束の例が `！移動` になっていた（pasta が意味を知る 10 個に在るのは「位置」）。`！位置` に直した。
