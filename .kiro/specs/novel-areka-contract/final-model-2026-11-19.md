## 1. 言葉

| 言葉 | 意味 |
| ---- | ---- |
| 台本 | pasta DSL（`*.pasta`）。柱・ト書き・台詞から成る |
| さくらスクリプト | pasta が、ベースウェアのイベント 1 回に返す文字列。この文書では「1 本」と数える |
| 再生モード | 走り方を決める柱（`＆再生モード`）。値は、トーク・演劇・設定 |
| 演劇 | アクション行ごとに、さくらスクリプトを 1 本返して待ち、記録する走り方 |
| 設定 | アクション行ごとに 1 本返して待つが、記録せず、物語の再生位置を動かさない走り方（設定やセーブの画面） |
| トーク | 演劇でない、今までどおりの走り方（シーンをまとめて 1 本で返す） |
| 今のシーン | イベント（選択肢・時間切れを含む）か、最後の行の `＞`（ジャンプ）で、最後に着いたシーン。途中の行の `＞` で呼んだ先は、今のシーンの続きとして数える |
| 再生位置 | 今のシーンと、そこから数えた行の番号。演劇の再生位置は、いつも 1 つである |
| 目印 | 演劇の 1 本ごとに、pasta がさくらスクリプトに付ける印。バックログの行と 1 対 1 になる |
| 控え | pasta が 1 本ごとに覚える物。その 1 本の始まりの、再生位置・変数・アクター状態 |
| 状況 | 柱で決まる物（曲・環境の音など） |
| アクター状態 | 誰が出ているか（並び）と、アクターごとの表情（サーフェスと着せ替え）・位置・重ね順・大きさ・透明度 |
| ベースウェア | SSP か areka。pasta の「台本」「演劇」「シーン」を知らない。知るのは、さくらスクリプトの中の命令だけ |

## 2. 決まり

どの決まりも、1 文で言える形にしてある。開発者の原則は次の 4 つである。

- ルールは直観的に、簡潔に。作者にとって直感的でない挙動を組み込まない。
- `＞`（最後の行）は、末尾再帰の無限ジャンプである。物語は前へ進む。「シーンが終わって戻る」時点に、意味を持たせない。
- 場合で処理が変わる設計は、一般化が出来ていない兆候である。
- 全ての画面はシーンであり、さくらスクリプトである。状態を管理するのは pasta（SHIORI）で、ベースウェアは、イベントの起動が付いたさくらスクリプトを再生するだけである。

### 2.1 再生モード（走り方）

- 走り方は、柱 `＆再生モード`（仮）で書く。値は、トーク・演劇・設定の 3 つである。

| 値 | 走り方 |
| -- | ------ |
| トーク | シーンをまとめて、さくらスクリプト 1 本で返す（今までのゴースト） |
| 演劇 | アクション行ごとに 1 本返して待つ。記録する（目印・バックログ・セーブ） |
| 設定 | アクション行ごとに 1 本返して待つ。記録しない。物語の再生位置を動かさない |

- 柱なので、2.4 の決まりが、そのまま効く。上書きで、書いていなければ前のモードが続く。その行のモードは、シーンの階層を引いて決まる。
- ふつうのゴーストの途中から始められる。演劇のモードのシーンへ飛べば、着いた時に演劇になる。舞台の窓を開くことは、別の制御である（2.7）。
- シーンの途中では、走り方を切り替えられない。切り替えたい所で、シーンを分ける。
- シーンが最後の行まで走って `＞` が無くても、モードは変わらない。次のイベントを待つ（4 章の A）。
- 演劇と設定のモードの間は、時報とランダムトークを返さない。
- 設定のモードの場面から、物語へ単に戻るときは、`＞演劇再開` を書く。何も戻さず、待っていた物語の行が、もう一度出る。ロードで戻るときは、`＞スロット読込` を書く（4 章の C）。

```pasta
＆再生モード：演劇

＊第一章
    さくら：むかしむかし。
    うにゅう：ほう。
    ＞エンディング

＊エンディング
    さくら：おしまい。
    ＞あとがき

＊あとがき　＆再生モード：トーク
    さくら：また読みたくなったら言ってね。

＊OnMouseClick　＆＄ｒ４＝「設定」　＆再生モード：設定
    さくら：どうする？
    ＠？セーブする「セーブ」
    ＠？ロードする「ロード」
    ＠？もどる「物語へ戻る」

    ・セーブする
        ＞スロット保存（１）
        さくら：保存したよ。
        ＞演劇再開

    ・ロードする
        ＞スロット読込（１）

    ・もどる
        ＞演劇再開
```

### 2.2 1 行ずつ進む（区切り）

- 1 本は「前の区切りの次から、次のアクション行（と、その継続行）の末尾まで」である。字の無いアクション行（表情だけ）も 1 本になる。
- ト書き（`！` 行）・柱・アクター指定行は、直後のアクション行の 1 本に、書いた順で入る（ト書きは、直後のアクション行を修飾する）。
- pasta は、1 本の末尾に `\x\![raise,OnPlayNext]` を付ける。作者は `\x` を書かない。
- 選択肢の行（`＠？`）と `！select` は、直前のアクション行の 1 本に入る。その 1 本は、クリックでなく、選ばれるのを待つ。
- 待たせたくない表情は、アクター辞書の単語に、待たない印（仮 `\![parallel]`）を書く。印の在るアクション行は、末尾で待たずに、次のアクション行と同じ 1 本になる。areka では、印から単語の終わりまでが、並んで再生される（見た目と音だけ）。SSP では、順に再生される。
- 後ろにアクション行が無い残り（シーンの終わりのト書きなど）は、待たない 1 本として出る。目印は付かない。
- 行の番号は、区切り（1 本）の通し番号で数える。途中の `＞` で呼んだ先の行も、同じ通し番号で数える。

```pasta
％教室
    ＠稲光：\![parallel]\s[12]\_w[200]\s[10]\_w[200]\s[12]

＊嵐の教室　＆曲：雨音
    ％教室、さくら
    さくら：降ってきたね。
    ！効果音（雷）
    教室：＠稲光
    さくら：＠驚き　きゃっ！
```

1 本目は、柱・並びと「降ってきたね。」。2 本目は、雷・稲光と「きゃっ！」（稲光の単語に印が在るので、教室の行では待たない）。

### 2.3 分岐は 1 つの形

- 演劇の再生位置は、いつも 1 つである。
- クリックでも、選択肢でも、時間切れでも、イベントでシーンが選ばれたら、再生位置はそのシーンへ移る。今のトークと同じ動きである（続きは 1 つで、台詞を出すシーンが選ばれたら置き換わる。台詞を出さないシーンは、続きに触れない）。
- 演劇の間、イベントのシーンは、今のシーンのグローバルシーンのローカルシーン（`・OnMouseClick`）を先に探し、無ければグローバルシーン（`＊OnMouseClick`）を探す。その場面だけの反応は、その場面のローカルシーンで書く。
- 元の場面を読ませ直したいときは、最後の行に `＞` を書いて、そのシーンへ飛ぶ。シーンは頭から走る。
- 最後の行に `＞` が無ければ、物語はそこで止まり、次のイベントを待つ。
- どのシーンも拾わなかった左クリックは、「進める」として、次の行を返す（SSP では、`\x` を解くのは吹き出しのクリックだけなので、シェルのクリックは pasta が受けて進める）。選択肢を待っている 1 本では、進めない。
- **演劇と設定の間、イベントで選ばれるのは、`＆再生モード` に演劇か設定を書いたシーンだけである**（開発者: 「演劇の時はトークのイベントを発動させないとか」。2026-11-19 の暫定設計の議論 D3）。階層（ファイル属性 → グローバル → ローカル）に、演劇も設定も書いていないイベントのシーンは、演劇と設定の間は選ばれない。いつもの辞書のシーン（`＊OnMouseDoubleClick`・つつきと撫での近道・時報・ランダムトーク・`＊チェイントーク中断`）は、何も書いていないので、選ばれない。いつもの辞書は、書き換えなくてよい。
  - 今のシーンのローカルシーンは、書いていなくても、先に探して選ぶ（入口のシーンにだけ柱を書き、後ろのシーンが引き継ぎで演劇になっている台本でも、その場面の反応は選ばれる）。
  - 選択肢と時間切れの飛び先は、対象の外である（作者が名前で指した飛び先なので、書いていなくても飛ぶ）。止めるのは、イベントの名前のシーンだけである。
  - 2.1 の「演劇と設定の間は、時報とランダムトークを返さない」は、この決まりに入る。
  - 前の形（いつもの辞書のファイル属性に、条件 `＆＄演劇＝「」` を 1 行書く。変数 `＄演劇`）は、取り下げた（開発者: 「直観的では無い気がする」）。つつきと撫での近道が条件を見ない今の仕様は、変えない。
  - 閉じる時のイベント（`＊OnClose`）のように、演劇の間でも走ってほしい、いつもの辞書のシーンをどうするかは、決まっていない（`novel-talk-flow` の要件定義で決める）。
- 選択肢の行には、シーンの宣言と同じ形の条件を付けられる。`！select` の 2 つ目の引数で、時間切れの飛び先を書ける（どちらも文法に足す）。

```pasta
＊教室　＆曲：昼のテーマ
    さくら：気になる所を押してみて。

    ・OnMouseClick　＆＄ｒ４＝「ドア」
        さくら：鍵がかかってる。
        うにゅう：開かへんな。

    ・OnMouseClick　＆＄ｒ４＝「窓」
        さくら：もう行こうか。
        ＞廊下
```

### 2.4 状況（柱）とト書き

- 柱（`＆名前：値`）は、シーンに着いた時に自動で打たれるト書きである。柱は上書きで、書いていない物には触らない（前の音が続く）。同じ値なら、何も起きない。止めたいときは、「なし」と書く（`＆曲：なし`）。
- 柱が打たれるのは、イベント（選択肢・時間切れを含む）か、最後の行の `＞` で、シーンに着いた時だけである。途中の行の `＞` で呼んだ先は、呼んだ側のシーンの続きとして走り、柱は打たれない（4 章の F）。
- **台詞を出さなかったイベントのシーンは、着いたと数えない**（柱を打たない・今のシーンを動かさない。開発者の決定。2026-11-19 の暫定設計の議論 D2）。柱は、もともと、直後のアクション行の 1 本に入る。アクション行を 1 つも返さなかったシーンには、入る先が無いので、出ない。変数を書くだけの `＊OnKeyPress` や `＊OnMouseMove` が走っても、曲も、走り方も、読んでいた行も、そのままである。最後の行の `＞` で着いたシーンには、当てない（台詞の無い中継のシーンを通っても、柱は次の 1 本に入る）。2.3 の「台詞を出さないシーンは、続きに触れない」と、同じ向きである。
- 打つ柱は、そのシーンの階層を引いて決める。グローバルシーンの属性（ファイル属性を含む）に、ローカルシーンの属性を重ねる。
- 状況が変わるのは、シーンに到達した時だけである。呼んだシーンから戻っても、変わらない。状況を変えたいときは、ローカルでもグローバルでもよいので、シーンへ飛ばす。曲を変えたいときは、シーンを分ける。
- ト書き `！名前＠対象（引数…）` は、`\![名前,対象,引数…]` になる。対象はアクターの名前。日本語の名前は、`pasta.toml` の別名表でタグの頭の並びに置き換わる。別名の無い名前は、そのまま流す。
- 柱には、値を並べて書ける（`＆環境音：空調、遠い街`）。ト書きの引数と同じに読む。
- ト書きの対象と引数に、変数を書ける（文法に足す）。よく使う動きは、ふつうのシーンにまとめて、引数つきの呼び出しで呼ぶ（`＞消えて現れる（さくら、窓際）`）。
- 時間は、どれもミリ秒で書く。数字で始まる引数は「」で囲む。
- **`！select` の時間も、ミリ秒で書く**（`！select（２００００、時間切れ）`。開発者の決定。2026-11-19 の暫定設計の議論 D1）。今の `!select(10)` は秒で、pasta が 1000 倍している（公開済み。入門 9 章と見本ゴースト）。飛び先を足す版で、ミリ秒に替える。破壊的な変更なので、リリースノートに書く。台本に書く時間は、さくらスクリプトと同じミリ秒、で揃う（`＞ゴースト終了（３００）` は、前からミリ秒である）。`pasta.toml` のトークの間隔（`talk_interval_min` など。秒）は、台本でなく設定なので、今のままにする。
- pasta が意味を知るト書きは 10 個（舞台・曲・環境の音・効果音・待つ・時間で次へ・位置・透明度・大きさ・転換）。ほかのト書きは、意味を知らずに流す。
- 転換は `！転換（時間）`。直前の絵から新しい絵へ替わる（黒を挟まない。種類は書かない）。字は転換を待たない。待たせたいときだけ `！転換（時間、待つ）`。`！転換（０）` は、前の転換の組を終わらせる。
- アクター指定行は、シーンの頭にだけ書ける。途中で出したいアクターは、最初から並びに入れて、表情で隠しておく。
- 同じ台本を、SSP でも areka でも動かす。pasta が、ベースウェアが areka かどうかと areka の版を見て、タグへ直す。直せない物は、そのベースウェアでは出さない。判定の小道具を、Lua の公開関数にする。

### 2.5 戻る（目印・バックログ・セーブ・ロード）

- 状態が元へ戻るのは、バックログの行を選んだ時と、ロードした時だけである。
- 戻るのは、変数（スロット変数とローカル変数）と、再生位置と、アクター状態である。
- 曲など、アクターに付かない物は、保存しない。戻った時に、その行のシーンの階層（グローバル → ローカル）の柱を打って決める（シーンに着いた時と、することは同じ）。シーンをまたいで引き継いだだけの音・ト書きで途中に変えた音・ト書きで開いた舞台は、戻らない。ロードで戻したい物は、柱に書く。
- 演劇のどの 1 本にも、目印が付く（`\![play,mark,イベント名,ID]`）。ID の中身は pasta だけが読む。
- pasta は、1 本ごとに控えを持つ。控えは、その 1 本の始まりの状態である。1 本の途中でシーンに着いたら、着いた時の状態で取り直す。
- バックログの行を選ぶと、ベースウェアが目印のイベントを ID 付きで送り、pasta はその控えへ戻る。それより後の控えは捨てる。
- セーブ（`＞スロット保存`）は、いちばん新しい控えを、スロットへ書く。ロード（`＞スロット読込`）は、その控えへ戻る。バックログの巻き戻しと、同じ仕組みである。シーンの頭に書いた保存は、そのシーンの頭から続く。
- 戻るとき、pasta は 2 本返す。1 本目は、画面の状態だけ（出し直しの印 `\![play,again]` 付き。字は無い）。2 本目は、選ばれた行を、ト書きごとふつうに再生する。
- 再生位置へは、今のシーンを頭から、出力を捨てて早回しして着く（シーン 1 つは Lua の関数 1 つで、途中から入る口が無いため）。早回しの後に、控えの変数とアクター状態を置く。
- 乱数は、戻す対象にしない。早回しの途中で、行の数の違う同名シーンを引き直すと、着く行がずれる。受け入れる。
- スロット変数は、名前が「スロット」か `slot_` で始まるグローバル変数である。ほかのグローバル変数は、ロードでも巻き戻しでも戻らない（全セーブ共通）。
- **セーブの見出しは、保存した再生位置のシーンの属性（仮 `＆見出し`）である。書いていなければ、シーンの名前である**（開発者の決定。2026-11-19 の暫定設計の議論 D4）。保存しない。再生位置のシーンの階層（ファイル属性 → グローバル → ローカル）を引くだけである（曲や走り方と、同じ決まり方）。保存した日時だけは、pasta が、保存する時にスロットへ足す。セーブ画面では、スロットを読む関数（仮 `＠スロット見出し（１）`）で出す。「スロットにセーブが在るか」も、作者の印の変数でなく、スロットを読む関数の仲間で答える。前の形（見出しを、作者のスロット変数で持つ）は、控えが着いた時の状態なので、同じシーンの頭で書いた見出しが入らず、1 場面ぶん古くなる。取り下げた。
- セーブデータは pasta だけが持つ。置き場所は `save.toml` の中の予約の表（仮 `pasta_slots`）。`スロット保存` は、その場でファイルを書く。関数は 4 つ（保存・読込・消去・参照）。
- バックログの一覧は、ベースウェアの機能である。pasta.dll に依らない。目印の無いさくらスクリプトも、ふつうに貯まる。
- 待っている行が、外から消されたとき（別のアプリからのさくらスクリプト・吹き出しの速い 2 回押し）は、毎秒のイベントで、pasta が同じ行を出し直す（`\![play,again]` 付き）。
- 設定やセーブの画面は、柱 `＆再生モード：設定` のシーンで書く。その行は記録されず、物語の再生位置は動かない。単に戻るのは `＞演劇再開`（何も戻さない）、ロードで戻るのは `＞スロット読込` である（4 章の C）。

### 2.6 遊ぶ人の操作

- 進める: 台詞の箱を押す。どのシーンも拾わない所を押す。
- オートと「時間で次へ」: `\x` が自動で解けるまでの時間で表す。作者は、その行だけなら `！時間で次へ（ミリ秒）` と書く。areka へは `\![play,xtimeout,ミリ秒]`、SSP へは `\![timerraise,ミリ秒,1,OnPlayNext]\x\![timerraise,0,1,OnPlayNext]\![raise,OnPlayNext]` で出す。
- 高速再生: pasta が `\_q` を付け、`\x` と瞬間の命令を出さない。入切は pasta が覚える。選択肢では止まる。
- 既読は、pasta が、再生位置（今のシーンの名前と行の番号）で覚える。高速再生を、まだ読んでいない行で止めるのに使う（4 章の D）。
- 設定の画面への入口は、右クリック・常に出ているボタン・キーボードの 3 つ。どれも、イベントが届いてシーンが走るだけである。

### 2.7 舞台とアクター

- 画面の部品は、全部アクターである（人物・背景・小道具・台詞の箱・ボタンを載せた絵）。役や種別を、pasta に作らない。状態は表情で表す。
- 舞台の開け閉めは、作者がト書きか柱で書く。ロードで戻したいなら、柱で書く（`＆舞台：開く`）。舞台を開かない演劇は、デスクトップのゴーストのまま、1 行ずつ進む。
- 舞台が開いている間、デスクトップの窓とバルーンは隠れる。窓の形（ウィンドウ・全画面・ボーダーレス）は遊ぶ人の設定で、既定はウィンドウ。基準の大きさは 1920×1080。
- 台詞の字は、pasta が話者のスコープに打ち、ベースウェアが「トークの場所」の役のアクターの箱へ出す。箱のアクター自身の行で書いた字は、その箱に出る。トークの場所が居なければ、話者自身の箱に出る。

### 2.8 ベースウェアとの取り決め

- 正典に在る物は、正典のタグで出す。`play` の命令は、正典に無い物だけにする。
- 正典で出す物: 待ち（`\x`）・続きのイベント（`\![raise,…]`）・貯めない区間（`\__v[disable]`）・字を一度に出す（`\_q`）・音（`\![sound,…]`）・字の前の間（`\_w`）。
- `play` の命令（名前は仮）: 目印（`mark`）・出し直しの印（`again`）・`\x` の時間（`xtimeout`）・話者の名前（`speaker`）・舞台・並び・位置・重ね順・大きさ・透明度・転換・揺れ・フラッシュ・色調・カメラ。並走の区間は `\![parallel,1]`・`\![parallel,0]`。
- ベースウェアは、`\x` で待つ間と、`\![raise]` の返事が届くまで、Status の talking を立てたままにする。
- 取り決めの文書は、マニュアルの内部設計の部に 1 章として置く。3 つのフェーズを通して 1 本で持つ。

### 2.9 フェーズ

| フェーズ | ベースウェア | 中身 |
| -------- | ------------ | ---- |
| 1 | 今の SSP | 演劇（1 行ずつ進む）・分岐・ト書きと柱・曲と効果音・表情・選択肢の条件と時間切れ・セーブとロード・高速再生・オートと時間で次へ・アクターの窓の位置と透明度と大きさ（数値）。芯は SSP 2.9.34 の実機で確かめた（`research-ssp-capabilities.md` の D 節） |

## 4. 承認待ちの整理

洗い直しで見つけた、決定どうしのすき間である。開発者の返事（2026-11-19）: 「議題 B、C、E は要検討」。A と D は、discovery の推奨のまま承認された。B と C は、議論して、開発者が形を決めた（discovery の推奨は、どちらも退けられた）。E は取り下げた。F は、B・C の後に「ぱすた開発」の確かめで見つかり、開発者が決めた。**未決の議題は無い。**

### A. 演劇は、モードを替えるまで続く（**開発者が承認した**。その後の議題 C で、`＞トーク開始` は柱 `＆再生モード` に替わった）

- **すき間**: 前に承認された「演劇の流れが最後まで走ったら、演劇を終える」は、「演劇の状態は、呼んだ流れに付く」が前提だった。その前提は、後の決定（状態はゴーストに 1 つ・再生位置は 1 つ）で無くなった。今の形だと、その場面のクリックの反応を最後まで読んだだけで、演劇が終わる。
- **決まり**: シーンが最後の行まで走って `＞` が無くても、演劇は終わらない。演劇のまま、次のイベントを待つ。今のシーンは変わらないので、同じ場面のローカルの反応は、続けて当たる。議題 C の後は、「再生モードは、次に柱で上書きされるまで続く」と言い換わる。
- 「ぱすた開発」: 困らない。

```pasta
＊教室
    さくら：気になる所を押してみて。

    ・OnMouseClick　＆＄ｒ４＝「ドア」
        さくら：鍵がかかってる。
```

「鍵がかかってる。」を読み終えても、演劇は続く。もう一度ドアを押せば、同じ反応が出る。

### B. ロードで、曲や舞台をどう戻すか（**開発者が決めた**）

開発者: 「まず、アクション行に注目した時に、その場所のシーン属性を確定するには、グローバルシーン→ローカルシーンを引けばよいのです。保存しておかなくても、階層検索を行えば属性の復旧は可能です。」「曲：なし とかじゃなければ上書きしないから引き継ぐのでは？ただ、一般にグローバルシーンは柱でいう場所の転換と考えられるから、引き継ぐ必要性自体が薄いですね。ただ、設定画面とかで現在の曲を継続することはある。」

- **決まり**: 柱は上書きである。書いていない物には触らない（引き継ぐ）。止めたいときは、柱に「なし」と書く。ロードとバックログの巻き戻しでは、その行のシーンの階層（グローバル → ローカル）の柱を打つ。保存しない。
- **帰結**: シーンをまたいで引き継いだだけの音は、ロードでは戻らない。音の変わる場面のグローバルシーンには、柱を書く。物語を通して同じ物は、ファイル属性に 1 行書ける（「ぱすた開発」の台本の、同じ柱の繰り返しは、これで消える）。舞台を開くことも、ロードで戻したいなら柱で書く。ト書きで途中に変えた音は、戻らない。
- **経緯**: discovery は、「残る値を全部、控えに入れて戻す」、次に「最後に効いた柱の値を控えに入れる」、次に「別のグローバルシーンへ移ったら引き継がない」を出した。どれも開発者が退けた（保存は要らない。柱は上書きなので、書いていなければ引き継ぐ）。

```pasta
＊教室　＆曲：昼のテーマ
    さくら：気になる所を押してみて。

    ・OnMouseClick　＆＄ｒ４＝「ドア」
        さくら：鍵がかかってる。

＊夜道　＆曲：なし
    うにゅう：静かやな。
```

「鍵がかかってる。」でロードすると、昼のテーマが鳴る（階層を引くと、親の教室に在る）。夜道は、着いた時も、ロードした時も、無音である。

### C. 設定やセーブの画面から、物語へ戻る（**開発者が決めた**）

開発者: 「うーん、やりたいことは分かるんだけど、表現が直観的では無い。＆再生モード：トーク　演劇　設定　とか。。。」「（`＞演劇開始`／`＞トーク開始` も）柱に置き換える」「明示的に『＞演劇再開』でジャンプした方が良いのでは？」

- **すき間**: 設定の画面は、どの場面からも開ける。前の形では、画面のシーンが選ばれると、再生位置がそこへ移り、物語の元の行へ戻る書き方が無かった。画面の行も記録されるので、画面の中でセーブすると、画面の行が保存された。
- **決まり**: 走り方を、柱 `＆再生モード：トーク／演劇／設定` で書く（2.1）。設定のモードの場面は、記録せず、物語の再生位置を動かさない。

| 設定からの出口 | 書き方 | 起きること |
| -------------- | ------ | ---------- |
| 単に戻る | `＞演劇再開` | 何も戻さない。待っていた物語の行を、出し直しの印付きで、もう一度出す（字を一度に出し、瞬間の命令は出さない） |
| ロードで戻る | `＞スロット読込` | セーブした行の控えへ戻る。変数とアクター状態が戻り、行はト書きごと再生される |
| 別の場面へ行く | `＞シーン` | 飛んだ先のモードになり、物語はそこから続く |

- **経緯**: discovery は、呼び出しの対（`＞演劇中断`／`＞演劇再開`）、次に柱 `＆記録：なし`、次に「設定の場面を読み終えたら戻る」を出した。開発者は、「単に戻る場合と、ロードによる復旧の 2 通りがある」と指摘し（discovery の案は、単に戻る場合も巻き戻しと同じ仕組みにしていた）、書き方を `＆再生モード` と、明示の `＞演劇再開` に決めた。あわせて、演劇の入切の呼び出しの対（`＞演劇開始`／`＞トーク開始`。開発者の前の決定）も、この柱に置き換えた。
- 例は 2.1 に在る。

### D. 既読と、声（**開発者が承認した**）

- **すき間**: 2026-10-10 の合格ラインに「既読スキップ」が在る。古い brief は、そのために「台本を直さない限り変わらない行 ID」を作る案だった。2026-11-19 の決定に、既読は出てこない。
- **案（推奨）**: 既読は、pasta が、再生位置（今のシーンの名前と行の番号）で覚える。新しい ID は作らない。高速再生を「まだ読んでいない行で止める」のに使う。声をファイル名で自動で引く仕組みは、要望が出るまで作らない（声は、効果音と同じに、作者がト書きで鳴らす）。

### E. バックログを捨てる決まり（**取り下げた**）

- discovery は、areka の勧め（捨てる時を「選ばれた時」から「同じ目印の行を貯め直す時」へ移す）を、骨子の決定にする案を出した。理由は 2 つだった: 設定から戻った時に同じ行が 2 件貯まる・戻れない行を選ばれた時にバックログだけが欠ける。
- 議題 C で、設定から単に戻るのは「出し直し」（バックログに貯めない 1 本）になったので、1 つ目の理由は無くなった。2 つ目は、ベースウェアの中の作りの話で、遊ぶ人に見える結果を変えない。
- **開発者: 「取り下げる」。** 決まりは、今のまま（行を選ばれた時に、その行を含めて後ろを捨てる）。areka の勧めは、取り決めの要件定義へ送った（`novel-areka-contract` の brief）。

### F. 途中の `＞` で呼んだシーンの柱（**開発者が決めた**: 「打たない」）

- **すき間**（「ぱすた開発」の確かめ）: 前の文面は「どの入り方でも、シーンが始まるたびに柱を打つ」だった。議題 B・C で、柱が階層（ファイル属性を含む）から引かれ、走り方も柱になったので、呼んだ先にファイル属性が付いていると、呼んだ瞬間に、呼んだ側の曲が止まり、走り方が変わって、戻らない。
- **決まり**: 柱が打たれるのは、イベント（選択肢・時間切れを含む）か、最後の行の `＞` で、シーンに着いた時だけである。途中の行の `＞` で呼んだ先は、呼んだ側のシーンの続きとして走り、柱は打たれない。
- 帰結: ト書きの束や共通のシーンは、どのファイルに置いても、呼んだ側の状況を変えない。呼んだ先の行でロードした時も、打つのは、呼んだ側のシーン（今のシーン）の階層の柱である。呼んだ先のシーンの曲に替えたいときは、最後の行の `＞` で飛ぶ（「状況を変えたければ、シーンへ飛ばす」）。

```pasta
＆再生モード：演劇＆曲：なし

＊星ひとつ　＆曲：星の曲
    さくら：星って、ほんとに在るんだね。
    ＞灯りが戻る
    うにゅう：よかったな。
    ＞おしまい

＊灯りが戻る
    さくら：あ、戻った。
```

「あ、戻った。」の間も、戻った後の「よかったな。」でも、星の曲は鳴り続ける。

### 承認が要らない整理（決定の言い換えと、決定からの帰結）

- **「今のシーン」という言葉を 1 つにした。** 再生位置のシーン・ローカルの反応を探す先・セーブの続きの場所は、どれも「今のシーン」で決まる。
- **控えは 1 本ごとに作る。** 「戻るのは、その行を読んだ時の変数とアクター状態」（開発者の決定）から、「シーンの頭でだけ控える」「ID は控えの番号と行の番号」「`＞演劇開始` をシーンの途中で呼んだとき、最初の控えは次のシーンの頭」は、要らなくなった。
- **セーブは、いちばん新しい控えを書く。** バックログの巻き戻しと、ロードが、同じ仕組みになる。シーンの頭に書いた保存は、そのシーンの頭から続く（「ぱすた開発」の希望）。
- **目印の無い行は、選べない。** 演劇の行は全部に目印が付くので、目印の無い行は、ふつうのトークだけになる（areka も困らない）。
- **いつもの反応を演劇の間に止める書き方**は、作らない。演劇と設定の間は、`＆再生モード` に演劇か設定を書いたシーンだけが、イベントで選ばれる（2.3。開発者: 「演劇の時はトークのイベントを発動させないとか」。2026-11-19 の暫定設計の議論 D3）。前の案（ファイル属性の行に `＆＄演劇＝「」` を 1 行書く）は、取り下げた。
- **選択肢を待っている 1 本では、「進める」が効かない。**
- **出し直しの 1 本目は、いつも画面の状態を全部書く**（areka: 残る命令の値を全部既定へ戻してから当てる。舞台が閉じていたか・前に誰が居たかで、pasta が場合分けしなくて済む）。

## 6. 要件定義へ送ること

細かい決めごとは、各 brief の「決定（最終形）」の節の「要件定義へ送ること」に在る。spec をまたぐ物だけ、ここに並べる。

- **遅れて届いた続きのイベント**: 行が別の行へ移った後に、前の行の `\![raise]` やタイマーが届くと、行を 1 つ飛ばす。`\![raise,OnPlayNext,ID]` で今の行の ID を運び、合わない物を捨てる形が候補である（areka: 引数は Reference0 に載る。ID は英数字だけ）。持ち主は `novel-talk-flow`。
- **早回しの間に実行しない物**: 外へ効く関数（`スロット保存` など）。スロット変数でないグローバル変数への加算は、もう一度実行される。持ち主は `novel-checkpoint-rollback`。
- **控えを全部捨てた後のバックログ**: `スロット読込` などの後、ベースウェアのバックログに、古い ID の行が残る。areka の勧めは、「バックログを空にする」合図を足すこと。持ち主は `novel-areka-contract` と `novel-checkpoint-rollback`。
- **再生モードの細かい所**: 前の物語の控えを全部捨てる時（トークから演劇のモードに入った時、が候補）。物語が待っていない時の `＞演劇再開` の動き（開く前のモードへ戻る、が候補）。演劇の間でも走ってほしい、いつもの辞書のシーン（`＊OnClose` など）の扱い。持ち主は `novel-talk-flow`。
- **設定の値を切り替える口**: オート・高速再生・窓の形の入切を、設定のシーンからどう切り替えるか（組み込みの呼び出しにするか）。持ち主は `novel-talk-flow` と `cue-command-runtime`。
- **「スロットにセーブが在るか」を条件に書く形**: 持ち主は `novel-save-slots`。
- **演劇でなく、舞台だけが開いている間のランダムトーク**: 演劇の間は返さない、は決まっている。舞台だけが開いている間をどうするか。持ち主は `novel-talk-flow`。
- **pasta の既定の反応**（おすすめメニューなど）を、演劇の間に出すか。持ち主は `novel-talk-flow`。
- **見本とマニュアル**（`hello-novel-sample`・`manual-novel-guide`）: 置き場所・物語の長さ・Lua の範囲・章の割り方。設定の画面（4 章の C）と、待つ場面の書き方（その場面のローカルの反応）を、見本に入れる。
