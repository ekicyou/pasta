## 開発者が形を出し、areka も異論なし（このメモで初めて書く。brief へは、下の「まだ案のもの」が決まったときに一緒に書く）

- **バックログに貯める・貯めないは、トグルで切り替える**: `\![play,backlog,1]`／`\![play,backlog,0]`（開発者の案。値は 1／0。ukadoc の `\![bind,…,数値]`・`\f[bold,1]` と同じ流儀で、`on`／`off` の形は ukadoc に見当たらない）。既定は 1。pasta は、返す台本の頭に毎回 1 か 0 を打つ（戻し忘れを防ぐ。areka の勧め）。areka は、起動・ゴーストの切り替え・SHIORI の読み直しで 1 に戻し、1／0 と true／false の 4 つを受ける。
- **出し直しの印は、その台本 1 本だけに効く**: `\![play,again]`。areka は、バックログに貯めず、字を一度に出し、単発の音と転換を飛ばす。トグルにしない。
- オートと高速再生の命令も、同じ形にそろえる（仮 `\![play,auto,1]`・`\![play,skip,1]`）。入切の状態をどちらが持つかは、まだ議論していない（areka の勧めは「状態は areka、切り替えの口は `play` の命令」）。

## まだ案のもの（開発者の返事待ち）

### 物語の途中でセーブ画面などを開いたときの扱い

困りごと: セーブ画面も pasta のシーンなので、物語の途中で開くと、今のチェイントークの決まり（台詞を出すシーンが割り込むと続きを捨てる）で物語の続きが捨てられる。セーブ画面に目印が付き、字がバックログに貯まる。

案の移り変わり（開発者の指摘で 2 回改めた）:

1. シーンに印 `＆システム画面` を付ける → 取り下げ（開発者「シーンはシーン。現在の枠組みで扱えないか。パーサーはいじりたくない」）。
2. 関数の対 `＞物語停止`・`＞物語再開` → 取り下げ（開発者「OnXXX で扱いを変えれば？」）。
3. 物語のイベントで走ったシーンだけを、物語として扱う → 改める（開発者「考え方が汎用的じゃない気がする。ループというかステートが複数ある。演劇状態のステート、演劇画面・タイトル・設定画面などのステート」）。
4. **今の案: 状態は 2 層ある。扱いは、イベントの名前でなく、前に出ている画面で決まる。**（下の「状態は 2 層」の節。ホワイトボードの下半分に図がある）

#### 状態は 2 層（今の案・開発者の返事待ち・areka へ見立てを聞いている）

- **演劇の状態**（1 つ・長生き）: 止まっている続き・最後に返した行・目印と控え・スロット変数。セーブ・ロード・巻き戻しの相手はこれだけ。画面が替わっても残る。
- **画面の状態**（いま前に出ている画面・1 つだけ）: 演劇画面・タイトル・セーブ画面・設定画面など。それぞれが「出す → 入力を待つ → 出す」のループを持つ。演劇の状態を進めるのは、演劇画面だけ。

| 前に出ている画面 | 演劇画面 | それ以外の画面 |
| ---------------- | -------- | -------------- |
| 行の区切り | アクション行 1 つ＝台本 1 本 | 今までどおり |
| 目印 | シーンの頭に作る | 作らない |
| バックログ | 貯める（`\![play,backlog,1]`） | 貯めない（`\![play,backlog,0]`） |
| 続きの置き場 | 演劇の状態（画面が替わっても残る） | その画面の間だけ（今のチェイントークと同じ決まり） |
| 続き・選択肢のイベント | 演劇が受ける | その画面が受ける |

画面の移り変わり:

| 移り変わり | きっかけ | 決める人 |
| ---------- | -------- | -------- |
| 演劇を始める | 作者が台本で指す（形は未定。選択肢の飛び先を `On` で始めると、ベースウェアがそのイベントを直接送る今の仕組みが使える） | 作者 |
| 別の画面が開く | 演劇が待っている間に、別のイベントのシーンが台本を返す | pasta |
| 演劇へ戻る | その画面のシーンが、待ちを残さずに終わる。pasta が、そのイベントの返事として最後の行を出し直す（`\![play,again]`） | pasta |
| ロード・巻き戻し | 演劇を、控えたシーンの頭から始め直す | pasta |

- pasta が持つのは「演劇が、無い／前に出ている／裏で止まっている」の 3 つだけ。タイトル・セーブ・設定の区別は、作者のシーンと変数に任せる（今の条件の属性 `＊OnMouseClick　＆＄＊画面＝「設定」` で、状態ごとに受け口を分けられる）。
- 前の案から消えるもの: 「出し直す」イベント（仮 `OnPlayResume`）・「選択肢のイベントは、出した側の扱いを引き継ぐ」決まり・物語に入るための raise の往復。
- 残りの議題 6 の「ノベルゲームモードの切り替え」は、この案では「演劇画面が前に出ている間」になる。
- 未決: 「演劇を始める」の書き方。当たり判定のクリックで物語を進める形（`shell-element-click`）は、同じ口（演劇を、このシーンから続ける）で受ける見込み。

areka の見立て（2026-11-19・読むだけ・実機は未確認）:

- 困る点は無い。areka は、台本がどのイベントへの返事かで出し直しの扱いを変えない。areka に頼む物は前と同じで、軽くも重くもならない。
- 置き換えられたトークの残りは配られない（コードで確かめた事実）。だから、割り込まれた行の末尾の `\![raise,OnPlayNext]` は出ない。
- 再生中に届いた GET の返事の台本は、`OnSecondChange` と倍率（`OnShellScaling`・`OnBalloonScaling`）を除いて、全部が今のトークを置き換える。待っている間の `OnSecondChange` は NOTIFY で、pasta の自発のトークは割り込まない（`\x` の待ちが「再生中」の扱いになることは見立て）。
- 画面のシーンが台本を返して終わると、次に届くのは `OnSecondChange`（話していないときは GET）で、そこで出し直すと最大 1 秒の空きができる。空きを作らないには、閉じるボタンの返事でそのまま出し直しを返す。
- 落とし穴: バルーンの左ダブルクリックは台本を止めてバルーンを消す（中断）。末尾の `\![raise,OnPlayNext]` が出ず、物語が止まる。避け方は、演劇の台本の頭で正典の中断の抑止を打つか、pasta が `OnBalloonBreak` の返事で出し直すか（未決）。

前の案（3）の表（参考）:

| 届いたイベント | 走るもの | 扱い |
| -------------- | -------- | ---- |
| `OnBoot`・`OnMouseClick` など | 今までどおりのシーン | 今のゴーストと同じ。台本の頭に `\![play,backlog,0]` |
| 物語を始める（仮 `OnPlayStart`） | 名前で指したシーン | 物語 |
| 続きを求める（仮 `OnPlayNext`） | 止まっている続き | 物語 |
| 出し直す（仮 `OnPlayResume`） | 最後に返した行（`\![play,again]` 付き） | 物語 |
| 巻き戻す（仮 `OnRollback`） | 控えたシーンの頭 | 物語 |

- 物語として扱うとは、行ごとに区切り、シーンの頭に目印を作り、台本の頭に `\![play,backlog,1]` を打つこと。
- 物語に入る・戻るのは、正典の `\![raise,…]`。ト書きの行で書ける（`！raise（OnPlayStart、第一章）`・`！raise（OnPlayResume）`）。新しい文法も関数も作らない。ト書きを台本へ流す仕組みは `cue-command-runtime` の仕事で、まだ無い。
- 選択肢のイベントは、選択肢を出した側の扱いを引き継ぐ。
- 物語の続きは、チェイントークの続きとは別の置き場に持つ（チェイントークの今の決まりを変えない）。捨てるのは、巻き戻し・ロード・`スロット消去` だけ。

### 既定のスクリプトと「選択肢イベント」の読み

- 行の末尾に pasta が自動で付ける既定のスクリプトは、今の案では `\x\![raise,OnPlayNext]`（`pasta.toml` で差し替えられる）。開発者は「選択肢イベント」と言った。本物の選択肢（`OnChoiceSelect`）と同じ名前にする考えかどうかを、まだ確かめていない。

### クリックの切り分け（areka の勧め。開発者にまだ諮っていない）

- 名前つきの当たり判定の上のクリックはボタン（`OnMouseClick` が届く。待ちは解かない）。それ以外は待ちを解く（pasta には何も届かない）。
- `OnMouseUp` が先に届くので、pasta は 204 を返す。速い連打の 2 回目は `OnMouseDoubleClick` になるので、同じボタンとして受ける。

## 残りの議題（この順で、1 つずつ）

1. 上の「まだ案のもの」を閉じる。
2. バックログと巻き戻しの残り: 控えを何個まで持つか。セーブに控えの履歴を入れるか（ロードの直後にも戻れるか）。「ここより前へは戻れない」点の置き方。戻ったときに画面と音を元に戻す仕事の分担。
3. 話者の名前の運び方（areka は、スコープを分け合う話者の名前を台本から受け取るしかない。仮 `\![play,speaker,名前]`）。行と行の間でトークの場所が閉じないようにする決まり。オートと高速再生の入切の持ち主。
4. 取り決めの骨格（保留中）: 通り道は SHIORI/3.0 だけ・台本の頭で舞台の全部を宣言する（自己完結）・語彙は正典に在るものは正典・設定の値の持ち主・0.7.0 の合格を SSP で測って areka の実機確認を後追いにするか・配布はゴーストとして・文書の置き場所。
5. 柱とト書き（`cue-command-runtime`）: 出力の形・「場面に入る」の数え方・戻ったとき・背景の書き方・引数の穴・外見に記録するか。
6. ノベルの出力と流れの残り（`novel-talk-flow`）: 「ノベルゲームモード」をどう切り替えるか・話者名・起動時の場面・自動トークの停止との整理。
7. エレメントのクリック（`shell-element-click`）: areka では、名前つきの当たり判定のクリックが今の `OnMouseClick` の Reference4 で届く。「エレメント」は「当たり判定」と読み替える。
8. 見本とマニュアルと順番（`hello-novel-sample`・`manual-novel-guide`・roadmap）: 置き場所・Lua の範囲・ウェーブ・要件定義のモデルの付け直し（Fable → Opus）。
9. roadmap を直し、PR を 1 本にまとめる。
