# Implementation Plan

- [x] 1. (P) キューコマンド AST 型の定義
  - キューコマンド行を表現する AST ノード型を新設し、コマンド名（String）、オプショナルなスコープ付き識別子、引数トークン列、ソース位置を保持する
  - スコープ付き識別子型を定義し、`@name` は actor なし / name、`@actor:name` は actor あり / name として表現する
  - 引数トークン型を列挙型として定義し、識別子・文字列リテラル・整数・浮動小数点・@参照の 5 バリアントを持たせる
  - 既存の AST モジュールに新型を re-export し、ローカルシーンアイテムにキューコマンドバリアントを追加する
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [x] 2. (P) PEG 文法へのキューコマンド行ルール追加
  - `!` / `！` で始まるキューコマンド行を認識する PEG ルール群を追加する
  - コマンド名は既存の `id` ルールを再利用し、任意の識別子を受理する
  - スコープ識別子はアトミックルールとし、`actor:name` 全体を単一文字列として取得する
  - 引数リストは既存プリミティブ（number_literal, string_literal）を再利用し、汎用フォールバックとして自由形式識別子を受理する
  - ローカルシーンアイテムの選択肢にキューコマンド行をアクション行より前に挿入する
  - 既存ルールは一切変更せず、追記のみで後方互換性を維持する
  - _Requirements: 1.1, 1.2, 4.1_

- [x] 3. キューコマンド行のパース処理実装
  - ローカルシーンのパース処理にキューコマンド行の AST 構築ロジックを追加する
  - PEG パース結果を走査し、コマンド名・スコープ・引数を AST ノードに組み立てる
  - スコープ識別子の `:` 分割によるアクター名と識別子名の分解ロジックを実装する
  - 引数トークンの型判定（@参照・数値リテラル・文字列リテラル・汎用識別子）と適切なバリアントへの変換を実装する
  - 数値リテラルの正規化には既存ユーティリティを利用し、小数点の有無で整数・浮動小数点を判定する
  - `!id` / `!id@scope` / `!id(args)` / `!id@scope(args)` の 4 形式すべてが正しく変換されることを確認する
  - Task 1, 2 の完了が前提
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6_

- [x] 4. (P) 行種推定とキューコマンド検出ヘルパーの追加
  - 行頭文字による行種推定ロジックに `!` / `！` の判定を追加し、キューコマンド行ルールを返す
  - `!` はスコープ境界マーカーではないため、スコープ分割処理には影響しない
  - ローカルシーンスコープにキューコマンド行の有無を判定するヘルパーメソッドを追加する
  - グローバルシーンスコープにもいずれかのローカルシーンにキューコマンドが存在するかを判定するヘルパーメソッドを追加する
  - Task 1, 2 の完了が前提（Task 3 とは並行して作業可能）
  - _Requirements: 1.7, 2.1, 2.2_

- [x] 5. 下流クレートの新バリアント対応
  - Lua コード生成処理のローカルシーンアイテム走査に、キューコマンドバリアントの空ハンドラを追加する（キューコマンドは Lua 生成の対象外）
  - LSP のセマンティックトークン生成処理に、キューコマンドバリアントのトークン登録を追加する
  - 呼び出し可能判定への変更は不要（キューコマンドは callable ではない）
  - pasta_dsl のコンパイルが通る状態が前提（Task 1-4 完了後に着手）
  - _Requirements: 4.1, 4.2_

- [x] 6. テスト実装と後方互換性検証
