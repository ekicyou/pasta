# Implementation Plan

- [ ] 1. PEG 文法と AST 型の基盤整備
- [ ] 1.1 (P) call_scene 文法にコール式ターゲットを許容するルールを追加
  - `call_target_expr` 非 silent ラッパールールを追加し、`expr` を単一 Pair として捕捉できるようにする
  - `call_scene` ルールを静的 id と動的式の ordered choice に変更する（id を先行）
  - `id ∩ expr = ∅` の先頭文字素集合性によりバックトラックが最小であることを確認
  - _Requirements: 1.1, 1.2, 4.1_
- [ ] 1.2 (P) コールターゲットの型に静的コールと動的コールを区別する列挙型を導入
  - 静的（リテラルシーン名）と動的（式）の2バリアントを持つ列挙型を `CallScene` 直前に定義する
  - `CallScene` のターゲットフィールドをこの新型に変更する
  - _Requirements: 1.1, 1.3_

- [ ] 2. (P) パーサーに動的コールターゲットの解析分岐を追加
  - Task 1 完了後に着手（grammar ルールと型定義への依存あり）
  - `call_scene` のパース処理に式ターゲット検出分岐を追加し、式を `Dynamic` バリアントとして返す
  - `id` 検出時は `Static` バリアントとして返すよう既存パスを型変更に合わせて調整する
  - _Requirements: 1.1, 1.2_

- [ ] 3. (P) コードジェネレーターに動的コールの Lua コード生成分岐を追加
  - Task 1 完了後に着手（Task 2 とは独立した別ファイルで並列実行可能）
  - `Dynamic` バリアントに対して式を評価し `tostring()` でラップしたシーン名を渡す Lua コードを生成する
  - `Static` バリアントの既存出力は変更しない（`is_tail_call` フラグ・引数生成ロジックも Static / Dynamic 共通で維持）
  - _Requirements: 2.1, 2.2, 4.2_

- [ ] 4. (P) ランタイムにシーン名 nil ガードを追加
  - Tasks 1〜3 と独立しており並列実行可能（Lua ファイルへの変更のみ）
  - コール関数の先頭でシーン名が nil の場合に警告ログを出力し即時リターンする3行ガードを追加する
  - 既存の find_scene フロー・引数処理は一切変更しない
  - _Requirements: 3.5_

- [ ] 5. テストで動作を検証
- [ ] 5.1 (P) 動的コールのパーサー出力を検証するユニットテストを追加
  - `＞＄ローカル変数`・`＞＄＊グローバル変数` が `Dynamic` バリアントに解析されることを確認する
  - `＞シーン名` の静的コール AST が変化しないことを確認する
  - _Requirements: 1.1, 1.2, 1.3, 4.1_
- [ ] 5.2 (P) 動的コールの Lua 出力を検証するスナップショットテストを追加
  - 変数参照・グローバル変数参照・関数呼び出し等のパターンで生成 Lua コードのスナップショットを追加する
  - 静的コールの既存スナップショットが変化しないことを確認する
  - _Requirements: 2.1, 2.2, 4.2_
- [ ] 5.3 動的コールのエンドツーエンド動作を統合テストで検証
  - `＄target` に既存シーン名を代入して `＞＄target` で正常にシーンが呼び出されることを確認する
  - 複数候補時のシャッフル選択・候補不在時の空応答を確認する
  - Lua ブロックで変数設定後の動的コール解決を確認する
  - nil 式評価での nil ガード（警告ログ + nil 返却）を確認する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_
- [ ] 5.4 全テストスイートで既存機能の回帰がないことを確認
  - `cargo test --all` を実行して 950+ 既存テストが全パスすることを確認する
