# Implementation Plan

- [ ] 1. 再開の手順の共通化と戻り値の応答化
- [x] 1.1 通常のイベントの再開の手順を共通の駆動ルーチンへ切り出す
  - 現行のコルーチン分岐（出力が出るまで再開 → 予約の消費 → 継続の更新）を、順序を変えずに公開の駆動ルーチンへ移し、通常のイベントのコルーチン分岐をその呼び出しに置き換える
  - 消費されていない予約を捨てる関数をコールバック管理側に足し、駆動ルーチンの失敗の経路（エラーで終わったとき）だけが呼ぶようにする
  - 失敗時は予約が残らず、継続も空になる（通常のイベントのエラーと同じ）
  - 完了状態: 既存のテストの検査が変更なしで通り、「予約の後に中断せずエラーで終わるシーンを入口で動かした後、コルーチンを返す別のイベントを送っても、そのシーンが古いイベント名で待機に登録されず『multiple staging』にもならない」モジュールテストが通る（修正前に戻すと失敗する）
  - _Requirements: 1.2, 1.5, 1.7, 1.8, 2.4, 4.3, 5.2_

- [x] 1.2 ハンドラの戻り値の `SHIORI/` 接頭辞の素通しを入れる
  - ハンドラが返した文字列が `SHIORI/` で始まるときは包まずにそのまま応答にし、それ以外の文字列は従来どおり 200（空なら 204）、`nil` は 204 とする
  - シーンのコルーチンの出力は接頭辞にかかわらず常に `Value` の 200 にする
  - 素通しによりタイムアウト掃引の応答が 500 になるため、同じ変更で非同期コールバック E2E のタイムアウト掃引テストの 2 回目の応答を 500 と `X-Error-Reason` の完全一致に改め、「二重包みは既知の挙動」の記述を消す（遅れて届いた結果が 204 になる 3 回目は現行のまま）
  - 回帰テストはエントリのテストスイート（ハンドラの戻り値）とイベントのコルーチンのテストスイート（コルーチンの出力）に足す
  - 完了状態: `RES.ok`・`RES.no_content`・`RES.warn`・`RES.not_enough`・`RES.advice`・`RES.err` を返すハンドラの応答が返した文字列と完全に一致し、普通の文字列・空文字列・`nil` が 200・204・204、`SHIORI/` で始まる文字列を出力するコルーチンが 200 の `Value` になることを入口を通すテストで確かめられ（修正前に戻すと失敗する）、非同期コールバック E2E が通る
  - _Requirements: 2.8, 3.1, 3.2, 4.1, 4.2, 4.4, 4.5, 4.6, 4.7, 6.2, 6.3, 6.5_

- [ ] 2. コールバックの再開と掃引を共通の手順に載せる
- [x] 2.1 一致したコールバックの再開を駆動ルーチン経由にする
  - 一致の判定・待機の取り外し・Reference の配列化は現行のまま、再開を駆動ルーチン（呼び出し時に読み込む）に置き換え、エラーは例外として伝え、出力は 200（出力なしで終われば 204）にする
  - Lua テストのモジュール読み直しの組（イベント配送・コールバック管理・ストア）を、コールバックのモジュールテストの補助関数と、コールバック管理を使う他の Lua スイートのすべてでそろえる
  - コールバックのモジュールテストの既存の再開の検査を新しい挙動に改める
  - 完了状態: 既存の Lua スイートがすべて通り、モジュールテストで「遅れて届いた結果・一致しない名前は通常イベントへ」「再開したシーンのエラーが伝わり待機にも継続にも残らない」が通る

- [x] 2.2 タイムアウト掃引を「集める → 外す → 並べる → 順に再開」に書き換える
  - 期限切れを集めてから待機の表から外し、番号の小さい順（番号の無い名前は末尾・名前順）に駆動ルーチンで再開する
  - 理由付きの待機は警告ログを出し、エラーで終わったら `timeout_message` を理由とする 500 を候補にする。出力があれば 200 を候補にする。静かなタイムアウトのエラーは警告ログだけにする
  - 最初の候補を応答として採用し、2 番目以降は警告ログを出して捨てる。途中のエラーでも残りを続ける
  - コールバックのモジュールテストの既存の掃引の検査を新しい挙動に改める
  - 完了状態: モジュールテストで「1 → 2 → 10 の順で再開され最初の応答が返り、捨てた待機の警告ログが出る」「処理中に登録された待機は同じ回で扱われない」「出力付きの中断が継続に入る」「静かなタイムアウトの出力が 200 になる」「1 つ目がエラーでも 2 つ目が処理され、イベント名と理由の警告ログが出る」が通る（ログは既存のログのモックで検査する）
  - _Requirements: 2.1, 2.2, 2.3, 2.5, 2.7, 2.9, 3.1, 3.3, 3.4, 3.5_

## Implementation Notes
- 1.2: E2E フィクスチャの OnTestTimeout は理由 `test timeout` を明示して渡すため、タイムアウト応答の `X-Error-Reason` は `test timeout`（design の E2E #1 の `callback timeout: get_property` は理由省略時の既定値）。
- cargo は `env -u NoDefaultCurrentDirectoryInExePath` 付きで回す。`tests/fixtures/sample.generated.lua` はテスト実行で改行コードだけ変わるので stage しない。
- テスト実行で `crates/pasta_lua/profile/pasta/save/save.json` が書き換わることがある（既存の汚染）。stage しない。
- 2.2: 掃引の 500 は「理由付きの待機がエラーで終わる」ときだけ。本物の `act:get_property` は理由付きで再開されると `error(reason)` するので、テストの待機シーンも同じ形にする（エラーも出力も無く終わるシーンは候補を作らない）。
