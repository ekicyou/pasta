- [ ] 1.1 話し手・表情の登録簿とタグの解析を作る
  - 話し手と表情を 1 か所にまとめて定義する。
    - 話し手は Claudia（表情 14 種）とアンソニー（表情 2 種）。
    - 話し手ごとに、名前・名札・左右の配置・表情と画像番号の対応を持たせる。
    - 既定の話し手は Claudia、既定の表情は「素」とする。
  - 台詞の始まりの行を見分ける規則を作る。
  - `【】` の内側を解析する規則を作る。
    - 受け付ける形は「表情だけ」「話し手だけ」「話し手と表情」の 3 つ。
    - 話し手と表情の区切りは全角のコロンだけとする。
    - 話し手名はカタカナだけとする。
  - 解析に失敗したら、失敗の種類（malformed-tag・unknown-speaker・unknown-expression）と詳細を返す。未知の名前には候補の名前を添える。
  - 話し手と表情から、顔画像への相対パスを組み立てる。
  - 自己テストで次を確かめ、全件合格する。
    - 登録簿の決まり: 各話し手が「素」を持つ。話し手名と表情名が重ならない。画像名が全話し手で重ならない。id が英小文字だけでできている。
    - 全 16 表情を解析できる。話し手を省いた形も、表情を省いた形も解析できる。
    - 失敗の種類ごとに、正しい種類が返る。
  - _Requirements: 3.2, 3.3, 3.4, 3.8, 4.2, 4.8, 10.7_

- [ ] 1.2 章の Markdown の走査、領域の検査、表情の集計を作る
  - フェンスの外にある台詞ブロックを列挙する。ブロックごとに、開始行・終了行・タグ・本文を持たせる。フェンスかどうかは、リンク検証にある既存の判定を使って決める。
  - 次の不正を、行番号付きですべて列挙する（最初の 1 件で止めない）。
    - empty-body: 本文が空。
    - missing-blank-line: 前後に空行が無い。遅延継続の行も含む。
    - nested-talk: 字下げした台詞、リストの中の台詞、引用の中の台詞。
    - unsupported-content: 台詞の中にフェンス・表・入れ子の引用がある。
  - 指定した範囲を検査する。範囲が台詞ブロックだけでできていて、両方の話し手の台詞があれば合格とする。
    - 違反は prose-in-region（台詞以外の内容がある）と missing-speaker（話し手が揃わない）で返す。
    - 表紙の設定では、扉の HTML ブロックの内側も許す。
  - CRLF の入力は LF に直してから扱う。
  - 表情の集計コマンドを用意する。全章の表情の出現数と、章ごとの導入・締めの表情の組み合わせを表にして出力する。終了コードは常に 0 とする。
  - 自己テストで次を確かめ、全件合格する。
    - 9 種のエラーが、それぞれ正しい行番号で出る。
    - フェンスの中にある台詞のような行は無視される。
    - CRLF の入力を正しく扱える。
    - 表紙の設定で、扉の内側が許される。
  - _Requirements: 3.7, 4.1, 4.3, 4.6, 4.7, 10.3, 10.7_
