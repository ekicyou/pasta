# Brief: novel-areka-output

2026-11-20 の棚卸（`/kiro-next`・main `58aba27c`）で、`cue-command-runtime` と `novel-talk-flow` から、areka だけへ出す形を集めて起票した（経緯は、2 本の brief の「2026-11-20 棚卸の分割」）。ノベルゲーム（Phase 13）の道筋の 1 本で、フェーズ 3（areka）に入る。確かめるには、areka の実装を待つ。

## Problem

台本の書き方は、SSP でも areka でも 1 つである。pasta が、ベースウェアが areka かどうかと、areka の版を見て、タグへ直す。SSP へ出す形（正典のタグ）は、`cue-command-runtime`・`scene-stage-attributes`・`novel-talk-flow` が作る。

ところが、areka にしか無い働き（舞台の窓・並び・転換・舞台の中の立ち位置・続きの在る 1 本・高速再生の入切・早送り・並走）は、出す形の名前が、取り決め（`novel-areka-contract`）の要件定義まで仮で、areka の側にもまだ無い。フェーズ 1 の spec に混ぜたままでは、確かめようの無い半分を抱えることになる。

## Current State

- pasta の出力は、正典のタグだけである。`play` の命令（正典に無い物）を出す所は無い。
- ベースウェアの判定は、`cue-command-runtime` が Lua の公開関数として足す（未完了）。置き場の候補は、中身の無い `crates/pasta_lua/pasta_scripts/pasta/areka/init.lua`（15 行）。
- ト書きをベースウェアに合わせてタグへ直す所は、`cue-command-runtime` が作る（暫定設計の `pasta/shiori/cue_builder.lua`。未完了）。areka でない時、頭が `play` の命令は出さない。
- 1 本の枠（頭・末尾）は、`novel-talk-flow` が作る（暫定設計の `pasta/play.lua`。未完了）。SSP へは、1 本の末尾に `\x\![raise,OnPlayNext]`、高速再生では `\_q` を付ける。
- アクター指定行（`％教室、さくら`）は、今は立ち位置の番号を割り当てるだけである（`act:clear_spot()` と `act:set_spot(name, n)` を生成する。`crates/pasta_lua/src/code_gen/scope_gen.rs` 282〜292 行。グローバルシーンの頭の `__start__` だけ）。
- アクターの立ち位置（スポット）は、`pasta.toml` の `[actor."名前"]` の `spot` で、スコープの番号になる。座標の置き場は無い。
- 骨子は `novel-areka-contract/final-model-2026-11-19.md`（2.7・2.8・2.9 と 8 章の追記 1〜4）、areka の側の決定の写しは `novel-areka-contract/areka-developer-decisions-2026-11-20.md`。

## Desired Outcome

ベースウェアが areka のとき（版は判定で見る）、同じ台本から、次の形が出る。SSP へ出す形は、何も変わらない。

- 舞台の開け閉め、並び（誰がいるか）、転換、舞台の中の位置・重ね順・大きさ・透明度、スポットごとの座標が、`play` の命令で出る。
- 1 本の末尾が、続きを示す命令になる（行の ID と、自動で進むまでの時間を引数に持つ）。
- 高速再生の入切が、命令で出る。
- 拾わなかったクリックに、早送りの 1 本が、並走で返る。
- 作者が単語の中に書いた待たない印が、並走の区間の開く印と閉じる印の対になる。

例（`novel-talk-flow` の brief の「区切り」の例。名前は仮）:

```pasta
％教室
    ＠稲光：\![parallel]\s[12]\_w[200]\s[10]\_w[200]\s[12]

＊嵐の教室
    教室：＠稲光
    さくら：＠驚き　きゃっ！
```

areka へ返す形: `\![parallel,1]\p[0]\s[12]\_w[200]\s[10]\_w[200]\s[12]\![parallel,0]\p[1]\s[2]きゃっ！` に、続きを示す命令（仮 `\![play,next,OnPlayNext]`）が付く。

## Approach

決定（2026-11-19 の discovery「ノベルゲームの深掘り」・同じ日の暫定設計の議論・2026-11-20 の areka の側の決定と立ち位置の決定）。`cue-command-runtime` の brief の「決定（最終形）」の「並びと転換」「ベースウェアに合わせる」、「決定（2026-11-19 の暫定設計の議論）」、「立ち位置（2026-11-20 の決定）」と、`novel-talk-flow` の brief の「区切り」「areka の側の決定（2026-11-20）」「areka の側の決定 2（2026-11-20）」から、areka だけへ出す形を写した。どれも開発者の決定なので、要件定義で変えない。命令の名前と引数は、どれも仮で、取り決めの要件定義で決まる。

### ベースウェアに合わせる

- **同じ台本を、SSP でも areka でも動かす**（開発者の決定）。ト書きの書き方は 1 つにする。pasta が、ベースウェアが areka かどうかと、areka の版（セマンティックバージョン）を見て、タグへ直す。SSP では正典のタグへ、areka では `play` の命令へ直す。直せない物は、そのベースウェアでは出さない。
- 書き方は 1 つ。舞台を使う台本を、SSP で遊べるとは約束しない（骨子 8 章の議題 3）。
- 正典に在る物は、正典のタグで出す。`play` の命令は、正典に無い物だけにする。正典の `\x`・`\![raise]` の意味は、変えない（骨子 2.8）。
- ウィンドウモードでない間（舞台を開かず、デスクトップに浮いたまま進む演劇）は、位置・大きさ・透明度を、areka へも、SSP と同じ正典のタグ（`\![move,…]` など）で出す（`cue-command-runtime` が持つ）。`play` の命令は、ウィンドウモード（舞台）の中だけで使う（議題 5。開発者: 「舞台とはウィンドウモードのことですよね？」→ その読みで承認）。この議題の「舞台の中だけ」は、位置・重ね順・大きさ・透明度の話である。続きの命令・早送り・高速再生の入切・目印・出し直しは、舞台の外でも areka へ出す（骨子 8 章の追記 4）。

### 舞台・並び・転換（`cue-command-runtime` から）

- 舞台の開け閉めは、作者がト書きか柱で書く。ロードで戻したいなら、柱で書く（`＆舞台：開く`。骨子 2.7）。
- **舞台を閉じたとき**: ベースウェアは残る命令を全部「無い」に戻す。pasta の記録も、同じ時に空にする（`novel-checkpoint-rollback` の brief の「決定（最終形）」）。
- **誰がいるか**: アクター指定行を、名前の並びで伝える（仮 `\![play,cast,教室,さくら]`）。並びが「今の画面の全部」で、並びに無いアクターは消える。スコープの番号は並びの順（今の割り当てと同じ）。背景も、アクターとして並べる（状態は表情）。
- **アクター指定行は、シーンの頭にだけ書ける**（今の文法のまま）。途中で出したいアクターは、最初から並びに入れて、表情で隠しておく。
- **転換**（開発者: 「転換であればフェードでしょ？黒を挟むのは良くない」「直前の絵が常にフェードの出発点です」）: `！転換（時間）`。種類は書かない。その後の変更が、直前の絵から新しい絵へ、その時間をかけて替わる。字は転換を待たない。待たせたいときだけ `！転換（１０００、待つ）` と書く（pasta が、まとめの終わりに、同じ長さの待ち `\_w` を入れる）。まとめる範囲は、転換のト書きから「次の字・次の待ち・次の転換・1 本の終わり」のどれか早い所まで。`！転換（０）` は、前の転換の組を終わらせる。黒くしたい場面は、黒い背景のアクターへ替える。
- **シーンの頭の `！転換` は、着いた時の柱の変化も包む**（骨子 8 章の議題 10）。
- 舞台と並びのタグの形は、取り決め（`novel-areka-contract`）に合わせる。頭が `play` の命令は、areka でなければ出さない。

### 立ち位置（`cue-command-runtime` から。2026-11-20 の決定）

- **スポットごとの座標は、pasta の側に書き、pasta が、並びを打つ時に、位置の命令で渡す**（開発者の承認。元の決定: 「ウィンドウモード時、立ち位置に関する情報が areka との取り決めで必要。スポットごとに座標情報が必要になると思う。」）。areka は、送られた位置に置くだけである。
- 取り決めから、「位置を明示しないアクターを、並びと役（背景 → 役者 → トークの場所）から自動で置く」と「席の名前と位置の対応を、舞台の定義（`descript.txt` の areka の独自キー）に書く」を外す。「役」は、スポットごとの座標・重ね順・「字を受ける」印に置き換わる。
- この spec が持つ物: スポットごとの座標の置き場と、並びの命令に続けて位置の命令を打つ所。

### 1 本の末尾・高速再生・早送り・並走（`novel-talk-flow` から。2026-11-20 の areka の側の決定）

開発者: 「arekaの立場は、『イベントを投げて、さくらスクリプトが返ってきたら、再生する』という仕組みを壊さずに、仕様を拡張する姿勢」「ukadoc既存の動作に影響が出る決定は許容できない」。areka が自分で判断する形（返事が無ければ進める・モードを自分で持つ）は、採らない。

- **続きの在る 1 本**: `\x\![raise,OnPlayNext]` でなく、続きを示す命令を 1 本の末尾に置く（仮 `\![play,next,OnPlayNext]`）。areka は、そこで止まって押されるのを待ち、押されたらイベントを投げ、続きの 1 本が届くまで、話は続いていると扱う（バルーンを消さない・字も残す）。行の ID と、自動で進むまでの時間（今の `xtimeout`）は、この命令の引数にまとめられる。開発者: 「『このスクリプトには続きがあります』『クリックで進めてください』を示すキューコマンドがあった方がよい」「SSPには『続きのさくらスクリプトです』という概念自体が無い」。SSP へは、今の形（`\x\![raise,…]`）で出す。
- **高速再生**: 仮 `\![play,fastmode,1]`・`0`。「入」の間、areka は、届いた 1 本を次々に早送りする（選択肢では止まる）。pasta は、高速再生の時も、ふつうの時と同じさくらスクリプトを返す。読んでいない行で止める時は、pasta が、その行で「切る」を打つ。開発者: 「\_qだと、もともとのスクリプトに毎回いじる必要が出ます…\_qは必要ですが、それは『高速再生のため』ではありません」。SSP へは、今までどおり `\_q` で出す。
- **絵を押したら読み進める**: areka は、今までどおり `OnMouseClick` を投げる。pasta は、「再生を早送りする命令」を持つさくらスクリプトを、並走の 1 本として返す（仮 `\![parallel]\![play,fastforward]`）。開発者: 「『特定のリージョンをマウスクリックされたら、再生を早送りするコマンドを持つさくらスクリプト』を、並走モードでなげればよい」。舞台の台詞の箱を押した時も、`OnMouseClick` が pasta に届く。どこを押したら早送りかは、シェルと台本の作り（当たり判定の領域）で決まる。SSP は、今のまま（pasta が受けて進める）。
- 早送りは、中身を見ない（音だけ鳴らさない、は作らない）。
- **待たない印**: 作者が書くのは `\![parallel]` の 1 つ、ベースウェアへは `\![parallel,1]`・`\![parallel,0]` の対で出す（骨子 8 章の議題 14 の 8）。印から単語の終わりまでが、並走の区間になる。areka でないベースウェアへは、印を出さない（順に再生される）。
- **並走は並走**（開発者: 「勝ち負けとは？並走は並走。」）。areka は、届いた順に、そのまま当てる。「後から始まった流れが、あるアクターの表情を置いたら、前から走っている並走は、そのアクターへはもう書かない」の 1 文は、作らない（骨子 8 章の追記 3）。続いてほしくない並走は、作者が、短く作るか、終わりの絵を決めておく。
- 高速再生が「入」の間は、主の 1 本の中の並走の区間も、待ちを飛ばして一度に配る。先頭に並走の印の在る 1 本は、速く進めない（areka の側の決定 2）。
- 時期: areka の `play` に関わる物は、areka の v0.3.0 より後（骨子 8 章の追記 1）。

### 口の置き方

- 先に入る spec は、後に入る spec の関数を呼ばない。先に入る spec が口を置き、後の spec が登録する（2026-11-19 の暫定設計の照らし合わせ）。この spec は最後に入るので、`cue-command-runtime` のタグへ直す所と、`novel-talk-flow` の 1 本の枠に、areka の形を登録する。

## Scope

  6. areka では、物語の続きを再開するのは、続きの命令が投げるイベントだけ、と決めてよいか（discovery の読み。骨子 8 章の追記 4 の残した問い）。遅れて届いたイベントを捨てるための行の ID を、続きの命令の引数でどう運ぶか。
  7. 高速再生の入切を打つ時（入れた時・読んでいない行で切る時）と、SSP の `\_q` との出し分けの口の形。
  8. areka の版の判定で、どの版からどの形を出すか。判定できない時の扱い（SSP と同じに扱う見込み）。
  9. 並走の区間の印の対を出す位置（印から単語の終わりまで）と、戻る・ロード・高速再生で区間を出さない時の扱い（`novel-talk-flow` と合わせる）。
  10. いつも居るアクター（台詞の箱・ボタンを載せた絵）を、シーンごとの並びに書かずに済ます書き方（`cue-command-runtime` の「要件定義へ送ること」から移した）。
