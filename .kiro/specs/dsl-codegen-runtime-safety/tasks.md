# Implementation Plan

> 前提: `cargo build`／`cargo test` の前に環境変数 `NoDefaultCurrentDirectoryInExePath` を外す（LuaJIT のビルドが失敗するため）。生成形の変更は各タスクの中で影響するスナップショット・期待値まで更新し、各タスクの完了時点で `cargo test --workspace` が通る状態を保つ。

- [x] 1. act の存在確認付きメソッド（ランタイム）
- [x] 1.1 グローバル関数を名前で呼ぶメソッドを act に足す
  - 名前の値が関数なら act を第 1 引数にして呼び、戻り値をすべて返す。関数でない・無いときは関数名を含む警告を `act:expr_fn` と同じレベルで 1 行出し、値なしを返す
  - 関数の中で起きたエラーは握りつぶさずそのまま伝える
  - 新しいランタイムテストのファイルを作り、Lua テストの入口に登録する（既存の `act_test.lua` は膨らませない）
  - ランタイムテストで、定義済み関数が `(act, 引数…)` で呼ばれて戻り値が返ること、未定義・関数でない値で値なし＋警告 1 行になることが確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_
  - _Boundary: ActSafety_
- [x] 1.2 アクター名からプロキシを得るメソッドを act に足す
  - 登録済みアクターなら、従来の `act.名前` と同じプロキシを返し、ログ・トークンは出さない
  - 未登録の名前なら、名前だけを持つその場限りのアクターのプロキシを返す。直前の話者（トークン列を末尾から見て最初の talk／sakura_script の actor）が同じ未登録名ならそのアクターを再利用し、そうでなければ警告を 1 行出して目印 `【未登録アクター：名前】` の talk トークンを積む
  - アクターの登録状態・立ち位置・act のフィールドには何も書かない
  - ランタイムテストで、`talk`・`var`・`save`・`actors` という名前の登録済みアクターが話せること、未登録アクターの複数アクションで目印と警告が 1 回だけ出ること、実行後も `STORE.actors[名前]` と `act.名前` が nil のままであること、`talk` という名前のアクターを登録しても手書き Lua の `act.talk` がメソッドを返すことが確認できる
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7_
  - _Boundary: ActSafety_
- [x] 1.3 数値の二項演算メソッドを act に足す
  - 数値はそのまま、文字列は現行の数値変換で数値にし、それ以外は数値にできない値とする。両方が数値なら Lua のネイティブ演算の結果を返す
  - 数値にできない被演算子ごとに、演算子と説明（無ければ値と種類）を含む警告を出して値なしを返す。値なしで説明も無い被演算子（内側の失敗の伝播）は警告しない
  - 未知の演算子は警告して値なし。テーブルの被演算子は数値にできない扱いにし、メタメソッドを呼ばない
  - ランタイムテストで、数値・数値文字列・`「1」＋2`・負数の剰余・0 除算がネイティブ演算と同じ結果になり、16 進・指数・前後の空白・全角数字・空文字列の数値化が現行の変換と一致し、nil・非数値文字列・真偽値が値なし＋警告、入れ子の外側が値なし＋追加の警告なしになることが確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.5, 3.7_
  - _Boundary: ActSafety_

- [x] 2. (P) さくらスクリプトのトークナイザで `\\` を 1 単位として読む
  - タグのパターンの先頭に `\\` 2 文字の選択肢を足し、`\\` を分割できない 1 トークン（既存のタグ種別）として読む。ドキュメントコメントも更新する
  - トークナイザの単体テストで、`C:\\new`・行末の `\\`・`\\\\`・`\\` の直後の `\n`・`\\s[0]` のトークン列が期待どおりで、既存のタグのトークン列が変わらないことが確認できる
  - ウェイト挿入あり・改行位置推定ありで、`\\` の 2 文字の間にウェイトや改行が入らないことを改行推定側のテストで確認できる（改行推定・ウェイト挿入の本体は変更しない）
  - 外見の追跡が `\\s[0]` を表情タグと読み誤らないことを、既存の外見のランタイムテスト（`appearance_test.lua`）に場合を足して確認できる（外見の実装は変更しない。1 が作るランタイムテストのファイルには触れない）
  - 1 と独立（別ファイル・別コンポーネント）のため並行できる
  - _Requirements: 4.2, 4.4, 4.5, 4.7_
  - _Boundary: Tokenizer_

- `crates/pasta_shiori/tests/support/scripts/` は古いランタイムの写しで act の新メソッドを持たない。生成コードを実行する E2E フィクスチャは `lua_search_paths` から `scripts` を外して埋め込みランタイムを通す（4.2 の codegen_runtime_safety フィクスチャ参照）。
