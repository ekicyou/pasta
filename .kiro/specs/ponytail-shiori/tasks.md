# Implementation Plan

> 進め方：設計の Migration Strategy（S1〜S10）の順に、1 つ直すごとに関門（`cargo fmt --check`・`cargo clippy -p pasta_shiori --all-targets` の警告 0・`cargo test -p pasta_shiori`・i686 のリリースビルド）を通して 1 コミットにする。cargo の前に環境変数 `NoDefaultCurrentDirectoryInExePath` を外す。挙動を変える直し（要件 1・2・3・5）は、1 の特性化テストで直す前を固めてから、直すタスクでそのテストを直した後の期待に改める。すべて同じクレートの同じファイル群を順に触るので、並列の印 `(P)` は文書の 2 本だけに付ける。

- [x] 1. 直す前の振る舞いを固める特性化テストを置く
- [x] 1.1 unload を呼ばずに外す統合テストの足場を作り、前提を確かめる
  - 親のテストが同じテストの実行ファイルを子のプロセスとして起こし（役は環境変数で指示・`PASTA_DEBUG` などは外す）、子は実行ファイルの隣の pasta.dll を読み込んで入口を引く形にする。子の役が無いときは何もせずに通る
  - dev-dependencies の `windows-sys` に `Win32_System_LibraryLoader` の機能を足す（子が `LoadLibraryW`・`GetProcAddress`・`FreeLibrary`・`GetModuleHandleW` を使う。`pasta_lua` の機能の合流に頼らない）
  - Lua の C モジュール（システムの DLL を `ffi.load` する）を読むゴーストのフィクスチャを置く
  - 前提 2 つを最初に確かめる：`cargo test` がテストの実行ファイルの隣に pasta.dll を作ること、`ffi.load` でシステムの DLL を読めること。崩れたら設計の Open Questions 8 のとおり場合 A を外し、場合 B・C だけで進める（その旨をテストのコメントに 1 行残す）
  - 場合 A（旧来・C モジュールあり・unload なしで外す）は直す前の期待（4 秒以上かかる・子が落ちることは許す）、場合 B（版 3 のインスタンスを手放したまま外す）は直す前の期待（モジュールが外れる）、場合 C（loadu → unload → 外す）は前後で同じ期待（モジュールが外れる）で書く
  - 3 つの場合が直す前の期待のとおりに通り、子の標準出力にかかった時間とモジュールの有無が 1 行ずつ出る
  - _Requirements: 1.2, 1.3, 1.5, 1.8, 9.4_
- [x] 1.2 フォルダが無いときの 500 の特性化テストを置く
  - 旧来の入口に存在しないフォルダを渡すと load が FALSE、GET が 500（理由は今の `Not initialized error`）、NOTIFY が 204 であることを固める
  - ANSI で表せない文字を含むパスの場合も同じ作りで固める（ACP が 65001 のときは飛ばす）
  - 版 3 の load がフォルダの無いときに NULL を返すことと、フォルダがあるときの失敗の理由（`Load error: …`）が変わらないことを確かめる
  - 新しいテストが今のコードで通る
  - _Requirements: 2.1, 2.3, 2.5, 2.6, 9.4_
- [x] 1.3 値の空いた見出しの行の特性化テストを置く

  - 入口の段で、SSP の記録の 3 つの要求（47 行の OnInitialize・720 行の OnNotifyUserInfo・1236 行の GET OnTranslate）をテストの文字列として持ち（720 行の利用者の名前は仮の値に替える）、届いた要求の数を返すフィクスチャへ旧来の意味と版 3 の両方で送る。今は数が増えない（旧来 204・版 3 400）ことを固める

  - 旧来の意味は今と同じ 204、版 3 は今と同じ 400（`unreadable request`）を返す
  - 2 行目のコロンが抜けた要求（後ろの行に目印の文字列）を送るテストで、ログのファイルに warn が 1 行あり、`line=2`・列・1 行目を含み、目印を含まないことを確かめる。2.x の要求では warn の行が増えない

- [ ] 6. アクタースレッドに pasta.dll の参照と「join の約束」を持たせる
- [ ] 6.1 モジュールの参照の部品を足す
  - この関数を含むモジュールの参照を 1 つ足す・返す・返してスレッドを終える 3 つの操作を 1 つの部品に閉じ込める（`unsafe` はこの部品の 3 か所だけで、それぞれに SAFETY のコメント）。非 Windows では何もしない
  - 通常の依存の `windows-sys` に `Win32_System_LibraryLoader` の機能を足す
  - 参照を足して返すと釣り合う（足した後もモジュールが読まれたまま・返した後に二重に返さない）ことを確かめる単体テストが通る
  - _Requirements: 1.2, 1.3_
- [ ] 6.2 アクタースレッドの起動・join・手放しを参照と約束で組む
  - スレッドを起こす前に参照を取り、約束のチャネル（容量 1）を作る。閉包は今の順（ログの文脈 → VM と load → ready → ループ → VM を落とす → 受け口を落とす → ack）を変えず、その後に持つ値を落としてから約束を待つ。約束が届けば普通に戻り、送り手が落ちていれば参照を返してスレッドを終える
  - join は「約束を送る → join → 参照を返す」の順に閉じる。手放しは約束の送り手を落とすだけにする。ready の前に終わった・起動に失敗した場合もその場で参照を返す。参照が取れなければ起動の失敗にする
  - インスタンスの後始末は ack が届けば join、受け口が既に閉じていても join し、ack が来ないときだけ手放す（警告の文言は今のまま）
  - 後始末の決まりの選択の Detach（DllMain の道）は 7 まで今の振る舞いのままにし、1.5 のテストは直す前の期待のまま通る
  - 1.1 の場合 A・B を直した後の期待（1 秒未満で戻る・モジュールは外れない・子は 0 で終わる）に改め、場合 C は前後で同じまま通る
  - 版 3 のインスタンスに 1 秒回る要求を送った直後に短い上限で後始末すると ack も join も偽になり、その後 3 秒以内にそのアクタースレッドがスレッドの数え上げから消えるテストを足す
  - 既存の join・ack・冪等・占有の引き継ぎのテストと 1.1 のテストが通る
  - _Depends: 1.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.8_

- [ ] 7. DllMain を何もしない形にし、手放しの後始末の道を消す

  - load・loadu・unload・request の型・長さ・HGLOBAL の所有は変えない
  - 1.5 のテストを直した後の期待（detach の後も置き場は埋まったまま・unload で片付く）に改め、プロセスの終了と attach は 1 を返すだけのまま通る
  - FFI の型と長さのテスト・プロセスに 1 つの状態を錠で直列にするテストが通る

  - kick がシーンの最初の拍まで届くこと（複数拍・ゲート・割り込みを含む）を 4 本のテストが確かめ続け、通る

  - 使い手のテスト（kick の単体・アクターと VM・ハーネス・debug の保持・ログの文脈・FFI のログ・実行時の誤りの吹き出しなど）を、残る marshal の口・メッセージの直の組み立て・文字列の応答・残る起動の口に直す。DAP のポートはゴーストのログの `debug backend listening addr=` の行から読む共通の補助に移し、フィクスチャの既定のロガーがその行をファイルへ書くことを最初に確かめる
  - 短い上限を差し込む 3 つの口とテストのファイルは残す
  - 書き直したテスト（debug の保持・ログの文脈・アクターと VM・ハーネスなど）が通る
