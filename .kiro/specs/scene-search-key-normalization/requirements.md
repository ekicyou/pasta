# Requirements Document

## Project Description (Input)
ゴースト作者は、記号（英数字以外の文字）を含むシーン名（グローバル・ローカル）やアクター名を書くことがある。現状、これらの名前は登録時に英数字以外を `_` に置き換えた（サニタイズした）キーで登録されるが、検索は作者が書いた元の名前のまま行われる。そのため、`＊会話・朝` のような名前は元の名前で Call・シーン検索ができず（「見つからない」警告・何も出力しない・204）、記号を含むアクター名のアクター単語（`:__actor_X__:`）も引けない（U30、ランタイム内部ドキュメント吸収台帳付録 B）。

この spec では、登録キーと検索キーを作る規則を 1 か所にまとめ、作者が書いた元の名前で Call・シーン検索・アクター単語参照ができるようにする。あわせて修正を固定するテストを足し、マニュアル（`grammar/call-jump.md`・`internals/internal-modules.md` ほか）に名前に使える文字と検索の扱いを書き、生成スキルの `references/` を再生成する。

## Introduction

Pasta は、シーン名・アクター名を登録するとき、Unicode の英字・数字（かな・漢字を含む）と `_` 以外の文字を `_` に置き換えた名前（以下「照合用の名前」）で登録する。一方、Call・シーン検索・アクター単語参照は作者が書いた元の名前で探すため、`・`（中黒）や `·`、`＿`（全角下線）など、識別子に書けるが置き換えの対象になる文字を含む名前は見つからない。

本仕様は、作者が書いた名前と登録された名前を **同じ規則** で照合用の名前に揃え、記号を含むシーン名（グローバル・ローカル）・アクター名でも元の名前で Call・シーン検索・アクター単語参照ができるようにする。挙動の変更に合わせて、利用者向けマニュアル（文法・API の唯一の権威）と、マニュアルから生成するスキルの `references/` を更新する。

本書で使う用語:

- **照合用の名前**: 名前のうち、Unicode の英字・数字と `_` 以外の文字を `_` に置き換えた名前（現行の登録時の置き換え規則と同じもの）。例: `会話・朝` → `会話_朝`。
- **登録名**: 実行時にシーンを指す名前。グローバルシーンは照合用の名前に同名シーンの通し番号を付けたもの（例: `会話_朝1`）、ローカルシーンは照合用の名前に `_` と通し番号を付けたもの（例: `選択_A_1`）。`search_scene` が返し、第 2 引数（スコープ）に渡す名前である。
- **記号を含む名前**: 照合用の名前が元の名前と異なる名前。

## Boundary Context

- **In scope**:
  - グローバルシーン名・ローカルシーン名の、Call・Lua からのシーン検索（`SCENE.search`・`@pasta_search` の `search_scene`）での照合。
  - アクター名の、アクター単語参照（アクター付きの単語参照 A2 段）での照合。
  - 照合規則を登録・検索で共有すること（二度と食い違わないこと）。
  - 名前が照合用の名前で重なる場合（衝突）の扱いの明文化。
  - 修正を固定するテスト。
  - マニュアルの該当章の更新とスキル `references/` の再生成。
- **Out of scope**:
  - 登録名の形式（名前と通し番号の区切り、末尾が数字のシーン名の問題）。後続の `scene-identity-format` が持つ。
  - シーン検索のアルゴリズム（前方一致・シャッフル＆順次消費・Call の 5 段の順序）の変更。
  - 選択肢の自動ルーティング（棚卸の即時修正で修正済み）。
  - 単語名（単語キー）の照合。単語名は登録・検索とも書いたままで一致しており、本仕様では変えない。
  - Lua のテーブルを完全一致で引く段（Call の 1・3・4 段、アクター付き単語参照の A1 段）。これらは Lua 側のキーをそのまま使い、本仕様では変えない。
  - 名前に使える文字（文法）の変更。
  - マニュアルの内部構造の章だけに載る内部 API（`PASTA.create_scene` など）を、生成コード以外から置き換え前の名前で呼ぶ利用。内部 API は利用者向けの保証の対象外である。
  - アクタープロキシの呼び出し規約、Call のハンドラー探索の手順、ランダム選択の変更（Wave 1 で並走する他の spec、または後続の spec が持つ）。
- **Adjacent expectations**:
  - `scene-identity-format` は、登録名の区切り文字を照合規則で消えない文字から選ぶ。本仕様は、登録名を検索に渡したときの結果を変えないこと（要件 3.2）で、その前提を保つ。
  - `actor-proxy-act-delegation`・`search-selector-indices`・`call-attribute-filter` は、本仕様の後に同じ箇所（アクター単語検索・レジストリ・`search_scene` の入口）を触る。本仕様は、それらが前提にする呼び出しの形（`search_scene(name, global_scene_name)` の引数と戻り値の意味）を変えない。

## Requirements

### Requirement 1: 記号を含むグローバルシーン名での Call とシーン検索

**Objective:** As a ゴースト作者, I want 記号を含むグローバルシーン名を、定義に書いたとおりの名前で Call・検索できること, so that 名前の付け方を気にせずにシーンを呼び出せる。

#### Acceptance Criteria

1. When ゴースト作者が `＊会話・朝` と定義したグローバルシーンを `＞会話・朝` で Call したとき, the Pasta runtime shall そのグローバルシーンを実行し、「見つからない」警告を出さない。
2. When 動的ターゲット（`＞＄変数`・`＞＠関数（）`・`＞「文字列」` など）の値が記号を含むグローバルシーン名の文字列であるとき, the Pasta runtime shall 同じ名前を `＞シーン名` で書いた場合と同じグローバルシーンを実行する。
3. When Lua から `SCENE.search("会話・朝")`（第 2 引数なし）または `@pasta_search` の `search_scene("会話・朝")` を呼んだとき, the Pasta runtime shall グローバルシーン `＊会話・朝` を検索結果として返す。
4. When 記号を含む名前の先頭部分（例: `会話・`）で検索したとき, the Pasta runtime shall 照合用の名前どうしの前方一致で候補を決め、記号を含まない名前と同じ前方一致・シャッフル＆順次消費の規則で 1 つを選ぶ。
5. When SHIORI イベントの処理で、記号を含むグローバルシーンを Call したとき, the Pasta runtime shall そのシーンの出力を応答として返し、何も出力しない応答（204）にしない。

### Requirement 2: 記号を含むローカルシーン名での Call とシーン検索

**Objective:** As a ゴースト作者, I want 記号を含むローカルシーン名を、定義に書いたとおりの名前で Call・検索できること, so that グローバルシーンと同じ感覚でローカルシーンに名前を付けられる。

#### Acceptance Criteria

1. When グローバルシーンの中で `・選択・A` と定義したローカルシーンを、同じグローバルシーンの中から `＞選択・A` で Call したとき, the Pasta runtime shall そのローカルシーンを実行する。
2. When Lua から `SCENE.search("選択・A", 登録名)`（第 2 引数にそのグローバルシーンの登録名）を呼んだとき, the Pasta runtime shall ローカルシーン `・選択・A` を検索結果として返す。
3. When 記号を含むローカルシーン名の先頭部分で検索したとき, the Pasta runtime shall グローバルシーンと同じく、照合用の名前どうしの前方一致で候補を決める。

### Requirement 3: 名前の照合規則（共通）

**Objective:** As a ゴースト作者, I want 登録と検索が常に同じ規則で名前を照合すること, so that 書いた名前で見つからないという食い違いが二度と起きない。

#### Acceptance Criteria

1. The Pasta runtime shall シーン名・アクター名を登録するときと、作者が書いた名前で検索するときに、同じ照合規則（Unicode の英字・数字と `_` 以外を `_` に置き換える規則）を使う。
2. When 検索する名前として登録名（例: `会話_朝1`・`選択_A_1`）を渡したとき, the Pasta runtime shall 本仕様の変更前と同じ検索結果を返す。
3. The Pasta runtime shall ローカル検索の第 2 引数（グローバルシーンの登録名）には照合規則を適用せず、渡された登録名のまま扱う。
4. When 記号を含まない名前で Call・シーン検索・アクター単語参照をしたとき, the Pasta runtime shall 本仕様の変更前と同じ候補・同じ選択・同じ出力を返す。
5. If 記号を含む名前で探したシーンが存在しないとき, the Pasta runtime shall 本仕様の変更前と同じく警告をログに出して次の行へ進み、警告には作者が書いた元の名前を表示する。
6. When 第 2 引数なしで `:` で始まる名前を検索したとき, the Pasta runtime shall 本仕様の変更前と同じく、ローカルシーンを候補にしない。
7. While シーン辞書の確定前（`main.lua`・`entry.lua` の実行中）であるとき, the Pasta runtime shall 確定後と同じ照合規則で、作者が書いた名前を照合する。

### Requirement 4: 記号を含むアクター名でのアクター単語参照

**Objective:** As a ゴースト作者, I want 記号を含む名前のアクターでも、そのアクターのアクター辞書の単語を引けること, so that アクター名の付け方によってアクター辞書が使えなくなることが無い。

#### Acceptance Criteria

1. When `％さくら・改` のアクター辞書に単語 `通常` を定義し、アクション行で `さくら・改：＠通常` と参照したとき, the Pasta runtime shall そのアクター辞書の `通常` の値を出力する。
2. When Lua の `WORD.create_actor(アクター名, キー)` で記号を含むアクター名に単語を登録し、そのアクターを付けた単語参照でキーを参照したとき, the Pasta runtime shall 登録した単語の値を返す。
3. When pasta.toml の `[actor."名前"]` で記号を含む名前のアクターを設定し、同じ名前のアクター辞書を定義したとき, the Pasta runtime shall そのアクターを付けた単語参照で、アクター辞書の単語を返す。
4. When 記号を含むアクター名のアクター辞書に、参照したキーに前方一致する単語が無いとき, the Pasta runtime shall 本仕様の変更前と同じく、アクター辞書の次の段（通常の単語参照の 5 段）へ進む。
5. The Pasta runtime shall アクター単語の参照でも、登録と同じ照合規則でアクター名を照合用の名前に揃えてから探す（登録時の置き換えはやめない）。
6. When アクター名が `:` などの記号を含むとき, the Pasta runtime shall そのアクターの単語を、別のアクターの単語と取り違えない（例: アクター `a__:b` の単語 `x` と、アクター `a` の単語 `b__:x` を区別する）。

### Requirement 5: 照合用の名前が重なる名前（衝突）の扱い

**Objective:** As a ゴースト作者, I want 照合用の名前が同じになる別々の名前がどう扱われるかを知っていること, so that 意図しないシーン・単語が選ばれる理由を理解し、名前を付け分けられる。

#### Acceptance Criteria

1. When 照合用の名前が同じになる 2 つのグローバルシーン（例: `＊会話・朝` と `＊会話_朝`）があり、どちらかの名前で検索したとき, the Pasta runtime shall 両方のシーンを同じ名前の候補として扱い、同名のグローバルシーンを複数定義した場合と同じ規則で 1 つを選ぶ。【前提: 現行の挙動を保つ。読み込み時に警告するかは未決（OPEN QUESTION 2）】
2. When 照合用の名前が同じになる 2 つのアクター名（例: `さくら・改` と `さくら_改`）にアクター単語を登録したとき, the Pasta runtime shall 両方のアクター単語を同じアクター辞書の単語として扱う。【前提: 同上】
3. The Pasta manual shall 照合用の名前が同じになる名前は区別されず、同じ名前の候補になることを書く。

### Requirement 6: マニュアルと生成スキルの更新

**Objective:** As a ゴースト作者, I want マニュアルが名前に使える文字と検索での扱いを正しく書いていること, so that マニュアルを読めば記号を含む名前の挙動が分かる。

#### Acceptance Criteria

1. The Pasta manual shall Call の章（`grammar/call-jump.md`）に、シーン名に記号を使えることと、検索では照合用の名前どうしで照合することを書く。
2. The Pasta manual shall アクター辞書の章に、記号を含むアクター名でもアクター辞書の単語を引けることと、照合用の名前で照合することを書く。
3. The Pasta manual shall 「書いた名前をそのまま検索キーにする」「検索キーとして渡す名前はサニタイズされない」など、本仕様の変更後の挙動と食い違う記述を残さない。
4. The Pasta manual shall `@pasta_search` の `search_scene` の説明に、第 1 引数は照合用の名前で照合されることと、返る登録名・第 2 引数に渡す登録名は照合用の名前を元にした名前（例: `会話・朝` の 1 つ目は `会話_朝1`）であることを書く。
5. The Pasta manual shall 内部構造の章（`internals/internal-modules.md`・`internals/registry-search.md` ほか）に、登録と検索が同じ照合規則を共有することを書く。
6. When マニュアルを更新したとき, the 生成スキルの `references/` shall マニュアルから再生成され、鮮度の検査とリンク検査に通る。

### Requirement 7: 修正を固定するテスト

**Objective:** As a Pasta の開発者, I want 記号を含む名前の照合をテストで固定すること, so that 登録と検索の食い違いが再発したらすぐに気づける。

#### Acceptance Criteria

1. The Pasta test suite shall 記号を含むグローバルシーン名を元の名前で Call・検索できることを確かめるテストを含む。
2. The Pasta test suite shall 記号を含むローカルシーン名を元の名前で Call・検索できることを確かめるテストを含む。
3. The Pasta test suite shall 記号を含むアクター名のアクター単語を、アクターを付けた単語参照で引けることを確かめるテストを含む。
4. The Pasta test suite shall 登録名を検索に渡したときの結果が変わらないこと（要件 3.2）と、照合用の名前が重なる名前の扱い（要件 5.1）を確かめるテストを含む。
5. When 本仕様の変更を入れたとき, the Pasta test suite shall 記号を含まない名前に関する既存のテストを、期待値を変えずにすべて通す。
6. If 照合規則が登録と検索のどちらか一方だけで変わったとき, the Pasta test suite shall 少なくとも 1 つのテストで失敗する。
