# Implementation Plan

> 設計の Migration Strategy の 6 手順に沿って、小さく戻せる順に並べる。各コミットの時点でワークスペース全体のテストを通す。3.1〜3.4 は 1 つのコミットに入れる（3.1・3.2 は先に赤を確かめるテストなので単独ではコミットせず、赤の結果は記録として残す）。luacheck は手元で実行する（luarocks の lfs・argparse を `LUA_PATH`・`LUA_CPATH` に足す。CI 任せにしない）。

- [x] 1. 被演算子の変換関数を足す（挙動は変わらない）
- [x] 1.1 算術・連結の被演算子を必ず数値・文字列にする変換関数を、ランタイムに足して pasta モジュールから公開する
  - 算術用の変換は、数値はそのまま、数字だけの文字列は数値に、nil は黙って 0 に、それ以外は従来と一字一句同じ文言の警告を 1 行出して 0 にする
  - 連結用の変換は、文字列はそのまま、数値は従来の表記で文字列に、nil は黙って空文字列に、それ以外は従来と同じ文言の警告を 1 行出して空文字列にする
  - 表の値のメタメソッド（加算・連結・文字列化）を呼ばず、act のメソッドには載せない（`＠名前` の検索とぶつからない）
  - 既存の演算メソッド・生成コードには触らない
  - 完了時: 生成コードと同じく `require "pasta"` から 2 つの関数が呼べ、手元の luacheck（複雑度 15 以下）が通り、既存テストはすべてそのまま通る
  - _Requirements: 1.1, 1.3, 1.6, 1.8, 2.1, 2.5, 3.1, 3.2, 4.1, 4.2, 4.3, 4.4, 4.5_
- [x] 1.2 変換関数の規則を Lua の単体テストで固定する
  - 数値化の範囲の表（16 進・前後の空白・指数は数値、全角数字・空文字列・数字でない文字列は 0＋警告 1 行）がネイティブの数値化の成否と一致する
  - nil は説明の有無にかかわらず 0・空文字列で、warn・debug を含むログが 0 件
  - 真偽値・表・関数は 0・空文字列＋従来と同じ文言の警告 1 行で、表のメタメソッドが呼ばれない
  - 数値の文字列化の表記（整数・小数・循環小数・大きな数・inf）が従来と同じで、戻り値の型が常に数値・文字列
  - 完了時: Lua の単体テストが新しいケースを含めて通る
  - _Requirements: 1.8, 2.5, 3.1, 4.1, 4.2, 4.3, 4.4, 4.5, 7.1_

- [ ] 2. 式文を Lua の文として正しく出す（挙動は変わらない）
- [ ] 2.1 関数呼び出しそのものでない式文を、値を捨てるブロックの形で書き出す
  - 式が関数呼び出し・動的関数呼び出しそのものなら現行どおり 1 行に書き、それ以外（二項演算・括弧・リテラル・変数参照）はブロックの中のローカルに代入して捨てる形にする
  - 生成形のテストに、関数呼び出し・二項演算・括弧・リテラル・変数参照の式文のケースを足し、影響するスナップショットを更新する
  - トランスパイル→実行のテストで、`＄＝１`・`＄＝＄x`・`＄＝（＠f（））` を含むシーンが読み込めて、`＄＝（＠f（））` の副作用がちょうど 1 回起きることを固定する（現行の潜在的な欠陥の修正）
  - 完了時: ワークスペース全体のテストが通り、スナップショットの差分が式文の行だけである
  - _Requirements: 1.4, 2.4, 7.1_

- [ ] 3. 二項演算の生成形を切り替える（挙動が変わる手順）
- [ ] 3.1 新しい規則を、トランスパイル→実ランタイムのテストで先に書く
  - 全レベル（trace〜error）のログを集める補助を足す
  - nil の出どころ × 文脈: 未代入のローカル・グローバル・リクエスト変数、渡されていないシーン引数、値を返さない関数、見つからない `＠＊未定義（）`（既存の関数の警告 1 行だけ）、`＠＄未代入（）`（既存の未代入の警告 1 行だけ）、値なしを代入した変数で、結果が 0・空文字列になり nil 由来のログが 0 件
  - 5 つの演算子と左右（`１－＄未代入`=1、`＄未代入＊２`=0、`１／＄未代入`=inf、`１％＄未代入` は非数 など）と、変数代入・式文・関数の引数・Call の引数・動的コールのターゲットの各位置で同じ結果
  - 入れ子と境界: `（「abc」＊２）＋１` は 1＋警告 1 行、`（＄未代入＆「x」）＋1` は 1＋算術の警告 1 行（値は `'x' (string)`）、`「合計」＆（＄未代入＋１）` は `合計1`、真偽値の連結は内側の警告 1 行で外側に使われる、`＄x＝「」` のあとの `＄x＋１` は 1＋警告 1 行、表を返す関数の演算でメタメソッドが呼ばれない
  - 変えない規則: 台詞の未代入の変数は空文字＋既存の警告、関数の引数に nil を 1 つ渡すとそのまま nil が届く
  - コミットはしない（3.4 と同じコミットに入れる）
  - 完了時: 新しいテストが現行の生成形で失敗する（期待どおりの赤）ことを確かめてある
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.1, 3.3, 4.1, 4.2, 4.4, 4.5, 5.1, 5.5, 7.1, 7.2_
- [ ] 3.2 (P) 作例・再起動・Call のターゲットを、SHIORI を通す E2E テストで先に書く
  - 回数の作例: `＊会話` で `＄＊回数＝＄＊回数＋１` に続けて回数を台詞に使い、1 回目に 1、2 回目に 2 を話し、ログに警告が無い
  - 再起動: 同じ一時フォルダで読み込み → 2 回発火 → 破棄（保存）→ 再読み込み → 発火で 3 を話す
  - Call のターゲット: `＞＄時間帯＆「の挨拶」`（未代入）で `＊の挨拶` が呼ばれる、`＞＄未代入＆＄未代入２` は空文字列の失敗表記と既存の警告（`＞＄未代入＆「x」` の既存シーン `OnFcConcatMid` の書き直しは 3.4 の持ち場で、ここでは触らない）
  - 変えない規則: ターゲットが変数 1 つ（`＞＄未代入`）・関数呼び出し 1 つ（`＞＠f（）`）で nil のときは、従来どおりの警告と失敗表記になる（新しいシーンで確かめる）
  - 新しいシーンとテスト関数を足すだけで、既存のシーンの期待は変えない
  - コミットはしない（3.4 と同じコミットに入れる）
  - 完了時: 新しい E2E テストが現行の生成形で失敗する（期待どおりの赤）ことを確かめてある

  - _Boundary: pasta_shiori E2E テストとフィクスチャ（新しいシーン・テスト関数のみ）_
