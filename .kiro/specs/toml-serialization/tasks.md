- [x] 1.2 Lua の値を TOML の値にする変換を、外すモードと厳しいモードで作る
  - 設計の分類の表どおりに、書ける値（文字列・真偽値・整数・浮動小数点数・配列・文字列のキーの表・空の表・配列の印の付いた空の表）を TOML の値にし、書けない値を決まった理由の言葉で断る
  - 外すモードでは、いちばん近い文字列のキーだけを外して一覧に足し、配列の要素が書けなければ配列のキーごと外す（その配列の中で先に足した件は一覧から取り除く）。根の文字列でないキーは 1 つずつ外し、根を配列として書かない
  - 深さの上限（セーブ 32 段・ログが渡す 10 段）で再帰を必ず止め、祖先の表の列で循環を見つける。同じ表を 2 つのキーから指すだけなら 2 回書く。メタテーブルは配列の印だけを見て、中身は生のたどり方で読む
  - 厳しいモードでは、どこか 1 つでも書けなければ全体を理由つきの失敗にする
  - 分類の表の各行、`flags.secret` だけが外れる、`inventory[1].f` だけが外れる、配列の要素が関数なら配列ごと外れる、32 段は書けて 33 段目のキーが外れる、`t.me = t` が `recursive table`、10 万段でも落ちない、根の `save[1]`・`save[true]` が 1 件ずつ外れる、UTF-8 でない文字列とキー、キーの順を変えた 2 つの表が同じ文書になる、を単体テストで確かめ、すべて通る
  - _Requirements: 1.8, 4.1, 4.2, 4.3, 4.4, 4.7, 4.8, 4.10_

- [x] 1.3 TOML の値を Lua の値に戻す変換を作り、往復を確かめる

  - 公開の読み書きの関数を TOML の文書の型にし、誤りの種類の JSON の項を TOML の読み・書きの項に替え、保存を止めたことを表す項を足す。モジュールの説明の文字列を `"Persistent data storage (TOML/gzip)"` にする。書き込みは今の原子的な書き込み（フォルダを作る・一時ファイル・`sync_all`・名前の置き換え・失敗したら一時ファイルを消す）を保つ

  - `load()` は 2.1 の読み込みの表を Lua の表にして返し、`save(data)` は外したキーがあっても `true, nil`、失敗で `nil, "Failed to save: …"` を返す。パスの検査と `debug_mode` のログは今のまま
  - 終了時の自動保存を、`pasta.save` の表を共通の保存の道に渡す 1 回の呼び出しにし、JSON への変換と直接の書き込みを消す。ログの文言 `"Failed to save persistence data on drop"`・`"Saved persistence data on drop"` は変えない
  - 既存の結合テストの材料を、コンパイルが通るだけ TOML の文書に替える（新しい場面は 4 で足す。3.1 と並行するので、テストは保存先の既定に頼らず `file_path` を明示する）。セーブ機能と終了時の保存のファイルに `serde_json` が残らない
  - 移したテストを TOML の材料に直したもの（gzip の判別・`obfuscate` に関係なく両方の形を読めること・原子的な書き込み・フォルダの作成・パスの検査・`load()`・`save()` の戻り値）と、保存しない印の状態で `save()` が `nil, err` を返し保存先と一時ファイルが変わらない、印が無いまま `save()` を呼ぶと壊れたファイルを先に退避してから書く、Windows の共有なしで開いたままの保存先で `save()` が `nil, err` を返し中身が変わらない、書けない値を含む表の `save()` が `true, nil` を返してほかのキーを書く、の単体テストが通り、`pasta_lua` の全テストがコンパイルされて通る

## Implementation Notes

- 1.2: SAVE_MAX_DEPTH・DroppedKey・lua_table_to_toml_document には 2.2 で、lua_value_to_toml_strict には 3.3 で使い始めたら `#[cfg_attr(not(test), allow(dead_code))]` と `shortcut:` の注記を外す。
- 1.2: mlua の LuaJIT は `n.to_bits() == (i as f64).to_bits()` のときだけ Integer にするので -0.0 は Float のまま届く。テストの Lua リテラルの扱いで Integer(0) に見えることがある。
- 1.3: toml_to_lua にも dead_code の許可がある（2.2 で外す）。表の中の i64::MAX は LuaJIT の倍精度で Float(2^63) に丸まる（確定した設計判断 6 の限界）。ファイルを通す往復の確認は 2.2 で足す。
- 2.1: SaveGate・load_toml_from_file・set_gate・read_or_quarantine にも dead_code の許可がある（2.2 で外す）。PersistenceError に TomlParseError を先に足した（2.2 で JsonError を消し SaveDisabled・TomlWriteError を足す）。persistence.rs が 696 行で、2.2 で JSON の道を消したあと行数を確かめる。
- 2.2: 既定の保存先に書くテストが、追跡されている crates/pasta_lua/profile/pasta/save/save.json（中身 {}）を save.json.broken へ移して TOML を書く。テストの後は git checkout -- で戻し .broken を消す。3.1 で既定が save.toml（gitignore 済み）になったら、この追跡ファイルを残すかは完了時に判断する。保存先にフォルダがあっても読めない物として .broken へ退避する（設計どおり）。persistence.rs は 665 行。
- 6: PR（squash）の件名にも `!` を付ける（例 `feat(toml-serialization)!: セーブファイル・ログの表・サイドカーを TOML にする`）。リリースノートの詫びの文案は design.md「移行とリリースノートへの申し送り」にあり、release スキルが doc/release-notes/v0.4.3.md へ写す。
