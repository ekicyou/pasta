# Brief: scene-pick-modes

> **ステータス**: 未着手（2026-10-21 の `/kiro-discovery`「PastaDSL機能ヒアリング」で起票。ghost_dev の「emo2 開発」「ぱすた開発」セッションからの聞き取り）。版は未定（開発者の判断）。`scene-attribute-store` の後に入る。要件定義は Opus。

## Problem

同名シーンの選び方が「シャッフル＆順次消費」の 1 つしか無い。作者は比率や順番を、シーンの複写と Lua で作っている。

- **重み**: emo2 の `dispatch.pasta` は「通常トーク：スキット：季節トーク」の比率を、同名の `＊OnTalk` の個数で表している（5:3:1）。コメントには 5:2:1 とあり、複写の数を数え間違えても気づけない。窓際のぱすたさんの `talk_gal.pasta` は `＊OnTalk_ギャル` を 15 個複写している。表情の候補でも、emo2 は同じ表情コードを重ねて書いて腕の向きを 2:1 にしている（`murasaki1000.lua`）。
- **定義順の巡回**: 窓際のぱすたさんの `ball.pasta` は、12 本のシーンを決まった順に 1 本ずつ出す。位置を `save["ボール巡回"]` に持つ Lua（`ball_next`）で書いている。同名シーンにするとシャッフルになるからである。

## Current State

2026-10-21（main `71e18f42`）に確かめた。

- 同名シーンの候補は、シャッフル＆順次消費で 1 つ選ぶ（`book/src/lua/modules/pasta-search.md` L40-42）。1 巡の間は重ならない。
- `SEARCH:set_scene_selector(0)` で定義の順にできるが、テストの道具で、全部の単語・Call・OnTalk に効く（同 L159-195）。シーンごとには選べない。
- 属性（`＆重み：5` など）は解析して記録するが、実行時に何の効果も無い（`book/src/grammar/block-structure.md` L271。`scene.lua` L148・L206 と `act.lua` L678 の `attrs` は使われない）。
- 重みを付ける手段は、シーンや単語の値（`＠w：A、A、B`）の複写だけである。

## Desired Outcome

- 同名シーン（Call の前方一致の候補を含む）に、属性で重みを付けられる。`＊OnTalk　＆重み：5` と書けば、複写しなくても比率が付く。
- 候補を番号の順に 1 本ずつ出す書き方（`＆順番：番号`）がある。最後まで出たら最初へ戻る。位置はゴーストを閉じても続く。
- マニュアルとスキルの `references/` が書き方を載せる。

## Approach

**重み（2026-10-21 開発者の決定）**:

- **書く場所**: 候補のシーンの宣言行に `＆重み：数` と書く。属性の名前は `重み` と `weight` の両方を受け付ける。前方一致の候補にも、`＞＞`（`scene-exact-match`）の完全一致の候補にも効く。書かなければ重みは 1 である。
  ```
  ＊OnTalk　＆重み：5
  　＞通常トーク
  ＊OnTalk　＆重み：2
  　＞スキット
  ＊OnTalk
  　＞季節トーク
  ```
- **意味**: 袋の中の枚数として扱う。重み 5 の候補は、1 巡の中で 5 回出る。今の複写と同じ動きで、シャッフル＆順次消費のままにする（候補の ID を重みの数だけ並べる）。毎回の確率のくじにはしない。
- **不正な値**: 1 以上の整数でなければ（`0`・負の数・小数・数でない値）、辞書の読み込みエラーにする。`pasta_check validate` も同じ誤りを知らせる。`[scene.alias]` の書き間違いを読み込みエラーにした先例に合わせる。
- **属性の早い部分実装にしない**: `＆重み` だけを先に特別扱いで読む道は作らない。次の論点は `scene-attribute-store` が決めた規則に従う。
  - 属性を実行時まで運ぶこと
  - 値の型の解釈（全角の数字 `５` を数として読むか、など）
  - ファイルの先頭の `＆重み` をシーンが受け継ぐか
  
  重みは、数の属性の最初の読み手として、`scene-attribute-store` の要件の材料にする。

**順番（2026-10-21 開発者の決定）**:

- **書き方**: 候補のシーンの宣言行に `＆順番：番号` と書く。英語の別名は `index`。属性はかならず `＆キー：値` の形である（`grammar.pest` L164）。値の無い `＆巡回` のような書き方はしない。
  ```
  ＊ボール巡回　＆順番：１０
  　ぱすた：（1 本目）
  ＊ボール巡回　＆順番：２０
  　ぱすた：（2 本目）
  　…
  ＊OnMouseClick
  　＞ボール巡回       ＃ １０ → ２０ → … → 最後 → １０ に戻る
  ```
- **出す順**: 番号の小さい順に 1 本ずつ出す。最後まで出たら、最初へ戻る。最後で止める道は、使う人の事例が出るまで作らない。順番はファイルを読む順に左右されない。
- **番号**: 飛んでいてよい（`１０`・`２０` と振れば、後から間に `１５` を差し込める）。同じ番号が 2 つあれば、辞書の読み込みエラーにする。
- **覚えるもの**: 最後に出した番号を、保存ファイルの pasta の内部のキーに、探した名前ごとに覚える。作者の変数（`＄＊…`）とはぶつけない。次は、それより大きい番号のうち最小のものを出す。無ければ、いちばん小さい番号へ戻る。シーンを差し込んでも消しても崩れない。
- **混ざったとき**: 候補に `＆順番` の有るものと無いものが混ざったら、実行時は警告を出して、今のシャッフルで選ぶ。名前が決まった Call なら、`pasta_check validate` が前もって誤りとして知らせる。
- **重みと一緒のとき**: 同じシーンに `＆重み` と `＆順番` を両方書いたら、辞書の読み込みエラーにする。
- **値の読み方**: 全角の数字を数として読むかなどは、重みと同じく `scene-attribute-store` の規則に従う。
- **要件で決めること**: 内部のキーの置き場所を、`novel-variable-scope` が決める保存の範囲のどれに入れるか。

**単語の重み（2026-10-21 開発者の決定）**:

- **書き方**: 値のすぐ後ろに `＠整数` と書く。全角の数字も半角の数字も受け付ける。
  ```
  ＠挨拶：こんにちは＠３、やあ      ＃ こんにちは 3、やあ 1
  ＠挨拶：「こんにちは、」＠３
  ＠表情：\s[10]＠２
  ```
- **今の辞書とぶつからない理由**:
  - 「」で囲んだ値やさくらスクリプトの値の後ろの `＠３` は、今は構文エラーである。
  - 囲まない値は、今は読点か改行までがそのまま値になる（`grammar.pest` L155 の `word_nofenced`）。重みとして読むのは、値の最後が `＠` と数字だけで終わるときに限る。最後に「＠３」という文字を出したいときは、「」で囲む。
  - 単語の名前は数字で始められない。バックログの「単語の値の中の単語参照」を後で入れても、`＠３` が単語参照と取り違えられることは無い。
- **意味**: シーンの `＆重み` と同じく、袋の中の枚数として扱う。1 巡の中で、重みの数だけ出る。
- **効く範囲**: グローバルの単語、ローカルの単語、アクター辞書の単語。Lua の `WORD.create_*` は範囲の外にする。
- **不正な値**: `＠０` は辞書の読み込みエラーにする。

要件フェーズで次を決める。

- 囲まない値の最後の `＠数` を重みとして読み替えることの、変更履歴での書き方（今は文字として出ている）。

## Scope

- **In**: 同名シーンの選び方の重み（`＆重み`）と順番（`＆順番`）、その属性の読み方、単語の値の重み（`＠整数`）の文法と単語表の選び方、LSP と VSCode の着色、`pasta_check validate` の検査、テスト、マニュアル、スキルの `references/` の再生成
- **Out**: 属性の保持・継承（`scene-attribute-store`）、条件による絞り込み（`call-attribute-filter`）、「一度だけ」のシーン（フラグと絞り込みで書く。`call-attribute-filter` へ申し送った）

## Boundary Candidates

- 候補の選び方（`pasta_core` の `RandomSelector`・シーン表、`pasta_lua` の検索の文脈）
- 順番の位置の保存
- マニュアル・生成スキル

## Out of Boundary

- 属性の構文と保持（`scene-attribute-store`）
- イベントの受け口のシーン探しの規則（`scene-exact-match`）

## Upstream / Downstream

- **Upstream**: `scene-attribute-store`（属性を実行時に読めること）
- **Downstream**: `call-attribute-filter`（絞り込んだ後に残った候補から、この選び方で選ぶ）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `scene-attribute-store`・`call-attribute-filter`（候補の控えのキーと選び方を共有する。同じウェーブに置かない）、`ponytail-core-registry`（`pasta_core` のシーン表を `BTreeMap` に替える。先に入る）

## Constraints

- 規模は 9〜11 タスクの見込み（単語の重みを範囲に入れたため。2026-10-21）。

## 申し送り（2026-11-03・`scene-attribute-store` の要件ディスカッションより）

- **全角の数字は数として読む**（`＆重み：５` は整数 5）。パーサの今の読み方を実行時まで保つ。
- **ファイル属性行の `＆重み`・`＆順番` は、その行より後のそのファイルのグローバルシーンに受け継がれる**（議題 3）。ファイル属性は常に 1 行で、途中に再び書いた行は前の行を丸ごと置き換える（議題 4）。同じ名前の宣言は「書いた順で後が勝つ」で 1 つに畳まれるので、シーン側の `＆重み` が勝つ。ファイル先頭の `＆順番` は後のシーン全部に同じ番号を写すので、この spec の「同じ番号は読み込みエラー」に当たる（作者の書き間違いとして止める）。
- **ローカルシーンは親の属性を受け継がない**（議題 1）。名前なしの `＊` は名前だけを受け継ぎ、`＆重み`・`＆順番` は受け継がない。その代わり `＊＆順番：２０` のように名前なしの `＊` 行にも属性を付記できる（議題 2。開発者の決定）。順番を振った短い候補は `＊ボール巡回＆順番：１０` → `＊＆順番：２０` → `＊＆順番：３０` と書ける。
- Lua からは `SCENE.attrs(global_name, local_name)` で書いた順の配列が読める。Rust のシーン表の型はあちらの設計で決まる。

## 申し送り（2026-11-03・`scene-condition-attributes` の要件・設計ディスカッションより）

- **並びの形が決まった**（開発者の決定）: 候補の並びは、条件で絞らずに名前の全候補で作る。シャッフルの後、`＆優先` の降順に安定に並べ替える。状態は今の「並び＋次の位置」のまま。条件は取り出すときにだけ効かせ、見て漏れた候補もその巡では使ったものとする。巡が尽きたら並びをシャッフルし直す（候補は集め直さない）。やり直しは 1 回の選択で 1 回まで。brief とロードマップにある「外れた札を袋に残す」は改めた。
- **今の段**: 1 回の選択のたびに全候補の条件を評価し、満たす候補の最大の優先を「今の段」とする。今の段より低い札に来たら巡をやり直す。`＆重み`・`＆順番` は、この「今の段の中」に入れる（重み＝札の枚数、順番＝同じ段の中の並べ方）。
- **`＆優先` は独占の意味**: 優先の高い場面が条件を満たしている間は、低い場面は出ない。マニュアルは「優先＝独占・重み＝出やすさ」と書き分ける。
- **API の変更**: `SceneTable::resolve_scene_id_unified`・`resolve_scene_id_exact`・`resolve_global_owning_local_exact` は、`filters` の代わりに述語 `Option<CondFn>`（`&mut dyn FnMut(&SceneInfo) -> bool`）を受ける。`filter_by_attributes`・`SceneCacheKey.filters` は消す。`NoMatchingScene { scene }` は「名前に合うシーンはあるが条件を満たす候補が無い」の意味になる。優先の読み方は `scene_types.rs` の `scene_priority`・`PRIORITY_KEYS`。
- 参照: `.kiro/specs/completed/scene-condition-attributes/design.md`（SceneTable の節・「1 回の選択」の図）、同 `requirements.md` の Requirement 4・5。
