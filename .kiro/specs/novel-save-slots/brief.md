# Brief: novel-save-slots

`/kiro-discovery` で起票（2026-10-10・main `88c4bc0e`）。0.5.0「areka でノベルゲームが作れる」の道筋の 6 番目。

## Problem

ノベルゲームには、スロットを選んで行うセーブとロードが要る。pasta の保存は、1 つのファイルへ終了時に書くだけで、スロットの考え方が無い。セーブの画面は、シェルとして組んで pasta の場面が動かす（2026-10-10 の決定）ので、場面からスロットの中身（いつ・どの章か）を読めなければ、画面を作れない。

## Current State

- 永続化の API は `load()` と `save(data)` の 2 つで、設定した 1 つのパスに結び付いている（`crates/pasta_lua/src/runtime/persistence.rs` 130〜157 行）。`save(x)` を呼ぶと、本体の保存ファイルを上書きする。終了時の保存も同じパスへ書く（`runtime/lifecycle.rs` 24・46 行）。パスを選ぶ口は無い。
- 置き場所は `profile/pasta/save/save.json`。難読化（gzip）の設定がある。書き込みは、一時ファイルへ書いてから名前を替える。
- 宿主が、終了の手続きを踏まずに落ちると、保存されない。

## Desired Outcome

- 遊ぶ人が、スロットを選んでセーブとロードができる。ロードすると、セーブした所の続きから読める。
- 場面から、スロットの一覧と、それぞれの中身（日時・章の名前など）を読める。
- 全セーブ共通の変数は、スロットとは別に保存され、ロードで戻らない。書いたらすぐ保存される。
- セーブは、巻き戻しと同じ仕組みに乗っている。作る物が 1 つで済む。

## Approach

セーブは「直近の区切りの控えを、スロットへ書く」こと、ロードは「スロットの控えを読んで、その区切りへ戻す」ことである。戻した後は、巻き戻しと同じく、控えた台本を目印の位置から切り出して返す（`novel-checkpoint-rollback`）。

セーブ画面の例（記法は仮）:

```pasta
＊セーブ画面
    ％セーブ画面

    ・slot1
        ！セーブ（1）
        ＞セーブ画面
    ・back
        ！画面を閉じる
```

エレメントのクリックは、選択肢と同じ振り分けで場面に届く（`shell-element-click`）。

要件定義で決めること。

- **スロットの持ち主**: 1 つのスロットは、pasta の側の控え（状態と台本）と、areka の側の控え（画面と音・直近の ID・縮小画像）の 2 つで出来る。番号で結び付けて別々に持つか、どちらかが相手の控えを預かるか。
- **セーブとロードの起こし方**: 場面からの命令（`！セーブ（1）`）で起こすか、areka からのイベントで起こすか。両方か。
- **スロットの中身を読む口**: 日時・章の名前・自由な一言を、場面からどう読むか。章の名前を、どこから取るか（柱の属性か、変数か）。
- **保存の場所と形**: スロットのファイルの名前、難読化の設定との関係、書き込みの途中で落ちたときの扱い。
- **オートセーブとクイックセーブ**: 入れるかどうか。
- **台本を直した後の古いセーブ**: 控えた台本をそのまま返すので、続きは読める。その先で、消えた場面を呼んだときの見え方（`failure-output-unification`）。
- **全セーブ共通の変数の保存**: 書いたらすぐ保存するか、区切りごとか。

## Scope

- **In**: スロットへの読み書きの API（Rust と Lua）。セーブとロードの命令またはイベントの処理。スロットの一覧と中身を読む口。全セーブ共通の変数の保存。テスト、マニュアル、スキル references の再生成。
- **Out**: セーブ画面の見た目と配置（シェル。見本は `hello-novel-sample`）。画面と音の控え・縮小画像（areka）。区切りの控えの中身（`novel-checkpoint-rollback`）。

## Boundary Candidates

- 永続化（`runtime/persistence.rs`・`lifecycle.rs`・`pasta_scripts/pasta/save.lua`）。
- セーブとロードの入口（命令またはイベント）。
- スロットの情報を読む Lua の口。

## Out of Boundary

- エレメントのクリックの振り分け（`shell-element-click`）。
- CG 鑑賞・回想・音楽室。全セーブ共通の変数があれば作者が組めるので、専用の仕組みは作らない。

## Upstream / Downstream

- **Upstream**: `novel-checkpoint-rollback`（区切りの控えと、変数の保存の範囲）、`novel-areka-contract`（セーブとロードの命令・イベントの名前）。
- **Downstream**: `hello-novel-sample`（セーブ・ロードの画面の見本）、`manual-novel-guide`。

## Existing Spec Touchpoints

- **Extends**: なし。
- **Adjacent**: `.kiro/specs/completed/pasta-config-restructure/`（`[persistence]` の設定）、`pasta-check-dic-validate`（`pasta_check release` が配布物に `profile/` を入れない決まり）。

## areka への依頼

- スロットごとに、areka の側の控え（画面と音・直近の ID）を持つ。
- 画面を画像に撮る（縮小画像）。エレメントの絵を、その画像に差し替える。
- ロードのとき、控えた画面と音を、演出なしで即時に再現する（巻き戻しと同じ）。

要件が固まったら、取り決めの文書へ書き、areka のセッションへ知らせる。手順は `novel-areka-contract` の brief の「依頼の出し方」。

## Constraints

- 今のゴーストの保存（1 つのファイル・終了時）を変えない。
- 書き込みは、今と同じく、一時ファイルへ書いてから名前を替える。
- セーブのファイルは、利用者の `profile/` の下に置く。配布物に入れない。
