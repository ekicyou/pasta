# Brief: novel-save-slots

`/kiro-discovery` で起票（2026-10-10・main `88c4bc0e`）。0.5.0「areka でノベルゲームが作れる」の道筋の 6 番目。

## Problem

ノベルゲームには、スロットを選んで行うセーブとロードが要る。pasta の保存は、1 つのファイルへ終了時に書くだけで、スロットの考え方が無い。セーブの画面は、シェルとして組んで pasta の場面が動かす（2026-10-10 の決定）ので、場面からスロットの中身（いつ・どの章か）を読めなければ、画面を作れない。

## Current State

- 永続化の API は `load()` と `save(data)` の 2 つで、設定した 1 つのパスに結び付いている（`crates/pasta_lua/src/runtime/persistence.rs` 130〜157 行）。`save(x)` を呼ぶと、本体の保存ファイルを上書きする。終了時の保存も同じパスへ書く（`runtime/lifecycle.rs` 24・46 行）。パスを選ぶ口は無い。
- 置き場所は `profile/pasta/save/save.json`。難読化（gzip）の設定がある。書き込みは、一時ファイルへ書いてから名前を替える。
- 宿主が、終了の手続きを踏まずに落ちると、保存されない。

## Desired Outcome

- 遊ぶ人が、スロットを選んでセーブとロードができる。ロードすると、セーブした所の続きから読める。
- 場面から、スロットの一覧と、それぞれの中身（日時・章の名前など）を読める。
- 全セーブ共通の変数は、スロットとは別に保存され、ロードで戻らない。書いたらすぐ保存される。
- セーブは、巻き戻しと同じ仕組みに乗っている。作る物が 1 つで済む。

## Approach

セーブは「直近の区切りの控えを、スロットへ書く」こと、ロードは「スロットの控えを読んで、その区切りへ戻す」ことである。戻した後は、巻き戻しと同じく、控えたさくらスクリプトを目印の位置から切り出して返す（`novel-checkpoint-rollback`）。

セーブ画面の例（記法は仮）:

```pasta
＊セーブ画面
    ％セーブ画面

    ・slot1
        ！セーブ（1）
        ＞セーブ画面
    ・back
        ！画面を閉じる
```

エレメントのクリックは、選択肢と同じ振り分けで場面に届く（`shell-element-click`）。

要件定義で決めること。

- **スロットの持ち主**: 1 つのスロットは、pasta の側の控え（状態とさくらスクリプト）と、areka の側の控え（画面と音・直近の ID・縮小画像）の 2 つで出来る。番号で結び付けて別々に持つか、どちらかが相手の控えを預かるか。
- **セーブとロードの起こし方**: 場面からの命令（`！セーブ（1）`）で起こすか、areka からのイベントで起こすか。両方か。
- **スロットの中身を読む口**: 日時・章の名前・自由な一言を、場面からどう読むか。章の名前を、どこから取るか（柱の属性か、変数か）。
- **保存の場所と形**: スロットのファイルの名前、難読化の設定との関係、書き込みの途中で落ちたときの扱い。
- **オートセーブとクイックセーブ**: 入れるかどうか。
- **台本を直した後の古いセーブ**: 控えたさくらスクリプトをそのまま返すので、続きは読める。その先で、消えた場面を呼んだときの見え方（`failure-output-unification`）。
- **全セーブ共通の変数の保存**: 書いたらすぐ保存するか、区切りごとか。

## Scope

- **In**: スロットへの読み書きの API（Rust と Lua）。セーブとロードの命令またはイベントの処理。スロットの一覧と中身を読む口。全セーブ共通の変数の保存。テスト、マニュアル、スキル references の再生成。

### スロット変数

- **セーブデータは pasta だけが持つ**（開発者の決定）。ベースウェアの側の控えは作らない。
- 変数の種類も文法も足さない。**スロット変数は、名前が「スロット」か `slot_` で始まるグローバル変数である**（`＄＊スロット好感度`）。これだけが、スロットに出し入れされ、ロードと巻き戻しで戻る。
- ほかのグローバル変数は、今の `save.toml` のままで、スロットに入らず、ロードで戻らない（全セーブ共通。見た結末や、設定の値を持つ）。
- 2 つの頭は印が 2 種類あるだけで、`スロット好感度` と `slot_好感度` は別の変数である。英字の頭は下線まで含める（`slots` などを巻き込まない）。
- 「スロット」は、作者向けの言葉としては初出である（マニュアルに無い）。立ち位置の「スポット」と 1 字違いである。

### 関数

場面から呼ぶ、組み込みの関数にする（`＞自動トーク停止` と同じ流儀。日本語と英字の対）。

| 日本語 | 英字 | すること |
| ------ | ---- | -------- |
| `スロット保存` | `slot_save` | いちばん新しい控えを、指定のスロットへ書く |
| `スロット読込` | `slot_load` | 指定のスロットの控えへ戻る |
| `スロット消去` | `slot_clear` | 今のスロット変数を全部消す（「はじめから」に使う） |
| `スロット参照` | `slot_get` | 読み込まずに、スロットの中の変数を 1 つ読む（セーブ画面の見出しに使う） |

```pasta
＊セーブ画面
    ・slot1
        ＞スロット保存（１）
```

- スロットの指定は、番号でも名前でも受ける（`＞スロット保存（「オート」）`）。オートセーブとクイックセーブに、専用の仕組みを作らない。
- セーブ画面の見出しは、作者が決めたスロット変数で持つ（`＄＊スロット章＝「第一章」` と書き、セーブ画面は `スロット参照` で読む）。空のスロットは、`スロット参照` が値なしを返すことで分かる。

### スロットに入るもの

開発者: 「変数と再生位置（シーン）とアクター状態が戻る」

- スロットには、**いちばん新しい控え**が入る: 再生位置（今のシーンの名前と行の番号）・スロット変数・ローカル変数・アクター状態（`novel-checkpoint-rollback` の「控えと、戻り方」）。控えの履歴は入れない。
- 控えは、1 本の始まりの状態で、1 本の途中でシーンに着いたら取り直される。だから、**シーンの頭に書いた `＞スロット保存` は、そのシーンの頭から続く。** 行が待っている間の保存（設定の画面から）は、待っている行から続く（その行が、ト書きごともう一度再生される）。
- **ロードは、バックログの行を選んだときと、同じ仕組みである。**
- 演劇でないとき（控えが無いとき）の `スロット保存` は、今のスロット変数だけを書く（続きの場所は無い）。
- 写し取る・戻す口は、`novel-checkpoint-rollback` が作る 2 つの関数を使う。
- 【承認待ち】曲・環境の音・舞台などの「残る」値も、控えと一緒に入れる（骨子 4 章の B）。設定やセーブの画面の中（`＞演劇中断` の間）から保存したときは、中断した行の控えが入る（骨子 4 章の C）。

### 置き場所

**スロットは `save.toml` の中に持つ**（開発者の決定）。グローバル変数の表（`pasta.save`）の中の、エンジン予約の表（仮 `pasta_slots`）に、スロットの名前をキーにして入れる。スロットごとの別ファイルは作らない。

```toml
"スロット好感度" = 5
"クリアＡ" = true

[pasta_slots.1]
"スロット好感度" = 3
"スロット章" = "第一章"

[pasta_slots."オート"]
"スロット好感度" = 5
```

- 保存の新しい仕組みを作らない。関数は、表の中で値を深く写すだけの Lua になる。スロット用のファイルを読み書きする Rust の口は要らない（`persistence.rs`・`lifecycle.rs` は触らない見込み）。入れ子の表は、今の保存でそのまま書ける（32 段まで）。
- **`スロット保存` は、表に写した後、その場で `save.toml` を書く**（既存の `persistence.save(save)` を 1 回呼ぶ）。終了時にしか書かない今のままだと、セーブを押した後の強制終了でセーブが消えるためである。
- **スロットの名前は文字列にそろえる。** `＞スロット保存（１）` の `１` はキー `"1"` にする。番号の `1` と名前の `「1」` は同じスロットになる。
- 表の名前は、エンジン予約の `pasta_` で始める。名前が「スロット」・`slot_` で始まらないので、スロット変数には数えない。
- 引き換えに失うもの: `save.toml` が読めなくなると、全スロットを一度に失う。スロット 1 つだけを写して持ち運ぶことはできない。作者から見える形は置き場所に依らないので、要るようになったら別ファイルへ切り替えられる。

### 要件定義へ送ること

- 台本を直した後の古いセーブで、行の番号がずれたとき・行の数を超えたときの扱い。シーンの名前が残っていれば、ロードそのものはできる。
- `スロット参照` を式の中から呼ぶ書き方が、今の文法で通るか。
- 「スロットにセーブが在るか」を、シーンや選択肢の条件に書ける形（「つづきから」を出し分けるため。「ぱすた開発」の台本は、今は自分の変数で印を立てている）。
- 全セーブ共通の変数の保存は、`スロット保存` のたびに `save.toml` が書かれることで足りるか。
- 早回し（ロード・巻き戻し）の間は、`スロット保存` を実行しない（シーンの頭に `＞スロット保存（「オート」）` を書く形が在るため。`novel-checkpoint-rollback`）。
- 規模は 4〜5 ほどの見込み（置き場所が `save.toml` の中に決まったため）。
