# Brief: novel-save-slots

`/kiro-discovery` で起票（2026-10-10・main `88c4bc0e`）。0.5.0「areka でノベルゲームが作れる」の道筋の 6 番目。

## Problem

ノベルゲームには、スロットを選んで行うセーブとロードが要る。pasta の保存は、1 つのファイルへ終了時に書くだけで、スロットの考え方が無い。セーブの画面は、シェルとして組んで pasta の場面が動かす（2026-10-10 の決定）ので、場面からスロットの中身（いつ・どの章か）を読めなければ、画面を作れない。

## Current State

- 永続化の API は `load()` と `save(data)` の 2 つで、設定した 1 つのパスに結び付いている（`crates/pasta_lua/src/runtime/persistence.rs` 130〜157 行）。`save(x)` を呼ぶと、本体の保存ファイルを上書きする。終了時の保存も同じパスへ書く（`runtime/lifecycle.rs` 24・46 行）。パスを選ぶ口は無い。
- 置き場所は `profile/pasta/save/save.json`。難読化（gzip）の設定がある。書き込みは、一時ファイルへ書いてから名前を替える。
- 宿主が、終了の手続きを踏まずに落ちると、保存されない。

## Desired Outcome

- 遊ぶ人が、スロットを選んでセーブとロードができる。ロードすると、セーブした所の続きから読める。
- 場面から、スロットの一覧と、それぞれの中身（日時・章の名前など）を読める。
- 全セーブ共通の変数は、スロットとは別に保存され、ロードで戻らない。書いたらすぐ保存される。
- セーブは、巻き戻しと同じ仕組みに乗っている。作る物が 1 つで済む。

## Approach

セーブは「直近の区切りの控えを、スロットへ書く」こと、ロードは「スロットの控えを読んで、その区切りへ戻す」ことである。戻した後は、巻き戻しと同じく、控えた台本を目印の位置から切り出して返す（`novel-checkpoint-rollback`）。

セーブ画面の例（記法は仮）:

```pasta
＊セーブ画面
    ％セーブ画面

    ・slot1
        ！セーブ（1）
        ＞セーブ画面
    ・back
        ！画面を閉じる
```

エレメントのクリックは、選択肢と同じ振り分けで場面に届く（`shell-element-click`）。

要件定義で決めること。

- **スロットの持ち主**: 1 つのスロットは、pasta の側の控え（状態と台本）と、areka の側の控え（画面と音・直近の ID・縮小画像）の 2 つで出来る。番号で結び付けて別々に持つか、どちらかが相手の控えを預かるか。
- **セーブとロードの起こし方**: 場面からの命令（`！セーブ（1）`）で起こすか、areka からのイベントで起こすか。両方か。
- **スロットの中身を読む口**: 日時・章の名前・自由な一言を、場面からどう読むか。章の名前を、どこから取るか（柱の属性か、変数か）。
- **保存の場所と形**: スロットのファイルの名前、難読化の設定との関係、書き込みの途中で落ちたときの扱い。
- **オートセーブとクイックセーブ**: 入れるかどうか。
- **台本を直した後の古いセーブ**: 控えた台本をそのまま返すので、続きは読める。その先で、消えた場面を呼んだときの見え方（`failure-output-unification`）。
- **全セーブ共通の変数の保存**: 書いたらすぐ保存するか、区切りごとか。

## Scope

- **In**: スロットへの読み書きの API（Rust と Lua）。セーブとロードの命令またはイベントの処理。スロットの一覧と中身を読む口。全セーブ共通の変数の保存。テスト、マニュアル、スキル references の再生成。
- **Out**: セーブ画面の見た目と配置（シェル。見本は `hello-novel-sample`）。画面と音の控え・縮小画像（areka）。区切りの控えの中身（`novel-checkpoint-rollback`）。

## Boundary Candidates

- 永続化（`runtime/persistence.rs`・`lifecycle.rs`・`pasta_scripts/pasta/save.lua`）。
- セーブとロードの入口（命令またはイベント）。
- スロットの情報を読む Lua の口。

## Out of Boundary

- CG 鑑賞・回想・音楽室。全セーブ共通の変数があれば作者が組めるので、専用の仕組みは作らない。

## Upstream / Downstream

- **Downstream**: `hello-novel-sample`（セーブ・ロードの画面の見本）、`manual-novel-guide`。

## Existing Spec Touchpoints

- **Adjacent**: `.kiro/specs/completed/pasta-config-restructure/`（`[persistence]` の設定）、`pasta-check-dic-validate`（`pasta_check release` が配布物に `profile/` を入れない決まり）。

## areka への依頼

- スロットごとに、areka の側の控え（画面と音・直近の ID）を持つ。
- 画面を画像に撮る（縮小画像）。エレメントの絵を、その画像に差し替える。
- ロードのとき、控えた画面と音を、演出なしで即時に再現する（巻き戻しと同じ）。

要件が固まったら、取り決めの文書へ書き、areka のセッションへ知らせる。手順は `novel-areka-contract` の brief の「依頼の出し方」。

## Constraints

- セーブのファイルは、利用者の `profile/` の下に置く。配布物に入れない。

## 決定（2026-11-19 の discovery「ノベルゲームの深掘り」）

- **セーブデータは pasta だけが持つ**（開発者の決定）。スロットに入るのは、名前が「スロット」か `slot_` で始まるグローバル変数（`＄＊スロット好感度`）と、区切りの控えである。ほかのグローバル変数は今の `save.toml` のままで、スロットに入らず、ロードで戻らない（全セーブ共通）。変数の種類も文法も足さない。
- **スロットの出し入れは、場面から呼ぶ関数で行う**（開発者の決定）。`自動トーク停止` と同じく、`＞関数名（引数）` で呼ぶ組み込みの関数にする。関数は 4 つある（下の「関数」）。

```pasta
＊セーブ画面
    ・slot1
        ＞スロット保存（１）
```

- 写し取る・戻す口は、`novel-checkpoint-rollback` が作る 2 つの関数を使う。`novel-variable-scope` は閉じた（roadmap の「統合して閉じたもの（2026-11-19）」）。上の「申し送り（2026-10-17 の棚卸の分割より）」の `novel-variable-scope` は、この節と読み替える。
- 「Approach」の「セーブとロードの起こし方」は、場面からの関数に決まった。「スロットの持ち主」のうち pasta の側は決まった。areka の側の控えを持つかは、同じ discovery の取り決めの回で決める。
- 関数の名前・ロードの後の台本の続け方・ファイルの置き場所は、巻き戻しとセーブの回で決めて、この節に書き足す。
- 「スロット」は、作者向けの言葉としては初出である（マニュアルに無い）。立ち位置の「スポット」と 1 字違いである。

### 関数（2026-11-19。開発者の承認）

日本語と英字の名前を対で持つ（`自動トーク停止`／`pause_auto_talk` と同じ流儀）。名前は仮で、形は決まり。

| 日本語 | 英字 | すること |
| ------ | ---- | -------- |
| `スロット保存` | `slot_save` | 今のスロット変数を、指定のスロットへ書く |
| `スロット読込` | `slot_load` | 指定のスロットの中身で、今のスロット変数を全部置き換える |
| `スロット消去` | `slot_clear` | 今のスロット変数を全部消す（「はじめから」に使う） |
| `スロット参照` | `slot_get` | 読み込まずに、スロットの中の変数を 1 つ読む（セーブ画面の見出しに使う） |

- スロット変数とは、名前が「スロット」か `slot_` で始まるグローバル変数のこと。2 つの頭は印が 2 種類あるだけで、`スロット好感度` と `slot_好感度` は別の変数である。英字の頭は下線まで含める（`slots` などを巻き込まない）。
- スロットの指定は、番号でも名前でも受ける（`＞スロット保存（「オート」）`）。オートセーブとクイックセーブに専用の仕組みを作らない（「Approach」の「オートセーブとクイックセーブ」はこれで足りる）。
- セーブ画面の見出しは、作者が決めたスロット変数で持つ（`＄＊スロット章＝「第一章」` と書き、セーブ画面は `スロット参照` で読む）。章の名前を取る専用の決まりを作らない（「Approach」の「スロットの中身を読む口」はこれで決まった）。空のスロットは、`スロット参照` が値なしを返すことで分かる。
- `スロット参照` を式の中から呼ぶ書き方が今の文法で通るかは、確かめていない。

### 続きの場所（2026-11-19。保留）

- 決まっているのは 1 つだけ: **スロットに、続きの場所を表す何らかのマーキング文字列を保存する**（開発者の決定）。
- マーキング文字列の中身（何を指すか・誰が作るか・ロードの後にどう続けるか）は、バックログの取り方に依るので、保留にした。バックログと巻き戻しの議論で一緒に決める。
- discovery で出た案（決まっていない。材料として残す）: 直前に返した物語の台本そのものを、予約のスロット変数に入れる。場面を走り直さないので、変数の二重の加算と、乱数の言い回しの変化が起きない。場面の名前だけを覚えて走り直す案は、その 2 つが起きる。
- 物語でない場面（タイトル・セーブ画面）の見分け方も、同じ議論まで保留。

### 置き場所（2026-11-19。開発者の決定）

**スロットは `save.toml` の中に持つ。** グローバル変数の表（`pasta.save`）の中の、エンジン予約の表（名前は仮に `pasta_slots`）に、スロットの名前をキーにして入れる。スロットごとの別ファイルは作らない。

```toml
"スロット好感度" = 5
"クリアＡ" = true

[pasta_slots.1]
"スロット好感度" = 3
"スロット章" = "第一章"

[pasta_slots."オート"]
"スロット好感度" = 5
```

- 上の 2 行が今の値、`[pasta_slots.…]` がスロットに控えた値である。
- 保存の新しい仕組みを作らない。4 つの関数は、表の中で値を深く写すだけの Lua になる。スロット用のファイルを読み書きする Rust の口は要らない（「Scope」の「スロットへの読み書きの API（Rust と Lua）」は Lua だけになる。`persistence.rs`・`lifecycle.rs` は触らない見込み）。
- 入れ子の表は、今の保存でそのまま書ける（32 段まで。`crates/pasta_lua/src/runtime/persistence.rs`・`book/src/lua/modules/pasta-persistence.md`。2026-11-19 に確かめた）。
- **`スロット保存` は、表に写した後、その場で `save.toml` を書く**（既存の `persistence.save(save)` を 1 回呼ぶ）。終了時にしか書かない今のままだと、セーブを押した後の強制終了でセーブが消えるためである。グローバル変数の全部が一緒に書かれるので、全セーブ共通の変数も、セーブのたびにファイルへ届く（「Approach」の「全セーブ共通の変数の保存」は、これで足りるかを要件で確かめる）。
- **スロットの名前は文字列にそろえる**。`＞スロット保存（１）` の `１` はキー `"1"` にする。数のままだと、TOML に書くときに配列と表のどちらになるかが番号の並びで変わるためである。番号の `1` と名前の `「1」` は同じスロットになる。
- 表の名前は、エンジン予約の `pasta_` で始める（作者の `＄＊slot` とぶつけない）。名前が「スロット」・`slot_` で始まらないので、スロット変数には数えない。
- 引き換えに失うもの: `save.toml` が読めなくなると、全スロットを一度に失う（今のグローバル変数と同じ危うさ。書き込みは一時ファイルへ書いてから名前を替える）。スロット 1 つだけを写して持ち運ぶことはできない。作者から見える形（スロット変数と 4 つの関数）は置き場所に依らないので、要るようになったら別ファイルへ切り替えられる。
- 「Approach」の「保存の場所と形」はこれで決まった。規模は 8〜12 から 4〜5 ほどに減る見込み。

### 続きの場所（2026-11-19 の続き。保留を解いた）

- 巻き戻しの方式が「シーンの頭で控えて、そこから走り直す」に決まった（`novel-checkpoint-rollback` の「巻き戻しの方式」。開発者の決定）。**マーキング文字列は、シーンの名前である。** スロットには、直近の目印の控え 1 つ分（シーンの名前・着いた時点のスロット変数・着いた時点のローカル変数）が入る。
- `スロット保存` が書くスロット変数は、今の値ではなく、**直近の目印に着いた時点の値**になる（今の値は、そのシーンが走り終えた後の値だからである。ロードでシーンを頭から走り直すと、今の値へ進む）。上の「関数」の表の「今のスロット変数を、指定のスロットへ書く」は、こう読み替える。
- `スロット読込` は、変数を戻してから、そのシーンを頭から走らせる。
- 上の「続きの場所（保留）」の「台本そのものを予約のスロット変数に入れる」案は採らない。
- 直近の目印を pasta が正しく知るには、ジャンプのたびに台本を区切って返す必要がある。これはまだ決まっていない。
