# Implementation Plan

部品の名前（HighlightsDoc・VerifyTag・ReleaseNotes・GithubRelease・ReleaseYml・ScriptsTest・HighlightsCheck・PretagCheck・ReleaseSkillDocs・Docs・V038Retrofit）、ファイルの場所、コマンド、合否の基準は、`design.md` にある。タスクは、部品の名前でそれを指す。

## 進め方の約束

- タスク 1〜6.2 は、作業ブランチの中だけで行う。外に見える変更（main への統合・公開済みのページの編集）を行うのは、タスク 6.3 だけである。
- スキルを編集するタスク（4.1・4.2・4.3・4.4・5.2）とタスク 6.3 は、**開発者の許可・承認を得てから**、メインの文脈で行う。サブエージェントへ任せない。許可の判定に拒まれたら、別の手段を試さず、入った分と残りを開発者に示して止まる。
- `release` スキルの直し（タスク 4.1〜4.4）が入らないまま、リリース CI の側（タスク 2）だけを main へ入れない。
- リリース（`/release`）が実行中の間は、タスク 6.3 の main への統合を行わない。
- `.kiro/specs/completed/release-ci/` の下と、`.claude/settings.json` を変えない。完了した spec `release-workflow`（`.kiro/specs/completed/release-workflow/`）の文書を変えない。
- Rust のコードを変えない。`cargo test`・clippy の対象は増えない。

## Implementation Notes
