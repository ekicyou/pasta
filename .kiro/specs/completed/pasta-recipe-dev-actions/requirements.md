# Requirements Document

## Project Description (Input)

**誰が困っているか**: `pasta-recipe` で辞書を書くゴーストの作者。

**今の状況**: `pasta-recipe` は編集・色分け・診断・検査はできるが、書いたシーンを鳴らして確かめる手段が無い。作者は結局 SSP の右クリックや VS Code に戻ることになる（`pasta-recipe` の完了のとき、開発者が実物を触って最初に「シーン再生とかの機能は実装されていないのか？」と尋ねた）。VS Code 拡張には、シーンの実行・SHIORI のリロード・保存変数の表示があるが、VS Code の外では使えない。作者からは、グローバル変数（`＄＊`）をその場で書き換えたい・シーンを呼ぶときにローカル変数を入れてから鳴らしたい、とも求められている。

**何を変えるか**: `pasta-recipe` に、シーンの ▶（ツリーとエディタの見出し）・SHIORI のリロード・出力の欄・保存変数の表（表示・書き換え・削除）・ローカル変数を入れて鳴らす窓を足す。実行の流れ（MCP の頼み・相手の探し方・読み込み直しの待ち方・台本の取り出し・保存変数の書き出しの読み取り）は VS Code 拡張から共有の 1 本へ移し、拡張とアプリが同じものを使う。拡張の振る舞いは変えない。版は 0.5.3。

## Introduction

`pasta-recipe` から、開いているゴーストを動かせるようにする。流れは VS Code 拡張の「▶ シーンを実行」と同じで、アプリはその流れの入出力（ベースウェアへの頼みとゴーストのファイルの読み取り）を自分で受け持つ。

```text
ツリーのシーン「＊挨拶」で ▶ シーンを実行
  → 未保存のタブを保存
  → SHIORI の読み込み直し（pasta.log の読み込みの終わりの行を待つ・誤りがあれば止める）
  → OnPastaSceneAt  Reference0=C:\…\hello\ghost\master\dic\挨拶.pasta  Reference1=3
  → 出力の欄に「台本: \0\s[0]こんにちは。\e」

「値を入れて実行…」で ＄天気＝雨（文字列）・＄回数＝3（数）を入れる
  → OnPastaSceneAt  …  Reference2={ "天気" = "雨", "回数" = 3 }

保存変数の表で ＄＊pasta_talk_interval_min を 60 → 10（数）に書き換える
  → OnPastaSetSaveVariable  Reference0=pasta_talk_interval_min  Reference1=10  Reference2=number
  → 表を読み直して 10 を出す（ファイルへはランタイムの終了時に書かれる）
```

> **discovery の決定**: 実行の流れは拡張と共有の 1 本にし、入出力だけをそれぞれが差し込む（2026-11-12 開発者の承認）。ローカル変数を受ける口は `scene-play-locals`（実装済み）が持ち、この spec は入力の画面とその口を呼ぶことだけを持つ。

> **brief の読み直し**: brief の Constraints の「`OnPastaSetSaveVariable` はデバッグが有効なときだけ効く」は誤り（brief の 2026-11-12 の再測定のとおり、`external_control.lua` はデバッグの有無によらず働き、SecurityLevel が external のときだけ何もしない）。この要件は正しいほうで書いた。デバッグが要るのは `OnPastaSceneAt`・`OnPastaDumpVariables`。

### 要件ディスカッションで決めたこと（2026-11-13 開発者の承認）

brief で決まっていなかった点は、次のとおり決めた。

- 保存変数の表に、表に無い名前の**追加**も入れる（マニュアルの使い道の例 `＄＊pasta_talk_interval_min` は、まだ保存されていないことが多い）。追加と書き換え・削除の操作は、表を読めたときだけ出す（書き換えはデバッグによらず働くが、結果を表で確かめられない書き換えは出さない）。7.4・7.5・7.11。
- 保存変数の表は、押したとき・書き換えの後に読むほか、表を出している間は ▶（値を入れて実行も含む）で鳴らした後にも読み直す。ゴーストを開いただけでは読まない。6.8・6.9。
- 「値を入れて実行…」の組は、アプリを閉じるまでシーンごとに覚える（ファイルに残さない）。8.10。

次の点は、議題にせずに閉じた。

- 削除は確かめてから送る・「値を入れて実行…」の入口は ▶ と同じ 2 か所・知らせは出力の欄の中（アプリに通知の仕組みは無い）・保存の範囲は拡張と同じ（流れを 1 本にするので揃う）。
- 送る前に弾く（8.6〜8.8）。数として読めない値と名前の重なりは TOML のインライン表にならず、組み立てる側で止めるしかない。名前はランタイムと同じ決まりで先に弾き、遅い往復（保存 → 読み込み直し → 再生）の前に分かるようにする。
- 操作の途中のゴーストの切り替えは、待つか、操作を前のゴーストに閉じ込めるかは設計で決める。要件は「結果を混ぜない」ことだけにした（5.2）。

## Boundary Context

- **In scope**:
  - `pasta-recipe` の 5 つの画面: シーンの ▶（ツリー・エディタの見出し）・SHIORI のリロード・出力の欄・保存変数の表（表示・書き換え・削除・追加）・ローカル変数を入れて鳴らす窓。
  - 送る相手のベースウェア（SSP・areka）の探し方と選び方（拡張と同じ）。
  - 実行の流れを拡張とアプリで 1 本にすること。拡張は共有のものへ差し替えるが、振る舞いは変えない。
  - `pasta-recipe` のつなぐ先と読む範囲の広がり（127.0.0.1 のベースウェアへの頼み・`profile` の下の 2 つのファイルの読み取り）。
  - マニュアルの `pasta-recipe` の章と、試験。
- **Out of scope**:
  - ランタイムの変更（`OnPastaSceneAt`・`OnPastaSetSaveVariable`・`OnPastaDumpVariables` と、Reference2 を受ける側。`scene-play-locals` が持つ）。
  - VS Code 拡張への新しい機能（保存変数の書き換え・ローカル変数を入れた実行を拡張に足すかは、別に決める）。
  - `OnPastaScene`（名前で鳴らす）の画面。
  - 表（テーブル）の値の保存変数の書き換え（`OnPastaSetSaveVariable` が扱うのは文字列・数・真偽だけ。表は見るだけ）。
  - `pasta-recipe` のエディタ・ツリー・保存・単一インスタンスの仕組みそのもの（`pasta-recipe` が持つ）。別の窓や別の起動の口は足さない。
- **Adjacent expectations**:
  - ランタイムは、`OnPastaSceneAt`・`OnPastaDumpVariables` をデバッグが有効なとき（`pasta.toml` の `[debug] enabled = true`）だけ受ける。`OnPastaSetSaveVariable` はデバッグの有無によらず働く。どれも SecurityLevel が external のときは何もしない（204）。
  - Reference2 の書き方と誤りの表記は、マニュアル `book/src/lua/shiori-events.md` の「シーンを再生するイベントの共通の決まり」の「ローカル変数を入れる（Reference2）」が正本。
  - ベースウェアの MCP の窓口（SSP・areka）が有効で、そのベースウェアが開いているゴーストを動かしていること。

## Requirements

### Requirement 1: シーンを ▶ で鳴らす

**Objective:** As a ゴーストの作者, I want 書いたシーンを `pasta-recipe` からその場で鳴らしたい, so that VS Code や SSP の右クリックに戻らずに確かめられる

#### Acceptance Criteria

1. When ツリーのシーン（グローバル・ローカル）の行で「▶ シーンを実行」を選んだとき, the アプリ shall そのシーンを、保存 → SHIORI の読み込み直し → `OnPastaSceneAt` → 出力の欄に台本、の順で鳴らす。
2. When タブで開いた `.pasta` の、シーンの見出し（グローバル・ローカル）の上の「▶ シーンを実行」を押したとき, the アプリ shall 1 と同じ流れで、その見出しのシーンを鳴らす。
3. The アプリ shall `OnPastaSceneAt` に、ファイルの絶対パス（Reference0）と見出しの行（Reference1。1 から数える）を、拡張と同じ形で送る。
4. The アプリ shall 送る行を、保存した中身での、その見出しの今の行にする（書き換えた直後に押しても、書き換える前の行を送らない。タブで開いていないファイルはディスクの中身の行）。
5. When 鳴らす前に未保存の書き換えのあるタブがあるとき, the アプリ shall 開いているゴーストの `.pasta`・`.lua`・`pasta.toml` の未保存のタブを全部保存してから、読み込み直しを頼む（拡張と同じ範囲）。
6. If 保存できなかったタブが 1 つでもあるとき, the アプリ shall 読み込み直しも再生も頼まず、保存できなかったファイルを出力の欄に並べて止める。
7. If 読み込み直しを頼めなかった・読み込みの終わりを確かめられなかった・`loaded=false` だった・誤りが 1 件以上出たとき, the アプリ shall シーンを鳴らさず、その理由と誤り・警告の中身を出力の欄に出す（拡張と同じ止め方と文言）。
8. When ゴーストが台本を返したとき, the アプリ shall 台本を出力の欄に出す。
9. When `OnPastaSceneAt` の応答が無かったとき, the アプリ shall 拡張と同じく、送る前より後の再生の記録から台本を上限の時間まで探し、見つかれば「再生の記録から」と添えて出し、見つからなければ台本を確かめられなかったことと最後の理由を出す。
10. When ゴーストが台本を返さなかったとき（204）, the アプリ shall デバッグを有効にする案内（`pasta.toml` に `[debug] enabled = true` を書いてリロード）と、その再生の間に増えた `pasta.log` の `OnPastaSceneAt:` の警告を出力の欄に出す。
11. When ゴーストが失敗の表記（`【シーンが見つからない：…】` など）を台本として返したとき, the アプリ shall それを台本として出力の欄に出す（アプリで読み替えない）。

### Requirement 2: SHIORI をリロード

**Objective:** As a ゴーストの作者, I want 辞書を直した後に SHIORI を読み込み直したい, so that 誤りの有無を、シーンを鳴らさずに確かめられる

#### Acceptance Criteria

1. When ツールバーの「SHIORI をリロード」を押したとき, the アプリ shall Requirement 1.5・1.6 と同じく未保存のタブを保存してから、SHIORI の読み込み直しを頼み、`pasta.log` の読み込みの終わりの行を待って、誤りと警告の件数と中身を出力の欄に出す（拡張と同じ要約）。
2. The アプリ shall リロードではシーンを鳴らさない。
3. If `pasta.log` を読めなかったとき, the アプリ shall ベースウェアの誤りの記録だけで要約したことと、読もうとした場所を出す（拡張と同じ）。
4. If `pasta.toml` の `[logging] file_path` を読めない・`profile/` の下のファイルでないとき, the アプリ shall 既定の `profile/pasta/logs/pasta.log` を読み、そのことを出力の欄に添える（拡張と同じ）。
5. While ゴーストを開いていないとき, the アプリ shall リロードのボタンを出さない（開始の画面のツールバーには並べない）。

### Requirement 3: 送る相手のベースウェア

**Objective:** As a ゴーストの作者, I want 開いているゴーストを動かしているベースウェアへ、迷わず頼みが届いてほしい, so that SSP と areka のどちらでも同じに使える

#### Acceptance Criteria

1. When 開発の操作（▶・値を入れて実行・リロード・保存変数の表示・書き換え・削除・追加）を始めたとき, the アプリ shall 拡張と同じ候補のポート（127.0.0.1 の 9801・9821・9802・9822・…・9810・9830）を一度に尋ね、開いているゴーストを動かしているベースウェアを探す。
2. The アプリ shall 開いているゴーストのルート（`ghost/master` の 2 つ上）の絶対パスで、ゴーストを指名する（拡張と同じ）。
3. If 1 つも見つからないとき, the アプリ shall 何も送らず、見つからないことと確かめること（ベースウェアでこのゴーストを起動しているか・ベースウェアの MCP の窓口が有効か）を出力の欄に出す。
4. When 2 つ以上のベースウェアが見つかったとき, the アプリ shall ベースウェアの名前とポートを並べて選ばせ、選ばずに閉じたら何も送らない。
5. The アプリ shall 選んだ相手を、アプリを閉じるまでゴーストごとに覚え、次の操作では 1 回の問い合わせで確かめ、名前が変わった・応えないときは探し直す（覚えはファイルに残さない）。
6. If 開いている `ghost/master` に `descript.txt`（大文字・小文字を問わない）が無いとき, the アプリ shall 何も送らず、ゴーストのフォルダとして扱えないことを出力の欄に出す（拡張と同じ判定）。
7. The アプリ shall `descript.txt` の `name` を出力の見出しのゴーストの名前に使い、読めないときはゴーストのフォルダの名前を使う（拡張と同じ）。
8. The アプリ shall 拡張と同じ待ちの長さ（相手を探す 1 件 2 秒・頼み 1 件 15 秒・読み込みの終わり 20 秒・応答の無い台本の引き直し 5 秒・書き出しの待ち 5 秒）を使う。
9. The アプリ shall SSP・areka のどちらにも、拡張と同じ形の頼みを送る（`Origin` を付けない。areka は loopback 以外の `Origin` を断る）。

### Requirement 4: 出力の欄

**Objective:** As a ゴーストの作者, I want 開発の操作の結果を 1 か所で読みたい, so that 台本・誤り・案内を見落とさない

#### Acceptance Criteria

1. The アプリ shall 開発の操作ごとに、時刻・操作の名前・ゴーストの名前とルート・送った相手（ベースウェアの名前とポート）の見出しの行を出し、その下に結果の行を足す（拡張の「Pasta 開発」の出力と同じ行）。
2. When 開発の操作が行を出したとき, the アプリ shall 出力の欄を見える状態にし、エディタの焦点を奪わない。
3. When 開発の操作が失敗か警告で終わったとき, the アプリ shall 拡張が通知に出す短い文を、出力の欄で誤りと警告を見分けられる形で目立たせる（成功では出さない）。
4. The アプリ shall 前の操作の行をアプリを閉じるまで残し、新しい行を後ろに足して、新しい行が見える位置へ送る。
5. The アプリ shall 台本・ログ・パスなどディスクやゴーストから来た文字列を、そのまま文字として出す（マークアップとして働かせない）。
6. While 開発の操作が進んでいる間, the アプリ shall 進んでいることを画面に示す。

### Requirement 5: 操作の重なりとゴーストの切り替え

**Objective:** As a ゴーストの作者, I want 操作が混ざって違う結果を見ることがないようにしたい, so that 出力の欄の結果を信じられる

#### Acceptance Criteria

1. While 開発の操作が進んでいる間, when もう 1 つの開発の操作を始めたとき, the アプリ shall 後のものを始めず、このゴーストへの操作が進んでいることを出力の欄に出す（拡張と同じ）。
2. While 開発の操作が進んでいる間, when 別のゴーストを開いたとき, the アプリ shall 進んでいる操作に新しいゴーストのファイルを読ませず、その結果を前のゴーストの見出しの下に出す（新しいゴーストの結果として見せない）。
3. When 別のゴーストを開いたとき, the アプリ shall 前のゴーストの保存変数の表を消す（出力の欄の前の行は残す）。

### Requirement 6: 保存変数の表

**Objective:** As a ゴーストの作者, I want 今のグローバル変数の値を表で見たい, so that シーンの分かれ道になる値を確かめられる

#### Acceptance Criteria

1. When 「保存変数を表示」（表の欄の読み直し）を押したとき, the アプリ shall `OnPastaDumpVariables` を送り、新しく書き出された `profile/pasta/debug/variables.toml` だけを読み、グローバル変数を名前・型・値の表に出す（保存も読み込み直しもしない。拡張と同じ待ち方）。
2. The アプリ shall 型を 文字列・数・真偽・表 に分けて出す。
3. Where 値が表のとき, the アプリ shall その中身を読める形で出し、書き換え・削除の操作を出さない。
4. If `variables.toml` が上限の時間までに新しく書き出されなかったとき, the アプリ shall 古い中身を出さず、デバッグを有効にする案内と、その間に増えた `pasta.log` の `OnPastaDumpVariables:` の行を出す（拡張と同じ）。
5. If 書き出された `variables.toml` を読めない・TOML として読めないとき, the アプリ shall 表を出さず、読めなかった理由とファイルの場所を出力の欄に出す。
6. When グローバル変数が 1 つも無いとき, the アプリ shall 表の代わりに、保存変数が無いことを出す。
7. The アプリ shall 表のそばに、書き換えはランタイムのメモリの上で効き、ファイル（`profile/pasta/save/` の保存先）へはランタイムの終了時（ゴーストの終了・SHIORI の読み込み直し）に書かれることを示す。
8. The アプリ shall ゴーストを開いただけでは表を読みに行かない。
9. While 保存変数の表を読めている間（下の欄でどれを見ているかによらない）, when ▶ か「値を入れて実行…」でシーンを鳴らし終えたとき, the アプリ shall 1 と同じく表を読み直す。

### Requirement 7: 保存変数の書き換え・削除・追加

**Objective:** As a ゴーストの作者, I want グローバル変数をその場で書き換えたい, so that 値を変えたときの話の分かれを、辞書を書き換えずに確かめられる

#### Acceptance Criteria

1. When 表の文字列・数・真偽の行の値を書き換えて決めたとき, the アプリ shall `OnPastaSetSaveVariable` に、名前（Reference0）・入れた値（Reference1）・型（Reference2。`string`・`number`・`boolean`）を送る。
2. The アプリ shall 書き換えの型を、今の型を初めの値にして、文字列・数・真偽から選べるようにし、真偽の値は `true`・`false` から選ばせる。
3. When 行の削除を選んだとき, the アプリ shall その名前と、ゴーストの保存変数から消えることを示して確かめ、決めたときだけ型 `delete` で送る。
4. When 表に無い名前で追加を決めたとき, the アプリ shall 1 と同じく、名前・値・型を送る（`＄＊pasta_talk_interval_min` のように、まだ保存されていない予約グローバル変数にも入れられる）。
5. If 追加の名前が空のとき, the アプリ shall 送らず、名前が要ることを示す。
6. When 書き換え・削除・追加を送り終えたとき, the アプリ shall Requirement 6.1 と同じく表を読み直し、送った後の値を出す。
7. If ゴーストが失敗の表記（`【数にできない値：…】` など）を返したとき, the アプリ shall その表記を出力の欄に出し、警告として目立たせ、表を読み直して今の値（変わっていない値）を出す。
8. If 頼みが届かなかった・応答の形が違ったとき, the アプリ shall その理由を出力の欄に誤りとして出し、表の値を書き換えたように見せない。
9. The アプリ shall 書き換え・削除・追加で、ファイル（保存先・`variables.toml`）を直に書かない。
10. The アプリ shall 値と名前を 1 行の文字列として入れさせる（改行は入れられない）。
11. While 保存変数の表を読めていない間（まだ読んでいない・デバッグが無効などで読めなかった）, the アプリ shall 書き換え・削除・追加の操作を出さない。

### Requirement 8: ローカル変数を入れて鳴らす

**Objective:** As a ゴーストの作者, I want ローカル変数に値を入れた状態でシーンを鳴らしたい, so that 変数の値で分かれる話を、前置きのシーンを書かずに確かめられる

#### Acceptance Criteria

1. When ツリーのシーンの行か、エディタの見出しの上で「値を入れて実行…」を選んだとき, the アプリ shall そのシーンの名前を示し、ローカル変数の名前・型・値の組を入れる窓を出す。
2. The アプリ shall 組を足す・消すことができ、型を文字列・数・真偽から選ばせ、真偽の値は `true`・`false` から選ばせる。
3. When 窓で鳴らすことを決めたとき, the アプリ shall 組を TOML のインライン表にして `OnPastaSceneAt` の Reference2 に付け、Requirement 1 と同じ流れ（保存 → 読み込み直し → 再生 → 出力）で鳴らす。
4. The アプリ shall 名前と文字列の値が、どの文字（日本語・`'`・`"`・`\`・空白）を含んでも、入れたとおりにシーンの `＄名前` へ届くように組み立てる（日本語のキーも引用符で包む）。
5. When 組が 0 のまま鳴らすことを決めたとき, the アプリ shall Reference2 を付けずに、「▶ シーンを実行」と同じく鳴らす。
6. If 名前が `＄名前` と書けるローカル変数の名前でないとき（空・数字だけ・`__名前__` の形・空白や `-`・`.` などの記号を含む）, the アプリ shall 送らず、窓の中でその組と理由を示す（判定はランタイムの `@pasta_debug.is_local_var_name` と同じ決まり）。
7. If 同じ名前の組が 2 つ以上あるとき, the アプリ shall 送らず、窓の中で重なった名前を示す。
8. If 型が数の組の値が数として読めないとき, the アプリ shall 送らず、窓の中でその組を示す。
9. If ランタイムが Reference2 の誤りの表記（`【表にできない値：…】`・`【名前にならない値：…】`・`【代入できない値：…】`）を返したとき, the アプリ shall Requirement 1.11 と同じく、それを台本として出力の欄に出す。
10. The アプリ shall 最後に鳴らした組を、アプリを閉じるまで覚え、次に窓を開いたときの初めの値にする（ファイルに残さない。シーンごとに覚える）。
11. The アプリ shall 「▶ シーンを実行」では、窓で入れた組を送らない（値は窓から鳴らしたときだけ届く）。

### Requirement 9: つなぐ先と読む範囲

**Objective:** As a ゴーストの作者, I want アプリがつなぐ先と読むファイルが決まった範囲に収まってほしい, so that 安心して手元で動かせる

#### Acceptance Criteria

1. The アプリ shall 頼みを送る先を 127.0.0.1 の候補のポート（Requirement 3.1）だけに限り、宛先を変える設定を持たない。
2. The アプリ shall 開発の操作のほかでは、どこにもつながない（編集・色分け・診断・検査は、これまでどおりつながずに動く）。
3. The アプリ shall 1 つの頼みを 1 回だけ送り、失敗しても送り直さない（台本を 2 回鳴らさない）。
4. The アプリ shall 開発の操作で読むファイルを、開いている `ghost/master` の中の 直下の `descript.txt`・`pasta.toml` と、`profile` の下のファイル（`pasta.log`（Requirement 2.4 の場所）・`profile/pasta/debug/variables.toml`）に限り、読むだけで書かない（`pasta.log` の場所は `pasta.toml` で `profile` の下のどこにでも置けるため、`profile` の下は読むだけで通す）。
5. The アプリ shall `profile` フォルダを、これまでどおりツリーに出さず、タブで開かない。
6. If 画面から、開いている `ghost/master` の外のファイルを読む求めが来たとき, the アプリ shall 読まずに断る（これまでの読み書きの範囲の決まりと同じ）。

### Requirement 10: 実行の流れは 1 本・VS Code 拡張は変わらない

**Objective:** As a pasta の開発者, I want 実行の流れの実装を拡張とアプリで 1 本にしたい, so that 2 つの道具の振る舞いがずれない

#### Acceptance Criteria

1. The 実行の流れ（MCP の頼みと応答の読み取り・相手の探し方・読み込み直しの待ち方・再生と台本の取り出し・保存変数の書き出しの読み取り・`pasta.log` と `descript.txt` の読み取り・出力の行と案内の文言） shall 拡張とアプリで同じ 1 つの実装を使う。
2. The VS Code 拡張 shall 3 つのコマンド（▶ シーンを実行・SHIORI をリロード・保存変数を表示）の振る舞いを変えない（ポートの順・`Origin` を送らないこと・待ちの長さ・保存の範囲・相手の覚え方・出力の行と通知の文言・`executeCommand(id, uri, line0)` の受け取り）。ただし、BOM 付きの `pasta.toml` の 1 行目の `[logging]` を読み落とす今の不具合は、共有の 1 本で直す（拡張でも直る）。
3. The VS Code 拡張 shall 保存変数の書き換えと、ローカル変数を入れた実行を足さない（`OnPastaSceneAt` に Reference2 を送らないまま）。
4. The VS Code 拡張 shall 今と同じく配布物（`.vsix`）を作れる。

### Requirement 11: 画面の見た目と操作

**Objective:** As a ゴーストの作者, I want 新しい欄が今の画面になじみ、エディタを狭めすぎないでほしい, so that 書きながら鳴らせる

#### Acceptance Criteria

1. The アプリ shall 起動の窓の大きさ（1000×680）で出力の欄と保存変数の表を出しても、エディタに書ける高さを残す。
2. The アプリ shall 出力の欄と保存変数の表を、今の一覧（診断・ゴースト全体の検査）と同じ見た目（見出しの帯・中身の色・選んだ行の印）にし、Windows の明暗の設定の両方で読めるようにする。
3. The アプリ shall ツールバーのリロードのボタンを、今のボタンと同じ並びの形で足し、ツリーのシーンの操作を、今のツリーのメニュー（作成・名前の変更）と並べて足す。
4. The アプリ shall 新しい操作（▶・値を入れて実行・リロード・表の読み直し・書き換え・削除・追加・相手の選択）を、キーボードだけでも行えるようにし、読み上げで名前が分かるようにする。

### Requirement 12: マニュアル

**Objective:** As a ゴーストの作者, I want `pasta-recipe` でゴーストを動かす使い方をマニュアルで引きたい, so that 迷わず使い始められる

#### Acceptance Criteria

1. The マニュアル shall `pasta-recipe` の章に、シーンの ▶・SHIORI のリロード・出力の欄・保存変数の表と書き換え・削除・追加・ローカル変数を入れて鳴らす使い方を、送る相手の探し方（2 つ以上のときに選ぶこと）とあわせて載せる。
2. The マニュアル shall シーンの ▶・保存変数の表示にはデバッグを有効にすること（`pasta.toml` の `[debug] enabled = true`）が要り、書き換えはデバッグによらず働くが、結果を表で見るにはデバッグが要ることを示す。
3. The マニュアル shall 保存変数の書き換えはメモリの上で効き、ファイルへはランタイムの終了時（ゴーストの終了・SHIORI の読み込み直し）に書かれること、表の値は見るだけであることを示す。
4. The マニュアル shall 今の「まだできないこと」の「ゴーストを動かすこと」と、「ネットワークにはつながない」の記述を、開発の操作のときだけ 127.0.0.1 のベースウェアにつなぐ、に直す（章の締めの「鳴らすのは VSCode 拡張の出番」の台詞も合わせる）。
5. When マニュアルを書き換えたとき, the マニュアル shall マニュアルの CI の検査（リンクの検証と、スキルの参照資料の照合）に通る。

### Requirement 13: 試験と CI

**Objective:** As a pasta の開発者, I want 共有の流れと 2 つの入出力を自動の試験で確かめたい, so that 拡張とアプリのどちらを直しても、もう一方を壊さない

#### Acceptance Criteria

1. The 共有の実行の流れ shall 偽の入出力で、読み込み直しの待ちと止め・再生と応答の無いときの引き直し・書き出しの待ち・保存変数の書き換えの頼み・Reference2 を付けた再生を確かめられる。
2. The アプリ shall ローカル変数のインライン表の組み立て（日本語のキー・`'`・`"`・`\`・空白を含む値、数・真偽）と、送る前の弾き（Requirement 8.6〜8.8）を、自動の試験で確かめられるようにする。
3. The VS Code 拡張 shall 今の試験（`mcpClient`・`ghostFiles`・`dumpVariables`・`runSceneAtCursor`・`reloadShiori`・偽の MCP の窓口・`devCommands` の通しの試験）を、確かめていることを減らさずに通す。
4. The アプリの入出力の実装 shall 試験で、127.0.0.1 の外へ送らないこと・`Origin` を付けないこと・開いている `ghost/master` の外を読まないことを確かめられる。
5. The アプリ shall 日々の CI（型の検査・画面の試験・ビルド・ネイティブの試験・clippy・依存の検査）に通り、足した部品の第三者の表示が配布物の `THIRD_PARTY_LICENSES.txt` に入る。
