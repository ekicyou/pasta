## 前提条件（共通）

検証開始前に以下をすべて満たすこと。

- [ ] **SSP がインストール済み**で起動できる。
- [ ] **pasta エンジン（pasta.dll / SHIORI）を組み込んだゴースト**がビルド済みで、SSP に導入されている。
- [ ] デバッグバックエンドが **`127.0.0.1:9276`** で待ち受ける構成になっている
      （`PASTA_DEBUG=1` 等、デバッグトランスポートを opt-in で有効化した状態）。
- [ ] **VSCode 拡張（VSIX）がビルド＋インストール済み**。
  - VSIX ビルドには `wasm-pack` が必要。手順:
    1. `cd editors/vscode`
    2. `npm run build:wasm`（`scripts/build-wasm.ps1` を実行。`powershell.exe` 5.1 の AllSigned で
       失敗する場合は `pwsh` 経由で `build-wasm.ps1` を直接実行してから次へ進む）
    3. `npm run package`（`vsce package` で `.vsix` を生成）
    4. 生成された `.vsix` を VSCode に手動インストール（拡張ビューの「VSIX からのインストール」）。
- [ ] 検証用の `.pasta` 辞書を用意し、以下を含むこと:
  - グローバルシーン（`＠` で始まる global シーン宣言）が 1 つ以上。
  - グローバルシーン配下に **ローカルシーン（`・` で始まる local シーン宣言）** が 1 つ以上。
  - 各シーンが SSP 上で視認できる固有のトーク（例: 「グローバルです」「ローカルです」）を持つ。

## ゲート項目 1.5 — シーン位置 → ライブ SSP 再生

**目的:** カーソル位置からのキックが、確定したシーンを **実 SSP 上で** 再生することを確認する
（R1.1 / R1.5）。特に **ローカルシーン（`・`）位置のキックが、グローバル先頭ではなく当該ローカル
シーンを再生する**（local-kick 合成経路）ことを確認する（R2.2）。

### 1.5-A: グローバルシーンの位置キック

| 手順 | 操作 | 期待結果 |
| ---- | ---- | -------- |
| 1 | SSP でゴーストを起動し、VSCode で Pasta デバッグ構成（`type: 'pasta'`, attach, `127.0.0.1:9276`）でアタッチする。 | デバッグセッションが接続され、`debugType == 'pasta'` 状態になる。 |
| 2 | 検証用 `.pasta` を開き、**グローバルシーン本文の行**にカーソルを置く。 | カーソルがその行にある。 |
| 3 | 右クリック → コンテキストメニュー最上段の **「▶ シーンを実行」** を選択する。 | メニュー最上段に項目が表示され、選択できる。 |
| 4 | 再生を観測する。 | **SSP 上で当該グローバルシーンがライブ再生される**（対応する固有トークが表示される）。シーン名の手入力は一切求められない。 |

### 1.5-B: ローカルシーン（`・`）の位置キック（local-kick 合成経路）

| 手順 | 操作 | 期待結果 |
| ---- | ---- | -------- |
| 1 | （1.5-A から継続。未接続なら再アタッチする。） | セッション接続済み。 |
| 2 | 同じ `.pasta` で、グローバルシーン配下の **ローカルシーン（`・`）本文の行**にカーソルを置く。 | カーソルがローカルシーン範囲内にある。 |
| 3 | 右クリック → **「▶ シーンを実行」** を選択する。 | 項目が表示され選択できる。 |
| 4 | 再生を観測する。 | **SSP 上で当該ローカルシーンが再生される**（ローカル固有のトークが表示される）。**グローバル先頭シーンではない**ことを確認する（最内シーン＝local 優先・R2.2 の合成経路が機能している）。 |

**判定:** 1.5-A／1.5-B いずれも期待トークがライブ表示されれば PASS。
ローカルケースでグローバル先頭が再生された場合は FAIL（local-kick 合成経路の不具合）。

## ゲート項目 9.3 — SHIORI リロード → デタッチ → 自動再アタッチ

**目的:** 「SHIORIリロード」が `\![reload,shiori]` を経て SSP に SHIORI を再読み込みさせ、
それに伴うデバッグデタッチ後に **拡張が自動で再アタッチ**（過渡失敗時はリトライ）すること、
**再アタッチ後にシーンを自動再キックしない**（手動再キックのみ）ことを確認する（R9.1 / R9.3 / R9.4）。

### 9.3-A: editor/context からのリロードと自動再アタッチ

| 手順 | 操作 | 期待結果 |
| ---- | ---- | -------- |
| 1 | Pasta デバッグセッションを接続した状態にする。 | `debugType == 'pasta'`。editor/context とデバッグツールバーの両方に「SHIORIリロード」が表示される（接続中のみ・R9.1）。 |
| 2 | `.pasta` エディタで右クリック → **「SHIORIリロード」** を実行する。 | コマンドが実行され、エンジンが `\![reload,shiori]`（SHIORI のみ・非同期）を出力する。 |
| 3 | SSP 側を観測する。 | SSP が SHIORI を再読み込みし、それに伴い **デバッグセッションがデタッチ**される。 |
| 4 | 数秒待機する。 | 拡張が `vscode.debug.startDebugging`（`type: 'pasta'`）で **自動的に再アタッチ**する。過渡的に失敗した場合は短間隔でリトライし、最終的に再接続する（上限／タイムアウトあり）。 |
| 5 | 再アタッチ完了後の挙動を観測する。 | **シーンの自動再キックは行われない**（リロード前に再生していたシーンが勝手に再生されない）。再生したい場合は作者が手動で「▶ シーンを実行」を再実行する必要がある（R9.4）。 |

### 9.3-B: デバッグツールバーからのリロード

| 手順 | 操作 | 期待結果 |
| ---- | ---- | -------- |
| 1 | 接続中の状態で、**デバッグツールバー**上の「SHIORIリロード」ボタンを押す。 | ツールバーにボタンが表示され、押下できる（接続中のみ・R9.1）。 |
| 2 | 9.3-A の手順 3〜5 と同様に観測する。 | デタッチ → 自動再アタッチ（必要ならリトライ）→ 自動再キックなし、が再現する。 |

### 9.3-C: 再アタッチ失敗時の挙動（任意・過渡失敗の確認）

| 手順 | 操作 | 期待結果 |
| ---- | ---- | -------- |
| 1 | リロード直後の数秒、バックエンドが未待受の状態を作る（SSP の SHIORI 再読込が完了する前のタイミング）。 | 初回アタッチが失敗し得る。 |
| 2 | そのまま待機し、拡張のリトライを観測する。 | 短間隔でリトライし、バックエンド待受復帰後に再アタッチが成功する。上限／タイムアウトを超えた場合は失敗が作者に提示される（誤って成功扱いにならない）。 |

**判定:** 9.3-A／9.3-B でデタッチ → 自動再アタッチが成立し、かつ再キックが発生しなければ PASS。
