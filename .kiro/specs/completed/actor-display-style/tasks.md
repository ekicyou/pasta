# Implementation Plan

- [x] 1. 装いの規則の土台
- [x] 1.1 装いの属性の検査とタグ列への変換を pasta_core に作る
  - 受け付ける 12 属性の一覧を 1 か所に置き、大文字・小文字を区別した完全一致で照らす
  - 値は文字列・整数・真偽値だけを受け、空の文字列と `]`・`\` を含む文字列を誤りにする。中身（色の書き方・範囲・書体名）は見ない
  - 表でない装いを誤りにし、1 つの表の中の誤りは入力の順にすべて集める
  - 書いた順に `\f[属性名,値]` を連ねたタグ列を作る（文字列はそのまま、整数は 10 進で負数は `-` 付き、真偽値は `1`/`0`、属性 0 個は空文字列）
  - 誤りの種類（表でない・知らない属性・値の誤り＝型違い／空／タグを壊す文字）をエラー型に足し、英語の文言にアクター名と属性名を含める（pasta.dll のログと読み込みエラーに出る。pasta_check の日本語の文言は 2.2 が持つ）
  - 単体テストで、12 属性が書いた順に並ぶこと、`Color` などの大文字違い、浮動小数点数・配列・表、空文字列、`]`・`\`、負の整数、真偽値、空の表、表でない装いがすべて期待どおりになり、`cargo test -p pasta_core` が通る
  - _Requirements: 1.2, 1.3, 1.4, 7.1, 7.2, 7.3, 7.4, 7.6_

- [x] 2. 読み込み・検査・出し入れの各部品

  - `[actor]` が無い・表でない・`font` が無いときは何もせず、`font` 以外のキーには触れない
  - 誤りは読み込みエラーにし、文言にアクター名・属性名・行番号を入れる（アクターをまたぐときは名前順で最初のアクターで止める）
  - 成功したら `@pasta_config` の `actor."名前".font` が検査済みのタグ列の文字列になる（空の表は空文字列）
  - 設定の読み込みのテストで、7.1〜7.4 の各誤りで読み込みが失敗し文言にアクター名・属性名・行が入ること、3 つの書き方で書いた順が保たれること、`font` 以外のキーの値が変わらないことを確かめて通る
  - _Boundary: ActorFontLoader_
  - _Depends: 1.1_
  - _Requirements: 1.1, 1.5, 7.1, 7.2, 7.3, 7.4_

- [x] 2.2 (P) pasta_check validate に装いの書き間違いの報告を足す
  - 新しい報告の種類 `config-actor-font`（誤り）を足し、種類の一覧を 25 件にする
  - pasta_check 側に、pasta.dll と同じ取り出し（書いた位置の順・行番号）を実装して `[actor.*.font]` を読み（pasta_lua には依存しない）、1 つの誤りにつき 1 件、属性の値の行（表でないときは `font` の値の行）で報告する
  - 誤りがあっても検査は続け、飛び先の検査を止める理由（skip_reasons）には入れない
  - 知らない属性・型と空・禁止文字・表でないの 4 種の日本語の文言を、設計の文面どおりに出す
  - 設定の検査のテストと報告の種類の表のテストで、`config-actor-font` の行・文言・分類・code が、3 つの書き方（インライン表・節・ドット付きキー）それぞれで確かめられ、`cargo test -p pasta_check` が通る
  - _Boundary: FontFindingReader, ValidateReport_
  - _Depends: 1.1_
  - _Requirements: 7.5_

- [x] 2.3 (P) 装いの出し入れを受け持つ状態を持たない Lua モジュールを作る
