# Brief: manual-reader-first

マニュアル（`book/`）を、読む人の側から書き直す。要件 → 設計 → タスク → 実装のフェーズは取らない（開発者の指示）。全体を見ながら対話で方針を決め、複数のサブエージェントで並行して直す。進み具合と決定は [status.md](status.md) に残す。

## Problem

ゴーストを作りたい人が、マニュアルを開いて「使いやすそう」と思う前に「難しそう」と思ってしまう。

- 入門ガイドは、最初の台詞が出るまでに 3 章・約 400 行（前提環境 → 最小一式を手で組む）を読ませる。
- 文法の部は、細部の分解から始まる。通しの作例が最初に出るのは最後の章である。根にある「日本の台本の書式（柱・ト書き・台詞）」は、マニュアルに 1 行も書かれていない。
- デバッグの部は、使う人が意識しなくてよい仕組み（WebView2・ポート番号・前の版からの移行）に紙幅を割く。題も回りくどい。
- リファレンスは項目の説明ばかりで、実物（ログの 1 行・設定の断片・画面に出る文）が少ない。「〜に変わった」という経緯が混ざる。
- 内部設計は、実装の逐語の書き起こしと、章をまたぐ同じ説明の繰り返しで目が滑る。

## Current State

- 章は 68。入門・文法・Lua・デバッグ・リファレンス・内部設計・雑記の 7 部（`book/src/SUMMARY.md`）。
- 執筆規約 `book/AUTHORING.md` と検査（`book/tools/*.mjs`・`crates/` のテスト）が、章の並び・見出し・文体・作例の逐語一致を機械で縛る。読みにくさの一部は、この規約そのものから来ている（例: 入門の「台詞に書いた事実は、台詞以外にも必ず書く」）。
- 文法・リファレンス・Lua の 24 章は、AI 向けスキルの参照ファイルの生成元である（`book/tools/gen-skill-refs.mjs`）。
- 入門の作例は hello-pasta の辞書 13 枚と逐語で照合され、実機の絵 16 枚が辞書の台詞を写している。
- 2026-11-19 の調査の結果は status.md の「調査の要点」にある。

## Desired Outcome

- 入門: 最初の 5 分で「入れたらしゃべった・1 行書き換えたら、そのとおりにしゃべった」まで行ける。前提や準備の説明は、要るときに読む場所へ下がっている。見本ゴーストの台詞が、読んでくすっとできる。
- 文法: 最初のページで「Pasta DSL は台本である」と分かり、通しの作例 1 本で全体が見える。そこから細部へ下りる順に並ぶ。
- デバッグ: 「pasta-recipe で書く」「VS Code で書く」の 2 本立てで、入門と同じ気軽さで読める。Windows 11 のアプリとして、使う人が要ることだけを書く。
- リファレンス: 今の動きだけを書く。抽象の規則には実物の例が 1 つ付く。
- 内部設計: 構成はそのまま。経緯・重複・壁になった段落を削り、入力 → 出力の例を足す。
- 全章: 具体例がある。Windows 11 で自明なことを説明しない。

## Approach

- 規約と検査を、読む人を優先する形に同じ変更で改める（規約に合わせて文章を曲げない）。
- 影響の小さい所から波で進める。波ごとにプレビューで開発者が確かめ、議題が閉じてから PR にする。
  1. リファレンス 3 章・デバッグの部・内部設計・シェルの章
  2. 文法の部
  3. 入門ガイド（見本ゴーストの台詞・絵・検査の直しを含む）
- 事実はソースから引く。例に書くログ・出力・画面の文は、書式の実装かテストの期待値から写す。
- プレビューは `http://localhost:3939`（`.claude/launch.json` の `pasta-manual`）。作り直しの手順は status.md にある。

## Scope

- **In**: `book/src/` の入門・文法・デバッグ・リファレンス・内部設計の章、`book/AUTHORING.md`、章を縛る検査（`book/tools/`）、hello-pasta の辞書と段階表・絵・それを縛るテスト、スキルの参照ファイルの再生成。
- **Out**: 雑記（開発者の記事。そのまま）。Lua の部は、ほかの章の直しに伴うリンクと語の直しだけ。文法・ランタイムの挙動の変更。

## Boundary Candidates

- 章の文章の直し（部ごと）
- 規約と検査の直し（`AUTHORING.md`・`verify-content.mjs`・`verify-scripts-test.mjs`・`tutorial-check.mjs`）
- 見本ゴーストの台詞の書き直しと、絵の撮り直し
- 配布物に触る案（入門用の nar を足す・hello-pasta の `pasta.toml` を変える）。採るかどうかは議題で決める

## Out of Boundary

- ノベルゲームの作り方の部（`manual-novel-guide`）。文法の部の「台本」の説明は、対応の表と作例 1 本にとどめ、背景・曲・効果音の書き方は教えない。
- ト書きを実行時に流す仕組み（`cue-command-runtime`）。`！` 行は今の動き（`!select` だけが働く）で書く。
- 回避レシピ（書けない形の「代わりの書き方」）は載せない。

## Upstream / Downstream

- **Upstream**: `manual-claudia-theme`（台詞部品）、`getting-started-story-guide`（入門の型）、`hello-pasta-tutorial-stages`（段階辞書）、`getting-started-screenshots`（絵）、`manual-ssot-authority`（スキルの生成）、`pasta-recipe` 系（エディタ）。いずれも完了済み。
- **Downstream**: `manual-novel-guide`（文法の部の「台本」の説明を前提にできる）。

## Existing Spec Touchpoints

- **Extends**: 完了済みの上記 spec が決めた規約と検査を改める。
- **Adjacent**: `manual-novel-guide`・`cue-command-runtime`・`hello-novel-sample`（柱・ト書き・台詞の語り方を食い違わせない）。

## Constraints

- マニュアルは利用者向けの情報の唯一の権威である。事実を変えない。
- 生成元の章は、本体（最初と最後の `---` の間）に台詞部品と口調を置けない。変えたら `node book/tools/gen-skill-refs.mjs` で作り直す。
- `pasta.toml` リファレンスの 6 つのキーの表とテンプレートの行は、`config_defaults_test` が照合する。
- main へは PR だけで入る。main に入ると GitHub Pages に出る。リリースに無い配布物へのリンクは、次のリリースまで切れる。
