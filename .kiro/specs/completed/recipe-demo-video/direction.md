## 1. 結論

1. **撮るのはノート PC の画面（主画面）1 枚**。窓だけの録画ではゴーストが入らない。開発者は左の画面で作業を続け、ノート PC の画面は撮影の間だけ「舞台」にする。
2. **舞台は画面の右下の 1/4（1440×900・16:10）。表示の倍率は 100% のまま**。録画の後に Openscreen の切り抜き（`cropRegion`）でこの範囲だけにする。前の案（右下の 2/3・1920×1200）より、画は 1.33 倍に詰まる。
3. **背景は真っ白の壁紙そのまま**。白の窓は敷かない。Openscreen の飾り（背景・余白・枠・角丸・影）は全部切る。
4. **ゴーストは画面の右下の隅に立ち、いつも pasta-recipe の窓より手前にある**。ゴーストは SSP が初めに立たせた位置のまま動かさない。pasta-recipe の窓（既定の大きさ 1000×680）は下の辺を画面の下に付け、右の端の約 300 px を男の子の立ち絵の後ろに差し込む。男の子は窓の上に重なり、女の子は窓の右に立つ。吹き出しは 2 つとも、エディタの空いている右側に出る。

6. **鳴らす場面では、カメラを動かさない**。押す所（見出しの上の ▶）・吹き出し・立ち絵・ダイアログ・保存変数の表が、1 つの画（主の画）に入る。カメラが動くのは、出力の欄を読ませるときと、ツールバーを押すときだけで、どちらも 100〜300 px の短い滑りである。回転（3D）は使わない。

## 2. 決定どうしの縛り合い

次の 5 つは、1 つを変えるとほかが動く。この順で決めると戻りが少ない。

| 決めること | 縛るもの | 理由 |
| -- | -- | -- |
| どの画面を撮るか・どこを切り抜くか | 舞台の広さと形（16:10）・書き出しの形 | 録画は画面 1 枚。映す範囲は、録画の後に切り抜きで決める |
| ゴーストの立つ所 | 吹き出しの出る所・窓を寄せられる限り | 立ち絵は画面の下の辺に立つ。吹き出しは立ち絵の左上に、シェルの決めた位置で出る（動かせない） |
| pasta-recipe の窓の位置と大きさ | 重なりの幅・ダイアログの出る所・エディタの空き | 下の欄は窓の幅いっぱいで、右半分が保存変数。ダイアログは窓の真ん中に出る。どれもアプリの決まりで、動かせない |
| 寄りの倍率 | 1 つの画に入る範囲・文字の大きさ | 見える範囲は「舞台 ÷ 倍率」。文字 10 px には、見える幅 975 px まで |
| 撮る辞書（写しの中身） | エディタの行の数と長さ・台詞の長さ・絵コンテの秒 | 行が長いと吹き出しの下に入る。行が多いと男の子の吹き出しにかかる |

### 2.1 表示の倍率（開発者の設定）

主画面の画素は 2880×1800 で、倍率を変えても変わらない。変わるのは、pasta-recipe の文字と窓が画素をいくつ使うかである。SSP のゴーストは SSP の側の拡大率で決まり、Windows の倍率とは別に選べる。

文字の大きさは次の式で見積もる（本文の幅 750 px で再生したとき）。

```text
本文の幅での文字の高さ（px）＝ 画面の上の文字の高さ（px）× 750 ÷ 画に見えている幅（px）
```

| 文字 | 画面の上（100%） | 引き（幅 1440） | 寄り（幅 975） |
| -- | -- | -- | -- |
| エディタの台詞（Monaco の既定 14 px と見込む） | 14 | 7.3 px（読めない） | 10.8 px |
| 出力の欄・保存変数の表・ダイアログ・ツールバー（CSS の 13 px） | 13 | 6.8 px（読めない） | 10.0 px |
| 吹き出し（SSP 100% で 12 px と見込む） | 12 | 6.3 px（読めない） | 9.2 px |

- **引きの画では文字は読めない**。引きは「どこに何があるか」を見せる画で、読ませるのは寄りだけである。これは前の案と変わらない。舞台を 1440 まで詰めても、引きで読める大きさ（10 px）には届かない。
- **寄りは約 1.48 倍（見える範囲 975×609）**。アプリの 13 px の文字がちょうど 10 px になる幅が 975 である。高さ 609 は、立ち絵の足元から女の子の吹き出しの上の端まで（605 px）がちょうど入る高さである。
- **吹き出しの文字は約 9.2 px で、10 px に少し届かない**。吹き出しと立ち絵のかたまりの高さ（605 px）が、16:10 の画では幅 968 px 以上を求めるからである。入門ガイドの絵（幅 894）は 10 px だが、あれは 16:10 ではない。要件 2.6 の案では、吹き出しだけ 9 px 以上とした（10.1 節）。試し撮りで吹き出しの文字の実際の大きさを測って決め直す。
- 寄りに入る元の画素は横 975 で、1152×720 の書き出しでは 1.18 倍の引き伸ばしになり、少し甘く映る。本文の幅（750 px）で見る分には、元の画素のほうが多いので差は出にくい。
- SSP のシェルとバルーンは 100% にする（立ち絵 333×500 の等倍。`SCREENSHOTS.md` の絵と同じ見え方）。表示 100% なら、SSP は 100% で始まる見込みである。

### 2.2 右下の 1/4 を切り抜く

- 録画は画面の全部で撮り、編集で `setClipRange` の `cropRegion` を `{x: 0.5, y: 0.5, width: 0.5, height: 0.5}` にして、右下の 1440×900 だけにする。寄り・見出し・書き出しは、切り抜いた画の上でいつもどおりに働く。道具は Openscreen だけで済む（要件 7.1）。
- 形は画面と同じ 16:10 にしてある。書き出しの形が切り抜きに従わないときの備えである。
- 「引き」は、切り抜いた画を寄らずに映した画である。始めと終わりの「全体」（要件 2.3）にそのまま合う。
- 舞台の上の 188 px ほどは白い地だけになる（窓の上の端は 1088、舞台の上の端は 900）。引きの画ではここが空きになる。詰めたければ、切り抜きを 16:9（1440×810・`{x: 0.5, y: 0.55, width: 0.5, height: 0.45}`）にできるが、書き出しの形が従うかを試し撮りで確かめてからにする。
- **切り替えの決まり**: 試し撮りを 1152×720 で書き出し、寄りのコマ（`getFrames`）でエディタの台詞と出力の欄の字がにじんで読みにくければ、書き出しを 1440×900 に上げる。それでも読みにくければ、開発者に表示の倍率（150%）を相談する。
- 採らない方法: 書き出しの後に ffmpeg で切る（寄った後の画を切ることになり、寄りの画が欠ける）。

切り抜きを使うときに、設計で気を付けること:

- `setPointerTrack` に渡す位置は、**録画した画面（2880×1800）に対する割合**である。切り抜いた画に対する割合ではない。
- 寄りの中心（`addZoom` の `focus`）と見出しの位置が、切り抜いた画に対する割合かどうかは、定義からは読み切れない。試し撮りで確かめる。

## 3. 撮り方

### 3.1 画面か窓か

| 案 | 中身 | 判定 |
| -- | -- | -- |
| 窓を撮る | pasta-recipe の窓だけ | 採れない。ゴーストは別の窓なので映らない（要件 1.1） |
| 画面を撮る | 画面 1 枚の全部を録画し、映す範囲を切り抜きで決める | 採る。映したくない物は、切り抜く範囲に置かないことで外す |

### 3.2 どの画面か

確かめた事実（2026-11-15）:

| 画面 | 位置 | 大きさ | タスクバー | 使い道 |
| -- | -- | -- | -- | -- |
| DISPLAY1（主画面・ノート PC） | 右 | 2880×1800（100%） | 自動で隠してある（作業域は画面の全部） | 開発者が空けた。**舞台にする** |
| DISPLAY2 | 左 | 論理 1707×1067（2560×1600・150% と見込む） | 無い | 開発者が作業する |

- Openscreen の `listSources` は「画面 1」（index 0）と「画面 2」（index 1）を返す。どちらが主画面かは道具からは分からない。配置を見せるための試し撮り（3.5 節）のコマで確かめる。
- SSP のゴーストは主画面の右下に出るので、右下の隅を舞台にすると、動かす距離が短い。

### 3.3 残る危うさと、開発者に頼むこと

- 隠れたタスクバーは、本物のポインタが主画面の下の辺に触れると出てくる。知らせのあるアプリが光ったときも出ることがある。CDP の操作では本物のポインタは動かず、`setPointerTrack` が描くポインタはタスクバーを出さない。
- 開発者に頼むことは、要件 7.15 のとおりである: 撮影の間（約 3 分）、ノート PC の画面に窓を動かさない・マウスを入れない（下の辺でタスクバーが出る。窓の上に乗るとボタンの色が変わる。ゴーストに乗ると触り反応が出る）・どこも押さない（押した窓が前に出て、重なりの順が変わる）。
- 本物のポインタそのものは動画に映らない（Openscreen はポインタをデータで持ち、`setPointerTrack` で入れ替える）。
- Openscreen の録画のバーとカウントダウンが主画面に出るかは分からない。出るなら、頭の数秒を切る。
- 書き出したコマの確かめ（要件 3.3）で、タスクバーが出たコマが無いことも見る。出ていたら撮り直す。

### 3.4 背景: 真っ白の壁紙をそのまま使う（開発者の決定）

- 撮る画面の壁紙は真っ白である。アイコンも通知も無い。だから、壁紙がそのまま無地の地になる。**白の窓は敷かない**（前提 A6・要件 3.1 もこのとおりに直っている）。
- 白の窓が要らなくなったので、「白の窓を開く」「白の窓が前に出て pasta-recipe を隠す」という手間と危うさが消えた。
- 動画はマニュアルの白いページの続きに見える。無地は符号の量をほとんど食わないので、5 MB に収めやすい。
- pasta-recipe のエディタも白である。窓と地の境は、窓の枠と影と、色の付いた帯（題名・ツールバー・タブ・下の欄）で分かる。吹き出しの縁が白に溶けて見えにくいかは、配置を見せるコマ（3.5 節）で見る。溶けるときは開発者に相談する（壁紙の色は開発者の設定なので、撮影の作業は変えない）。
- 隠れたタスクバーの細い線が、下の辺（切り抜く範囲の中）に残らないかも、同じコマで見る。

### 3.5 撮る前の手順: 配置を開発者に見せる（要件 7.13・7.14）

本番を撮り始める前に、次の順で進める。開発者が「よい」と答えるまで、本番は撮らない。

1. 写しのゴーストを試験用の SSP で立て、pasta-recipe で写しを開き、`10-save.pasta` を開く。
2. pasta-recipe の窓を 4.2 節の位置と大きさに置く。ゴーストは SSP が立たせた位置のまま動かさない（測った位置から動いていないことだけ見る）。
3. `＊会話` を 1 回鳴らして、吹き出しを 2 つとも出す（吹き出しの位置は、出ている間しか分からない）。このあと「保存変数を表示」を押して、表も出しておく。
4. **その状態で、Openscreen の短い試し撮り（2〜3 秒）をする**。切り抜き（`cropRegion`）をかけ、`getFrames` で 1 コマ取り出す。これが「引き」の絵そのものである。同じ録画に寄りを置いて、主の画・左の画・左上の画（5.1 節）のコマも取り出す。
5. コマと、配置の数字（窓の位置と大きさ・立ち絵 2 人の位置・切り抜く範囲・寄りの倍率）を開発者に見せ、「この配置でよいか」を尋ねる。
6. 直すよう言われたら、直して 3〜5 をやり直し、もう一度尋ねる。
7. よいと言われたら、保存変数を消して最初の状態に戻し（1 回鳴らしたので数が 1 になっている）、撮影の間の頼みごと（要件 7.15）を伝えてから、本番を撮る。

- 絵の取り方に Openscreen の試し撮りを推す理由: 本番と同じ道（録画 → 切り抜き → 書き出し前のコマ）を通るので、開発者が見る絵が、動画に映る絵と同じになる。撮る画面の番号・切り抜きの数字・録画のバーの映り込み・重なりの順も、同じ 1 回で確かめられる。画面の写し（スクリーンショット）は別の道具が要り、開発者のデスクトップの操作を奪うおそれがある（要件 7.5）。
- 試し撮りの録画は Openscreen のプロジェクトに残る（前提 A10 のとおり、消さなくてよい）。

### 5.1 4 つの画

寄りはどれも同じ倍率（約 1.48 倍・見える範囲 975×609）にする。画どうしの移りは「滑り」だけで、大きさは変わらない。

| 引き | 舞台の全部（1440〜2880・900〜1800） | 窓の全部とゴースト。文字は読めない | 始め・終わり・話の切れ目（1 回） |
| 主の画 | 1820〜2795・1191〜1800（見出しの上の ▶ の左から女の子の右まで） | 見出しの上の ▶・エディタの行・吹き出し 2 つ・立ち絵 2 人・ダイアログ・保存変数の欄の全部 | 鳴らす・直す・値を入れる・保存変数を書き換える・締め |

- 主の画では、出力の欄は右の 200 px しか入らず、行が左で切れる。エディタの行の番号も左で切れる。出力を読ませるときだけ、左の画へ滑る。
- 主の画の横の余りは少ない（押す ▶ の左に 約 24 px・女の子の右に 3 px）。ゴーストを動かさずに 1 つの画に入る、ぎりぎりの幅である。入らなければ、男の子を右へ 50 px ほど寄せ、窓も同じだけ右へ寄せる。

### 5.2 規則

1. **鳴らす場面は主の画のまま動かさない**。押す所と吹き出しが同じ画に入っているので、押した瞬間（波紋）から台詞が出そろうまで、見る人の目だけが左から右へ動く。
2. **出力の欄を読ませるときだけ、左の画へ滑る**（1 秒）。ポインタを結果の行のそばへ滑らせて「ここ」と指す。押さない。読ませたら主の画へ戻る。
3. **待ちは、止まった画の上で切る**。読み込み直しの待ちは、押した後、台詞が出る前の止まった絵で切る。吹き出しが閉じるのを待つ間も同じ。滑りと寄りの出入りの最中は切らない（画が飛ぶ）。
4. **速めるのは手の動きだけ**。打ち込みとダイアログへの入力は 1.5〜2 倍に速める。ゴーストの台詞は等倍のまま映す（喋る速さはゴーストの持ち味である）。
5. **台詞が出そろってから 2 秒以上止める**（前提 A5）。出力の欄の結果も 2 秒以上止める。
6. **`setPointerTrack` が自動で付ける寄りは使わない**。自動の寄りは押した所だけに寄り、画が押すたびに動く。自動の寄りを消し、上の 4 つの画を置き直す。
7. **回転（3D）・背景の動き・動きのぼかしは使わない**。映すのは文字で、傾けると読めなくなる。大きさも増える。
8. **ポインタ**: 矢印・大きさは 2 倍ほど・押したときの弾みと波紋を付ける。音が無いので、押した瞬間は波紋で見せる。
9. **▶ はいつもエディタの見出しの上から押す**。ツリーのメニューは使わない。押す所が毎回同じなので、見る人は 1 回で場所を覚える。
10. **ダイアログは、男の子の吹き出しが閉じてから開く**（4.2 節の注意）。

- 置く所: 画の左上の隅に固定する（Openscreen の文字は画の枠に付くので、寄っても滑っても動かない）。主の画では、押す ▶ のすぐ上（ファイルの 1 行目のコメントの上）に乗る。左の画ではツリーの上の端、左上の画では題名の帯の左に乗る。右上の隅は、女の子の吹き出しの角に重なるので避けた。ボタンや台詞に重ねない。どちらの隅にするかは、配置を見せるコマで決め直せる（11 節の D）。
- 形: 濃い色の板に白い字・1 行・現れ方は「ふわっと出る」だけ。打ち出し・跳ねる動きは使わない。
- 文は、画面のボタンやメニューの名前をそのまま使う（要件 1.7）。番号は、動画の前の説明の番号と同じにする。
- 始めと終わりの引きには出さない。題名も出さない（章の見出しが題名である）。
- 矢印は使わない。指すのはポインタの役目である。

### 7.2 「字幕を付けない」との関係

brief の範囲外は「音声や字幕を付けること」である。見出しは字幕ではないと考える。

- **字幕**は、流れに合わせて台詞や説明を文で出し続けるもの。読む量が増え、画面の文字と取り合いになり、文を直すたびに撮り直しになる。これは付けない。Openscreen の字幕の機能（音声の書き起こし）も使わない。
- **見出し**は、いまどの操作かを示す名前だけである。5 つで、文ではない。音の無い動画では、途中から見た人や戻して見る人が、いまどこかを知る手掛かりがほかに無い。
- 見出しの文は画面の名前の写しなので、名前が変われば動画そのものが撮り直しになる。見出しのせいで撮り直しが増えることはない。
- 範囲外の言い方を「音声・ナレーション・台詞や説明を文で流す字幕」に直し、見出しは要件に入れる（10 節）。

見出しも付けない案（画だけ）も成り立つ。そのときは、動画の前の説明の番号だけが手掛かりになる。

### 7.3 動画の前の説明と動画の分け方

| 説明の文が受け持つこと | 動画が受け持つこと |
| -- | -- |
| 操作の順（番号 1〜5。見出しと同じ名前） | 押す所はどこか |
| 画面のどこを見るか（右下の手前がゴースト・左下が出力・その右が保存変数） | 押した後に何がどこに出るか |
| 音声が無いこと・長さ（約 77 秒） | 待ちの長さの感じ（切ってあることは文で断る） |
| 撮ったゴーストは入門ガイドの hello-pasta の写しで、`＊天気` は撮影のために足したこと | — |

- 仕組み（保存・読み込み直し・`OnPastaSceneAt`）は説明の文に書かない。すぐ下の小節が書いている。
- 説明は 1 段落でもよいが、番号の付いた短い並びのほうが、見出しの番号と突き合わせやすい。

### 8.2 動画で起きること

| 手順 | 操作 | ゴーストの台詞・画面の値 |
| -- | -- | -- |
| 1.2 | `＊会話` を ▶ | 「この話をするのは 1 回目だよ！」「……ずっと数えてたの？」 |
| 1.3 | 男の子の台詞を「……数えなくていいよ。」に書き換えて ▶ | 「2 回目だよ！」「……数えなくていいよ。」 |
| 1.4 | `＊天気` に `天気`・文字列・`雨` を入れて鳴らす | 「今日の天気は雨だって。」 |

- `天気`・`雨` は、`recipe.md` の「値を入れて実行」の例と同じである（要件 1.7）。
- 書き換える台詞は短くする。打つ字が少なく、吹き出しでも 1 行で読める。
- 採らなかった案: `13-calendar.pasta` に `行事`＝`バレンタイン` を入れる（既にあるシーンだけで済むが、入れた値が台詞に字として出ない。音の無い動画では伝わらない）。台本用のファイルを新しく作る（行は減るが、入門ガイドの 10 段目とのつながりが切れる）。

### 8.3 割り込みを避ける

- 自然なおしゃべり: `talk_interval` を延ばす（上の表）。
- 起動の台詞: 試験用の SSP は毎回 `OnFirstBoot` を喋る。喋り終わって吹き出しが消えてから撮り始める。
- 時報: 正時をまたいで撮らない（毎時 55 分〜5 分は撮らない）。
- 触り反応: 本物のマウスをゴーストに乗せない（3.3 節）。

### 12.2 重ねる配置の危うさと、試し撮りで確かめること

そのほかに確かめること:

- `listSources` の「画面 1」が主画面か。録画のバーとカウントダウンが撮る画面に映るか。
- 形を「録画のまま」にして飾りを切ったとき、書き出しが切り抜いた範囲（1440×900）をそのまま映すか。書き出しの「元のまま」の高さが 900 になるか。
- 切り抜き（`cropRegion`）の後で、寄りの中心と見出しの位置が切り抜いた画に対する割合になるか。
- 約 1.48 倍の寄りが通るか（Openscreen は、録画がぼける手前より深い寄りを断る）。寄りから寄りへの滑り（同じ倍率）がなめらかか。
- 寄りのコマで、字がにじまずに読めるか（2.2 節の切り替えの決まり）。
- 壁紙の白の上で、吹き出しの縁と窓の縁が見えるか。隠れたタスクバーの細い線が下の辺に残らないか。
- 保存変数を書き換えた後の ▶（読み込み直し）で、値が残って 100 になるか。読み取り専用の SSP でも保存先に書けるか。
- 入れた値が無いときの `＄天気` は動画に出ない（▶ では鳴らさない）が、`＊天気` の見出しの上の「▶ シーンを実行」を誤って押さない台本にする。
- 送り主の表示が吹き出しに出ないか。
- 1152×720・30 fps・約 77 秒で 5 MB に収まるか。1440×900 でも収まるか。書き出した MP4 に音声のトラックが付くか（付くなら要件 7.12 のとおりに除く）。
