## 概要

pasta の Lua ランタイムの土台の mlua を 0.11（0.11.6）から 0.12（0.12.2）へ上げた。features（`luajit52`・`vendored`・`serialize`）はそのままで、同梱の LuaJIT は mlua-sys 0.13.0 が引く新しい版（`luajit-src 210.7.4`）になった。

ゴーストの作者から見て、今まで動いていた辞書と `scripts/` の Lua は、前と同じ結果になる。エラーの文言・コルーチンの扱い・`require` の探し方・配列の印・`@toml`・`@enc`・`ffi.load`・VS Code のデバッガの止まり方は変わらない（版を上げる前に特性化テストで押さえ、上げた後も同じ期待のまま通ることを x86・x64 の両方で確かめた）。

## 動きが変わる変更

### Rust のライブラリとして使う人へ: `pasta_lua::mlua` が 0.12 になる

`pasta_lua` が公開している `pasta_lua::mlua` は mlua 0.12 になった。`pasta_lua` を Rust のライブラリとして使い、`pasta_lua::mlua` の型を使っている場合は、0.12 の名前で書き直す。pasta の中で当たった名前の移りは次の 2 つである。

| これまで（0.11） | これから（0.12） |
| ---------------- | ---------------- |
| `mlua::Debug` | `mlua::debug::Debug` |
| `mlua::String` | `mlua::LuaString` |

ほかの移りは mlua 0.12 の変更履歴を見てほしい。辞書と Lua だけでゴーストを作る人には関係しない。

### 同梱の LuaJIT が新しい書き方を受け付ける

新しい LuaJIT は、Lua 5.1 に無い書き方の一部を構文の誤りにしなくなった。

| 書き方の例 | これまで | これから |
| ---------- | -------- | -------- |
| ループの中の `continue` | 構文の誤り | 受け付ける |
| `const` の宣言、`!=`・`&&`・`\|\|`・`??`・`?.` | 構文の誤り | 受け付ける |
| ビット演算の記号 `<<`・`>>`・`~>>` | 構文の誤り | 受け付ける |
| `\|x\| -> 式` の短い関数、数の `_` 区切り（`1_000`） | 構文の誤り | 受け付ける |

今まで動いていた書き方の結果は変わらない。変わるのは「今まで読み込みで落ちていた書き方が通る」ことだけである。LuaJIT にパッチを当てないと戻せないので、受け付けるまま固定した（`continue` 文を受け付けることをテストで押さえた）。

マニュアルはこれらの書き方を前提にせず、Lua 5.1 系と LuaJIT の拡張の範囲だけを案内する。これらの書き方は同梱の luacheck が読めない（[Lua の基本](https://ekicyou.github.io/pasta/lua/basics.html) の「前提」）。

### `os.time` が、ちょうど `-1` になる時刻で `nil` を返さなくなる

LuaJIT の不具合の直しが入った。これまでの `os.time` は、結果がちょうど `-1`（1970-01-01 00:00:00 UTC の 1 秒前）になる時刻を誤りと見なして `nil` を返していた。これからは、その時刻の数 `-1` を返す。ほかの時刻の結果は変わらない。

### x86 の pasta.dll のセーブの整数が、x64 と同じ文字で書かれる

x86 の pasta.dll で、32 ビットに収まらない整数をセーブに書くと、浮動小数の文字になっていた。これからは x64 と同じく TOML の整数で書く。

| Lua で入れた値 | x86 のこれまで | x86 のこれから（x64 と同じ） |
| -------------- | -------------- | ---------------------------- |
| セーブの表の `x` に `3000000000` | `x = 3000000000.0` | `x = 3000000000` |
| 表に入った `-2^63` | 浮動小数 | 整数 |

決まりは x64 と同じく「64 ビットの整数に戻しても同じビットになる数は整数として書く」で、`-0.0` と 64 ビットの整数に収まらない数は浮動小数のまま書く。x64 の書き出しは変わらない。配列の印を決めるために表の整数のキーを数えるときも、x86 と x64 で同じ表を同じように判定する。前にセーブした `3000000000.0` は、読み込むと同じ値の数になる。

これは mlua の版上げではなく、main にあった x86 の不具合の直しである（pasta.dll の本番は x86）。

## 主な変更

- ルートの `Cargo.toml` の mlua を `0.12.2` にした。`Cargo.lock` で動いたのは mlua・mlua-sys・luajit-src・lua-src の 4 つだけである
- 0.12 で移った名前（`mlua::debug::Debug`・`mlua::LuaString`）と非推奨になった名前を置き換えた。Lua から見える挙動を変える直しは入れていない
- 段 1 で、Lua の数を 64 ビットの整数として読む決まりを 1 か所（`lua_int`）にまとめ、値の書き出し・配列のキー・文字列でないキー・TOML の整数の読み込みを揃えた。x86・x64 の整数のテストを足し、Rust の側で値の持ち方が違う期待は `target_pointer_width` で分けて両方で走らせる
- 段 2 で、版を上げる前の mlua 0.11 の上で、変わりうる挙動を特性化テストで押さえた（セーブとログの表が `__pairs` を呼ばないことなど）。版を上げた後も同じ期待のまま通る
- x86・x64 の `cargo test --all`・clippy、`pasta_lsp` の WASM のビルドがすべて通る
- `tech.md` の mlua の版、`roadmap.md` の前提（`pasta_lua` を触る後の spec がギャップ分析をやり直す前提が満ちた）、マニュアルの Lua の基本の「前提」、版を書いたソースの説明を直した
