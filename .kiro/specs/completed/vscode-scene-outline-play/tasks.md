- [x] 1. 解析器がシーンの並びを作る

  - 名前・種類（グローバルかローカルか）・見出しの位置・範囲・子を持つ、エディタに寄らない公開の項目の型を作り、JSON の欄の名前と種類の綴り（`global`・`local`）を設計の API Contract のとおりにする
  - 解析の結果に欄 `scenes` を `tokens`・`diagnostics` の後ろに足し、全体の解析と部分解析の両方の分かれで、着色に渡すのと同じ構文木から並びを作る（構文木を作り直さない）。統合試験は公開の `analyze` の結果の `scenes` を通して確かめる（並びを作る関数は crate の外から呼べないため）
  - 欄を足すと構造体の値で結果を作る `transport.rs` の JSON の形の試験がコンパイルできなくなるので、同じタスクで、子を 1 つ持つグローバルシーンの `scenes` を足して欄の名前・順・種類の綴りを固定する（形の試験はこのタスクだけが触る）
  - グローバルシーン（続きのシーンを含む）を 1 つずつ項目にし、続きのシーンは受け継いだ名前にする。名前のあるローカルシーンだけを子にし、名前の無い最初の部分・作り物の位置のシーン・アクター辞書・単語定義・属性は項目にしない
  - 見出しの位置を、見出しの行の最初の空白でない文字から行の終わり（`\r` を除く）まで、0 始まりの行・UTF-16 の列で出す
  - 新しい試験で、要件の例の文書の項目の名前・種類・見出しの位置・子の並びが設計の JSON の例と同じになり、全角と半角の印が同じ木になり、コードブロックの中・コメントの行・名前の無い最初の部分が項目にならず、空の文書とアクター辞書・単語定義だけの文書が空の並びになり、サロゲートペアと全角の空白を含む見出しの列が UTF-16 で合う
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.9, 1.10, 1.13, 2.4, 2.8, 3.2_

- [x] 1.2 シーンの範囲の式を pasta.dll と揃える
  - グローバルシーンは次のグローバルシーンの見出しの前の行まで（無ければ文書の最後の行まで）、ローカルシーンは同じ親の次のローカルシーンの見出しの前の行まで（無ければ親の最後の行まで）とし、「次の見出し」は並びに出た見出しだけで決める
  - 範囲の終わりを、その行の UTF-16 の長さ（`\r` を数えない）にし、改行で終わる文書は最後の改行の後ろの空の行の頭で終える。計算で panic しない
  - `crates/pasta_lua/tests/scene_identity_index_test.rs` の試験の文書を写した試験（写した元を注記に書く）で、終わりの行が pasta.dll の表と同じになる。シーンの後ろのアクター辞書の塊はそのシーンの範囲に入る
  - 改行で終わる・終わらない・CRLF の 3 通りで終わりの位置が決まりどおりになり、すべての試験の文書で「見出しは範囲に含まれる・子の範囲は親の範囲に含まれる・兄弟は重ならない」が成り立つ
  - _Requirements: 1.7, 1.8, 1.9_

- [x] 1.3 書きかけの文書の並びを確かめ、既存を壊していないことを確かめる

  - 3 つのシーンの真ん中に構文の誤りがある文書で、前後のシーンが出て誤りのシーンが出ず、前のシーンの範囲が次に出たシーンの見出しの前の行までになる試験が通る
  - 既存の `crates/pasta_lsp/tests` の試験を変えずに `cargo test -p pasta_lsp` が全部通る（LuaJIT のビルドの都合で `NoDefaultCurrentDirectoryInExePath` を外して走らせる）

  - 再生の部品（ファイルの絶対パスと 1 始まりの行を受ける部分）の形と、`package.json`（題・メニュー・分類）は変えない
