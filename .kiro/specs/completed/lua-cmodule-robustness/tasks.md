## Implementation Notes
- 1.2: 長いパスの道は `\\?\` に確定（CI run 39141129339、`LongPathsEnabled=0` の x86・x64 で依存 DLL も解けた）。8.3 名へ変える呼び出しは 3.1・3.2 に置かない。
- 1.2: ローダー（`LoadLibrary*`）は長いパスの設定の外にあり、接頭辞なしの 260 文字超えでも読める。前提の確かめは `GetFileAttributesW`（プロセスの側）とレジストリの直読み（OS の側）で行う。
- 1.2: `\\?\` の形で読んだモジュールに `GetModuleFileNameW` が返すパスは `\\?\` 付き。文言・ログに出すときは要件 2.7 に気をつける。
- 共通: CI は PR を作らず `gh workflow run build.yml --ref <branch>` で回す（draft PR の作成は分類器が拒んだ）。
- 共通: Bash ツールの引数ではバックスラッシュが潰れる。`\\?\` を含む編集は Edit/Write かスクリプトのファイルで行う。
- 3.1: `C:foo` のようにドライブの `:` を含む名前は区切りが無くてもパスとして基点の下で解く（`is_path`）。`resolve.rs` 先頭の `#![cfg_attr(not(test), allow(dead_code))]` は 4.1 で外す。
- 3.2: 理由の文言は `FormatMessageW` の 512 u16 のバッファ（LuaJIT は `FormatMessageA` の 128 バイト）。長い文言では LuaJIT が空になる差がある。6.3 の「LuaJIT と違う点」に書く。`win32.rs` 先頭の dead_code の許可も 4.1 で外す。
- 4.1: ラッパは `function(...)` の形で引数をそのまま渡す（設計の Lua の写しの `function(name, ...)` だと `pcall(ffi.load)` が `got nil` になり 6.4 を破る）。5.6 の比べるテストに `pcall(ffi.load)`（`got no value`）を入れる。
