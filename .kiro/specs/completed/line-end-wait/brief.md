# Brief: line-end-wait

## Problem

ghost_dev のゴースト「窓際のぱすたさん」（pasta-in-windows・縦書きバルーン）の作者からの要望（2026-11-25。ghost_dev 側のセッションが、作者の指示で起こした）。

縦書きなので、辞書の 1 行（アクション行・継続行）が画面の 1 列になる。「？」「！」で終わる行の次の行は、始まるのが少し早い。作者は、そのたびに行末へ `\_w[500]` を手で足している。

- 今の設定（`ghost_dev/debug/pasta-in-windows-debug/ghost/master/pasta.toml`）: `[talk]` `script_wait_normal = 90`・`script_wait_period = 1200`・`script_wait_comma = 600`・`script_wait_strong = 750`・`script_wait_leader = 300`。`chars_period` に絵文字を多数足してある（ギャルは句点の代わりに絵文字で締める）。`[ghost] line_newlines = 1.8`。
- 行末の「？」の後は 700ms（750−50）、「。」の後は 1150ms。手で足した 500ms を加えると 1200ms で、「。」の行末とほぼ同じになる。作者は、行が終わるときは「。」でも「？」でも同じくらいの間が欲しい。
- 行の途中の「？」「！」は今の短い間がちょうどよい（「明日は晴れ？それとも、雨？」「喋りすぎたかな？ふふ。」「お休みですか？　それとも、さぼり？」）。`script_wait_strong` を上げると、行の途中が間延びする。今の `[talk]` では行末と行の途中を分けられない。

辞書の数（2026-11-25、ghost_dev の `dic/*.pasta` のアクション行・継続行。ghost_dev 側の集計）:

| 行の最後の字 | 行の数 | 行末に手で `\_w` を足した行 |
|---|---|---|
| 「。」 | 696 | 2 |
| 「？」「！」 | 346 | 40（`\_w[500]` が 36、`\_w[1000]` が 4） |
| 「、」 | 179 | 1 |
| リーダー「‥」 | 39 | 2（`\_w[1200]`） |
| 句読点なし（その他） | 195 | 26（`\_w[1200]` が 18 など） |

- 行の途中の「？」「！」は 84 か所。
- 「句読点なし」で手で足しているのは、主に幼稚園児の「妹」の台詞（句読点を打たない話し方。「ぱすたおねえちゃん　こんにちは\_w[1200]」）と、「‥‥」で終わる行（「お母さんに怒られた‥‥\_w[1200]」）。

作者の心配: 待ちを入れる方向だけで調整されると、演出のために待ちを消したいときに手段が無くなる。

## Current State

- 自動の待ちは `crates/pasta_lua/src/sakura_script/wait_inserter.rs` の `insert_waits` が入れる（`sakura-script-wait` で作った。completed）。字の種類ごとに `値 − 50` を入れる。
  - ふつうの字とリーダーは、クラスタ 1 つごとに 1 つ。
  - 句点・読点・強調（？！）・行頭禁則（」など）は、続く並びの最後にまとめて、並びの中で一番長い値を 1 つ入れる（「？」」は `？」\_w[700]`）。
  - さくらスクリプトのタグは待ちを入れず、並びを打ち切る。辞書に書いた `\_w[500]` は sakura_script トークンとして同じ変換を通り、タグとしてそのまま残る。だから今は、自動の待ちに**足される**（`？\_w[700]\_w[500]`）。
- 値は `[talk]`（`crates/pasta_lua/src/loader/config/sections.rs` の `TalkConfig`）と、アクターの表の `script_wait_*` 5 キー（`sakura_script/mod.rs` の `resolve_wait_values`。アクター → `[talk]` → 既定の 3 段）で決まる。アクターの表は `talk_to_script` のたびに読み直す。
- 変換の単位は、アクターのまとまりの中で続く台詞をつないだ 1 つのテキスト（`act.lua` の `merge_consecutive_talks`）。行の切れ目は、変換に渡る時点では消えている。
- 行の頭の印は、もうある。トランスパイラはアクション行と継続行の頭に必ず `act:line()` を出す（`code_gen/element_gen.rs`）。ただし `ACT_IMPL.line` が台詞に継ぎ目（`seams`。行の頭のバイト位置）を付けるのは、`[ghost] line_newlines` が nil でも 0 でもないときだけ（`actor-line-newlines` で作った。completed）。継ぎ目は `merge_consecutive_talks` でずらしてつながれ、`sakura_builder.lua` の `join_lines` が、継ぎ目と字の見え方（`read_unit`）を見て行の改行を差し込む。
- 行の頭に割り付けの単語が来る書き方がある。ghost_dev の `＠左` は `\_l[-283,0]`（`dic/layout.pasta`）で、`：＠左　＠苦笑い　わたしの部屋、…` のように継続行の頭に置く。その前の行の行末は、継ぎ目の前の最後の字で決まる。

## Desired Outcome

- 行末の句読点（または字）の後の待ちを、行の途中とは別に設定できる。例（ghost_dev の値で、行末の強調を 1200 にしたとき）:

  ```
  ：明日は晴れ？それとも、雨？
  ：じゃあ、行ってきます。
  ```

  - 今: `…れ\_w[40]？\_w[700]そ…、\_w[550]雨\_w[40]？\_w[700]`（行末も 700）
  - 後: `…れ\_w[40]？\_w[700]そ…、\_w[550]雨\_w[40]？\_w[1150]`（行の途中の「？」は 700 のまま、行末だけ 1150）
- 未設定なら、今とバイト単位で同じさくらスクリプトになる（既存のゴーストの出力を変えない）。
- 演出のために、特定の行末の自動の待ちを消せる・変えられる。
- `[actor."名前"]` で、アクターごとに変えられる（妹の行末だけ長くする、など）。
- 句読点の無い行末・リーダーで終わる行末にも、行末の待ちを設定できる。
- ghost_dev の作者が、手で足した `\_w` を外せる（外すのは pasta の対応が入った後に ghost_dev 側で行う）。

## Approach

推奨（要件の議論で決める。下の「要件で決めること」）:

1. **字の種類ごとの行末のキー**を足す。今の `script_wait_*` 5 キーと 1 対 1 の、行末用の 5 キー（名前は要件で決める。例: `script_wait_period_eol`）。未設定のキーは、行の途中の値（今の `script_wait_*`）に落ちる。行末のキーを 1 つにまとめる案より、表の「その他」（句読点の無い行末）を「？」と別に決められる。ghost_dev の数では、その他の 195 行のうち手で足したのは 26 行だけなので、まとめると多くの行に要らない間が入る。
2. **アクターの上書き**は、今の `resolve_wait_values` の 3 段（アクター → `[talk]` → 既定）にそのまま 5 キーを足す。行末のキーが未設定なら、そのアクターの行の途中の値に落ちる（アクター → `[talk]` の行末 → 行の途中、の順は要件で決める）。
3. **行末を知らせる**: `ACT_IMPL.line` が付ける継ぎ目を、行末の待ちのためにも付ける（今は `line_newlines` があるときだけ）。変換に、行の終わりの位置を渡す。行末は「継ぎ目の前の、最後の見える字（または並び）」と、「アクターのまとまりの最後の見える字」。継ぎ目の前に `＠単語` が展開したタグや `\s[…]`・`\_l[…]` だけが続いても、その前の字が行末である。
4. **消す・変える手段**は案 A を推奨する: 行末の句読点（並び）のすぐ後ろに作者が書いた `\_w[…]` は、自動の行末の待ちに足さず、置き換える（`\_w[0]` で消せる）。ただし、**その行末に行末のキーが効いているときだけ**置き換える。行末のキーを書かないゴーストは、今のまま足される。作者は「行末をこれだけ待つ」と、欲しい長さを書けばよい（新しい語彙を覚えなくてよい）。案 B（今の動きのまま、行末の自動の間を入れない印を別に設ける）は、DSL に語彙が 1 つ増え、作者の自然な書き方（行末に欲しい `\_w` を書く）から離れるので、推奨しない。

却下した案:
- `script_wait_strong` などを全体で上げる: 行の途中が間延びする（作者が困っていることそのもの）。
- 行末のキーを 1 つにまとめる: 上の 1. の理由。要件の議論で比べ直してよい。
- 案 A を無条件に入れる（行末のキーが無くても置き換える）: `。\_w[500]` を行末に書いた既存のゴーストの出力が変わる。

## Constraints

- 未設定なら、今とバイト単位で同じ出力。`hello-pasta` などの見本ゴーストの出力も変えない。
- `[talk]` は `TalkConfig` へ `try_into().ok()` で読むので、型の合わない値を書くと、ウェイトの設定が黙って既定に落ちる（今もそう）。新しいキーで、この落ち方を広げない（書き間違いが分かるようにするかは要件で決める）。
- アクターの表は `talk_to_script` のたびに読み直す。行末のキーも同じ読み方にする（Lua で書き換えれば次の台詞から効く）。
- 縦書き（ghost_dev）でも横書きでも同じ規則にする。バルーンの向きで分けない。
- x86 と x64 の両方でテストを走らせる。

## 要件で決めること（作者に確かめたい点を含む）

1. キーの名前と単位（字の種類ごと 5 キーか、行末として 1 つか）。推奨は種類ごと。既定値は「未設定＝行の途中の値」。
2. 「行末」の定義。推奨は、アクション行の終わりと継続行の終わりの両方。話者が替わる所と、同じ話者の列が続く所は分けない（作者に確かめる。縦書きでは、どちらも列の終わり）。トークの最後（スクリプトの終わり）の行末も同じに扱う。
3. 行頭禁則の字や句読点が続いて終わるとき（「？」」「！？」）。推奨は、今と同じく並びの最後に 1 つだけ入れ、値は並びの中の字の種類ごとの行末の値の一番長いもの。
4. 行末の後ろにタグや `＠単語` だけが続くとき。推奨は、見える字が無ければ行末とみなし、待ちは今と同じく句読点の直後（タグの前）に入れる。
5. 消す・変える手段。推奨は案 A（行末のキーが効く行末だけ、すぐ後ろの `\_w[…]` が置き換える）。「すぐ後ろ」に `\s[…]` などのタグを挟んだ `\_w` も含めるかは要件で決める。案 A では、ghost_dev の 40 か所の `\_w[500]` は外し、`\_w[1000]` の 4 か所は欲しい長さに書き直すことになる（作者に確かめる）。
6. アクターの上書きの順（アクターの行末 → `[talk]` の行末 → アクターの行の途中 → `[talk]` の行の途中、か）。
7. 句読点の無い行末（ふつうの字）・リーダーで終わる行末にも行末の値を持つか。推奨は持つ（5 キーの中に含まれる）。妹の台詞だけ長くするなら、妹のアクターに行末のふつうの字の値を書く。ただし、妹の行の中で行末の間が要らない行（手で足していない行）にも入るので、作者に確かめる。
