## 1. 結論

1. **撮るのはノート PC の画面（主画面）1 枚**。窓だけの録画ではゴーストが入らない。開発者は左の画面で作業を続け、ノート PC の画面は撮影の間だけ「舞台」にする。
2. **舞台は画面の右下の 2/3（1920×1200・16:10）。表示の倍率は 100% のまま**。pasta-recipe の窓とゴーストをこの隅に寄せ、録画の後に Openscreen の切り抜き（`cropRegion`）でこの範囲だけにする（開発者の案。2.1・2.2 節）。ゴーストは普段どおり画面の下の辺に立つ。
3. **舞台の後ろは無地の白の窓**（`book/SCREENSHOTS.md` の決まりと同じ）。壁紙は映さない。Openscreen の飾り（背景・余白・枠・角丸・影）は全部切る。動画はマニュアルの白いページの続きに見える。
4. **左に pasta-recipe、右にゴースト**を重ねずに並べる。pasta-recipe の窓は「1 回の寄りで窓の全部が入る大きさ」（およそ 900×560）にする。ゴーストは SSP の拡大率 100% で、窓とほぼ同じ大きさに並ぶ。
5. **カメラの位置は 3 つだけ**: 「引き（舞台の全部）」「手元（pasta-recipe の窓）」「ゴースト（立ち絵と吹き出し）」。押すときは手元、喋るときはゴーストへ横に流す。回転（3D）は使わない。
6. **撮るファイルは 1 つ（`10-save.pasta`）で通す**。「N 回目だよ！」の数が鳴らすたびに増えるので、鳴らし直したことが台詞で分かる。終わりは、保存変数を 99 に書き換えた後にもう一度鳴らして「100 回目だよ！」で締める。
7. **画面の文字は、操作の名前の短い見出しを 5 つだけ**。台詞や説明を文で流す字幕は付けない。矢印も題名も付けない。
8. **長さは約 80 秒・1152×720（16:10）・30 fps・音声なし**を目安にする。5 MB に余るなら 1728×1080 にする。

## 2. 決定どうしの縛り合い

次の 5 つは、1 つを変えるとほかが動く。この順で決めると戻りが少ない。

| 決めること | 縛るもの | 理由 |
| -- | -- | -- |
| どの画面を撮るか・どこを切り抜くか | 舞台の広さと形（16:10）・書き出しの形 | 録画は画面 1 枚。映す範囲は、録画の後に切り抜きで決める |
| 表示の倍率（100%・150%・200%） | 舞台の広さ（論理 px）・寄りの深さ・寄りの鮮やかさ・引きの画の埋まり方・SSP の拡大率 | 画面の画素は 2880×1800 で変わらない。倍率は、同じ窓が画素をいくつ使うかを決める（2.1 節） |
| 寄りの倍率 | pasta-recipe の窓の大きさ・エディタに入る行の数・文字の大きさ | 寄ったときに見える範囲は「舞台 ÷ 倍率」。窓をその範囲に合わせる |
| pasta-recipe の窓の大きさ | ゴーストの置ける幅・SSP の拡大率・撮る辞書の行の数 | 2 つを重ねずに横に並べる。幅の合計は舞台の幅まで |
| 撮る辞書（写しの中身） | エディタの行の数・台詞の長さ・絵コンテの秒 | 行が多いと窓が大きくなり、寄りが浅くなって文字が小さくなる |

### 2.1 表示の倍率（開発者の設定）

主画面の画素は 2880×1800 で、倍率を変えても変わらない。変わるのは、pasta-recipe の文字と窓が画素をいくつ使うかである。SSP のゴーストは SSP の側の拡大率で決まり、Windows の倍率とは別に選べる。

文字の大きさは次の式で見積もった（本文の幅 750 px で再生したとき）。

```text
本文の幅での文字の高さ（px）＝ 画面の上の文字の高さ（物理 px）× 寄りの倍率 × 750 ÷ 2880
```

pasta-recipe の窓を論理 900×560（エディタに 12〜13 行）にして、寄りで窓を画いっぱいにしたときの比べ。

| 見る点 | 100%（いま）で画面の全部 | 150% で画面の全部 | 200%（前の設定）で画面の全部 |
| -- | -- | -- | -- |
| 舞台（論理 px） | 2880×1800 | 1920×1200 | 1440×900 |
| pasta-recipe の文字（13 px）の物理 px | 13 | 19.5 | 26 |
| 引きの画での文字（本文の幅） | 3.4 px（読めない） | 5.1 px（読めない） | 6.8 px（読めない） |
| 窓が舞台の幅に占める割合 | 31% | 47% | 62% |
| 手元の寄り | 約 3.0 倍 | 約 2.0 倍 | 約 1.5 倍 |
| 手元の寄りでの文字（本文の幅） | 約 10 px | 約 10 px | 約 10 px |
| 手元の寄りに入る元の画素（横） | 約 960。書き出しの 1152 より少なく、引き伸ばしでぼける | 約 1440。足りる | 約 1920。足りる |
| ゴースト（SSP の拡大率）が占める幅 | 100% で 31% | 150% で 47% | 100% で 31%（200% にすると 62% で、窓と並ばない） |
| ゴーストの寄り | 約 3.0 倍（元の画素 約 960。ぼける） | 約 2.0 倍（足りる） | 約 3.0 倍（ぼける） |
| 寄りの出入りの長さ | 約 1.2 秒 | 約 1.0 秒 | 0.8 秒と 1.2 秒が混ざる |
| 引きの画 | 広い地の中に小さな物が 2 つ。3 割強が空く | 同じ大きさの 2 つが舞台を埋める | 窓が大きく、ゴーストが小さい |

- **どの倍率でも、引きの画では文字は読めない**。引きは「どこに何があるか」を見せる画で、読ませるのは寄りだけである。目安は `SCREENSHOTS.md` と同じ「10 px 以上」とする。
- **寄りでの文字の大きさは、倍率を変えても約 10 px で変わらない**。窓を画いっぱいにするので、決め手は窓の論理の幅（900）である。文字を大きくしたければ、倍率でなく窓を狭くする（4 節の分ける案）。
- 倍率で変わるのは、鮮やかさと引きの画である。100% は、寄りが元の画素を引き伸ばすのでぼけ、全画面で見ても細かくならない。Openscreen は「録画がぼける手前」より深い寄りを断るので、約 3 倍の寄りそのものが通らないおそれもある。
- 150% は、窓とゴーストが同じ大きさになる。手元の寄りとゴーストの寄りが同じ深さ（約 2 倍）になり、横に流すときに大きさが変わらない。寄りはどちらも足りる画素で映る。
- 200% は、手元は最も鮮やかだが、ゴーストだけ深い寄りになってぼける。`SCREENSHOTS.md` の「表示 200%・SSP 100%」は、立ち絵を 1:1 で写す静止画のための決まりで、縮めて映す動画には要らない。
- 上の表は、画面の全部を映すときの比べである。切り抜きを使うと、100% のままで 150% の列と同じ画が作れる（2.2 節）。
- **決定**: 100% のまま、隅に寄せて切り抜く。SSP のシェルとバルーンも 100%。
- 吹き出しの文字は SSP 100% で約 12 px と見込んだ。立ち絵と吹き出しのかたまり（約 894×613）を画いっぱいにすると、本文の幅で約 10 px になる（入門ガイドの絵と同じ大きさ）。

### 2.2 隅に寄せて切り抜く（開発者の案。これに決める）

表示 100% のまま、小さめの pasta-recipe の窓とゴーストを画面の隅に寄せ、その範囲だけを映す。

- 寄せる範囲は、窓（900×560）とゴースト（SSP 100% で約 894×613）を並べた 1920×1200 である。画面（2880×1800）の右下の 2/3 に当たる（ゴーストは下の辺に立つ）。形は画面と同じ 16:10 にする。
- 録画は画面の全部で撮り、編集で `setClipRange` の `cropRegion` を `{x: 0.3333, y: 0.3333, width: 0.6667, height: 0.6667}` にして、この範囲だけにする。寄り・見出し・書き出しは、切り抜いた画の上でいつもどおりに働く。道具は Openscreen だけで済む（要件 7.1 のまま）。
- 「引き」は、切り抜いた画を寄らずに映した画である。始めと終わりの「拡大せずに全体」（要件 2.3）にそのまま合う。
- **映る画は、表示 150% で画面の全部を映すのと同じになる**。窓とゴーストが画に占める割合（どちらも約 47%）も、寄り（どちらも約 2 倍）も、寄りで読める文字の大きさ（約 10 px）も同じである。
- 違いは画素の数である。手元の寄りに入る元の画素は横 約 960 で、150% のとき（約 1440）の 2/3 になる。1152×720 の書き出しでは 1.2 倍の引き伸ばしになり、少し甘く映る。本文の幅（750 px）で見る分には、元の画素のほうが多いので差は出にくい。全画面や高精細の画面で見ると差が出る。
- ファイルの大きさは、書き出しの大きさと動きの量で決まる。倍率では変わらない。

比べ:

| 見る点 | 100% のまま隅を切り抜く（採る） | 150% にして画面の全部を映す |
| -- | -- | -- |
| 映る画・文字の大きさ | 同じ | 同じ |
| 寄りの鮮やかさ | 少し甘い（元の画素 約 960） | くっきり（約 1440） |
| 開発者の操作 | 無い（いまの設定のまま） | 倍率を変えて、後で戻す |
| 白の窓 | 隅の 1920×1200 を覆えば足りる | 画面の全部を覆う |
| 道具 | Openscreen の切り抜き | 切り抜きは要らない |

- **決定**: 100% のまま隅を切り抜く。開発者の案で、いまの設定のまま撮れ、道具は Openscreen だけである。
- **切り替えの決まり**: 試し撮りを 1152×720 で書き出し、手元の寄りのコマ（`getFrames`）でエディタの台詞と出力の欄の字がにじんで読みにくければ、150% で画面の全部を映す案に切り替える（そのときだけ、開発者に倍率の変更を頼む）。配置の数字（4 節）は、論理 px でそのまま使える。
- 採らない方法: 書き出しの後に ffmpeg で切る（寄った後の画を切ることになり、寄りの画が欠ける）。動画の全部に浅い寄りをかけ続けて切り抜きの代わりにする（切り抜きがあるので要らない）。

切り抜きを使うときに、設計で気を付けること:

- `setPointerTrack` に渡す位置は、**録画した画面（2880×1800）に対する割合**である。切り抜いた画に対する割合ではない。
- 寄りの中心（`addZoom` の `focus`）と見出しの位置が、切り抜いた画に対する割合かどうかは、定義からは読み切れない。試し撮りで確かめる。ぼかし（使わない見込み）は録画の画に付く。
- 書き出しの形が切り抜いた範囲の形（16:10）に従うこと。従わないときに備えて、切り抜きは画面と同じ 16:10 にしてある。

## 3. 撮り方

### 3.1 画面か窓か

| 案 | 中身 | 判定 |
| -- | -- | -- |
| 窓を撮る | pasta-recipe の窓だけ | 採れない。ゴーストは別の窓なので映らない（要件 1.1） |
| 画面を撮る | 画面 1 枚の全部を録画し、映す範囲を切り抜きで決める | 採る。映したくない物は、切り抜く範囲に置かないことで外す |

### 3.2 どの画面か

確かめた事実（2026-11-15）:

| 画面 | 位置 | 大きさ | タスクバー | 使い道 |
| -- | -- | -- | -- | -- |
| DISPLAY1（主画面・ノート PC） | 右 | 2880×1800（いまは 100%。前は 200%） | 自動で隠してある（作業域は画面の全部） | 開発者が空けた。**舞台にする** |
| DISPLAY2 | 左 | 論理 1707×1067（2560×1600・150% と見込む） | 無い | 開発者が作業する |

- Openscreen の `listSources` は「画面 1」（index 0）と「画面 2」（index 1）を返す。どちらが主画面かは道具からは分からない。撮る前に、短い試し撮りのコマで確かめる。
- 主画面を使う良い点: 画素が多く（2880×1800）、寄りが鮮やかに映る。SSP のゴーストは主画面に出るので、動かす距離が短い。
- 主画面の気になる点だったタスクバー・通知・アイコンは、開発者の設定で片付いた。

### 3.3 残る危うさと、開発者に頼むこと

- 隠れたタスクバーは、本物のポインタが主画面の下の辺に触れると出てくる。知らせのあるアプリが光ったときも出ることがある。CDP の操作では本物のポインタは動かず、`setPointerTrack` が描くポインタはタスクバーを出さない。
- 開発者に頼むことは 3 つ: 撮影の間（約 3 分）、ノート PC の画面に窓を動かさない・ノート PC の画面へマウスを入れない（下の辺でタスクバーが出る。窓の上に乗るとボタンの色が変わる。ゴーストに乗ると触り反応が出る）・ノート PC の画面を押さない（白の窓が前に出て pasta-recipe を隠す）。
- 本物のポインタそのものは動画に映らない（Openscreen はポインタをデータで持ち、`setPointerTrack` で入れ替える）。
- Openscreen の録画のバーとカウントダウンが主画面に出るかは分からない。出るなら、頭の数秒を切る。
- 書き出したコマの確かめ（要件 3.3）で、タスクバーが出たコマが無いことも見る。出ていたら撮り直す。

### 3.4 壁紙か、白の窓か

アイコンと通知が無くなったので、白の窓が無くても個人の情報の心配は壁紙だけになった。それでも白の窓を推奨する。

| 見る点 | 壁紙のまま（前提 A6） | 白の窓（`SCREENSHOTS.md`） |
| -- | -- | -- |
| 個人の情報 | 壁紙が私的な絵なら映る。開発者が見て決める | 映らない |
| 見やすさ | 絵柄があると、吹き出しの縁・窓の縁・ポインタが埋もれる | 文字と立ち絵だけが立つ。吹き出しが溶けるなら薄い灰色 |
| マニュアルとのなじみ | 動画だけ別の世界に見える | 白いページの続きに見える。入門ガイドの絵と同じ地 |
| 大きさ | 絵柄は、寄りと流れのたびに符号の量を食う | 無地はほとんど食わない。5 MB に収めやすい |
| 「デスクトップで動いている」感じ | 出る | 薄い。ただしゴーストが画面の下の辺に立つので、足元で伝わる |
| 手間 | 無い | 白の窓を 1 枚開く。押すと前へ出るので、3.3 節の頼みごとが要る |

## 4. 舞台の配置

切り抜いた範囲（1920×1200）の中の px（表示 100% なので物理 px と同じ。範囲の左上が原点で、画面の上では 960・600 に当たる）。数字は目安で、試し撮りで合わせる。

```text
0                                                                      1920
+------------------------------------------------------------------------+ 0
|  白の窓（舞台の地）                              見出しの出る所 →  [1 …] |
|                                                                        |
|                                                                        |
|                                                                        |
|  40                           940        +----------+ +----------+     |
|  +-----------------------------+ 600     | 吹き出し | | 吹き出し |     |
|  | hello-pasta - pasta-recipe… |         +----------+ +----------+     |
|  +-----------------------------+                                       |
|  | [SHIORI をリロード]         |                                       |
|  +--------+--------------------+             男の子     女の子          |
|  | ツリー | ▶ シーンを実行｜値…|            (立ち絵)   (立ち絵)         |
|  |        | ＊会話             |                                       |
|  |        | 　女の子：…        |                                       |
|  +--------+----------+---------+                                       |
|  | 出力              | 保存変数|                                       |
|  +-------------------+---------+ 1160                                  |
+------------------------------------------------------------------------+ 1200
   ←── 手元の画（寄り約 2 倍）──→          ←─ ゴーストの画（寄り約 2 倍）─→
                                            ゴーストは画面の下の辺に立つ
```

| 部品 | 置き方 | 理由 |
| -- | -- | -- |
| 白の窓 | 切り抜く範囲より一回り大きく（画面いっぱいでもよい）。無地の白。吹き出しの縁が溶けるなら薄い灰色 | `SCREENSHOTS.md` と同じ。壁紙とアイコンを映さない |
| pasta-recipe の窓 | 左の下寄り。およそ 900×560。下の辺は画面の下から 40 ほど上（下の辺に付けない）。1 回の寄り（約 2 倍。見える範囲 960×600）に窓の全部が入る | 手元の画が 1 つで済む。押す所（見出しの上・ツールバー）・窓（値を入れて実行・書き換え）・結果（出力・保存変数）が全部同じ画に入る |
| ゴースト | 右。画面の下の辺に立ったまま（SSP の普段の位置。動かすのは横だけ）。SSP のシェルとバルーンは 100%（立ち絵 333×500 の等倍。かたまりは約 894×613 で、窓とほぼ同じ大きさ） | 重ねない。上へ動かす細工が要らない。「デスクトップに立っている」ことが足元で伝わる |
| 間 | 窓とゴーストの間・舞台の端に 20〜40 の白 | 寄ったときに隣の物の端が入らない |

- pasta-recipe の窓に入るエディタの行は、およそ 12〜13 行である（窓の高さ 560 から、題名・ツールバー・タブ・下の欄 180 を引く）。撮る辞書を短く保つ理由はここにある（8 節）。
- 下の欄は高さ 180 で、左が出力、右が保存変数である。頭の行は長いので、出力の欄の中で 2〜3 行に折り返す。
- 窓が 560 の高さに収まらないとき（行・窓・保存変数の表が切れる）は、窓を 780×640 ほどにして、手元の画を上と下の 2 つに分ける（寄りを 2 割ほど深くする）。カメラの位置は 1 つ増えるが、文字は 12 px になる。**規則**: 文字 10 px 以上を満たす中で、カメラの位置がいちばん少ない案を採る。
- ゴーストと pasta-recipe を重ねる案（今の VSCode の動画の形）は採らない。ゴーストが下の欄（保存変数の表）を隠し、吹き出しがエディタにかかるからである。
- SSP の拡大率は、表示の倍率と同じ 100% にする（立ち絵は等倍で、`SCREENSHOTS.md` の絵と同じ見え方になる）。窓とゴーストが同じ大きさに並び、2 つの寄りが同じ深さになる。

## 5. カメラの言葉

### 5.1 3 つの画

| 名前 | 映す範囲 | 役目 | 使う所 |
| -- | -- | -- | -- |
| 引き | 舞台の全部 | どこに何があるかを見せる | 始め・終わり・話の切れ目（1 回） |
| 手元 | pasta-recipe の窓の全部 | 押す所と、窓の中に出る結果を読ませる | 押すとき・出力の欄・保存変数の表 |
| ゴースト | 立ち絵と吹き出し | 台詞を読ませる | ゴーストが喋るとき |

### 5.2 規則

1. **押すときは手元、喋るときはゴースト**。押した直後（0.3 秒後）に、手元からゴーストへ横に流す（Openscreen の「続いた寄り」。1 秒で流れる）。寄りを解いて寄り直さない。
2. **結果が窓の中に出るときは、カメラを動かさない**。出力の欄や保存変数の表は手元の画に入っているので、ポインタを結果のそばへ滑らせて「ここ」と指す。押さない。
3. **待ちは、止まった画の上で切る**。読み込み直しの待ちは、カメラがゴーストの画に着いた後、台詞が出る前の止まった絵で切る。寄りの出入りと流れの最中は切らない（画が飛ぶ）。
4. **速めるのは手の動きだけ**。打ち込みと窓への入力は 1.5〜2 倍に速める。ゴーストの台詞は等倍のまま映す（喋る速さはゴーストの持ち味である）。
5. **台詞が出そろってから 2 秒以上止める**（前提 A5）。その後に手元へ戻る。
6. **`setPointerTrack` が自動で付ける寄りは使わない**。自動の寄りは押した所だけに寄り、離れた所に出る台詞を映さない。自動の寄りを消し、上の規則で寄りを置き直す。
7. **回転（3D）・背景の動き・動きのぼかしは使わない**。映すのは文字で、傾けると読めなくなる。大きさも増える。
8. **ポインタ**: 矢印・大きさは 2 倍ほど・押したときの弾みと波紋を付ける。音が無いので、押した瞬間は波紋で見せる。
9. **▶ はいつもエディタの見出しの上から押す**。ツリーのメニューは使わない。押す所が毎回同じなので、見る人は 1 回で場所を覚える。

### 5.3 手順ごとの対応

| 要件 | 押す所（手元） | 結果の出る所 | カメラ |
| -- | -- | -- | -- |
| 1.2 ▶ シーンを実行 | `＊会話` の見出しの上の「▶ シーンを実行」 | ゴーストの台詞 → 出力の欄 | 手元 → ゴースト → 手元（ポインタで出力の欄を指す） |
| 1.3 書き換えて ▶ | エディタの男の子の行 → 同じ「▶ シーンを実行」 | ゴーストの台詞 | 手元 → ゴースト → 手元 |
| 1.4 値を入れて実行… | `＊天気` の見出しの上の「値を入れて実行…」→ 窓 →「鳴らす」 | ゴーストの台詞 | 手元 → ゴースト → 引き（切れ目） |

## 7. 画面の文字

### 7.1 推奨: 操作の名前の見出しを 5 つだけ

| # | 見出しの文 | 出す間 |
| -- | -- | -- |
| 1 | 1　▶ シーンを実行 | 3〜16 秒 |
| 2 | 2　台詞を直して、もう一度 ▶ | 16〜30 秒 |
| 3 | 3　値を入れて実行… | 30〜47 秒 |
| 4 | 4　SHIORI をリロード | 50〜58 秒 |
| 5 | 5　保存変数を書き換え… | 58〜79 秒 |

- 置く所: 画の右上の隅に固定する（Openscreen の文字は画の枠に付くので、寄っても流れても動かない）。手元の画では窓の題名の右の空きに、ゴーストの画では白の地に乗る。ボタンや台詞に重ねない。
- 形: 濃い色の板に白い字・1 行・現れ方は「ふわっと出る」だけ。打ち出し・跳ねる動きは使わない。
- 文は、画面のボタンやメニューの名前をそのまま使う（要件 1.7）。番号は、動画の前の説明の番号と同じにする。
- 始めと終わりの引きには出さない。題名も出さない（章の見出しが題名である）。
- 矢印は使わない。指すのはポインタの役目である。

### 7.2 「字幕を付けない」との関係

brief の範囲外は「音声や字幕を付けること」である。見出しは字幕ではないと考える。

- **字幕**は、流れに合わせて台詞や説明を文で出し続けるもの。読む量が増え、画面の文字と取り合いになり、文を直すたびに撮り直しになる。これは付けない。Openscreen の字幕の機能（音声の書き起こし）も使わない。
- **見出し**は、いまどの操作かを示す名前だけである。5 つで、文ではない。音の無い動画では、途中から見た人や戻して見る人が、いまどこかを知る手掛かりがほかに無い。
- 見出しの文は画面の名前の写しなので、名前が変われば動画そのものが撮り直しになる。見出しのせいで撮り直しが増えることはない。
- 範囲外の言い方を「音声・ナレーション・台詞や説明を文で流す字幕」に直し、見出しは要件に入れる（10 節）。

見出しも付けない案（画だけ）も成り立つ。そのときは、動画の前の説明の番号だけが手掛かりになる。

### 7.3 動画の前の説明と動画の分け方

| 説明の文が受け持つこと | 動画が受け持つこと |
| -- | -- |
| 操作の順（番号 1〜5。見出しと同じ名前） | 押す所はどこか |
| 画面のどこを見るか（右がゴースト・左下が出力・右下が保存変数） | 押した後に何がどこに出るか |
| 音声が無いこと・長さ（約 80 秒） | 待ちの長さの感じ（切ってあることは文で断る） |
| 撮ったゴーストは入門ガイドの hello-pasta の写しで、`＊天気` は撮影のために足したこと | — |

- 仕組み（保存・読み込み直し・`OnPastaSceneAt`）は説明の文に書かない。すぐ下の小節が書いている。
- 説明は 1 段落でもよいが、番号の付いた短い並びのほうが、見出しの番号と突き合わせやすい。

## 8. 撮る中身（hello-pasta の写し）

### 8.1 写しに入れる変更

| 変えるもの | 中身 | 理由 |
| -- | -- | -- |
| 置き場所 | ユーザー名の入らない場所（例 `C:\pasta-demo\hello-pasta`） | 出力の欄に絶対パスが出る（9 節）。フォルダの名前は `hello-pasta` のまま（前提 A2） |
| `descript.txt` の `name` | `hello-pasta-demo` など、見て不自然でない名前 | 普段の SSP の hello-pasta と重なる。名前は出力の欄の頭の行に映る |
| `pasta.toml` | `[debug] enabled = true` を足す。`talk_interval_min`・`max` を 3600 にする | デバッグが要る。45〜75 秒ごとの自然なおしゃべりが撮影に割り込む |
| `dic/10-save.pasta` | 頭の説明のコメントを 1 行に縮め、下に `＊天気` のシーンを足す | エディタに入る行は 12〜13 行で、長いコメントは右で切れて見苦しい。入れた値を台詞に出すシーンが hello-pasta に無い |
| `profile/` | 持ってこない（保存変数が無い状態で始める） | 1 回目の ▶ が「1 回目だよ！」になる |

　男の子：＠困惑　……ずっと数えてたの？

### 8.2 動画で起きること

| 手順 | 操作 | ゴーストの台詞・画面の値 |
| -- | -- | -- |
| 1.2 | `＊会話` を ▶ | 「この話をするのは 1 回目だよ！」「……ずっと数えてたの？」 |
| 1.3 | 男の子の台詞を「……数えなくていいよ。」に書き換えて ▶ | 「2 回目だよ！」「……数えなくていいよ。」 |
| 1.4 | `＊天気` に `天気`・文字列・`雨` を入れて鳴らす | 「今日の天気は雨だって。」 |
| 1.5 | SHIORI をリロード | 出力の欄に要約 |
| 1.6 | 保存変数を表示 → `回数` を `99` に書き換え | 表の値が `2` → `99` |
| 締め | `＊会話` を ▶ | 「この話をするのは 100 回目だよ！」 |

- 1 つのファイルで通すので、タブを切り替えない。押す所はずっと同じ 2 か所（`＊会話` の上・`＊天気` の上）である。
- 数が 1 → 2 → 100 と変わるので、「鳴らすたびに読み込み直して本当に動いている」「書き換えた保存変数が効いた」が台詞だけで分かる。
- `天気`・`雨` は、`recipe.md` の「値を入れて実行」の例と同じである（要件 1.7）。
- 書き換える台詞は短くする。打つ字が少なく、吹き出しでも 1 行で読める。
- 採らなかった案: `13-calendar.pasta` に `行事`＝`バレンタイン` を入れる（既にあるシーンだけで済むが、入れた値が台詞に字として出ない。音の無い動画では伝わらない）。台本用のファイルを新しく作る（行は減るが、入門ガイドの 10 段目とのつながりが切れる）。

### 8.3 割り込みを避ける

- 自然なおしゃべり: `talk_interval` を延ばす（上の表）。
- 起動の台詞: 試験用の SSP は毎回 `OnFirstBoot` を喋る。喋り終わって吹き出しが消えてから撮り始める。
- 時報: 正時をまたいで撮らない（毎時 55 分〜5 分は撮らない）。
- 触り反応: 本物のマウスをゴーストに乗せない（3.3 節）。

## 12. 設計で確かめること

試し撮り（数秒）で確かめる。どれも、いまは読み取りだけなので確かめていない。

- `listSources` の「画面 1」が主画面か。録画のバーとカウントダウンが撮る画面に映るか。
- 形を「録画のまま」（16:10）にして飾りを切ったとき、書き出しが切り抜いた範囲をそのまま映すか。
- 寄りの倍率の上限（録画がぼける手前で断られる）。約 2 倍の寄りが通るか。
- 切り抜き（`cropRegion`）の後で、寄りの中心と見出しの位置が切り抜いた画に対する割合になるか。書き出しの形が 16:10 のままか。書き出しの「元のまま」の高さが切り抜きの高さ（1200）になるか。
- 手元の寄りのコマで、字がにじまずに読めるか（2.2 節の切り替えの決まり）。
- 続いた寄りで、手元からゴーストへなめらかに流れるか（倍率が違う組み合わせになったときも）。
- pasta-recipe の窓を 900×560 にしたとき、エディタの行・値を入れて実行の窓・保存変数の表（表の上の注意書きを含む）が切れずに入るか。エディタの文字の大きさ（14 px と見込んだ）。
- 前面でない pasta-recipe の窓で、エディタのカーソルが見えるか（CDP の焦点のまねで補えるか）。題名の色が薄くなるのを許すか。
- ゴーストを横へ動かす方法（試験用の SSP には普段の MCP の道具が届かない。写しのシーンからさくらスクリプトで動かすか、開発者が 1 回ドラッグするか）。吹き出しが立ち絵のどちら側に出るか。表示 100% で、SSP の拡大率が 100% で始まるか。
- 白の窓を置いたとき、隠れたタスクバーの細い線が下の辺（切り抜く範囲の中）に残らないか。
- 保存変数を書き換えた後の ▶（読み込み直し）で、値が残って 100 になるか。読み取り専用の SSP でも保存先に書けるか。
- 入れた値が無いときの `＄天気` は動画に出ない（▶ では鳴らさない）が、`＊天気` の見出しの上の「▶ シーンを実行」を誤って押さない台本にする。
- 送り主の表示が吹き出しに出ないか。
- 1152×720・30 fps・約 80 秒で 5 MB に収まるか。1728×1080 でも収まるか。書き出した MP4 に音声のトラックが付くか。
