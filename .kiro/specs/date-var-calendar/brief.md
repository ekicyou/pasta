# Brief: date-var-calendar

## Problem

ゴーストの作者（pasta の開発者と同じ人。2026-11-14）が、祝日やゴーストの行事（誕生日・お正月など）の日に、その日らしいトークへ Lua なしで振り分けたい。作者の言葉は「イベントテーブルを持ちたい」「0101-0103,元旦 とか」「20270111 とか、特定日指定ができると良い」。あわせて「内閣府の『国民の祝日』csv に対応するだけでよい？ あまりややこしいルールだと面倒くさい」「スラッシュは使ってほしくない。0101 とかの方が入力しやすい」。

## Current State

- `＞transfer_date_to_var`（`crates/pasta_lua/pasta_scripts/pasta/shiori/act.lua`。イベントのシーンでは選ぶ前に自動で入る）は、日時の変数と `＄季節`・`＄節句`（五節句の日だけ名前、ほかは `なし`）を入れる（完了 spec `date-var-season-sekku`）。祝日と、作者の行事は無い。
- シーンの条件（`scene-condition-attributes`）で、範囲も「第 n 月曜」も今でも書ける（`＊行事_お正月　＆＄month＝1　＆＄day≦3`、`＆＄曜日＝「月曜日」　＆＄day≧8　＆＄day≦14`）。ただし日付の条件をシーンごとに書き直すことになり、「今日の行事の名前」を 1 か所で決められない。
- 条件では書けないもの: 春分の日・秋分の日（天文の計算）、振替休日・国民の休日（ほかの祝日との兼ね合い）。

## Desired Outcome

```csv
# ghost/master/calendar.csv（UTF-8）
0101-0103,お正月
0315,誕生日
20270111,一周年
```

```pasta
＊OnMouseDoubleClick
　＞「祝日_」＆＄祝日
　＞「行事_」＆＄行事

＊祝日_成人の日
　女の子：＠通常　今日は成人の日だね。

＊祝日_なし

＊行事_お正月
　女の子：＠通常　あけましておめでとう！

＊行事_なし
```

## Approach（2026-11-14 開発者の承認。日付の書き方は開発者の指示）

- **`＄祝日`（作者は何も書かない）**: `＄節句` と同じく、祝日の日はその名前、ほかの日は `なし`（空にすると `＞「祝日_」＆＄祝日` が前方一致で全部の祝日を候補にする）。今の法律の規則を pasta の中で数える。固定の日、ハッピーマンデー（成人の日＝1 月の第 2 月曜＝8〜14 日の月曜、海の日・敬老の日＝第 3 月曜、スポーツの日＝10 月の第 2 月曜）、春分の日・秋分の日の式、振替休日（祝日が日曜なら、その後のいちばん近い祝日でない日）、国民の休日（祝日に挟まれた祝日でない日）。名前は内閣府の CSV に合わせる（CSV は振替休日も国民の休日も `休日`）。
- **確かめたこと（2026-11-14 の discovery）**: 上の規則で数えた結果は、内閣府の CSV（1955〜2027 年・Shift_JIS・`Y/M/D` のゼロ埋めなし）と 2022〜2027 年の全部の日で一致した。合わないのは 2021 年以前の特例だけ（2019 年までの天皇誕生日 12/23・体育の日の名前、2019 年の即位の休日、2020・2021 年のオリンピックで動いた海の日・スポーツの日・山の日）。春分・秋分の式が 2028 年以降に官報と合うかは、まだ確かめようがない。
- **内閣府の CSV は同梱しない。テストの答え合わせに使う**: CSV は翌年の分までしか載らず、毎年足される。伺かのゴーストは何年も更新されないことが多く、同梱だと何年か後に祝日が黙って出なくなる。規則なら古くならない（法律が変わったら pasta を直す）。
- **`＄行事`（作者の表・`ghost/master/calendar.csv`）**: 1 行に `日付,名前` の 2 列。日付の書き方は数字の 3 つだけ（スラッシュは使わない）。
  - `MMDD`（毎年その日。例 `0315`）
  - `MMDD-MMDD`（毎年の範囲。年をまたぐ `1231-0103` も）
  - `YYYYMMDD`（その年のその日だけ。例 `20270111`）
  - 「第 n 曜日」は表に入れない（母の日などはシーンの条件で書ける）。iCalendar の繰り返しの規則は重すぎるので採らない。
  - 同じ日に複数の行が当たるときは、先に書いた行が勝つ。同じ名前を複数の行に書いてよい（別々の日に同じ行事）。
- **書式を CSV にする（2026-11-14 開発者「toml ってこういうの書くとき冗長よね」）**: TOML 案（`[calendar]` に `"お正月" = ["0101-0103"]`）は、両辺に引用符が要り、同じキーを 2 回書けず、書いた順が Lua に届かない（`toml` クレートに `preserve_order` が無く、Lua の表にも順が無い）ので重なりの決め方が作れなかった。CSV は 1 行 1 件で、行の順がそのまま優先になる。pasta の書式を TOML に揃える方針の例外で、開発者の判断。シーンの振る舞いは今までどおり DSL で書く。
- 不正な行（`0230`・`0101-`・桁違い・列の数の違い）は、ファイル名と行番号を付けて読み込みのエラーにする（`[scene.alias]` と同じく、警告で続けない）。ファイルが無ければ `＄行事` はいつも `なし`。
- 今の日時変数と同じ日付（`CLOCK.date`）から作るので、SSP の仮想時刻と `X-Pasta-Time` に従う。

## Scope

- **In**: `act.lua` の `transfer_date_to_var`（`＄祝日`・`＄行事`）、祝日の規則、`calendar.csv` の読み込みと検査、Lua のテスト（祝日は内閣府の CSV の今の法律の年と突き合わせる）、マニュアル（`book/src/grammar/variables.md` の日時変数の表・注意文・例、`calendar.csv` の書き方の節）、スキルの `references/`（`book/tools/gen-skill-refs.mjs` で生成）。
- **Out**: 内閣府の CSV の同梱・読み込み（形も文字コードも違う）、TOML の `[calendar]`、iCalendar（.ics）、「第 n 曜日」の書き方、二十四節気・雑節、英語名の版（`＄holiday` など）、祝日の規則の設定（外す・足す）。

## Boundary Candidates

- 祝日の規則（年 → その年の祝日の表を作る純粋な関数）。
- `calendar.csv` の読み込みと検査（起動時に 1 回）。
- 日付 → `＄祝日`・`＄行事` の転記（`act.lua`）。

## Out of Boundary

- イベントのシーンを選ぶ前の自動転記の仕組み（`scene-condition-attributes` が持つ。`transfer_date_to_var` に足せば乗る）。
- 条件の書き方そのもの（`＆＄行事＝「お正月」` は今のままで使える）。

## Upstream / Downstream

- **Upstream**: `transfer_date_to_var`・`pasta.shiori.clock`（仮想時刻）・ゴーストの読み込み（`calendar.csv` を Rust で読むか Lua で読むかは設計で決める）。
- **Downstream**: ゴーストの季節・行事のトーク、シーンの条件（`＆＄祝日≠「なし」` で「休みの日」）。

## Existing Spec Touchpoints

- **Extends**: 完了 spec `date-var-season-sekku`・`onhour-date-var-transfer`。
- **Adjacent**: `scene-condition-attributes`（自動転記で `＄祝日`・`＄行事` もイベントのシーン全部に入る）、`[scene.alias]` の読み込みエラーの扱い（同じ作りに揃える）。

## Constraints

- 要件で決めること:
  - `calendar.csv` の細かい形: 注釈の行（`#`）と空行を許すか、見出しの行を許すか、BOM の扱い、ファイル名（`calendar.csv` は仮）。
  - 2019〜2021 年の特例（即位の日、オリンピックで動いた海の日・スポーツの日・山の日）を持つか。推奨は持たない（今の法律の規則だけ）。
  - `＄祝日` の振替休日・国民の休日の名前（内閣府の CSV どおり両方 `休日` にするか、`振替休日`・`国民の休日` と分けるか）。
  - `pasta_check validate` で `calendar.csv` を検査するか（推奨は検査する。SSP を起動せずに書き間違いが分かる）。
- 名前の衝突は、マニュアルの注意文に `＄祝日`・`＄行事` を足す（`＄節句` と同じ扱い）。
