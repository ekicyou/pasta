# Implementation Plan

- [ ] 1. 属性の文法と構文木
- [x] 1.1 構文木の属性を「名前・中身・位置」の形に改め、宣言の 1 種だけで今の挙動を保つ
  - 属性の中身を宣言・条件・フラグの 3 種で表せる形にし、比較演算子の型と正規形の文字列を用意する（この段では宣言だけを作る）
  - 属性の値を読む側（pasta_dsl のテスト、pasta_lua の登録、pasta_check の検査、pasta_lsp の着色）を、新しい形の読み方へ機械的に直す
  - ワークスペースのビルドと既存のテストが、挙動の変化なしで通る
  - _Requirements: 2.1, 2.3_

- [x] 1.2 条件とフラグの形、名前なしの `＊` 行の属性を文法とパーサで受ける
  - 属性の中で条件・フラグ・宣言の順に試す規則を足し、比較演算子 6 種（全角・半角。2 文字の半角を先に）を受ける。右辺の変数と `＄０` の条件はパースエラーにする
  - 名前なしの `＊` 行に属性を書けるようにし、ファイルの範囲の規則名の書き間違いを直す。引用なし文字列の値の規則は変えない
  - 条件の項目は変数の印を全角に揃えた名前・正規形の演算子・値を持ち、フラグは名前だけを持つ
  - 新しいパーステストで `＆＄＊経験値≧500`・`＆＄hour>5`・`＆＄ｒ０＝「changed」` が条件、`＆＄＊初回待ち` がフラグになり、6 種が正規形になり、`＆＄ｒ０＝＄ｒ１`・`＆＄０＞1` がパースエラー、`＆k：a＝b` の値が `a＝b` のままであることを確かめて通る
  - _Requirements: 1.5, 2.1, 2.2, 2.3, 2.4, 2.6, 2.7, 4.6_

- [x] 1.3 宣言行の属性を構文木に残す
  - グローバル・名前なしの `＊`・ローカルの宣言行の属性を、そのシーンの属性として残す。グローバルは宣言行の属性を先、初期部の属性行を後に並べる
  - 名前なしの `＊` は名前だけを受け継ぎ、直前のシーンの属性を持たない
  - 値の型（整数・全角の数字・小数・引用あり／なしの文字列・空の引用）が今の読み分けのまま入る
  - パーステストで、3 種の宣言行の属性が書いた順に残ること、ローカル宣言の次の行の属性行とコンテンツ行の後の属性行がパースエラーのままであること、部分パースで位置がずれることを確かめて通る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 4.1, 4.2, 4.3, 4.4_

- [ ] 1.4 ファイル属性の 2 行目をパースエラーにする
  - 最後のグローバルシーンの後に見たファイル属性の行を覚え、2 行目で位置（2 行目の行頭）と前の行の番号を添えた構文エラーを返す。グローバルシーンを組み立てたら忘れ、アクター辞書とグローバル単語では忘れない
  - 2 行続きのファイル属性を使っている既存のテスト（実行の属性の受け継ぎ・最終回帰の属性の種類・属性のあるスナップショット）の入力を 1 行にまとめる。今の生成器はファイル属性を出さないので、生成物は変わらない
  - パーステストで、2 行続き・アクター辞書を挟んだ 2 行がエラー、グローバルシーンを挟んだ 2 行が通ることを確かめ、ワークスペースの既存のテストも通る
  - _Requirements: 3.3_

- [ ] 2. 受け継ぎと重なりの規則を 1 か所で決める

  - 新しいテストで、要件 3.6 の例・後の行での丸ごとの置き換え・条件を畳まないこと・名前なしの `＊` への受け継ぎ・2 つのファイルで持ち越さないこと・ローカルを空の受け継ぎで作ると宣言行の中だけ畳むことを確かめて通る

- [ ] 3. シーン表の属性を順と型を持つ並びにする

  - 構文木の属性から倉の項目への写し（3 種すべて）を、pasta_lua の登録の文脈と pasta_check の検査にそれぞれ 1 つずつ置く
  - 登録の口とシーン情報の属性を新しい並びの型にし、呼び出し側（テストに約 130 か所、pasta_lua・pasta_check の登録）を空の並び、または写しで作った今と同じ宣言の項目へ機械的に置き換える。意味は変えない
