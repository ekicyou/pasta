# 実装計画

進め方は design.md の Migration Strategy（S2〜S8）に沿う。リファクタリングは「特性化の試験を先に・1 つの抽出＝1 つの確かめ＝1 つのコミット」で進め、各タスクの終わりに Windows（x86・x64）の `cargo test --all` と x64 の clippy が通ることを確かめる。

- [ ] 1. 芯の型を、旧来の窓口の後ろへ抜き出す（S2）
- [x] 1.1 VM の持ち主が、kick の送り先をインスタンスから受け取れるようにする
  - VM を作るときに kick の送り先を外から渡せるようにし、読み込みは旧来の置き場の kick の送り先を呼ばずに、渡された送り先を使う
  - 既定の作り方では kick の送り先は無し（kick の道は働かない）
  - 読み込みでゴーストのディレクトリを、ディレクトリの有無を確かめる前に覚えるようにし、ディレクトリが無いときも VM の片付けでログの登録が外れるようにする
  - この時点では呼び出し側（アクタースレッド）が今の旧来の置き場の送り先を渡すので、振る舞いは変わらない。既存の試験が期待を変えずに通る
  - _Requirements: 5.5, 2.7, 3.9_
- [x] 1.2 アクタースレッドの起動を、失敗を返す形と、kick の送り先を受ける形にする
  - スレッドの起動の失敗と、ready を返す前にスレッドが終わったことを、パニックではなく誤りとして返す新しい起動の口を足す
  - 新しい口は kick の送り先を受け、VM に渡す（占有の札の引数は、札の型ができる 3.3 で足す）
  - 今の形の起動の口は名前と形を残し、新しい口を呼んで失敗は今どおりパニックにする（既存の試験が使う）
  - 既存の `actor_*` の試験が期待を変えずに通る
  - _Requirements: 2.3, 2.4_
- [x] 1.3 インスタンス 1 つ＝アクター 1 つの芯の型を作る
  - 芯の型が mailbox の送信端・アクタースレッドのハンドル・ディレクトリ・要求の連番を持ち、グローバルな状態を参照しない（ログの登録を除く）
  - 起動・読み込みの真偽・旧来の意味の要求（読めなければ 204）・GET（5 秒の安全網）・NOTIFY（即 204）・kick（送れなければ偽）・停止の要求だけ・後始末を口として持つ
  - kick の送り先は自分の送信端の弱い参照を閉じ込めたものにし、VM を作る前に渡す（kick の送り先が受け口を生かし続けない）
  - 後始末は Stop と ack を待ち、ack が届いて「ack の後に join」の決まりなら join、それ以外は手放す。ack が来なければ手放したことを警告のログ（`seam = "instance.abandon"`）に出す。二度目の後始末は冪等
  - 後始末の報告に「join を終えた」の印を足し、上限の時間を試験から短く注入できる内部の口を持つ。5 秒の上限の定数は旧来の置き場からこの型へ移す
  - Drop はまだ片付けていなければ「ack の後に join」の後始末と同じことをする
  - 芯の型が `Send + Sync` であることをコンパイルの検査で確かめる
  - 単体の試験: 芯の型の kick の送り先が生きている間はアクターに kick が届き、インスタンスを片付けた後は送れずに偽を返す（1.4 で旧来の置き場から移す kick の届きの試験をここで持つ）
  - _Requirements: 2.3, 3.8, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.5, 6.3_
- [x] 1.4 旧来の置き場を、芯の型 1 つを持つ置き場に置き換える
  - プロセスに 1 つの状態を「芯の型の置き場」1 つにし、mailbox・スレッドのハンドル・要求の連番のグローバルを消す
  - 窓口の自由関数（起動・要求・後始末・kick の送り先）は名前と形を残し、置き場の芯の型へ委ねる。送信の道はロックを取らない
  - 後始末は置き場から取り出して持ち主になってから行い、持ち主になれない（規約に反する同時の呼び方）ときは停止の要求だけをして最後の参照の Drop で手放す
  - この段の後始末は今どおり join しない（「ack の後に join」への切り替えは 5.1）
  - モジュールの説明に、旧来の入口の置き場であることと、ハンドルの無い ABI のためにプロセスに 1 つ残す理由を書く
  - 置き場の中の単体テスト（kick の届き・置き場が空のときの kick・アクター無しの後始末の冪等）を、置き場が空のときと実際に起こした芯の型のときの形に書き直す（確かめる中身は同じ）。生の送信端で kick の届きを確かめる試験は、芯の型の kick の送り先の試験として 1.3 の側へ移す
  - 旧来の置き場を呼ぶ既存の試験（12 ファイル）と `shiori_*`・`byte_invariant_test` が期待を変えずに通る
  - _Requirements: 5.7, 7.1, 7.2, 7.4_
- [x] 1.5 芯の型の後始末の決まりを試す試験と、試験用のゴーストを作る
  - 試験用のゴーストを作る: 呼ばれた回数を返す ID・壊れた開始行を返す ID・1 秒ほど回り続ける ID を持つ
  - 芯の型を直に起動し、「ack の後に join」の後始末が「ack あり・join 済み」、「手放す」の後始末が「ack あり・join なし」で返ること
  - 回り続ける ID を NOTIFY で積み、上限を 100 ミリ秒に注入した後始末が「ack なし・join なし」で返り、手放しの警告が出ること
  - 新しい試験が Windows で通る
  - _Requirements: 4.2, 4.4_

- [ ] 3. ログの量の設定とディレクトリの占有を、ロガーの登録の項目ごとに持つ（S4）
- [x] 3.1 ロガーの登録の項目を「ロガー＋量の設定＋世代」にし、占有の口を足す
  - 項目が無ければ新しい世代で足して札を返す占有の口、世代を新しくして引き継ぐ口、札の世代が今の世代と同じときだけ項目を消す口を足す
  - 項目の量の設定の差し替えと、選んだ項目の量の設定でイベントを判定する口と、全部の項目の量の最大を返す口を足す
  - 項目の選び方は「スレッドのディレクトリの文脈があればその項目、無ければロガーを持つ項目がちょうど 1 つならそれ、ほかは選ばない」とし、ほかのゴーストの設定へ逃げない
  - 表を変えたら、ロックを外した後でコールサイトの関心の表を作り直す
  - 単体の試験: 占有は 1 回目だけ札・解放の後は再び札・末尾の区切りの違う同じパスは同じ鍵・引き継ぎの後に古い札で解放しても項目が残り新しい札でなら消える・選び方の 3 通り
  - _Requirements: 5.3, 5.4, 5.7, 6.2_
- [x] 3.2 tracing の量の判定を、登録の項目に任せる形に替える

  - 購読者を入れる関数を引数なしに改名し、量の設定を替える関数がゴーストのディレクトリを引数で受けるようにする（`pasta_lua` の公開 API の破壊的な変更）
  - 量の設定の作り方（環境変数→`filter`→`level`）は変えない
  - 呼び出し元（ローダーの Stage 1.5・VM の持ち主・`pasta_lua` の試験 2 本）の形を合わせる
  - 新しい専用のテストバイナリで、2 つのディレクトリを読み、ディレクトリの文脈を替えるとそれぞれの `[logging]` に従って判定が分かれることを確かめる
  - 既存の量の差し替えの試験が期待を変えずに通る
  - _Requirements: 5.4, 5.7_
- [x] 3.3 芯の型と VM と旧来の置き場に、ディレクトリの占有をつなぐ
  - 芯の型の起動の前に、普通は占有を、旧来の口の打ち切り直後の同じディレクトリなら引き継ぎを行って札を得る。占有に失敗したら占有している側のログに警告（`seam = "instance.claim"`）を出してディレクトリ使用中の誤りを返す
  - アクタースレッドの新しい起動の口に占有の札の引数を足し（今の形の起動の口は札なし）、札をアクタースレッド経由で VM に渡し、VM の片付けは札があれば札で外し、無ければ今どおりディレクトリで外す
  - スレッドを起こせない・ready の前に終わったときは、既定のロガーを登録して理由を誤りのログに出し、札で外し、終わったスレッドを join してから誤りを返す
  - 旧来の置き場の起動は、前の片付けが打ち切りに終わり同じディレクトリなら引き継ぎ、それ以外は普通の占有で起動し、占有に失敗したら偽を返して置き場を空にする
  - 旧来の置き場にも、後始末の上限を試験から短く注入できる内部の口（試験用・文書に出さない）を足す（芯の型の上限の注入と同じ作り。5 秒の本番の上限は変えない）
  - 試験: 芯の型で同じディレクトリの 2 つ目が使用中の誤りになり、ログに理由の行が出ること。旧来の窓口で、回り続けるアクターの片付けが打ち切りに終わった直後に同じディレクトリを読むと成功し、古いスレッドがあとで片付けを終えても新しいインスタンスのログと占有が残ること
  - _Boundary: ActorInstance, PastaShiori, LegacySlot, ActorThread_
  - _Requirements: 2.4, 2.5, 6.2, 7.1, 7.2_

## Implementation Notes

- 1.2: `spawn_actor_thread_with` は ready の前に終わったスレッドを中で join してから `io::Error::other` を返す（`io::Error` はハンドルを運べないため）。ActorInstance は `ErrorKind::Other` を NotReady に写すだけで、join を重ねない。
- 1.2: 今の形の `spawn_actor_thread` は旧来の `lifecycle::kick_sink()` を渡している（振る舞いを保つため）。1.4 で置き場が芯の型へ移った後に design どおり `None` へ戻す。
- 1.3: spawn の失敗時に既定の PastaLogger を登録する手順（design の spawn 手順 3・2.5）は占有と一緒に 3.3 で足す。`shutdown_with_timeout` は結合試験から呼ぶため pub（`marshal_get_with_timeout` と同じ作り）。
- 1.4: 旧来の置き場は `static LEGACY: ArcSwapOption<ActorInstance>` だけになった。「static MAILBOX」「lifecycle::MAILBOX」という古い言い方が windows.rs・windows_tests.rs・marshaling.rs・teardown.rs・mailbox.rs・shiori.rs・lib.rs・actor/mod.rs・tests/ffi_actor_lifecycle_test.rs・tests/ffi_extern_session_e2e_test.rs・tests/scene_kick_gate_e2e_test.rs・pasta_lua/src/debug/kick.rs に残る。2.1 の文言の直しで一緒に直す。
- 1.4: 置き場の後始末で持ち主になれない（規約に反する同時の呼び方）とき、最後の参照の Drop は JoinAfterAck を試みる。5.1 で DllMain 用の join しない窓口を足すとき、この道が loader lock の中で join しないかを見直す。
- 1.5: 試験用のゴースト `tests/fixtures/v3_probe/` の ID は `OnProbeCount`（Lua に届いた要求の数・その要求も含む）・`OnProbeBadStatus`（開始行 `SHIORI/3.0 2x0 OK`）・`OnProbeSpin`（1 秒回って 204）。4.3 はこの名前を使う。
- 2.3: 2.1 の後の Linux・macOS で `pasta_shiori` のテストは 302 本すべて通った（run 40154842867）。6.3 は直す対象が無いことを確かめるだけになる。
- 3.1: `set_filter`・`event_enabled`・`max_level_hint` に `cfg_attr(not(test), expect(dead_code))` を付けてある。3.2 でつないだら外す。
- 3.2: 層ごとのフィルタが 1 つのとき `tracing::enabled!` はディレクトリごとの断りを映さない（全部の項目の最大量だけで決まる）。書き出しはディレクトリの量に従う。7.1 の内部の章に、スパンの中身で絞る指定が効かないことと並べて書く。
