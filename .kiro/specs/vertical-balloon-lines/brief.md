# Brief: vertical-balloon-lines

`/kiro-discovery` で起票（2026-10-18・main `8298a46c`）。ghost_dev の「ぱすた開発」セッション（窓際のぱすたさん）からの要望で、同じ日に直接実装の候補「budoux の改行の幅」を spec に格上げした（開発者の承認）。0.4.1 に入れる（2026-10-18 開発者の決定）。要件定義は Opus。

## Problem

窓際のぱすたさんは、SSP の縦書きのバルーン（`vertical,1`。SSP 2.8.80 から標準）を使う。縦書きでは、改行が「次の列」になる。右の枠（台詞・1 列 20 字）から、左の枠（3 列）の 1 列目の頭へは、`\_l[-295,0]`（絶対位置）で飛ぶ（単語 `＠左` が返す）。

困っていることは 2 つある。

1. **budoux の改行の幅**: 話者の切り替えなど明示的な改行は `\n[180]`（約 39px）で出している。budoux が入れる改行は普通の `\n`（100%）なので、折り返した列だけ間隔が詰まる。縦書きのバルーンの descript には、列の間隔を変える設定が無い（ゴースト側が ukadoc で確かめた）。
2. **budoux の数え方**: budoux は、自分で入れた改行しか知らない。台詞の中のタグは字数に数えずに素通りさせるので（`crates/pasta_lua/src/sakura_script/line_breaker.rs` 133〜153 行）、`\n`・`\n[…]`・`\c`・`\_l[…]` で列が替わったことに気づかず、前の列の字数を引き継いで数え続ける。左の枠の 1 列目で、早すぎる（遅すぎる）改行が入る。**作者が書いた `\n`・`\c` の後も同じで、横書きのゴーストでも起きている今の不具合である。**

ゴースト側は、今は budoux を止めて SSP の字数による折り返しに任せている。語の途中で折り返す（例「空｜調」）ので、budoux を使いたい。

## Current State

- budoux は、アクター設定の `budoux = [1 行目の幅, 2 行目以降…]`（全角を 2 と数える）で働く（`sakura_script/mod.rs` 126〜151 行）。改行は `\n` で決め打ち（`line_breaker.rs` 163 行）。バルーンの先頭には改行を入れない（137〜147 行）。
- 字数の状態は、`talk_to_script` の呼び出しごと（＝台詞のトークンごと）に 0 に戻る。同じアクターの続いた台詞は 1 つにまとめられる（`pasta_scripts/pasta/act.lua` 94〜143 行）。

今の動き（コードを読んだ限り。2026-10-18）:

| 改行の出どころ | 数え直すか |
| -------------- | ---------- |
| 台詞の中に書いた `\n`・`\n[180]`・`\c`・`\_l[…]` | しない（不具合） |
| 単語・関数が返す `\n[180]`（台詞とつながる場合） | しない（同上）。ゴースト側の話者の単語はこれに当たる |
| `spot_newlines`・`choice_newlines`（トークンの境目に出る） | 結果として、する |
| budoux が自分で入れる改行 | する |
| 台詞の途中に表情などのトークンを挟んだとき | まだ同じ列なのに、数え直す見込み（逆向きの粗さ） |

- 選択肢と選択肢の間は、普通の `\n` で決め打ち（`pasta_scripts/pasta/shiori/sakura_builder.lua` 249・349 行）。縦書きでは選択肢 1 つが 1 列になり、選択肢どうしの間が約 22px（字は 20px）になる。ぱすたは、これを「デザイン的に詰まって見えて良い」とした（2026-10-18 開発者の判断）。

## Desired Outcome

```toml
[ghost]
spot_newlines = 1.8

[actor."ぱすた"]
spot = 0
budoux = [40]
budoux_newlines = 1.8   # → \n[180]。既定は 1.0（今のまま \n）
```

```pasta
＊ポエム_出来損ないのパスタ
　ぱすた：長い長い、記憶の糸。生まれてから、続いてる一本の長い記憶。＠左
　：そう、きっと、一本道。いつか来る終わりの日まで。
```

```
長い長い、記憶の糸。生まれてから、\n[180]続いてる一本の長い記憶。\_l[-295,0]そう、きっと、一本道。いつか来る終わりの\n[180]日まで。
（\_l の所で、列の頭から数え直す。どこで折り返すかは budoux の語の区切りで決まるので、この位置は例）
```

- budoux が入れる改行の幅を、倍率で指定できる。
- 台詞の中の、列を動かすタグの所で、budoux が数え直す。`\n`・`\n[…]` は次の列へ進め、`\c` は最初の列へ戻し、`\_l[…]` はその列の字数を 0 に戻す。作者が書いたものも、単語や関数が返したものも同じに扱う。
- 選択肢と選択肢の間の改行の幅を、倍率で指定できる（`[ghost]` のキー、既定 1.0。汎用の機能として。ぱすたは使わない）。これで、pasta が自分で出す改行（段落の区切り・選択肢の前・budoux の折り返し・選択肢どうしの間）が、すべて倍率で調整できる。
- 既定の設定のままなら、今の出力を変えない。ただし、作者が書いた `\n`・`\c` の後の数え直しは不具合の直しなので、budoux を使うゴーストの出力が変わることがある（要件で、その扱いを決める）。

## Approach

方式は (a)「budoux が台詞の中のタグを見て数え直す」に決めた（2026-10-18 開発者の承認）。budoux はもうタグを見分けている（`tag_regex`）ので、新しい API は要らない。(b)「`act:budoux_reset()` のような明示の手段」は採らない（Lua の API と作者の手間が増え、`\n`・`\c` の不具合は残る）。

要件定義で決めること:

- **どのタグで数え直すか**: `\n`・`\n[…]`・`\c`・`\_l[…]` の 4 つを候補にする。`\x`（クリック待ち）・`\_q` などを含めるか。
- **`\_l` の後の幅**: 左の枠は、ボールの上で列を止めるので、右の枠より短い列（13 字前後、幅 `[26]`）になる見込み（ゴースト側の任意の要望。長さは未確定）。候補は 2 つ。`\_l` の所で幅の並びの先頭から数え直す。アクター設定に、飛んだ後に使う別の幅の並びを書けるようにする。
  - ゴースト側の実測（2026-10-18・開発者のレビュー待ちの暫定）: 字送り 20px、列の間隔 36px（`\n[180]`）、1 列の上限は SSP の `wordwrappoint` で 20 字。右の枠は 3 列で各 20 字（4 列目はぱすたの髪にかかる）。左の枠（`\_l[-283,0]` で飛んだ先）は 4 列で、1 列目が 20 字、2〜4 列目がセキュリティボールにかかるので 14 字まで。字数で書くと「20,20,20 →（`\_l`）→ 20,14,14,14 → 超えたら `\c`」（budoux の幅は全角を 2 と数えるので、その倍）。**「先頭から数え直す」では左の 2 列目以降が 14 字にならず、「飛んだ後の幅の並びを別に書く」なら表せる。**
- **トークンをまたいだ字数**: 台詞の途中に表情などのトークンを挟むと、数え直してしまう見込み。同じ列が続く間は、トークンをまたいで字数を持ち越すか（持ち越すなら、出力の組み立て `sakura_builder.lua` が字数の状態を持つ）。
- **キーの名前**: `budoux_newlines`（2026-10-18 承認の形）と、選択肢どうしの間のキー（`choice_newlines` と並ぶ名前）。
- **`budoux_newlines` の置き場**: アクター設定（`budoux` の隣。承認の形）。

## Scope

- **In**: `budoux_newlines`、列を動かすタグでの数え直し（作者が書いたもの・単語や関数が返したもの）、`\_l` の後の幅（要件で決めたら）、トークンをまたいだ字数（要件で決めたら）、選択肢どうしの間の改行の幅、テスト、マニュアル（`reference/pasta-toml.md`・`lua/modules/pasta-sakura-script.md`・`internals/talk-output.md`）、スキル references の再生成。
- **Out**: budoux の禁則（バックログ「budoux の自動改行の禁則」。JIS X 4051 の方針のまま）。アクターごとの表示の装い（`actor-display-style`）。縦書きのバルーンそのもの（ゴースト側の descript）。左の枠へ飛ぶ単語（ゴースト側の `＠左`）。

## Boundary Candidates

- budoux の行の数え方（`line_breaker.rs`。タグの種類の見分けと、字数・列の番号の状態）。
- 設定の読み出し（`sakura_script/mod.rs` のアクターの表）。
- 出力の組み立ての改行（`sakura_builder.lua` の選択肢どうしの間。トークンをまたいで字数を持ち越すなら、その状態も）。
