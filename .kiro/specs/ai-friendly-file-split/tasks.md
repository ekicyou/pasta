- [x] 1. Phase A: pasta_dsl インラインテスト外部化

- [x] 1.1 パーサーモジュールのテストを専用テストファイルへ移動

  - テストファイルでクレートのパーサーAPIをインポートし、全テストが引き続き動作することを確認

- [x] 1.2 AST 型定義のテストを専用テストファイルへ移動

- [x] 2.2 シーンテーブルのテストを `#[path]` パターンで src/ 内別ファイルに分離

- [x] 6. Phase B: pasta_dsl ソース責務分割

- [x] 6.1 (P) パーサーをシーン解析・アクション解析・要素解析のサブモジュールに分割
  - パーサーエントリファイルをディレクトリモジュール化し、3つのサブモジュールに責務を分割
  - エントリモジュールに公開 API と mod 宣言を残し、サブモジュールを `pub(crate)` で提供
  - `parse_action` サブモジュール (~400行) は式・文パースの密連携のためガイドライン例外として許容
  - _Requirements: 1.1, 2.1, 2.2, 2.3, 2.4, 2.5, 5.3_

- [x] 6.2 (P) AST 型定義を Span 型・シーン型・アクション型のサブモジュールに分割
  - AST 定義ファイルをディレクトリモジュール化し、3つのサブモジュールに意味カテゴリ別に分割
  - ディレクトリモジュールのトップで全型を `pub use` re-export し、外部クレートからのアクセスパスを維持
  - _Requirements: 1.1, 2.1, 2.2, 2.4, 2.5, 4.1, 4.3, 5.3_

- [x] 7. Phase B: pasta_core ソース責務分割

- [x] 7.1 シーンテーブルから公開型定義を独立モジュールに分離
  - シーン ID・スコープ・情報型を独立した型定義ファイルに抽出
  - シーンテーブル実装は単一 struct の凝集した実装として残置（ガイドライン例外、~390行）
  - レジストリエントリポイントから型定義ファイルの公開型を re-export
  - _Requirements: 1.1, 2.1, 2.2, 2.3, 2.4, 4.1, 4.3, 5.3_

- [x] 8. Phase B: pasta_lua ソース責務分割

- [x] 8.1 (P) ランタイムモジュールをランタイム設定・モジュール登録に分割
  - ランタイム設定構造体と関連実装を独立ファイルに分離
  - モジュール登録関数群を独立ファイルに分離（分割 `impl` パターン）
  - ランタイムのコアファイルからこれらを `pub(crate) use` でインポート
  - 分割後のコアファイル (~400行) は単一構造体の凝集した実装として許容（ガイドライン例外）
  - _Requirements: 1.1, 2.1, 2.2, 2.3, 2.4, 5.3_

- [x] 8.2 (P) コード生成モジュールを `code_gen/` ディレクトリにリネーム・分割
  - `code_generator` モジュールを `code_gen` ディレクトリモジュールにリネーム
  - スコープ生成・要素生成の2サブモジュールに分割（分割 `impl` パターン）
  - `lib.rs` と内部依存箇所のモジュールパスを更新（外部クレートからの直接参照はゼロ確認済みのため re-export 不要）
  - _Requirements: 1.1, 2.1, 2.2, 2.4, 2.5, 4.1, 4.3, 5.3_
