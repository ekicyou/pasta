## デバッグの全体像

pasta のデバッグは、**動いているゴーストへ、ベースウェア（SSP か areka）の MCP の窓口を通して頼みごとを送る**方式である。送り手は 2 種類ある。

- **pasta VSCode 拡張**: 編集中の `.pasta` がどのゴーストのものかを見つけ、そのゴーストが動いている SSP か areka の MCP の窓口へ送る。
- **AI エージェント**: SSP・areka の MCP の道具を直に呼ぶ。手順は [SHIORI イベント一覧](../lua/shiori-events.md) の「MCP からの呼び方」節にある。

ベースウェアは受けた頼みごとを SHIORI イベントとしてゴーストへ渡し、pasta.dll が答える。

```text
VSCode 拡張・AI エージェント
        │  MCP（127.0.0.1）
        ▼
   SSP・areka
        │  SHIORI イベント（OnPastaSceneAt など）
        ▼
     pasta.dll
```

拡張のコマンドは次の 3 つである。

| コマンド | すること |
| -------- | -------- |
| ▶ シーンを実行 | SHIORI を読み込み直してから、カーソルの位置のシーンを `OnPastaSceneAt` で再生する |
| SHIORI をリロード | SHIORI を読み込み直し、増えた誤りを要約する |
| 保存変数を表示 | `OnPastaDumpVariables` で保存変数（`＄＊名前`）を書き出させ、その中身を見せる |

コマンドの動きの詳しい説明は [開発支援アクション](./dev-actions.md) を参照する。

## デバッグの有効化

デバッグは**既定で無効**である。シーンの再生（`OnPastaSceneAt`）と保存変数の書き出し（`OnPastaDumpVariables`）は、デバッグを有効にしたゴーストでだけ働く。無効なときは、ゴーストは何もせずに 204（返す台本が無い）を返す。

有効化には `pasta.toml` の設定と環境変数の 2 経路があり、後述のとおり環境変数が設定ファイルより優先される。

### pasta.toml による有効化

`pasta.toml` の `[debug]` セクションの `enabled` で設定する。

| キー | 既定 | 意味 |
| ---- | ---- | ---- |
| `enabled` | `false` | 開発用のイベント（シーンの再生・保存変数の書き出し）を許す |

設定例:

```toml
[debug]
enabled = true
```

`pasta.toml` は SHIORI を読み込むたびに読み直される。書き換えた後は、SHIORI を読み込み直す（拡張の「SHIORI をリロード」か、ゴーストの再起動）。読み込み直すまでは、前の設定のまま動く。

### 環境変数による有効化

環境変数 `PASTA_DEBUG` でも有効にできる。

`PASTA_DEBUG` は truthy な値で有効化される。truthy と判定される値は `1` / `true` / `yes` / `on` であり、大文字小文字は区別されない（前後の空白は除去して判定される）。`0` / `false` / `no` / `off` / 空文字列は無効とみなされる。

```text
PASTA_DEBUG=1
```

環境変数は、ベースウェアを起動したときの値が使われる。設定した後は、ベースウェアを起動し直す。

### 優先順位

設定ファイルと環境変数が併存する場合、**環境変数が設定ファイルより優先**される。最終的な値は次の順位で決まる。

```text
環境変数 > pasta.toml [debug] > 既定値
```

たとえば `pasta.toml` で `enabled = false` としていても、`PASTA_DEBUG=1` が設定されていればデバッグは有効になる。

### 有効になったかの確かめ方

デバッグが有効な状態で SHIORI を読み込むと、ゴーストの `pasta.log` に、開発用のイベントを許したことを示す info の行（`Debug enabled: development events are allowed`）が 1 行出る。読み込み直した後にこの行が無ければ、設定がまだ効いていない。`pasta.toml` の書き間違いや、読み込み直し忘れを確かめる。

## ウォークスルー（hello-pasta）

ここでは、サンプルゴースト hello-pasta を題材に、書いたシーンをその場で鳴らすまでの流れを簡潔に辿る。拡張の導入と送り先の詳細は [VSCode 接続と拡張導入](./vscode-setup.md) で扱う。

1. **デバッグを有効化する。** hello-pasta の `pasta.toml` で `[debug]` の `enabled = true` とする。
2. **ゴーストを起動する。** SSP か areka で hello-pasta を起動する。起動済みなら、そのままでよい（次の手順のコマンドが毎回読み込み直す）。
3. **`.pasta` を開く。** VSCode で hello-pasta のフォルダを開き、`dic` の下の `.pasta` ファイルを開く。
4. **シーンを鳴らす。** 鳴らしたいシーンの中にカーソルを置き、エディターの右クリックのメニューから「▶ シーンを実行」を選ぶ。拡張は SHIORI を読み込み直してからそのシーンを再生し、出た台本を出力のパネルに出す。
5. **直して、もう一度鳴らす。** シーンを書き直したら、もう一度「▶ シーンを実行」を選ぶ。保存と読み込み直しは拡張が行う。

コマンドが送り先を見つけられないときや、204 が返るときの確かめ方は [トラブルシューティング](./troubleshooting.md) にまとめている。
