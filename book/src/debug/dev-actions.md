# ▶・リロード・保存変数

> 【むらさき】鳴らす・読み込み直す・のぞく。うちらに届く頼みごとは、この 3 つだけやねん。

> 【エモ：静観】3 つ目の「のぞく」は、僕の頭の中まで見られるの？

> 【むらさき：冷笑】見られるんは保存変数だけや。あんたの頭の中は、のぞいても空っぽやろ。

---

pasta-recipe と VS Code の拡張は、同じ 3 つの操作を、同じ部品で行う。この章は、3 つの操作が何をして、何を返すかを扱う。

| 操作 | すること | 保存 | 読み込み直し | デバッグ |
| ---- | -------- | ---- | ------------ | -------- |
| ▶ シーンを実行 | シーンを、いま書いた辞書で鳴らす | する | 毎回する | 要る |
| SHIORI をリロード | 辞書を読み込み直し、増えた誤りを要約する | する | する | 要らない |
| 保存変数を表示 | 保存変数（`＄＊名前`）の今の値を見る | しない | しない | 要る |

押す場所は、[pasta-recipe で書く](./recipe.md#鳴らす) と [VS Code で書く](./vscode-setup.md#3-つのコマンドの出る場所) にある。デバッグの有効化は [デバッグの有効化](./index.md#デバッグの有効化) にある。

## どの操作でも先に起きること

### ゴーストを見つける

操作は、編集中のファイルのゴーストへ送られる。

- pasta-recipe は、開いているゴーストへ送る。
- VS Code の拡張は、開いているファイルのフォルダから上へ 3 フォルダまでの間で、`descript.txt` を持つ `ghost/master` を探す。

VS Code では、見つからないときに次の知らせが出る。

| 知らせ | 意味 |
| ------ | ---- |
| `ゴーストを特定できません（ディスク上の .pasta・.lua・pasta.toml を開いてください）` | 名前の無い新規の文書か、ほかの種類のファイルを開いている |
| `ゴーストのフォルダの中のファイルではありません: <パス>` | `ghost/master` の外のファイルを開いている |

### 送る相手を決める

そのゴーストが動いている SSP・areka を探して送る。ゴーストはフォルダの絶対パスで指名するので、同じ名前のゴーストや、別の場所に置いた写しを取り違えない。

| 見つかった数 | 動き |
| ------------ | ---- |
| 0 | 「このゴーストが動いている SSP・areka が見つかりません」と出して止まる（[送る相手が見つからない](./troubleshooting.md#送る相手が見つからない)） |
| 1 | その相手へ送る |
| 2 つ以上 | 相手の一覧から選ぶ。選ばずに閉じたら、何も送らない |

決まった相手は、エディタを閉じるまでゴーストごとに覚えている。

### 未保存のファイルを保存する

「▶ シーンを実行」と「SHIORI をリロード」は、読み込み直す前に、そのゴーストの未保存の `.pasta`・`.lua`・`pasta.toml` を、確かめずに全部保存する。1 つでも保存できなければ、そのパスを出して止まる。

「保存変数を表示」は保存しない。

### 結果を出す

結果は、pasta-recipe では下の欄の「出力」に、VS Code では出力のパネル「Pasta 開発」に、時刻の順に積まれる。操作ごとに、まず次の形の行が出る。

```text
[12:34:56] ▶ シーンを実行 — hello-pasta（C:\SSP\ghost\hello-pasta）→ SSP 127.0.0.1:9801
```

同じゴーストへの操作が進んでいる間に次を始めると、「このゴーストへのコマンドが進んでいます」と出て、次の操作は始まらない。

## シーン再生（▶ シーンを実行）

> 【エモ】同じ名前のシーンが 3 つあったら、どれを言わされるの。

> 【むらさき：笑顔】押した見出しのやつや！ くじ引きは無しやで。

押した見出しのシーン（右クリックのメニューなどからは、カーソルの行のシーン）を鳴らす。シーン名を入れる必要はない。同じ名前のシーンが複数あっても、押した見出しのシーンを鳴らす。

1. 未保存のファイルを保存する。
2. SHIORI の読み込み直しを頼み、終わるまで待つ。
3. 読み込みが誤り無く終わったら、シーンを鳴らす。
4. ゴーストが返したスクリプトを、`スクリプト:` に続けて出す。

```text
スクリプト:
\p[0]やっほー、\_w[450]今日もよろしくね。\_w[950]\e
```

読み込み直しの結果によっては、鳴らさない。

| 場合 | 動き |
| ---- | ---- |
| 読み込みの誤りが増えた | 鳴らさない。誤りの数と行を出し、「読み込みの誤りが N 件あります」と知らせる。警告だけなら鳴らす |
| 読み込みの終わりを確かめられない | 鳴らさない。「読み込みの終わりを確かめられませんでした」と知らせる（[読み込みの終わりを確かめられない](./troubleshooting.md#読み込みの終わりを確かめられない)） |

鳴らした後の答えは、次のように扱う。

| 答え | 動き |
| ---- | ---- |
| スクリプト | そのまま出す。`【シーンが見つからない：…】` などの失敗の表記も、そのまま出す |
| 応答が無い | 失敗とはしない。ベースウェアの再生の記録からスクリプトを引いて、`スクリプト（応答が無かったため、再生の記録から）:` に続けて出す |
| 応答が無く、記録にも無い | 「スクリプトを確かめられませんでした」と知らせる（[応答が無い](./troubleshooting.md#応答が無い)） |
| スクリプトが無い（204） | 下の案内を出す |

```text
ゴーストはスクリプトを返しませんでした（204）。pasta.toml に [debug] enabled = true を書いて、SHIORI をリロードしてください。
```

204 のいちばん多い理由は、デバッグが無効なことである。ほかの理由は [スクリプトが返らない（204）](./troubleshooting.md#スクリプトが返らない204) にある。

## SHIORI をリロード

辞書を読み込み直し、読み込みが終わるまで待って、その間に増えた誤りと警告を要約する。シーンは鳴らさない。

1. 未保存のファイルを保存する。
2. SHIORI の読み込み直しを頼む。
3. ゴーストの `pasta.log` に読み込みの終わりの行が出るまで待つ（上限はおよそ 20 秒）。
4. その間に増えた、`pasta.log` の誤り・警告と、ベースウェアの誤りの記録を数えて要約する。

誤りがあると、次の形で出る。行の頭の `[pasta.log]`・`[ベースウェア]` が、どちらの記録かを示す。

```text
誤り 1 件・警告 0 件
誤り:
  [pasta.log] 2026-11-08T11:04:20.912891Z ERROR pasta_lua::loader::process: Process failure path=C:\SSP\ghost\my-ghost\ghost\master\dic\talk.pasta error=Parse error: …
```

誤りも警告も増えていなければ、「読み込みは誤り無く終わりました」と出る。

## 保存変数を表示

動いているゴーストの保存変数（`＄＊名前`）の、今の値を見る。読み込み直しも保存もしないので、動いている間の値がそのまま見える。

ゴーストは、値を `ghost/master/profile/pasta/debug/variables.toml` に書き出す。pasta-recipe はこれを表にし、VS Code は `保存変数（<パス>）:` に続けて中身を出す。

```toml
回数 = 3
```

書き出しが新しくならなかったときは、古い中身を今の値として出さず、次の案内を出す。

```text
pasta.toml に [debug] enabled = true を書いてリロードしてください
```

`variables.toml` は書き出しの写しである。このファイルを書き換えても、ゴーストの値は変わらない。値を書き換えるには、pasta-recipe の [保存変数の表](./recipe.md#保存変数の表) を使う。

## AI エージェントから使う

AI エージェントは、SSP・areka の MCP の道具を直に呼んで、同じことができる。相手の確かめ方（`baseware.name` を聞く）、読み込み直しの待ち方、`OnPastaScene`・`OnPastaSceneAt` の送り方は、[MCP からの呼び方](../lua/shiori-events.md#mcp-からの呼び方) にある。
