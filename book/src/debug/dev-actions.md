# 開発支援アクション（シーン再生・SHIORI をリロード・保存変数を表示）

> 【クローディア】書いた `.pasta` をその場で鳴らし、直したらすぐ読み込み直して確かめる――生きたゴーストを相手に、試行錯誤を回しますの。

> 【アンソニー】走っている馬車の車輪を、止めずに替えるようなお話でございますね。

> 【高笑い】しかも替えたそばから、走り具合を確かめられますのよ！ 保存も読み込み直しも、拡張が引き受けますわ。さあ、熱く回して参りましょう！

---

このページでは、pasta VSCode 拡張の 3 つのコマンド――**▶ シーンを実行**・**SHIORI をリロード**・**保存変数を表示**――の動きを扱う。どれも、動いているゴーストへ、ベースウェア（SSP か areka）の MCP の窓口を通して送る。デバッグの有効化は [デバッグ概要](./index.md)、拡張の導入と MCP の窓口は [VSCode 接続と拡張導入](./vscode-setup.md) を参照する。

| コマンド | 選べるエディタ | 保存 | 読み込み直し | 送るもの |
| -------- | -------------- | ---- | ------------ | -------- |
| ▶ シーンを実行 | `.pasta` | する | 毎回する | `OnPastaSceneAt` |
| SHIORI をリロード | `.pasta`・`.lua`・`pasta.toml` | する | する | （読み込み直しだけ） |
| 保存変数を表示 | `.pasta`・`.lua`・`pasta.toml` | しない | しない | `OnPastaDumpVariables` |

3 つとも、コマンドパレット（分類 `Pasta`）からいつでも選べる。エディタの右クリックのメニューには、上の表の「選べるエディタ」のときだけ出る。「▶ シーンを実行」は `.pasta` のエディタでだけ、メニューの先頭に出る。また、`.pasta` のシーンの見出しの行の上にも出る（[見出しの上の「▶ シーンを実行」](#見出しの上の-シーンを実行)）。

シーンの再生と保存変数の表示は、デバッグを有効にしたゴーストでだけ働く（`pasta.toml` の `[debug] enabled = true` か `PASTA_DEBUG=1`。[デバッグの有効化](./index.md#デバッグの有効化)）。

## 3 つのコマンドに共通の動き

### 選べるファイル

コマンドを選んだときのエディタが、ディスク上にある名前の付いたファイルで、そのコマンドが受ける種類（上の表）のときだけ進む。新規の名前の無い文書や、ほかの種類のファイルでは、次の警告を出して止まる。

```text
ゴーストを特定できません（ディスク上の .pasta・.lua・pasta.toml を開いてください）
```

### ゴーストの見つけ方

拡張は、開いているファイルのフォルダから上へ 3 フォルダまでの間で、`descript.txt` を持つ `ghost/master` のフォルダを探す（`ghost`・`master` の大文字・小文字は区別しない）。見つかった `ghost/master` の 2 つ上のフォルダが、そのゴーストの**ルート**である。

- ベースウェアへゴーストを指名するときは、ルートの絶対パスを使う。`descript.txt` の `name` は使わないので、同じ名前のゴーストや、別の場所に置いた写しを取り違えない。
- 出力と通知に出す**表示名**には、`descript.txt` の `name` を使う。`name` を読めないときは、ルートのフォルダ名を使う。

見つからないときは、次の警告と、開いているファイルのパスを出して止まる。ベースウェアへは何も送らない。

```text
ゴーストのフォルダの中のファイルではありません: <開いているファイルのパス>
```

### 送る相手の選び方と覚え方

拡張は、`127.0.0.1` の MCP の窓口の番号（`9801`・`9821`・`9802`・`9822` … `9810`・`9830`）へ一度に聞き、ベースウェアの名前（`baseware.name`）を答え、かつそのゴーストが動いている相手だけを候補にする。2 秒で答えない番号は打ち切る。候補は、答えの来た順ではなく上の番号の順に並ぶ。同じ名前のベースウェアが 2 つの番号で答えたときは（SSP は 1 つで `9801` と `9821` の両方に答える）、前の番号の 1 つにまとめる。

| 候補の数 | 動き |
| -------- | ---- |
| 0 | 次の警告を出して止まる。確かめ方は [トラブルシューティング](./troubleshooting.md#送る相手が見つからない) |
| 1 | その相手へ送る |
| 2 つ以上 | 「名前（127.0.0.1:番号）」を並べて選ばせる。選ばずに閉じたら、何も送らずに止まる |

```text
このゴーストが動いている SSP・areka が見つかりません: <表示名>（<ルート>）。確かめること: ベースウェアでこのゴーストを起動しているか・ベースウェアの MCP の窓口が有効か
```

決まった相手は、ゴーストごとに、この VSCode の窓が開いている間だけ覚える。次のコマンドでは聞き直さずに同じ相手へ送る。ただし送る前に、覚えた番号の相手が同じベースウェアの名前を答え、そのゴーストがまだ動いているかを 1 回だけ確かめる。答えない・名前が違う・ゴーストがもういないときは、覚えを捨てて候補を探し直す。

### 出力のパネルと通知

結果は、出力のパネル「**Pasta 開発**」に時刻の順に積まれる。パネルはフォーカスを奪わずに表示される。コマンドごとに、まず次の形の頭の行が出る。

```text
[12:34:56] ▶ シーンを実行 — <表示名>（<ルート>）→ <ベースウェアの名前> 127.0.0.1:<番号>
```

- 止まったときと案内は、通知で短く知らせ、詳しい内容はパネルに出す。成功したときは通知しない。
- 相手が誤りを返した・つながらない・答えの形が違うときは、その文言をパネルに出し、誤りの通知を出して止まる。
- 相手とやり取りしている間だけ、ウィンドウの下端に進み具合が出る。送り先を常に出す表示は無い。
- 同じゴーストへのコマンドが進んでいる間は、次のコマンドを始めずに「このゴーストへのコマンドが進んでいます」と知らせる。

### 未保存のファイルの保存

「▶ シーンを実行」と「SHIORI をリロード」は、読み込み直す前に、そのゴーストのルートの下にある未保存の `.pasta`・`.lua`・`pasta.toml` を、確かめずに全部保存する。読み込み直しはゴースト全体を読むので、画面のとおりに動かすためである。ルートの外の文書は保存しない。1 つでも保存できなければ、そのパスを出して止まり、ベースウェアへは読み込み直しを頼まない。

「保存変数を表示」は保存しない。

## シーン再生（▶ シーンを実行）

カーソルの位置のシーン、または押した見出しのシーンを、いま保存した辞書で再生する。**シーン名を入力する必要はない。**

| 選び方 | 再生するシーン |
| ------ | -------------- |
| シーンの見出しの行の上の「▶ シーンを実行」を押す | その見出しのシーン |
| 右クリックのメニュー・コマンドパレットから選ぶ | カーソルの行のシーン |

どちらから選んでも、次の同じ流れで再生する。

1. ルートの下の未保存のファイルを保存する。
2. 相手へ SHIORI の読み込み直しを頼み、終わるまで待つ（[SHIORI をリロード](#shiori-をリロード) と同じ）。**読み込み直しは毎回行い、省く設定は無い。**
3. 読み込みが誤り無く終わったら、`OnPastaSceneAt` を、Reference0 に `.pasta` の絶対パス、Reference1 にカーソルの行（見出しの上の ▶ からは、その見出しの行。1 から数える）を付けて送る。行からシーンを引く規則は [OnPastaSceneAt](../lua/shiori-events.md#onpastasceneat位置でシーンを再生) を参照する。
4. ゴーストが返した台本を、パネルに `台本:` に続けて出す。

読み込み直しの結果によっては、再生を頼まない。

| 場合 | 動き |
| ---- | ---- |
| 読み込みの誤りが増えた | 再生しない。パネルに誤りの数と行、続けて「シーンを再生しませんでした」を出し、「読み込みの誤りが N 件あります」と知らせる。警告だけなら再生する |
| 読み込みの終わりを確かめられない（時間切れ） | 再生しない。「読み込みの終わりを確かめられませんでした」と知らせる |

再生を頼んだ後の答えは、次のように扱う。

| 答え | 動き |
| ---- | ---- |
| 台本 | パネルに出す。`【シーンが見つからない：…】` などの失敗の表記も、そのまま出す |
| `No response from server` | 失敗とはしない。相手の再生の記録から、この再生の台本を引いて `台本（応答が無かったため、再生の記録から）:` に続けて出す |
| `No response from server` で、記録にも台本が無い | 「台本を確かめられませんでした」と知らせる |
| 台本が無い（204） | 下の案内を出す。`pasta.log` に `OnPastaSceneAt:` の警告の行があれば、理由としてその行も出す |

```text
ゴーストは台本を返しませんでした（204）。pasta.toml に [debug] enabled = true を書いて、SHIORI をリロードしてください。
```

204 は、次のときに返る。

- デバッグが無効のとき。
- ベースウェアがイベントを外からのもの（SecurityLevel が external）として渡し、ゴーストが断ったとき。
- `pasta.toml` の `[logging]` に `balloon_warning = false` を書いていて、シーンが見つからない・引数が誤っているとき（失敗の表記を載せない）。

確かめ方は [トラブルシューティング](./troubleshooting.md#台本が返らない204) を参照する。

### 見出しの上の「▶ シーンを実行」

`.pasta` を開いていると、シーンの見出しの行――グローバルシーン（`＊名前`）・続きのグローバルシーン（`＊` だけの行）・ローカルシーン（`・名前`）――のすぐ上に「▶ シーンを実行」が出る。押すと、カーソルの位置にかかわらず、その見出しのシーンを上の流れで再生する。同じ名前のシーンが複数あっても、押した見出しのシーンを再生する。

この ▶ は VSCode の CodeLens の仕組みで出している。要らなければ、`settings.json` に次を書く。`.pasta` のエディタで見出しの上の ▶ が出なくなる。ほかの言語のエディタには効かない。右クリックのメニューとコマンドパレットからは、今までどおり選べる。

```json
{
    "[pasta]": {
        "editor.codeLens": false
    }
}
```

### シーンの並び（アウトライン）

`.pasta` のシーンの並びは、VSCode の次の場所に出る。

- エクスプローラーの「アウトライン」
- エディタの上のパンくず
- `Ctrl+Shift+O`（エディタの中のシンボルへ移動）
- スティッキースクロール（スクロールしても、カーソルのあるシーンの見出しが上に残る）

並びは グローバルシーン ＞ ローカルシーン の 2 階層である。続きのグローバルシーン（`＊` だけの行）は、前のグローバルシーンの名前を受け継いだ、別の項目として並ぶ。項目を選ぶと、そのシーンの見出しへ移る。

### 解析器を読み込めないとき

見出しの上の ▶ とシーンの並びは、拡張の解析器（WASM）が文書を読んで出している。解析器を読み込めなかったときは（シンタックスハイライトだけで動くとき）、▶ もシーンの並びも出ない。右クリックのメニューとコマンドパレットの「▶ シーンを実行」は、そのまま使える。

## SHIORI をリロード

相手へそのゴーストの SHIORI の読み込み直しを頼み、読み込みが終わるまで待って、その間に増えた誤りと警告を要約する。

1. ルートの下の未保存のファイルを保存する。
2. 相手へ読み込み直しを頼む。
3. ゴーストの `pasta.log` に、読み込みの終わりを示す `SHIORI load entry completed` の行が出るまで待つ（上限はおよそ 20 秒）。
4. 読み込み直しの間に増えた、次の 2 つの記録を数えて、パネルに要約する。
   - ゴーストの `pasta.log` の行（`ERROR` の行と、読み込みの失敗を示す `loaded=false` の行を誤り、`WARN` の行を警告に数える）
   - ベースウェアの誤りの記録のうち、そのゴーストの分

要約は次の形で出る。各行の頭の `[pasta.log]`・`[ベースウェア]` が、どちらの記録の行かを示す。

```text
誤り 1 件・警告 0 件
誤り:
  [pasta.log] <誤りの行>
```

増えた誤りと警告が無ければ、パネルに「読み込みは誤り無く終わりました」と出る。誤りがあれば「読み込みの誤りが N 件あります」と知らせる。

- `pasta.log` の場所は、`pasta.toml` の `[logging] file_path` に従う。書かれていなければ `ghost/master/` からの既定の `profile/pasta/logs/pasta.log` を読む。`file_path` を読めなかったときは、既定の場所を読んだことをパネルに添える。
- `pasta.log` が見つからない・読めないときは、ベースウェアの誤りの記録だけで要約し、`pasta.log` を読めなかったことと、そのパスを添える。
- 読み込みの終わりの行が上限の時間までに出なければ、「読み込みの終わりを確かめられませんでした」と知らせ、そこまでに増えた分を要約する。
- 読み込み直した後に、シーンを自分から再生することはない。確かめたいときは改めて「▶ シーンを実行」を選ぶ。

## 保存変数を表示

動いているゴーストの保存変数（`＄＊名前`）の、今の値を見る。

1. 相手へ `OnPastaDumpVariables` を送る。**読み込み直しも保存もしない**ので、動いている間の値がそのまま見える。
2. ゴーストが書き出した `ghost/master/profile/pasta/debug/variables.toml` を読み、パネルに `保存変数（<パス>）:` に続けて中身を出す。エディタでは開かない。パネルに積まれるので、前に出した値と見比べられる。

送った後しばらく待っても `variables.toml` が無い、または送る前から書き換わっていないときは、古い中身を今の値として出さない。代わりに、次の案内を出す。`pasta.log` に `OnPastaDumpVariables:` の行があれば、理由としてその行も出す。

```text
pasta.toml に [debug] enabled = true を書いてリロードしてください
```

## 典型的な開発の流れ

1. `pasta.toml` に `[debug] enabled = true` を書き、SSP か areka でゴーストを起動する。
2. 確かめたいシーンの見出しの上の「▶ シーンを実行」を押す（またはシーンの行にカーソルを置き、右クリックのメニューから選ぶ）。
3. `.pasta` を書き直し、もう一度「▶ シーンを実行」を選ぶ。保存と読み込み直しは拡張が行う。
4. 保存変数の値を確かめたいときは「保存変数を表示」を選ぶ。
5. 辞書の誤りだけを確かめたいときは「SHIORI をリロード」を選ぶ。

## AI エージェントから使う

AI エージェントは、SSP・areka の MCP の道具を直に呼んで、同じことができる。相手の確かめ方、読み込み直しの待ち方、`OnPastaScene`・`OnPastaSceneAt` の送り方などの手順は、[SHIORI イベント一覧](../lua/shiori-events.md) の [MCP からの呼び方](../lua/shiori-events.md#mcp-からの呼び方) にまとめている。

うまく動かないときは [トラブルシューティング](./troubleshooting.md) を確認する。
