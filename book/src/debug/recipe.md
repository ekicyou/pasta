# VS Code を使わずに書く（pasta-recipe）

> 【クローディア】辞書書き専用の小さな道具、pasta-recipe をご紹介しますわ。VSCode を入れなくても、拡張と同じ色と同じ診断の下で `.pasta` を書けますの。

> 【アンソニー】大きな道具箱はお持ちにならず、包丁一本でお台所に立つ、ということでございますね。

> 【したり顔】ええ。exe を 1 つ置くだけで、インストールも要りませんのよ。手に入れ方から、ゴーストの開き方まで、順にご案内いたしますわ。

---

このページでは、VSCode を使わずに `.pasta` を書くアプリ **pasta-recipe** の入手と置き方、初めての起動、ゴーストの開き方、書いたシーンを動いているゴーストで鳴らす開発の操作、できることとまだできないことを扱う。VSCode で書く場合は [VSCode 接続と拡張導入](./vscode-setup.md) を参照する。

pasta-recipe の色分け・書きながらの診断・ゴースト全体の検査は、VSCode 拡張と同じ解析器と同じ検査の核から出る。同じ文書・同じゴーストなら、拡張と同じ結果になる。

## 入手と置き方

pasta-recipe は、zip を落として入れる。zip は Windows の種類ごとに x64 版（`pasta-recipe.x64.zip`）と arm64 版（`pasta-recipe.arm64.zip`）の 2 つあり、どちらも [ダウンロード](../download.md#vs-code-を使わずに書くアプリ) のページから落とせる。

自分の Windows の種類は、Windows の「設定」→「システム」→「バージョン情報」の「システムの種類」で分かる。「x64 ベース プロセッサ」と出ていれば x64 版を、「ARM ベース プロセッサ」と出ていれば arm64 版を選ぶ。

配布の対象は、x64 と arm64 の Windows（Windows 10 の 1803 以降・Windows 11）である。32 ビットの Windows・mac・Linux 向けは無い。

落とした zip を好きなフォルダに展開する。中身は、どちらの zip も次の 2 つである。

| ファイル | 中身 |
| -------- | ---- |
| `pasta-recipe.exe` | アプリ本体。落とした zip の種類（x64 か arm64）の Windows 向け |
| `THIRD_PARTY_LICENSES.txt` | アプリに含まれる第三者の部品のライセンスの表示 |

インストールの手順は無い。展開した `pasta-recipe.exe` を、そのまま起動すればよい。VC++ の再頒布可能パッケージも要らない。画面の部品と着色の文法はすべて exe に入っている。ネットワークへは、開発の操作（[ゴーストを動かす](#ゴーストを動かす)）のときだけ、同じ PC の `127.0.0.1` のベースウェアにつなぐ。ほかへはつながない。

pasta-recipe は、exe のそばにもゴーストのフォルダにも、作業用のファイル・設定・ログを作らない。書くのは利用者ごとのアプリのデータの置き場だけで、最近開いたゴーストの記録（[最近開いたもの](#最近開いたもの)）は `%APPDATA%\io.github.ekicyou.pasta-recipe\` に、WebView2 の作業用のデータは `%LOCALAPPDATA%\io.github.ekicyou.pasta-recipe\EBWebView\` に置く。

アプリの版は窓の題名に出る（`pasta-recipe` の後ろの番号）。この版は、同じリリースの pasta の版と同じである。

## 初めての起動と SmartScreen

`pasta-recipe.exe` には署名が無い。そのため、初めて起動するときに Windows の SmartScreen が「Windows によって PC が保護されました」の画面を出して、起動を止めることがある。

この画面が出たら、次のとおりに通す。

1. 画面の「詳細情報」を押す。
2. アプリ名（`pasta-recipe.exe`）と「発行元: 不明な発行元」が出て、「実行」のボタンが現れる。
3. 「実行」を押す。

一度通せば、同じ exe では次から出ない。新しい版の exe に入れ替えたときは、また出ることがある。

## WebView2 ランタイム

pasta-recipe の画面は、Windows に入っている **Microsoft Edge WebView2 ランタイム**で描く。Windows 11 には、はじめから入っている。

WebView2 ランタイムが無い環境で起動すると、pasta-recipe は窓を開かずに、次のメッセージの箱を出して終わる。

```text
pasta-recipe を動かすには Microsoft Edge WebView2 ランタイムが要ります。https://developer.microsoft.com/microsoft-edge/webview2/ から入手してください。
```

このときは、メッセージにある Microsoft の配布ページ（<https://developer.microsoft.com/microsoft-edge/webview2/>）から WebView2 ランタイム（Evergreen 版）を入れてから、もう一度起動する。

## ゴーストを開く

pasta-recipe は、1 つの窓で一度に 1 つのゴーストを開く。開くのはゴーストの `ghost/master` で、渡すフォルダは次のどれでもよい。どれを渡しても、同じ `ghost/master` が開く。

```text
hello\                      ← ゴーストのフォルダ
  ghost\                    ← ghost のフォルダ
    master\                 ← ghost/master そのもの
      dic\
        挨拶.pasta          ← ghost/master の中のファイル・フォルダ
```

- ゴーストのフォルダ（`ghost/master` を含むフォルダ）
- `ghost` のフォルダ
- `ghost/master` そのもの
- `ghost/master` の中のフォルダかファイル（上へたどって、いちばん近い `ghost/master` を開く。ファイルなら、そのファイルもタブで開く）

フォルダの名前 `ghost`・`master` は、大文字・小文字を区別せずに見つける。`ghost/master` が見つからないとき（無いパス・ゴーストでないフォルダなど）は、渡したパスと見つからない理由を出し、開いているゴーストは変えない。

ゴーストを開くと、窓の題名に `{ゴーストのフォルダの名前} - pasta-recipe {版}` が出る。開いているゴーストに未保存のファイルがあるときに別のゴーストを開こうとすると、開き直す前に「保存する・保存しない・取り消す」を確かめる。

開き方は次の 4 つある。

### exe にドラッグドロップする

エクスプローラーで、ゴーストのフォルダを `pasta-recipe.exe`（かそのショートカット）の上へドラッグドロップする。pasta-recipe が起動して、そのゴーストを開く。複数のフォルダをまとめてドロップしたときは、最初の 1 つを開く。

### 窓へドロップする

ゴーストのフォルダを、pasta-recipe の窓へドラッグドロップする。ゴーストを開いていない間の開始の画面でも、ゴーストを開いている間の窓でも開ける。

### ダイアログで選ぶ

引数なしで起動すると、開始の画面が出る。開始の画面の「フォルダを選ぶ…」を押し、出てきたダイアログでゴーストのフォルダを選ぶ。ゴーストを開いている間は、ツールバーの「フォルダを開く…」で同じダイアログが出る。

ファイルを選んでも開ける。開始の画面の「ファイルを選ぶ…」か、ツールバーの「ファイルを開く… (Ctrl+O)」を押し、ゴーストの中の `.pasta` などのファイルを選ぶ。そのファイルを含むゴーストを開いて、そのファイルのタブを開く。`Ctrl+O` は開始の画面でも効く。

### 最近開いたもの

開始の画面には、最近開いたゴーストの一覧が出る。各項目には、ゴーストのフォルダの名前とフルパスが並ぶ。項目を押すと、そのゴーストを開く。ゴーストを開いている間は、ツールバーの「最近開いたもの」のメニューに同じ一覧が出る。

一覧は新しい順に最大 10 件で、同じゴーストを開き直すと先頭へ移る。選んだゴーストのフォルダが無くなっていたときは、無くなっていることを知らせて、その項目を一覧から消す。

記録は人が読める TOML で、次のファイルに書く。アプリを終えても残り、次の起動の開始の画面に出る。

```text
%APPDATA%\io.github.ekicyou.pasta-recipe\recent.toml
```

## 関連付けと「送る」で開く

Windows の機能を使えば、エクスプローラーから直に pasta-recipe でゴーストを開ける。pasta-recipe は Windows の設定（レジストリ）に自分では何も書かないので、関連付けと「送る」は作者が Windows の操作で行う。

### `.pasta` を「プログラムから開く」で関連付ける

1. エクスプローラーで、どれかの `.pasta` ファイルを右クリックし、「プログラムから開く」→「別のプログラムを選択」を選ぶ。
2. 一覧の下の「PC でアプリを選択する」（か「この PC で別のアプリを探す」）を選び、`pasta-recipe.exe` を指定する。
3. 「常にこのアプリを使って .pasta ファイルを開く」にして開く（Windows 11 では「常に」を押す）。

これで `.pasta` ファイルをダブルクリックすると、そのファイルを含むゴーストの `ghost/master` が開き、そのファイルがタブで開く。

### 「送る」にショートカットを置く

1. `Win+R` で「ファイル名を指定して実行」を開き、`shell:sendto` と入れて OK を押す。「SendTo」のフォルダが開く。
2. このフォルダに、`pasta-recipe.exe` のショートカットを置く（`pasta-recipe.exe` を `Alt` キーを押しながらドラッグドロップすると、ショートカットができる）。

これでゴーストのフォルダや `.pasta` ファイルを右クリックし、「送る」→ pasta-recipe を選ぶと、そのゴーストが開く（Windows 11 では、右クリックのメニューの「その他のオプションを確認」の中に「送る」がある）。

### 動いている pasta-recipe へ渡る

pasta-recipe が既に動いているときに、exe へのドロップ・関連付けたファイルのダブルクリック・「送る」をすると、新しい窓は開かない。渡したゴーストを今の窓で開き、今の窓を前に出す。渡したのが今開いているゴーストのファイルなら、そのファイルのタブを開くだけで、ゴーストは開き直さない。

## 画面と操作

窓の左にファイルとシーンのツリー、右にタブで開いたエディタ、上にツールバーが並ぶ。下の欄は、2 つの面を頭のボタンで切り替えて使う。「診断・検査」の面には診断の一覧とゴースト全体の検査の一覧が、「出力・保存変数」の面には開発の操作の出力の欄と保存変数の表が並ぶ（[ゴーストを動かす](#ゴーストを動かす)）。

### ツリー

ツリーには、`ghost/master` の中のフォルダとファイルが階層のとおりに並ぶ。同じ階層の中は、フォルダが先で、それぞれ名前の順（大文字・小文字を区別しない）である。`ghost/master` の直下の `profile` フォルダ（ランタイムが書く保存の置き場）は出さない。

各 `.pasta` ファイルの下には、そのファイルのシーンが グローバルシーン（`＊`）＞ ローカルシーン（`・`）の 2 階層で、ファイルの中の順に並ぶ。シーンを押すと、そのファイルがタブで開き、シーンの見出しの行へカーソルが移る。シーンの並びは、書き換えている途中の未保存の中身にも追う。

ツリーの行を右クリックする（か、行を選んで `Shift+F10` かアプリケーションキーを押す）と、メニューが出る。

| 行 | メニュー |
| -- | -------- |
| フォルダ（最上位の `ghost/master` を含む） | 新しいファイル・新しいフォルダ・名前の変更（最上位は除く） |
| ファイル | 名前の変更 |
| シーン | ▶ シーンを実行・値を入れて実行…（[ゴーストを動かす](#ゴーストを動かす)） |

名前の変更は、行を選んで `F2` でもできる。名前を変えたファイル（フォルダならその中のファイル）を開いているタブは、未保存の書き換えを保ったまま新しい名前に付け替わる。同じフォルダの既にあるもの（大文字・小文字を区別しない）と重なる名前・Windows のファイル名に使えない名前・空の名前は、理由を出して断る。

### タブと保存

`.pasta`・`.lua` はタブで開いて編集できる。ほかの UTF-8 のテキストファイル（`pasta.toml` など）も、色分けなしのテキストとして開いて編集できる。UTF-8 として読めないファイル（画像・Shift_JIS のテキストなど）は開かず、読めない理由を出す。

- 未保存の書き換えのあるタブには、名前の前に `●` が付く。
- 保存は `Ctrl+S` か、ツールバーの「保存 (Ctrl+S)」で行う。自動では保存しない。
- 保存のとき、開いたときの改行の種類（CRLF・LF）と、先頭の BOM の有無を変えない。
- 保存に失敗したときは理由を出し、エディタの中身と未保存の印をそのまま残す。
- 未保存のタブを閉じるとき・未保存のタブが残ったまま窓を閉じるときは、「保存する・保存しない・取り消す」を確かめる。

### 外でファイルが変わったとき

エクスプローラーやほかのエディタでファイルが変わると、pasta-recipe はそれに追う。

- ファイルやフォルダが増えた・消えた・名前が変わったときは、ツリーを作り直す。
- 開いているタブのファイルが変わり、そのタブに未保存の書き換えが無いときは、中身を読み直す。
- 未保存の書き換えがあるときは、外で変わったことを帯で知らせる。「読み直す」か「今の中身を残す」かを選ぶまで、エディタの中身は書き換えない。
- 開いているタブのファイルが消えたときは、消えたことを知らせ、タブの中身を未保存として残す。保存すれば、ファイルを作り直せる。

## ゴーストを動かす

pasta-recipe は、書いたシーンを、同じ PC で動いているゴーストでその場で鳴らせる。送り先は、ベースウェア（SSP か areka）の `127.0.0.1` の MCP の窓口である。読み込み直しの待ち方・答えの扱い・相手の探し方は、VSCode 拡張の [開発支援アクション](./dev-actions.md) と同じ部品で動き、同じ結果になる。

| 操作 | 出る場所 | 保存 | 読み込み直し | デバッグ |
| ---- | -------- | ---- | ------------ | -------- |
| ▶ シーンを実行 | ツリーのシーンの行のメニュー・エディタの見出しの上 | する | 毎回する | 要る |
| 値を入れて実行… | ツリーのシーンの行のメニュー・エディタの見出しの上 | する | 毎回する | 要る |
| SHIORI をリロード | ツールバー | する | する | 要らない |
| 保存変数を表示 | 保存変数の表の上 | しない | しない | 要る |
| 書き換え…・消す…・追加… | 保存変数の表 | しない | しない | 要らない。ただし、結果を表で見るには要る |

デバッグを有効にするには、`pasta.toml` に `[debug] enabled = true` を書く（か `PASTA_DEBUG=1`。[デバッグの有効化](./index.md#デバッグの有効化)）。デバッグが無効のゴーストでは、▶ を押してもシーンは鳴らず、保存変数の表も出ない。出力の欄に、デバッグを有効にする案内が出る。

開発の操作は、アプリ全体で一度に 1 つずつ進む。操作が進んでいる間に次の操作を始めると、「このゴーストへのコマンドが進んでいます」と出して、次の操作は始めない。

### 送る相手の探し方

操作を始めると、開いているゴーストの `ghost/master` に `descript.txt` があるかを確かめる（大文字・小文字は区別しない）。無ければゴーストのフォルダとして扱えないことを出して止まり、ベースウェアへは何も送らない。

送る相手は、拡張と同じく、`127.0.0.1` の候補の番号へ一度に聞いて、このゴーストが動いているベースウェアだけを候補にする（[送る相手の選び方と覚え方](./dev-actions.md#送る相手の選び方と覚え方)）。ゴーストはルートの絶対パスで指名するので、同じ名前のゴーストや別の場所の写しを取り違えない。

| 候補の数 | 動き |
| -------- | ---- |
| 0 | 「このゴーストが動いている SSP・areka が見つかりません」と、確かめることを出して止まる。確かめ方は [トラブルシューティング](./troubleshooting.md#送る相手が見つからない) |
| 1 | その相手へ送る |
| 2 つ以上 | 「`<ゴーストの名前>` へ送る相手を選んでください」の窓に「名前（127.0.0.1:番号）」が並ぶ。選んだ相手へ送る。選ばずに閉じたら、何も送らずに止まる |

決まった相手は、ゴーストごとに、pasta-recipe を終えるまで覚える。次の操作では、覚えた相手がまだそのゴーストを動かしているかを確かめてから送る。

### 未保存のファイルの保存

「▶ シーンを実行」「値を入れて実行…」「SHIORI をリロード」は、読み込み直す前に、開いているゴーストの未保存の `.pasta`・`.lua`・`pasta.toml` のタブを、確かめずに全部保存する。1 つでも保存できなければ、そのパスを出して止まり、読み込み直しは頼まない。保存変数の表の操作は保存しない。

### ▶ シーンを実行

シーンを、いま保存した辞書で鳴らす。シーン名を入れる必要はない。

- **ツリーから**: シーンの行を右クリックする（か、行を選んで `Shift+F10` かアプリケーションキーを押す）と、メニューの「▶ シーンを実行」で鳴らせる。
- **エディタから**: `.pasta` のタブでは、シーンの見出しの行――グローバルシーン（`＊名前`）・続きのグローバルシーン（`＊` だけの行）・ローカルシーン（`・名前`）――のすぐ上に「▶ シーンを実行」と「値を入れて実行…」が出る。押すと、カーソルの位置にかかわらず、その見出しのシーンを鳴らす。キーボードでは、見出しの行で `F1` を押し、「Show CodeLens Commands For Current Line」から選ぶ。

どちらから選んでも、次の流れで鳴らす。

1. 未保存のファイルを保存する。
2. 保存した中身から押したシーンの今の行を引き直す。書き換えて行がずれていても、押したシーンを鳴らす。保存した中身にそのシーンが無くなっていたときは、「シーン「…」が保存した中身に見つかりません」と出して止まり、読み込み直しは頼まない。
3. 相手へ SHIORI の読み込み直しを頼み、終わるまで待つ（[SHIORI をリロード](#shiori-をリロード)と同じ）。
4. `OnPastaSceneAt` を送る。
5. ゴーストが返した台本を、出力の欄に出す。

読み込みの誤りが増えたときは鳴らさない。答えの扱い（台本・応答が無いとき・台本が返らない 204）は拡張と同じである（[シーン再生](./dev-actions.md#シーン再生-シーンを実行)）。保存変数の表を出している間は、鳴らした後に表を読み直す。

### 値を入れて実行

シーンのローカル変数（`＄名前`）に値を入れてから鳴らす。「▶ シーンを実行」と同じ場所の「値を入れて実行…」を押すと、「値を入れて実行：`<シーン>`」の窓が開く。

窓には、名前・型・値の**組**を並べる。

- 「組を足す」で組を 1 つ足し、組の「この組を消す」で消す。
- 名前は、`＄` を除いたローカル変数の名前を入れる（`＄天気` なら `天気`）。
- 型は「文字列」「数」「真偽」の 3 つから選ぶ。値は、文字列なら入れた文字のまま、数なら整数か小数（`3`・`-1.5`）、真偽なら `true`・`false` から選ぶ。

「鳴らす」を押すと、組を TOML のインライン表にして `OnPastaSceneAt` の Reference2 に付け、上の ▶ と同じ流れで鳴らす。シーンは、組の名前のローカル変数にその値が入った状態で始まる（[OnPastaSceneAt](../lua/shiori-events.md#onpastasceneat位置でシーンを再生)）。たとえば組が `天気`・文字列・`雨` なら、`＄天気` が `雨` の状態で鳴る。組が 1 つも無ければ、▶ と同じく値を入れずに鳴らす。

次の組は弾く。弾いた組があるときは鳴らさず、窓を閉じずに、組の行のそばに理由を出す。

| 弾く組 | 理由の表示 |
| ------ | ---------- |
| 名前が `＄名前` と書けない（空・数字だけ・`__名前__`・空白や記号を含む） | `＄<名前> と書ける名前ではありません（空・数字だけ・__名前__・空白や記号を含む）` |
| 前の組と同じ名前 | `同じ名前の組があります: <名前>` |
| 型が数で、値が数として読めない（`abc`・空・`inf`・`nan`） | `数として読めません: <値>` |

入れた組は、シーンごとに、pasta-recipe を終えるまで覚える。同じシーンでもう一度「値を入れて実行…」を押すと、前に鳴らした組が入った窓が開く。組はファイルには残さない。「▶ シーンを実行」は、覚えた組を使わずに鳴らす。

### SHIORI をリロード

ツールバーの「SHIORI をリロード」を押すと、未保存のファイルを保存してから、相手へ SHIORI の読み込み直しを頼み、読み込みが終わるまで待って、その間に増えた誤りと警告を出力の欄に要約する。待ち方と要約の形は拡張と同じである（[SHIORI をリロード](./dev-actions.md#shiori-をリロード)）。読み込み直した後に、シーンを自分から鳴らすことはない。

### 出力の欄

操作の結果は、下の欄の「出力・保存変数」の面の「出力」に、時刻の順に積まれる。前の行は消えないので、前の結果と見比べられる。

- 操作を始めると、下の欄は「出力・保存変数」の面に切り替わる。焦点はエディタから動かないので、書く手を止めずに続けられる。
- 操作ごとに、まず操作の名前・ゴースト・送る相手を示す頭の行が出る。形は拡張と同じである（[出力のパネルと通知](./dev-actions.md#出力のパネルと通知)）。
- 止まったときと誤りは、行の頭に `誤り:`・`警告:` を付けて出す。別の窓や通知は出さない。
- 操作が進んでいる間は、欄の見出しが「出力（実行中: `<操作の名前>`）」になる。

### 保存変数の表

「出力・保存変数」の面の「保存変数」に、動いているゴーストの保存変数（`＄＊名前`）を表で出す。

「保存変数を表示」を押すと、相手へ `OnPastaDumpVariables` を送り、ゴーストが書き出した `ghost/master/profile/pasta/debug/variables.toml` を読んで表にする。読み込み直しも保存もしないので、動いている間の値がそのまま見える。

- 表には、名前・型・値・操作の列が並ぶ。型は「文字列」「数」「真偽」「表」のどれかで、名前の順に並ぶ。
- 保存変数が 1 つも無ければ「保存変数はありません」と出る。
- 書き出しを読めなかったとき（デバッグが無効など）は、表も操作のボタンも出さず、出力の欄に理由と案内を出す（[保存変数を表示](./dev-actions.md#保存変数を表示)）。
- 別のゴーストを開くと、前のゴーストの表は消える。

表の行と表の下のボタンで、保存変数を書き換え・削除・追加できる。どれも相手へ [OnPastaSetSaveVariable](../lua/shiori-events.md#onpastasetsavevariableグローバル変数に代入) を送り、送った後に同じ操作の中で表を読み直す。断られたとき・届かなかったときも読み直すので、表はいつもゴーストの今の値を見せる。

| 操作 | 窓 | 送るもの |
| ---- | -- | -------- |
| 行の「書き換え…」 | 「`＄＊<名前>` を書き換えます」の窓で型と値を選び、「書き換える」を押す | 選んだ型（文字列・数・真偽）と値 |
| 行の「消す…」 | 「`＄＊<名前>` をゴーストの保存変数から消します」を確かめて、「消す」を押す | 型 `delete` |
| 表の下の「追加…」 | 「保存変数を足します」の窓で名前・型・値を入れ、「足す」を押す。名前が空なら「名前が要ります」と出て閉じない | 入れた名前・型・値 |

- 書き換え・削除・追加は、デバッグの有無によらずゴーストで効く。ただし、送った後の表を読み直すのは「保存変数を表示」と同じ書き出しなので、結果を表で見るにはデバッグが要る。また、表を一度読めるまでは、行の操作も「追加…」も出ない。
- 書き換えはランタイムのメモリの上で効き、その後に読む `＄＊名前` にすぐ見える。ファイル（`profile/pasta/save/` の保存先）へは、ランタイムの終了時（ゴーストの終了・SHIORI の読み込み直し）に書かれる（[グローバル変数の保存先](../grammar/variables.md#グローバル変数の保存先)）。表の上にも、このことを書いてある。
- 型が「表」の行（テーブルの値）は見るだけで、操作のボタンは出ない。`OnPastaSetSaveVariable` が代入できるのは文字列・数・真偽だけである。
- `variables.toml` は書き出しの写しである。このファイルを書き換えても、ゴーストの値は変わらない。

## できること

- **色分け**: `.pasta` に、拡張と同じ着色の文法の下地と、その上に解析器のセマンティックトークンの色を重ねる。コードブロック（3 個以上のバッククォートの柵）の中の Lua にも色が付く。`.lua` にも Lua の色が付く。画面の明暗は Windows の明暗の設定に合わせる。
- **書きながらの診断**: 開いている `.pasta` の書き間違いに波線が付き、書き換えを止めてからおおむね 1 秒で書き換えた後の中身に合う。診断の一覧には、ファイル・行・列（1 から数える）・メッセージが並び、項目を押すとその位置へ移る。
- **ツリー**: ファイルとシーンを 1 つのツリーで見て、押したシーンの見出しへ一度で行ける。ファイルとフォルダの作成と名前の変更ができる。
- **ゴースト全体の検査**: ゴーストを開いたとき・`.pasta` か直下の `pasta.toml` を保存したとき・外でこれらのファイルが変わったときに、ゴースト全体を検査し直す。一覧には誤りか警告か・ファイル・行・列・メッセージと、誤りと警告の件数が出る。検査はディスクに保存した中身を使い、[`pasta_check validate`](./validate.md) と拡張のゴースト全体の検査と同じ結果になる。開いているファイルの構文の誤りは、書きながらの診断にだけ出し、検査の一覧に重ねて出さない。
- **ゴーストを動かすこと**: 書いたシーンを動いているゴーストで鳴らし（ローカル変数に値を入れても鳴らせる）、SHIORI を読み込み直し、保存変数を表で見て書き換え・削除・追加する（[ゴーストを動かす](#ゴーストを動かす)）。

## まだできないこと

- **書く手伝い**: 補完・ホバー・定義へ移動・参照の検索・シンボルの名前の変更・ゴースト全体の文字の検索は無い。
- **`.lua` の診断**: `.lua` には色が付くだけで、構文の誤りの波線は出ない。
- **ファイルとフォルダの削除**: ツリーからは消せない。消すときはエクスプローラーで消す（ごみ箱に入る）。
- **改行の混ざったファイル**: 1 つのファイルに CRLF と LF が混ざっているときは、開いたときに多いほうへそろう。保存すると、そろった改行で書かれる。
- **ほかの環境**: 配布は x64 と arm64 の Windows だけである（32 ビットの Windows・mac・Linux 向けは無い）。インストーラ・自動更新・複数の窓は無い。`.nar` の作成は [配布の章](../getting-started/13-nar.md) を参照する。
