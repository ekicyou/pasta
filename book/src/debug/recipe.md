# VS Code を使わずに書く（pasta-recipe）

> 【クローディア】辞書書き専用の小さな道具、pasta-recipe をご紹介しますわ。VSCode を入れなくても、拡張と同じ色と同じ診断の下で `.pasta` を書けますの。

> 【アンソニー】大きな道具箱はお持ちにならず、包丁一本でお台所に立つ、ということでございますね。

> 【したり顔】ええ。exe を 1 つ置くだけで、インストールも要りませんのよ。手に入れ方から、ゴーストの開き方まで、順にご案内いたしますわ。

---

このページでは、VSCode を使わずに `.pasta` を書くアプリ **pasta-recipe** の入手と置き方、初めての起動、ゴーストの開き方、できることとまだできないことを扱う。VSCode で書く場合は [VSCode 接続と拡張導入](./vscode-setup.md) を参照する。

pasta-recipe の色分け・書きながらの診断・ゴースト全体の検査は、VSCode 拡張と同じ解析器と同じ検査の核から出る。同じ文書・同じゴーストなら、拡張と同じ結果になる。

## 入手と置き方

pasta-recipe は、GitHub の Release から `pasta-recipe.zip` を落として入れる。最新版は次の固定のリンクで落とせる。

<https://github.com/ekicyou/pasta/releases/latest/download/pasta-recipe.zip>

落とした zip を好きなフォルダに展開する。中身は次の 2 つである。

| ファイル | 中身 |
| -------- | ---- |
| `pasta-recipe.exe` | アプリ本体。64 ビット版の Windows（Windows 10 の 1803 以降・Windows 11）向け |
| `THIRD_PARTY_LICENSES.txt` | アプリに含まれる第三者の部品のライセンスの表示 |

インストールの手順は無い。展開した `pasta-recipe.exe` を、そのまま起動すればよい。VC++ の再頒布可能パッケージも要らない。画面の部品と着色の文法はすべて exe に入っていて、ネットワークにはつながない。

pasta-recipe は、exe のそばにもゴーストのフォルダにも、作業用のファイル・設定・ログを作らない。書くのは利用者ごとのアプリのデータの置き場だけで、最近開いたゴーストの記録（[最近開いたもの](#最近開いたもの)）は `%APPDATA%\io.github.ekicyou.pasta-recipe\` に、WebView2 の作業用のデータは `%LOCALAPPDATA%\io.github.ekicyou.pasta-recipe\EBWebView\` に置く。

アプリの版は窓の題名に出る（`pasta-recipe` の後ろの番号）。この版は、同じリリースの pasta の版と同じである。

## 初めての起動と SmartScreen

`pasta-recipe.exe` には署名が無い。そのため、初めて起動するときに Windows の SmartScreen が「Windows によって PC が保護されました」の画面を出して、起動を止めることがある。

この画面が出たら、次のとおりに通す。

1. 画面の「詳細情報」を押す。
2. アプリ名（`pasta-recipe.exe`）と「発行元: 不明な発行元」が出て、「実行」のボタンが現れる。
3. 「実行」を押す。

一度通せば、同じ exe では次から出ない。新しい版の exe に入れ替えたときは、また出ることがある。

## WebView2 ランタイム

pasta-recipe の画面は、Windows に入っている **Microsoft Edge WebView2 ランタイム**で描く。Windows 11 には、はじめから入っている。

WebView2 ランタイムが無い環境で起動すると、pasta-recipe は窓を開かずに、次のメッセージの箱を出して終わる。

```text
pasta-recipe を動かすには Microsoft Edge WebView2 ランタイムが要ります。https://developer.microsoft.com/microsoft-edge/webview2/ から入手してください。
```

このときは、メッセージにある Microsoft の配布ページ（<https://developer.microsoft.com/microsoft-edge/webview2/>）から WebView2 ランタイム（Evergreen 版）を入れてから、もう一度起動する。

## ゴーストを開く

pasta-recipe は、1 つの窓で一度に 1 つのゴーストを開く。開くのはゴーストの `ghost/master` で、渡すフォルダは次のどれでもよい。どれを渡しても、同じ `ghost/master` が開く。

```text
hello\                      ← ゴーストのフォルダ
  ghost\                    ← ghost のフォルダ
    master\                 ← ghost/master そのもの
      dic\
        挨拶.pasta          ← ghost/master の中のファイル・フォルダ
```

- ゴーストのフォルダ（`ghost/master` を含むフォルダ）
- `ghost` のフォルダ
- `ghost/master` そのもの
- `ghost/master` の中のフォルダかファイル（上へたどって、いちばん近い `ghost/master` を開く。ファイルなら、そのファイルもタブで開く）

フォルダの名前 `ghost`・`master` は、大文字・小文字を区別せずに見つける。`ghost/master` が見つからないとき（無いパス・ゴーストでないフォルダなど）は、渡したパスと見つからない理由を出し、開いているゴーストは変えない。

ゴーストを開くと、窓の題名に `{ゴーストのフォルダの名前} - pasta-recipe {版}` が出る。開いているゴーストに未保存のファイルがあるときに別のゴーストを開こうとすると、開き直す前に「保存する・保存しない・取り消す」を確かめる。

開き方は次の 4 つある。

### exe にドラッグドロップする

エクスプローラーで、ゴーストのフォルダを `pasta-recipe.exe`（かそのショートカット）の上へドラッグドロップする。pasta-recipe が起動して、そのゴーストを開く。複数のフォルダをまとめてドロップしたときは、最初の 1 つを開く。

### 窓へドロップする

ゴーストのフォルダを、pasta-recipe の窓へドラッグドロップする。ゴーストを開いていない間の開始の画面でも、ゴーストを開いている間の窓でも開ける。

### フォルダを選ぶ

引数なしで起動すると、開始の画面が出る。開始の画面の「フォルダを選ぶ…」を押し、出てきたダイアログでゴーストのフォルダを選ぶ。

### 最近開いたもの

開始の画面には、最近開いたゴーストの一覧が出る。各項目には、ゴーストのフォルダの名前とフルパスが並ぶ。項目を押すと、そのゴーストを開く。ゴーストを開いている間は、ツールバーの「最近開いたもの」のメニューに同じ一覧が出る。

一覧は新しい順に最大 10 件で、同じゴーストを開き直すと先頭へ移る。選んだゴーストのフォルダが無くなっていたときは、無くなっていることを知らせて、その項目を一覧から消す。

記録は人が読める TOML で、次のファイルに書く。アプリを終えても残り、次の起動の開始の画面に出る。

```text
%APPDATA%\io.github.ekicyou.pasta-recipe\recent.toml
```

## 関連付けと「送る」で開く

Windows の機能を使えば、エクスプローラーから直に pasta-recipe でゴーストを開ける。pasta-recipe は Windows の設定（レジストリ）に自分では何も書かないので、関連付けと「送る」は作者が Windows の操作で行う。

### `.pasta` を「プログラムから開く」で関連付ける

1. エクスプローラーで、どれかの `.pasta` ファイルを右クリックし、「プログラムから開く」→「別のプログラムを選択」を選ぶ。
2. 一覧の下の「PC でアプリを選択する」（か「この PC で別のアプリを探す」）を選び、`pasta-recipe.exe` を指定する。
3. 「常にこのアプリを使って .pasta ファイルを開く」にして開く（Windows 11 では「常に」を押す）。

これで `.pasta` ファイルをダブルクリックすると、そのファイルを含むゴーストの `ghost/master` が開き、そのファイルがタブで開く。

### 「送る」にショートカットを置く

1. `Win+R` で「ファイル名を指定して実行」を開き、`shell:sendto` と入れて OK を押す。「SendTo」のフォルダが開く。
2. このフォルダに、`pasta-recipe.exe` のショートカットを置く（`pasta-recipe.exe` を `Alt` キーを押しながらドラッグドロップすると、ショートカットができる）。

これでゴーストのフォルダや `.pasta` ファイルを右クリックし、「送る」→ pasta-recipe を選ぶと、そのゴーストが開く（Windows 11 では、右クリックのメニューの「その他のオプションを確認」の中に「送る」がある）。

### 動いている pasta-recipe へ渡る

pasta-recipe が既に動いているときに、exe へのドロップ・関連付けたファイルのダブルクリック・「送る」をすると、新しい窓は開かない。渡したゴーストを今の窓で開き、今の窓を前に出す。渡したのが今開いているゴーストのファイルなら、そのファイルのタブを開くだけで、ゴーストは開き直さない。

## 画面と操作

窓の左にファイルとシーンのツリー、右にタブで開いたエディタ、下に診断の一覧とゴースト全体の検査の一覧が並ぶ。

### ツリー

ツリーには、`ghost/master` の中のフォルダとファイルが階層のとおりに並ぶ。同じ階層の中は、フォルダが先で、それぞれ名前の順（大文字・小文字を区別しない）である。`ghost/master` の直下の `profile` フォルダ（ランタイムが書く保存の置き場）は出さない。

各 `.pasta` ファイルの下には、そのファイルのシーンが グローバルシーン（`＊`）＞ ローカルシーン（`・`）の 2 階層で、ファイルの中の順に並ぶ。シーンを押すと、そのファイルがタブで開き、シーンの見出しの行へカーソルが移る。シーンの並びは、書き換えている途中の未保存の中身にも追う。

ツリーの行を右クリックする（か、行を選んで `Shift+F10` かアプリケーションキーを押す）と、メニューが出る。

| 行 | メニュー |
| -- | -------- |
| フォルダ（最上位の `ghost/master` を含む） | 新しいファイル・新しいフォルダ・名前の変更（最上位は除く） |
| ファイル | 名前の変更 |

名前の変更は、行を選んで `F2` でもできる。名前を変えたファイル（フォルダならその中のファイル）を開いているタブは、未保存の書き換えを保ったまま新しい名前に付け替わる。同じフォルダの既にあるもの（大文字・小文字を区別しない）と重なる名前・Windows のファイル名に使えない名前・空の名前は、理由を出して断る。

### タブと保存

`.pasta`・`.lua` はタブで開いて編集できる。ほかの UTF-8 のテキストファイル（`pasta.toml` など）も、色分けなしのテキストとして開いて編集できる。UTF-8 として読めないファイル（画像・Shift_JIS のテキストなど）は開かず、読めない理由を出す。

- 未保存の書き換えのあるタブには、名前の前に `●` が付く。
- 保存は `Ctrl+S` か、ツールバーの「保存 (Ctrl+S)」で行う。自動では保存しない。
- 保存のとき、開いたときの改行の種類（CRLF・LF）と、先頭の BOM の有無を変えない。
- 保存に失敗したときは理由を出し、エディタの中身と未保存の印をそのまま残す。
- 未保存のタブを閉じるとき・未保存のタブが残ったまま窓を閉じるときは、「保存する・保存しない・取り消す」を確かめる。

### 外でファイルが変わったとき

エクスプローラーやほかのエディタでファイルが変わると、pasta-recipe はそれに追う。

- ファイルやフォルダが増えた・消えた・名前が変わったときは、ツリーを作り直す。
- 開いているタブのファイルが変わり、そのタブに未保存の書き換えが無いときは、中身を読み直す。
- 未保存の書き換えがあるときは、外で変わったことを帯で知らせる。「読み直す」か「今の中身を残す」かを選ぶまで、エディタの中身は書き換えない。
- 開いているタブのファイルが消えたときは、消えたことを知らせ、タブの中身を未保存として残す。保存すれば、ファイルを作り直せる。

## できること

- **色分け**: `.pasta` に、拡張と同じ着色の文法の下地と、その上に解析器のセマンティックトークンの色を重ねる。コードブロック（3 個以上のバッククォートの柵）の中の Lua にも色が付く。`.lua` にも Lua の色が付く。画面の明暗は Windows の明暗の設定に合わせる。
- **書きながらの診断**: 開いている `.pasta` の書き間違いに波線が付き、書き換えを止めてからおおむね 1 秒で書き換えた後の中身に合う。診断の一覧には、ファイル・行・列（1 から数える）・メッセージが並び、項目を押すとその位置へ移る。
- **ツリー**: ファイルとシーンを 1 つのツリーで見て、押したシーンの見出しへ一度で行ける。ファイルとフォルダの作成と名前の変更ができる。
- **ゴースト全体の検査**: ゴーストを開いたとき・`.pasta` か直下の `pasta.toml` を保存したとき・外でこれらのファイルが変わったときに、ゴースト全体を検査し直す。一覧には誤りか警告か・ファイル・行・列・メッセージと、誤りと警告の件数が出る。検査はディスクに保存した中身を使い、[`pasta_check validate`](./validate.md) と拡張のゴースト全体の検査と同じ結果になる。開いているファイルの構文の誤りは、書きながらの診断にだけ出し、検査の一覧に重ねて出さない。

## まだできないこと

- **ゴーストを動かすこと**: シーンの実行・SHIORI のリロード・保存変数の表示は無い。書いたシーンをその場で鳴らすには、VSCode 拡張の [開発支援アクション](./dev-actions.md) を使う。
- **書く手伝い**: 補完・ホバー・定義へ移動・参照の検索・シンボルの名前の変更・ゴースト全体の文字の検索は無い。
- **`.lua` の診断**: `.lua` には色が付くだけで、構文の誤りの波線は出ない。
- **ファイルとフォルダの削除**: ツリーからは消せない。消すときはエクスプローラーで消す（ごみ箱に入る）。
- **改行の混ざったファイル**: 1 つのファイルに CRLF と LF が混ざっているときは、開いたときに多いほうへそろう。保存すると、そろった改行で書かれる。
- **ほかの環境**: 配布は 64 ビット版の Windows だけである。インストーラ・自動更新・複数の窓は無い。`.nar` の作成は [配布の章](../getting-started/13-nar.md) を参照する。
