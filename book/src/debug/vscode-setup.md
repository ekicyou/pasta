## pasta VSCode 拡張の導入

VSCode からシーンを鳴らしたり保存変数を見たりするには、**pasta VSCode 拡張が必須**である。この拡張が 3 つのコマンド（「▶ シーンを実行」「SHIORI をリロード」「保存変数を表示」）を提供する。本ページは拡張が未導入の読者を前提に、導入手順から説明する。

導入対象の拡張は次のとおり。

| 項目 | 値 |
| ---- | -- |
| 表示名（displayName） | Pasta DSL |
| 発行元（publisher） | ekicyou |
| 識別子（name） | pasta-vscode |

導入経路は 2 つある。通常は主経路（Marketplace）で導入すればよい。

### 主経路: VS Code Marketplace からインストール

VSCode の拡張機能ビュー（サイドバーの拡張アイコン、または `Ctrl+Shift+X`）を開き、検索ボックスに「Pasta DSL」と入力する。発行元が `ekicyou` の拡張を選び、「インストール」を押す。これが推奨される導入方法である。

### 代替経路: VSIX を手動インストール

Marketplace を利用できない環境では、GitHub Releases で配布される VSIX 資産を手動でインストールできる。VSIX は [ダウンロード](../download.md#vs-code-の拡張) のページから辿れる最新のリリースの Assets にある。資産名は次の形式である（`<version>` はリリース版番号に置き換わる）。

```text
pasta-vscode-<version>.vsix
```

ダウンロードした `.vsix` ファイルは、拡張機能ビュー右上のメニューから「VSIX からのインストール（Install from VSIX...）」を選んで指定する。

### VSCode 本体の導入について

VSCode 本体が未導入の場合は、まず VSCode をインストールする。本マニュアルでは本体のインストール手順は重複記述せず、公式サイトの案内に委ねる。

- VS Code 公式サイト: <https://code.visualstudio.com/>

## SSP と areka の MCP の窓口

拡張は、ゴーストが動いているベースウェア（SSP か areka）の **MCP の窓口**へ送る。窓口はベースウェアが自分で開くもので、pasta.dll は待ち受けを持たない。

窓口は `127.0.0.1`（同じマシンの中）だけで待ち受ける。番号は次の 20 個のどれかで、先に起動したベースウェアから順に、空いている番号を取る。

```text
9801・9821・9802・9822・9803・9823 … 9810・9830
```

拡張はこの 20 個を上の順に聞き、次の 2 つを確かめた相手だけを送り先の候補にする。

- 相手がベースウェアの名前（`baseware.name`）を答える。番号を取った別のプログラムには送らない。
- 編集中の `.pasta` のゴースト（ゴーストのルートフォルダの絶対パスで指名する）が、その相手で動いている。

送るたびに、出力のパネルへ相手の名前・番号・ゴーストの表示名・ルートのパスが出る。同じゴーストが 2 つ以上の相手で動いているときの選び方と覚え方は [開発支援アクション](./dev-actions.md) を参照する。

拡張には、送り先の番号や `127.0.0.1` の他の送り先を指定する設定は無い。SSP・areka の側でゴーストを起動し、MCP の窓口が開いていれば、拡張の側で用意することは何も無い。送り先が見つからないときは、ベースウェアでそのゴーストを起動しているか、ベースウェアの設定で MCP の窓口が有効になっているかを確かめる（[トラブルシューティング](./troubleshooting.md)）。

## 前の版から移るとき

前の版の拡張で使っていた次の設定は、もう効かない。残っていても害は無いが、消してよい。

- **`.vscode/launch.json` の pasta の構成**: `"type": "pasta"` の構成。今の拡張はこの構成を使わない。ほかの構成が無ければ、`launch.json` ごと消してよい。
- **`pasta.toml` の `[debug]` の古いキー**: `port`・`present_as`・`source_map_sidecar`。`[debug]` で効くのは `enabled` だけである（[pasta.toml による有効化](./index.md#pastatoml-による有効化)）。
- **環境変数 `PASTA_DEBUG_PORT`**: 拡張はもう番号を合わせてつながないので、要らない。

片付けた後の `[debug]` は次の形になる。

```toml
[debug]
enabled = true
```
