## スクリプトが返らない（204）

> 【エモ】▶ は届いたよ。でも合言葉が無かったから、黙っておいた。

> 【むらさき：ジト】‥‥あんた、そういうとこだけ律儀やな。

```text
ゴーストはスクリプトを返しませんでした（204）。pasta.toml に [debug] enabled = true を書いて、SHIORI をリロードしてください。
```

いちばん多い理由は、デバッグが無効なことである。次の順に確かめる。

1. `ghost/master/pasta.toml` に、次の 2 行があるか。

   ```toml
   [debug]
   enabled = true
   ```

2. 書いた後に、読み込み直したか（「SHIORI をリロード」か、もう一度 ▶）。
3. ゴーストの `pasta.log` に、次の行が出ているか。出ていれば、デバッグは有効である。

   ```text
   Debug enabled: development events are allowed
   ```

デバッグが有効なのに 204 が返るときは、次を確かめる。

- 環境変数 `PASTA_DEBUG` に `0` や `false` が入っていないか。環境変数は `pasta.toml` より優先される。
- `pasta.toml` の `[logging]` に `balloon_warning = false` を書いていないか。この設定では、シーンが見つからないときも、失敗の表記を載せずに 204 を返す。
- 出力に `OnPastaSceneAt:` を含む警告の行が添えられていれば、それが理由である。

「保存変数を表示」で `pasta.toml に [debug] enabled = true を書いてリロードしてください` と出たときも、同じ順に確かめる。`OnPastaDumpVariables:` の行が添えられていれば、それが理由である。

## 送る相手が見つからない

```text
このゴーストが動いている SSP・areka が見つかりません: hello-pasta（C:\SSP\ghost\hello-pasta）。確かめること: ベースウェアでこのゴーストを起動しているか・ベースウェアの MCP の窓口が有効か
```

- **括弧の中のパスのゴーストを、SSP で起動しているか。** 同じ名前のゴーストでも、別のフォルダに置いた写しが動いているだけでは見つからない。
- **ベースウェアの MCP の窓口が有効か。** ベースウェアの設定で確かめる。
- **開いているファイルが、ゴーストのフォルダの中にあるか。** VS Code で「ゴーストのフォルダの中のファイルではありません」と出たときは、`ghost/master` の外のファイルを開いている。

## 読み込みの終わりを確かめられない

読み込み直しを頼んだ後、ゴーストの `pasta.log` に読み込みの終わりの行（`SHIORI load entry completed`）が、およそ 20 秒のうちに出なかった。「▶ シーンを実行」は、このときシーンを鳴らさない。

- **辞書が大きくて、読み込みが長くかかっていないか。** もう一度押す。
- **`[logging]` の `level` を `warn` 以上にしていないか。** 読み込みの終わりの行は info の行である。`level` を `info` に戻す。`filter` や環境変数 `PASTA_LOG` で info の行を外しているときも同じである（[[logging]](../reference/pasta-toml.md#loggingログ出力)）。
- **`[logging]` の `file_path` を変えていないか。** 出力に「既定の profile/pasta/logs/pasta.log を読みます」と添えられたときは、`file_path` の値を読めていない。`file_path = "profile/…"` の 1 行で、`profile/` の下を指す相対パスを書く。

## 応答が無い

ベースウェアの答えが無いときは、ベースウェアの再生の記録からスクリプトを引いて出す。その記録にも見つからないと「スクリプトを確かめられませんでした」と出る。

- もう一度押して、同じになるかを見る。
- ゴーストのバルーンに `【時間切れ：…】` などの表記が出ていないかを見る（[止まるエラーの表記](../reference/runtime-failures.md#止まるエラーの表記)）。

## `pasta.log` を読めない

「pasta.log を読めなかったため、ベースウェアの誤りの記録だけで要約しました（<パス>）」と出たときは、要約に `pasta.log` の誤りと警告が数えられていない。「読み込みの終わりを確かめられませんでした」も一緒に出る。

- 括弧の中のパスに `pasta.log` があるか。ゴーストを一度も起動していないと、まだ無い。
- `[logging]` の `file_path` を変えているなら、その場所と合っているか。
- `pasta.log` を別のプログラムが開いたままにしていないか。
