# Call / Jump

シーンからシーンへ――話の流れを操る術を授けますわ。
Pasta は `if` も `while` も持たない宣言的な言語ですけれど、ご心配なく。
シーン定義と Call だけで、十分に豊かな会話の分岐が描けますのよ。

---

Pasta DSL は**宣言的言語**であり、命令型の制御構文（`if` / `while` 等）を持たない。制御フローは**シーン定義**と **Call**（`＞` / `>`）で実現する。Call は指定したシーンを呼び出し、実行後に元の場所へ戻る。

## Call の基本

Call 行はインデントした行頭に `＞`（または `>`）を置き、呼び出すターゲットを続ける。呼び出したシーンの出力は呼び出し元の出力に続けて連結され、呼び出したシーンが終わると Call 行の次の行へ戻る。

```pasta
＊メイン
    ぱすた：自己紹介を始めます
    ＞自己紹介
    ぱすた：自己紹介が終わりました

    ・自己紹介
        ぱすた：私はぱすたです
```

Call 行は暗黙の開始ブロックとローカルシーンに置ける。行末にはコメントを書ける（[コメント](block-structure.md#コメント)）。

## Call ターゲットの形式

Call のターゲットは 2 つの形式をとる。

| 形式 | 構文 | 説明 |
| ---- | ---- | ---- |
| シーン名 | `＞シーン名` | 書いた名前を検索キーにする |
| 動的ターゲット | `＞式` | 式を評価し、その値を文字列に変換して検索キーにする |

検索キーからシーンを選ぶ手順は、どちらの形式でも同じである（[シーン名の照合](#シーン名の照合)・[スコープ解決アルゴリズム](#スコープ解決アルゴリズム)）。

`＞` の直後が識別子ならシーン名、そうでなければ式として解釈される。動的ターゲットには変数に限らず任意の式（変数参照・関数呼び出し・文字列・数値・算術・連結）を書ける。式の値は Lua の `tostring` で文字列に変換されてから検索される。

```pasta
＊スタート
    ＄target＝「挨拶」
    ＄＊topic＝「天気話」
    ＞次のステップ
    ＞＄target
    ＞＄＊topic
    ＞＠話題を選ぶ（）
    ＞「挨拶」

    ・次のステップ
        ぱすた：次のステップに来ました
```

- `＞次のステップ`: シーン名 `次のステップ` を検索する。
- `＞＄target`: ローカル変数 `target` の値（`挨拶`）を検索キーにする。
- `＞＄＊topic`: グローバル変数 `topic` の値（`天気話`）を検索キーにする。
- `＞＠話題を選ぶ（）`: 関数 `話題を選ぶ` の戻り値を検索キーにする。関数呼び出しには括弧が必要で、`＞＠話題を選ぶ` のように括弧を省くとパースエラーになる。
- `＞「挨拶」`: 文字列 `挨拶` を検索キーにする。

式の値が `nil` になる場合の扱いは [任意の式の呼び出しと nil](#任意の式の呼び出しと-nil) で扱う。

### 動的ターゲットの連結

動的ターゲットには、括弧で囲まずに連結演算子 `＆` を書ける。連結した文字列が検索キーになり、ほかの動的ターゲットと同じ規則で検索される。連結の評価のされ方は [連結の評価](variables.md#連結の評価) で扱う。

```pasta
＊OnTalk
    ＄種類＝「朝」
    ＞＄種類＆「_挨拶」
    ＞「挨拶」＆＄種類

    ・朝_挨拶
        ぱすた：おはよう
    ・挨拶朝
        ぱすた：おはようございます
```

- `＞＄種類＆「_挨拶」`: `＄種類` の値と `_挨拶` をつないだ `朝_挨拶` を検索キーにする。
- `＞「挨拶」＆＄種類`: `挨拶朝` を検索キーにする。

式の `＆` の直後に置けるのは、被演算子の開始文字（`＄`・`＠`・数字・`－`・文字列の開き `「`・`"`・括弧の開き `（`・`(`）で始まるものだけである。名前（識別子）で始まるものは置けない。また、シーン名（`＞` の直後の識別子）は文字列の値ではないため、連結の被演算子にならない。次の Call 行はいずれもパースエラーになる。

| パースエラーになる Call 行 | 理由 |
| -------------------------- | ---- |
| `＞挨拶＆＄種類` | シーン名の直後に `＆` を書いている。連結したシーン名で呼ぶときは `＞「挨拶」＆＄種類` のように式で書く |
| `＞シーン名＆k＝v` | シーン名の直後に `＆` を書き、その後ろが名前で始まっている |
| `＞＄名前＆k＝v` | `＆` の直後が名前で始まっている |

## 前方一致によるターゲット解決

シーンの検索は**前方一致**で候補を列挙する。次のシーンがあるとき:

```pasta
＊挨拶朝
    ぱすた：おはよう
＊挨拶昼
    ぱすた：こんにちは
```

- `＞挨拶` → 「挨拶朝」「挨拶昼」の両方が候補
- `＞挨拶朝` → 「挨拶朝」のみが候補

候補が複数あれば、そこから 1 つが選ばれる。選び方は [候補の選択](#候補の選択) で扱う。

## シーン名の照合

シーン名には識別子に書ける文字を使える（[識別子](markers.md#識別子identifier)）。`＊会話・朝` の `・` のような記号も、識別子に書ける文字であれば使える。

シーンの検索では、検索キーとシーン名をどちらも**照合用の名前**に揃え、照合用の名前どうしで前方一致させる。照合用の名前とは、名前の中の文字と数字（平仮名・カタカナ・漢字・英字・数字など）と `_` 以外の文字を、1 文字ずつ `_` に置き換えた名前である。たとえば `会話・朝` の照合用の名前は `会話_朝` である。

```pasta
＊会話・朝
    ぱすた：おはよう
```

- `＞会話・朝`・`＞「会話・朝」` → どちらも照合用の名前 `会話_朝` で探し、「会話・朝」が候補
- `＞会話・` → 照合用の名前 `会話_` で前方一致し、「会話・朝」が候補

照合用の名前が同じになる名前は区別されない。`＊会話・朝` と `＊会話_朝` を両方定義すると、どちらの名前で呼んでも両方が同じ名前の候補になり、同名のグローバルシーンを複数定義した場合と同じく 1 つが選ばれる（[候補の選択](#候補の選択)）。

照合用の名前に揃えるのは、シーンを探す段（[スコープ解決アルゴリズム](#スコープ解決アルゴリズム)の 2 段目・5 段目）だけである。1・3・4 段は、書いた名前のまま完全一致で探す。Call のほか、SHIORI イベントに対応するシーンや選択肢のジャンプ先を探すときも、同じ照合をする。

## スコープ解決アルゴリズム

Call は検索キーに対応するハンドラーを次の 5 段の順に探し、最初に見つかったものを呼び出す。

| 段 | 探す対象 | 一致の仕方 |
| -- | -------- | ---------- |
| 1 | 実行中のグローバルシーンのシーンテーブル（Lua ブロックで `function SCENE.名前(act)` と定義した関数など） | 完全一致 |
| 2 | 実行中のグローバルシーンの配下のローカルシーン | 前方一致 |
| 3 | act のメソッド（`wait` など） | 完全一致 |
| 4 | `GLOBAL` テーブル（`＞チェイントーク`・`＞ゴースト終了` など） | 完全一致 |
| 5 | すべてのグローバルシーン | 前方一致 |

- 別のグローバルシーンの配下のローカルシーンは候補にならない。
- ローカルシーンの候補が 1 つでもあれば、2 段目で決まる。グローバルシーンの候補とは合わせない。ローカルシーンの候補が無いときだけ、3 段目以降へ進む。
- 段 1 は 2 段目より、段 3・4 は 5 段目より先に探される。たとえば Lua ブロックで定義した関数は前方一致するローカルシーンより、`GLOBAL` の関数は前方一致するグローバルシーンより優先される。

```pasta
＊OnTalk
    ぱすた：［
    ＞挨拶
    ぱすた：］

    ・挨拶ローカル
        ぱすた：ローカル

＊挨拶グローバル
    ぱすた：グローバル
```

この例の `＞挨拶` は、ローカルシーン「挨拶ローカル」が候補になるため、毎回「ローカル」を出力する。グローバルシーン「挨拶グローバル」は選ばれない。

5 段のどこにも見つからない場合は、警告をログに出し、何も出力せずに Call 行の次の行へ進む。エラーにはならない。

### 候補の選択

前方一致で候補が複数見つかった場合（2 段目・5 段目）は、候補をシャッフルし、呼び出しのたびに 1 つずつ順に使う。全候補を使い切ると並べ直して最初から使う。そのため、候補を一巡するまで同じシーンは繰り返し選ばれない。一巡の境目では、前の巡の最後と次の巡の最初が同じシーンになることがある。同名のグローバルシーンを複数定義した場合も、同じ方式で 1 つが選ばれる。

### 単語参照との違い

単語参照（`＠単語`）も同じ 5 段で探すが、2 段目と 5 段目で探す対象が異なる。Call はローカルシーン・グローバルシーンを探し、単語参照はローカル単語辞書・グローバル単語辞書を探す。そのため、Call で単語辞書の単語は呼べず、単語参照でシーンは呼べない。段 1・3・4 は両者で共通であり、Lua ブロックで定義した関数や `GLOBAL` の関数はどちらからも見つかる。単語参照の詳細は [単語定義](words.md) で扱う。

## 条件分岐の実現

条件分岐は、分岐先の名前を Lua の関数で決め、その関数を動的ターゲットとして呼び出すことで実現する。

````pasta
＊メイン
```lua
function SCENE.分岐判定(act)
    local score = act.var.スコア
    if score >= 90 then
        return "優秀"
    elseif score >= 50 then
        return "合格"
    end
    return "不合格"
end
```
    ＄スコア＝75
    ＞＠分岐判定（）

    ・優秀
        ぱすた：優秀です！
    ・合格
        ぱすた：合格です
    ・不合格
        ぱすた：不合格です
````

`＞＠分岐判定（）` は関数 `分岐判定` の戻り値（この例では `合格`）を検索キーにし、ローカルシーン「合格」を呼び出す。ローカル変数は Lua 側から `act.var.名前` で読める。Lua ブロックの置き場所は [Lua ブロックの配置](block-structure.md#lua-ブロックの配置) で扱う。

## 特殊な呼び出し

あらかじめ用意された次の名前を Call で呼ぶと、シーン以外の動作を起こせる。これらも 5 段の検索で解決される。

| 構文 | 動作 |
| ---- | ---- |
| `＞チェイントーク` / `＞yield` | ここまでの出力を返してシーンの実行を中断し、残りを次のトークの機会に出力する |
| `＞ゴースト終了` / `＞ゴースト終了（ミリ秒）` | ゴーストを終了させる |

### チェイントーク

`＞チェイントーク`（または `＞yield`）を書くと、それより前の出力がそのイベントの応答として返され、シーンの実行はそこで中断する。残りは、次に OnTalk（ランダムトーク）が発生する機会に、新しい OnTalk シーンの代わりに出力される。

```pasta
＊OnTalk
    ぱすた：ねえ、聞いて。
    ＞チェイントーク
    ぱすた：昨日面白いことがあったの。
    ＞yield
    ぱすた：……やっぱり内緒。
    ぱすた：またね。
```

- `＞チェイントーク` を複数回書くと、出力を 3 回以上に分けられる。この例は 3 回の OnTalk に分けて出力される。
- 最後の部分を出力し終えると、次の OnTalk からは通常どおりシーンが選ばれる。
- OnTalk 以外のイベント（`＊OnBoot` など）のシーンで使った場合も、残りは次の OnTalk の機会に出力される。
- 残りが出力されるのを待っている間に、別のイベントでシーンが実行される（時報のシーンを含む）と、待っていた残りは破棄される。
- 中断している間もローカル変数は保たれ、再開後のシーンから同じ値を参照できる。
- `＞チェイントーク` は `GLOBAL["チェイントーク"]`（4 段目）で、`＞yield` は act のメソッド `yield`（3 段目）で解決される。どちらも同じ動作である。`GLOBAL["チェイントーク"]` を Lua で定義し直すと `＞チェイントーク` の動作を変えられる。

### ゴースト終了

`＞ゴースト終了` は、ゴーストを終了させるさくらスクリプト `\-` を出力に加える。引数にミリ秒の数値を渡すと、その時間だけ待ってから終了する（`\_w[ミリ秒]\-` を出力する）。

```pasta
＊OnClose
    ぱすた：またね。
    ＞ゴースト終了（1500）
```

### 任意の式の呼び出しと nil

動的ターゲットの式の値は、検索の前に必ず文字列へ変換される。値が `nil` になる場合（代入していない変数を参照した、関数が値を返さなかった、など）は文字列 `"nil"` を検索キーにして検索する。通常はそのような名前のシーンが無いため、「見つからない」場合と同じく警告をログに出し、何も出力せずに次の行へ進む。連結の被演算子が値なしになった場合（`＞＄未代入＆「_挨拶」` など）も、連結の警告が出たうえで、連結の結果の `nil` から同じく `"nil"` を検索キーにする。

Lua から `act:call` を直接呼ぶ場合は、検索キーに `nil` を渡すと検索を行わずに警告を出して戻る。この扱いは DSL の Call 行からは起きない。

## 引数リスト

Call には括弧で囲んだ引数リストを付けられる。シーン名・動的ターゲットのどちらにも付けられる。

```pasta
＊OnTalk
    ＞紹介（「ぱすた」、3）
    ＞紹介（「ラザニア」，2＋3）

＊紹介
    ぱすた：＄０は＄１歳です
```

- 引数どうしは読点 `、`・全角カンマ `，`・半角カンマ `,` で区切る。空白で区切るとパースエラーになる。
- 各引数は式である。数値・文字列・変数参照・関数呼び出し・算術・連結・括弧を書ける。
- 引数は書いた順に位置で渡される。`名前：値` の形も受理されるが、名前は捨てられ、値だけが位置で渡される。
- `（）` のように空の引数リストも書ける。
- 呼び出されたシーンは、受け取った引数を `＄０`・`＄１`… で参照する（[変数・スコープ](variables.md)）。

Call は、明示した引数の後ろに、呼び出し元のシーンが受け取った引数をすべて付け足して渡す。引数リストを書かない `＞シーン名` は、呼び出し元の引数をそのまま渡す。動的ターゲットでも同じである。

アクション行や式の中の関数呼び出し（`＠関数（引数）`）の引数も、同じ規則で書く（[アクション行](action-line.md)）。
