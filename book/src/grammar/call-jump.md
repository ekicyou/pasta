# Call / Jump

シーンからシーンへ――話の流れを操る術を授けますわ。
Pasta は `if` も `while` も持たない宣言的な言語ですけれど、ご心配なく。
シーン定義と Call だけで、十分に豊かな会話の分岐が描けますのよ。

---

Pasta DSL は**宣言的言語**であり、命令型の制御構文（`if` / `while` 等）を持たない。制御フローは**シーン定義**と **Call**（`＞` / `>`）で実現する。Call は指定したシーンを呼び出し、実行後に元の場所へ戻る。

## Call の基本

Call 行はインデントした行頭に `＞`（または `>`）を置き、呼び出すターゲットを続ける。呼び出したシーンの出力は呼び出し元の出力に続けて連結され、呼び出したシーンが終わると Call 行の次の行へ戻る。

```pasta
＊メイン
    ぱすた：自己紹介を始めます
    ＞自己紹介
    ぱすた：自己紹介が終わりました

    ・自己紹介
        ぱすた：私はぱすたです
```

Call 行は暗黙の開始ブロックとローカルシーンに置ける。行末にはコメントを書ける（[コメント](block-structure.md#コメント)）。

## Call ターゲットの形式

Call のターゲットは 2 つの形式をとる。

| 形式 | 構文 | 説明 |
| ---- | ---- | ---- |
| シーン名 | `＞シーン名` | 書いた名前を検索キーにする |
| 動的ターゲット | `＞式` | 式を評価し、その値を検索キーにする |

検索キーからシーンを選ぶ手順は、どちらの形式でも同じである（[シーン名の照合](#シーン名の照合)・[スコープ解決アルゴリズム](#スコープ解決アルゴリズム)）。

`＞` の直後が識別子ならシーン名、そうでなければ式として解釈される。動的ターゲットには変数に限らず任意の式（変数参照・関数呼び出し・文字列・数値・算術・連結）を書ける。

```pasta
＊スタート
    ＄target＝「挨拶」
    ＄＊topic＝「天気話」
    ＞次のステップ
    ＞＄target
    ＞＄＊topic
    ＞＠話題を選ぶ（）
    ＞「挨拶」

    ・次のステップ
        ぱすた：次のステップに来ました
```

- `＞次のステップ`: シーン名 `次のステップ` を検索する。
- `＞＄target`: ローカル変数 `target` の値（`挨拶`）を検索キーにする。
- `＞＄＊topic`: グローバル変数 `topic` の値（`天気話`）を検索キーにする。
- `＞＠話題を選ぶ（）`: 関数 `話題を選ぶ` の戻り値を検索キーにする。関数呼び出しには括弧が必要で、`＞＠話題を選ぶ` のように括弧を省くとパースエラーになる。
- `＞「挨拶」`: 文字列 `挨拶` を検索キーにする。

式の値から検索キーを作る規則と、値が検索キーにならない場合の扱いは [動的ターゲットの値](#動的ターゲットの値) で扱う。

### 動的ターゲットの連結

動的ターゲットには、括弧で囲まずに連結演算子 `＆` を書ける。連結した文字列が検索キーになり、ほかの動的ターゲットと同じ規則で検索される。連結の評価のされ方は [連結の評価](variables.md#連結の評価) で扱う。

```pasta
＊OnTalk
    ＄種類＝「朝」
    ＞＄種類＆「_挨拶」
    ＞「挨拶」＆＄種類

    ・朝_挨拶
        ぱすた：おはよう
    ・挨拶朝
        ぱすた：おはようございます
```

- `＞＄種類＆「_挨拶」`: `＄種類` の値と `_挨拶` をつないだ `朝_挨拶` を検索キーにする。
- `＞「挨拶」＆＄種類`: `挨拶朝` を検索キーにする。

式の `＆` の直後に置けるのは、被演算子の開始文字（`＄`・`＠`・数字・`－`・文字列の開き `「`・`"`・括弧の開き `（`・`(`）で始まるものだけである。名前（識別子）で始まるものは置けない。また、シーン名（`＞` の直後の識別子）は文字列の値ではないため、連結の被演算子にならない。次の Call 行はいずれもパースエラーになる。

| パースエラーになる Call 行 | 理由 |
| -------------------------- | ---- |
| `＞挨拶＆＄種類` | シーン名の直後に `＆` を書いている。連結したシーン名で呼ぶときは `＞「挨拶」＆＄種類` のように式で書く |
| `＞シーン名＆k＝v` | シーン名の直後に `＆` を書き、その後ろが名前で始まっている |
| `＞＄名前＆k＝v` | `＆` の直後が名前で始まっている |

### 動的ターゲットの値

動的ターゲットの式の値は、次のように検索キーになる。

| 式の値 | 検索キー |
| ------ | -------- |
| 空でない文字列 | その文字列。文字列 `nil`（`＞「nil」` や、値が文字列 `nil` の変数）も、ほかの文字列と同じくそのまま検索キーになる |
| 数値 | アクション行で表示したときと同じ表記の文字列（`3` なら `3`、`7／2` なら `3.5`） |
| 値なし・空文字列・文字列と数値以外（真偽値・テーブルなど） | 検索キーにならない |

値が検索キーにならない場合、Call はシーンを探さずに失敗する。ログに警告を出し、Call 行の位置に失敗表記を出力して、Call 行の次の行へ進む（[Call が失敗したとき](#call-が失敗したとき)）。値なしになるのは、値を代入していない変数・値を返さない関数呼び出し・見つからない関数の呼び出し・値なしになった演算（連結・算術）である。値なしのときは何も探さないため、`nil` で始まる名前のシーンや関数があっても呼ばれない。

警告と失敗表記は、式の形と値によって次のようになる。

| 式の形 | 値 | 警告 | 失敗表記 |
| ------ | -- | ---- | -------- |
| 変数参照 1 つ（`＞＄名前`・`＞＄＊名前`・`＞＄０`） | 値なし | `act:call - undefined variable: 'var.名前'` | `【Call失敗：var.名前 が nil】` |
| 〃 | 空文字列 | `act:call - empty variable: 'var.名前'` | `【Call失敗：var.名前 が空文字列】` |
| 〃 | 文字列・数値以外 | `act:call - unsupported value type: 'var.名前' (boolean)` | `【Call失敗：var.名前 が boolean】` |
| 関数呼び出し 1 つ（`＞＠名前（…）`・`＞＠＊名前（…）`・`＞＠＄名前（…）`） | 値なし | `act:call - key is not a string or number: operand='@名前()', value=nil` | `【Call失敗：@名前() が nil】` |
| 〃 | 空文字列・文字列と数値以外 | `act:call - key is not a string or number: operand='@名前()', value=true (boolean)` | `【Call失敗：@名前() が boolean】`（空文字列なら `@名前() が空文字列`） |
| それ以外の式（文字列・算術・連結など） | 値なし | 出ない（値なしになった演算の警告だけが出る） | `【Call失敗：値が nil】` |
| 〃 | 空文字列・文字列と数値以外 | `act:call - key is not a string or number: value='' (string)` | `【Call失敗：値が空文字列】`（真偽値なら `値が boolean`） |

- 変数は Lua での書き方で示される。`＄名前` は `var.名前`、`＄＊名前` は `save.名前`、`＄０` は `args[1]` である。関数は `＠名前（…）` が `@名前()`、`＠＊名前（…）` が `@*名前()`、`＠＄名前（…）` が `@$var.名前()` になる。動的単語参照・連結の警告と同じ表記である（[値が使えないとき・見つからないとき](words.md#値が使えないとき見つからないとき)・[被演算子の値ごとの扱い](variables.md#被演算子の値ごとの扱い)）。
- 括弧で囲んだだけの式（`＞（＄名前）`）は、囲まれた変数参照・関数呼び出し 1 つと同じに扱われる。
- 型名（`boolean`・`table`・`function` など）は値の型である。
- 連結・算術の被演算子が値なしになった場合（`＞＄未代入＆「_挨拶」` など）は、連結・算術の警告（`act:concat - operand is not a string or number: op='&', operand='var.未代入', value=nil`）だけが出て、Call の警告は重ねて出ない。失敗表記は `【Call失敗：値が nil】` になる。
- 引数リストが付いていても、引数の式は書いた順に評価され、Call だけが行われない。失敗表記は、引数の式（関数呼び出しなど）が出力するものより前に出る。

## 前方一致によるターゲット解決

シーンの検索は**前方一致**で候補を列挙する。次のシーンがあるとき:

```pasta
＊挨拶朝
    ぱすた：おはよう
＊挨拶昼
    ぱすた：こんにちは
```

- `＞挨拶` → 「挨拶朝」「挨拶昼」の両方が候補
- `＞挨拶朝` → 「挨拶朝」のみが候補

候補が複数あれば、そこから 1 つが選ばれる。選び方は [候補の選択](#候補の選択) で扱う。

## シーン名の照合

シーン名には識別子に書ける文字を使える（[識別子](markers.md#識別子identifier)）。`＊挨拶・朝` の `・` のような記号も、識別子に書ける文字であれば使える。

シーンの検索では、検索キーとシーン名をどちらも**照合用の名前**に揃え、照合用の名前どうしで前方一致させる。照合用の名前とは、名前の中の文字と数字（平仮名・カタカナ・漢字・英字・数字など）と `_` 以外の文字を、1 文字ずつ `_` に置き換えた名前である。たとえば `挨拶・朝` の照合用の名前は `挨拶_朝` である。

```pasta
＊挨拶・朝
    ぱすた：おはよう
```

- `＞挨拶・朝`・`＞「挨拶・朝」` → どちらも照合用の名前 `挨拶_朝` で探し、「挨拶・朝」が候補
- `＞挨拶・` → 照合用の名前 `挨拶_` で前方一致し、「挨拶・朝」が候補

照合用の名前が同じになる名前は区別されない。`＊挨拶・朝` と `＊挨拶_朝` を両方定義すると、どちらの名前で呼んでも両方が同じ名前の候補になり、同名のグローバルシーンを複数定義した場合と同じく 1 つが選ばれる（[候補の選択](#候補の選択)）。

照合用の名前に揃えるのは、シーンを探す段（[スコープ解決アルゴリズム](#スコープ解決アルゴリズム)の 2 段目・5 段目）だけである。1・3・4 段は、書いた名前のまま完全一致で探す。Call のほか、SHIORI イベントに対応するシーンや選択肢のジャンプ先を探すときも、同じ照合をする。

### シーン名の別名

グローバルシーンの名前は、**別名表**で別の名前に置き換えられる。別名表は pasta.toml の `[scene.alias]` に書く（[pasta.toml リファレンス](../reference/pasta-toml.md#sceneシーン名)）。書かなければ既定の表が使われる。既定の表は `OnTalk = ["会話"]` の 1 件で、別名 `会話` を `OnTalk` に置き換える。そのため `＊会話` はランダムトーク（OnTalk）のシーンになる（[OnTalk](../lua/shiori-events.md#ontalk)）。`[scene.alias]` を書くと既定の表は丸ごと置き換わり、見出しだけを書くと別名は無くなる。

置き換えは次の規則で行う。

- **完全一致**: 書いた名前（照合用の名前に揃える前の名前）が別名と完全に一致するときだけ置き換える。`会話・朝`・`会話２` のように、別名で始まるだけの名前は置き換えない。
- **1 段だけ**: 置き換えは 1 回だけ行う。置き換えた後の名前を、さらに置き換えることはない。
- **グローバルシーン名だけ**: 置き換えるのはグローバルシーンの名前だけである。ローカルシーン（`・会話`）・単語（`＠会話`）・アクター・変数の名前は置き換えない。
- **置き換え後は前方一致**: 置き換えた後の名前を照合用の名前に揃え、ほかの名前と同じく前方一致で探す。

置き換えは、宣言と検索の両方で行う。

- 宣言: グローバルシーンの宣言 `＊名前`（名前を書かない単独の `＊` 行が受け継ぐ名前を含む）は、名前が別名に一致すると、置き換え先の名前のシーンとして登録される（[グローバルシーン](block-structure.md#グローバルシーン)）。
- 検索: [スコープ解決アルゴリズム](#スコープ解決アルゴリズム)の 5 段目（すべてのグローバルシーン）に進んだ検索は、すべて検索キーを置き換えてから探す。2 段目（実行中のグローバルシーンの配下のローカルシーン）と 1・3・4 段は、書いた名前のまま探す。そのため、実行中のグローバルシーンに `・会話` のローカルシーンがあれば、`＞会話` はそのローカルシーンを呼ぶ。

検索キーを置き換える入口は次のとおりである。

| 入口 | 例 |
| ---- | -- |
| Call のシーン名・文字列・動的ターゲットの値 | `＞会話`・`＞「会話」`・`＞＄話題`（値が `会話`） |
| 選択肢のジャンプ先 | `＠？会話` |
| SHIORI イベントに対応するシーンの検索・仮想イベント（OnTalk・OnHour） | [シーン関数フォールバック](../lua/shiori-events.md#シーン関数フォールバック) |
| Lua の検索 API（範囲を指定しない `SEARCH:search_scene`・`SCENE.co_exec`・`act:call`） | [@pasta_search](../lua/modules/pasta-search.md) |

範囲を指定した `SEARCH:search_scene`（第 2 引数あり）と、登録名（`OnTalk_1` など）を直接受け取る入口は置き換えない。

既定の表のもとで、次のシーンがあるとき:

```pasta
＊会話
    ぱすた：今日はいい天気だね。

＊OnTalk朝
    ぱすた：おはよう。

＊会話・朝
    ぱすた：朝の話をしよう。
```

- `＊会話` は `OnTalk` という名前で登録される。`＊OnTalk朝` とともにランダムトークの候補になる。
- `＊会話・朝` は別名と完全一致しないため、`会話・朝` という名前のまま登録される。ランダムトークの候補にはならない。
- `＞会話` → `OnTalk` に置き換えて前方一致で探し、「会話」と「OnTalk朝」が候補。「会話・朝」は候補にならない。
- `＞OnTalk` → 「会話」と「OnTalk朝」が候補（「会話」は `OnTalk` の名前で登録されているため）。
- `＞会話・朝`・`＞会話・` → 置き換えずに照合用の名前 `会話_朝`・`会話_` で前方一致し、「会話・朝」が候補。

置き換えた後の名前でも見つからない場合、Call の失敗表記は書いた名前で `【Call失敗：「会話」が見つからない】` になる（[Call が失敗したとき](#call-が失敗したとき)）。ログには、書いた名前と置き換えた後の名前の両方を記した警告も出る。

## スコープ解決アルゴリズム

Call は検索キーに対応するハンドラーを次の 5 段の順に探し、最初に見つかったものを呼び出す。

| 段 | 探す対象 | 一致の仕方 |
| -- | -------- | ---------- |
| 1 | 実行中のグローバルシーンのシーンテーブル（Lua ブロックで `function SCENE.名前(act)` と定義した関数など） | 完全一致 |
| 2 | 実行中のグローバルシーンの配下のローカルシーン | 前方一致 |
| 3 | act のメソッド（`wait` など） | 完全一致 |
| 4 | `GLOBAL` テーブル（`＞チェイントーク`・`＞ゴースト終了` など） | 完全一致 |
| 5 | すべてのグローバルシーン | 前方一致 |

- 別のグローバルシーンの配下のローカルシーンは候補にならない。
- ローカルシーンの候補が 1 つでもあれば、2 段目で決まる。グローバルシーンの候補とは合わせない。ローカルシーンの候補が無いときだけ、3 段目以降へ進む。
- 段 1 は 2 段目より、段 3・4 は 5 段目より先に探される。たとえば Lua ブロックで定義した関数は前方一致するローカルシーンより、`GLOBAL` の関数は前方一致するグローバルシーンより優先される。

```pasta
＊OnTalk
    ぱすた：［
    ＞挨拶
    ぱすた：］

    ・挨拶ローカル
        ぱすた：ローカル

＊挨拶グローバル
    ぱすた：グローバル
```

この例の `＞挨拶` は、ローカルシーン「挨拶ローカル」が候補になるため、毎回「ローカル」を出力する。グローバルシーン「挨拶グローバル」は選ばれない。

1 段目・2 段目の「実行中のグローバルシーン」は、その Call 行を書いたグローバルシーンである。別のグローバルシーンを Call で呼んで戻った後の行でも変わらない（[Call から戻った後の名前解決](#call-から戻った後の名前解決)）。

5 段のどこにも見つからない場合、Call は失敗する。警告 `act:call - handler not found: key='検索キー', mode='scene', via=act` をログに出し、Call 行の位置に失敗表記 `【Call失敗：「検索キー」が見つからない】` を出力して、Call 行の次の行へ進む（[Call が失敗したとき](#call-が失敗したとき)）。シーン名・値のある動的ターゲットのどちらでも同じである。

### 候補の選択

前方一致で候補が複数見つかった場合（2 段目・5 段目）は、候補をシャッフルし、呼び出しのたびに 1 つずつ順に使う。全候補を使い切ると並べ直して最初から使う。そのため、候補を一巡するまで同じシーンは繰り返し選ばれない。一巡の境目では、前の巡の最後と次の巡の最初が同じシーンになることがある。同名のグローバルシーンを複数定義した場合も、同じ方式で 1 つが選ばれる。

### 単語参照との違い

単語参照（`＠単語`）も同じ 5 段で探すが、2 段目と 5 段目で探す対象が異なる。Call はローカルシーン・グローバルシーンを探し、単語参照はローカル単語辞書・グローバル単語辞書を探す。そのため、Call で単語辞書の単語は呼べず、単語参照でシーンは呼べない。段 1・3・4 は両者で共通であり、Lua ブロックで定義した関数や `GLOBAL` の関数はどちらからも見つかる。単語参照の詳細は [単語定義](words.md) で扱う。

## Call から戻った後の名前解決

Call 行の次の行は、Call 行を書いたグローバルシーンを実行中のグローバルシーンとして名前を解決する。呼ばれた別のグローバルシーンが実行されている間は、そのグローバルシーンが実行中のグローバルシーンになるが、戻った後の行の単語参照・Call・関数呼び出しは、呼び出し元のグローバルシーンのシーンテーブル（1 段目）と配下のローカルシーン・ローカル単語（2 段目）を探す。

```pasta
＊OnTalk
    ＞挨拶
    ＞雑談
    ＞挨拶

    ・挨拶
        ぱすた：こんにちは。

＊雑談
    ＞挨拶

    ・挨拶
        ぱすた：ところで。
```

この例は「こんにちは。ところで。こんにちは。」を出力する。`＊雑談` の中の `＞挨拶` は `＊雑談` のローカルシーンを呼び、`＊雑談` から戻った後の `＞挨拶` は `＊OnTalk` のローカルシーンを呼ぶ。

- 呼ばれたシーンの中でさらに別のグローバルシーンを呼んだ場合も同じである。どの深さでも、Call から戻った行は、その行を書いたグローバルシーンとして解決される。
- 呼んだものがシーン以外（Lua ブロックの関数・`GLOBAL` の関数・act のメソッド）の場合も、その関数の中から別のグローバルシーンが呼ばれた場合も、Call が失敗した場合も、Call 行の次の行は呼び出し元のグローバルシーンとして解決される。
- 呼ばれたシーンが [チェイントーク](#チェイントーク) で中断した場合は、再開して最後まで実行された後に Call 行の次の行へ戻り、呼び出し元のグローバルシーンとして解決される。
- ローカルシーン（暗黙の開始ブロックを含む）の最後の行の Call は、呼ばれた側へ移ったまま戻る行が無い。最後の行の Call でシーンをつないでいく限り、何回つないでも呼び出しは深くならない。そのローカルシーンが別の Call 行から呼ばれていた場合は、その Call 行の次の行が、その行を書いたグローバルシーンとして解決される。
- 関数呼び出し（アクション行・式の中の `＠名前（…）`・`＠＊名前（…）`・`＠＄名前（…）`、単語参照で見つかった関数）が、中で別のグローバルシーンを実行した場合も同じである。その行の残りと次の行以降は、その行を書いたグローバルシーンとして解決される。
- 選択肢は、その選択肢行を出したグローバルシーンの配下から先にジャンプ先を探す。呼ばれたシーンが出した選択肢は呼ばれたシーンの、戻った後に出した選択肢は呼び出し元のローカルシーンへジャンプする（[選択肢行](block-structure.md#選択肢行)）。

## Call が失敗したとき

Call は、検索キーに対応するものが 5 段のどこにも見つからない場合（[スコープ解決アルゴリズム](#スコープ解決アルゴリズム)）と、動的ターゲットの値が検索キーにならない場合（[動的ターゲットの値](#動的ターゲットの値)）に失敗する。失敗した Call はエラーにならず、次のように動く。

- ログに Call の警告を 1 行出す（連結・算術の警告が出ている場合を除く。呼んだ関数が見つからない場合は、その前に関数側の警告も出る）。
- Call 行の位置に、失敗表記 `【Call失敗：…】` をバルーンに見える文字列として出力する。
- Call 行の次の行へ進む。最後の行の Call が失敗した場合は、そのシーンをそのまま終える。

```pasta
＊OnTalk
    ぱすた：今日は
    ＞＄話題
    ぱすた：……あれ？
```

`＄話題` に値を代入していない場合、この例は「今日は【Call失敗：var.話題 が nil】……あれ？」と表示し、ログに `act:call - undefined variable: 'var.話題'` を出す。

失敗表記は、直前に話したアクターのバルーンに続けて出る。出力の先頭（チェイントークで再開した直後を含む）では、さくらスクリプトのスコープを切り替えずに出る。失敗表記には、台詞と違って句読点のウェイトも自動の改行も入らない。失敗表記の文言は、見つからない場合が `【Call失敗：「検索キー」が見つからない】`、値が検索キーにならない場合が [動的ターゲットの値](#動的ターゲットの値) の表のとおりである。

## 条件分岐の実現

条件分岐は、分岐先の名前を Lua の関数で決め、その関数を動的ターゲットとして呼び出すことで実現する。

````pasta
＊メイン
```lua
function SCENE.分岐判定(act)
    local score = act.var.スコア
    if score >= 90 then
        return "優秀"
    elseif score >= 50 then
        return "合格"
    end
    return "不合格"
end
```
    ＄スコア＝75
    ＞＠分岐判定（）

    ・優秀
        ぱすた：優秀です！
    ・合格
        ぱすた：合格です
    ・不合格
        ぱすた：不合格です
````

`＞＠分岐判定（）` は関数 `分岐判定` の戻り値（この例では `合格`）を検索キーにし、ローカルシーン「合格」を呼び出す。ローカル変数は Lua 側から `act.var.名前` で読める。Lua ブロックの置き場所は [Lua ブロックの配置](block-structure.md#lua-ブロックの配置) で扱う。

## 特殊な呼び出し

あらかじめ用意された次の名前を Call で呼ぶと、シーン以外の動作を起こせる。これらも 5 段の検索で解決される。

| 構文 | 動作 |
| ---- | ---- |
| `＞チェイントーク` / `＞yield` | ここまでの出力を返してシーンの実行を中断し、残りを次のトークの機会に出力する |
| `＞ゴースト終了` / `＞ゴースト終了（ミリ秒）` | ゴーストを終了させる |

アクション行の中に `＠yield`・`＠チェイントーク`・`＠ゴースト終了` と書いても、`＞yield`・`＞チェイントーク`・`＞ゴースト終了` と同じ動作になる。単語参照の形（直後に空白を置く）でも、関数呼び出しの形（`＠yield（）`・`＠ゴースト終了（1500）` など）でもよい。

```pasta
＊OnTalk
    ぱすた：ねえ、聞いて。＠チェイントーク　昨日面白いことがあったの。
```

この例は、`＠チェイントーク` の前後で 2 回の OnTalk に分けて出力される。

### チェイントーク

`＞チェイントーク`（または `＞yield`）を書くと、それより前の出力がそのイベントの応答として返され、シーンの実行はそこで中断する。残りは、次に OnTalk（ランダムトーク）が発生する機会に、新しい OnTalk シーンの代わりに出力される。

```pasta
＊OnTalk
    ぱすた：ねえ、聞いて。
    ＞チェイントーク
    ぱすた：昨日面白いことがあったの。
    ＞yield
    ぱすた：……やっぱり内緒。
    ぱすた：またね。
```

- `＞チェイントーク` を複数回書くと、出力を 3 回以上に分けられる。この例は 3 回の OnTalk に分けて出力される。
- 最後の部分を出力し終えると、次の OnTalk からは通常どおりシーンが選ばれる。
- OnTalk 以外のイベント（`＊OnBoot` など）のシーンで使った場合も、残りは次の OnTalk の機会に出力される。
- 残りが出力されるのを待っている間に、別のイベントでシーンが実行される（時報のシーンを含む）と、待っていた残りは破棄される。
- 中断している間もローカル変数は保たれ、再開後のシーンから同じ値を参照できる。
- `＞チェイントーク` は `GLOBAL["チェイントーク"]`（4 段目）で、`＞yield` は act のメソッド `yield`（3 段目）で解決される。どちらも同じ動作である。`GLOBAL["チェイントーク"]` を Lua で定義し直すと `＞チェイントーク` の動作を変えられる。

### ゴースト終了

`＞ゴースト終了` は、ゴーストを終了させるさくらスクリプト `\-` を出力に加える。引数にミリ秒の数値を渡すと、その時間だけ待ってから終了する（`\_w[ミリ秒]\-` を出力する）。

```pasta
＊OnClose
    ぱすた：またね。
    ＞ゴースト終了（1500）
```

## 引数リスト

Call には括弧で囲んだ引数リストを付けられる。シーン名・動的ターゲットのどちらにも付けられる。

```pasta
＊OnTalk
    ＞紹介（「ぱすた」、3）
    ＞紹介（「ラザニア」，2＋3）

＊紹介
    ぱすた：＄０は＄１歳です
```

- 引数どうしは読点 `、`・全角カンマ `，`・半角カンマ `,` で区切る。空白で区切るとパースエラーになる。
- 各引数は式である。数値・文字列・変数参照・関数呼び出し・算術・連結・括弧を書ける。
- 引数は書いた順に位置で渡される。`名前：値` の形も受理されるが、名前は捨てられ、値だけが位置で渡される。
- `（）` のように空の引数リストも書ける。
- 呼び出されたシーンは、受け取った引数を `＄０`・`＄１`… で参照する（[変数・スコープ](variables.md)）。

Call は、明示した引数の後ろに、呼び出し元のシーンが受け取った引数をすべて付け足して渡す。引数リストを書かない `＞シーン名` は、呼び出し元の引数をそのまま渡す。動的ターゲットでも同じである。

アクション行や式の中の関数呼び出し（`＠関数（引数）`）の引数も、同じ規則で書く（[アクション行](action-line.md)）。
