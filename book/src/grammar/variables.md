# 変数・スコープ

会話に「記憶」を持たせたいときは、変数の出番ですわ。
一時的なもの、永続するもの、ベースウェアと共有するもの――三種を使い分けますの。
スコープを制する者がゴーストを制する、と申しておきましょう。

---

変数は `＄`（または `$`）マーカーで代入・参照する。Pasta の変数には、有効範囲（スコープ）の異なる 3 種類と、Call で渡された値を読むシーン引数がある。代入の値には式や関数呼び出しも使える。

## 変数の種類とスコープ

| 種類 | 代入 | 参照 | 有効範囲 |
| ---- | ---- | ---- | -------- |
| ローカル | `＄名前＝値` | `＄名前` | 1 回のイベント処理の間（[ローカル変数](#ローカル変数)） |
| グローバル | `＄＊名前＝値` | `＄＊名前` | 永続（ゴーストを終了しても保存される） |
| プロパティ | `＄％prop.path＝値` | `＄％prop.path` | ベースウェアのプロパティ（ベースウェアが管理） |
| シーン引数 | 代入できない | `＄０`・`＄１`… | そのシーンの呼び出し 1 回（[シーン引数](#シーン引数)） |

代入は変数代入行で、代入演算子 `＝`（または `=`）だけを使う。`＄score：100` のようにコロンで代入するとパースエラーになる。値として書けるものは [式（Expression）のサポート](#式expressionのサポート) のとおりである。真偽値のリテラル（`true`・`false`）は無い（[リテラル型](literals.md)）。

```pasta
＊初期化
    ＄score＝100
    ＄ユーザー＝「太郎」
    ＄＊最高点＝＄score＊2
```

変数代入行はシーンの中に置く。アクション行の中では変数を参照できるが、代入はできない（[アクション行](action-line.md#インライン要素)）。

### ローカル変数

`＄名前` は Lua の `var.名前` になる。ローカル変数は 1 回のイベント処理ごとに空の状態から始まり、イベント処理が終わると消える。

- Call で呼び出したシーンは、呼び出し元と同じローカル変数を読み書きする。
- `＞チェイントーク` などで中断したシーンは、次のイベントで再開したあとも、中断前と同じローカル変数を使い続ける。値はそのシーンが最後まで実行されるまで残る（[チェイントーク](call-jump.md#チェイントーク)）。

```pasta
％Alice

＊OnTest
    ＄ローカル変数＝10
    Alice：値は＄ローカル変数　です
```

### グローバル変数

`＄＊` 修飾子を付けると、グローバル変数になる。Lua 側では `save.名前` になり、ゴーストを終了しても値が保存されて、次の起動時に元に戻る（[グローバル変数の保存先](#グローバル変数の保存先)）。

```pasta
％Bob

＊OnTest
    ＄＊グローバル変数＝100
    Bob：値は＄＊グローバル変数　です
```

### プロパティ変数

`＄％` でベースウェアのプロパティ（SSP のプロパティシステム）を読み書きする。プロパティ名は ASCII 英字で始まり、ASCII 英数字・`_`・`.`・`(`・`)` が続く。`sakura.name` や `currentghost.scope(0).name` のような名前をそのまま書ける。全角文字や空白でプロパティ名が終わるため、名前の直後に半角の `(` を書くと名前に含まれる。

```pasta
％さくら

＊OnTest
    ＄％sakura.name＝「Alice」
    ＄name＝＄％sakura.name
    さくら：＄％sakura.name　です
```

- 書き込みは `＄％名前＝値`、読み込みは代入の右辺に単独で置く `＄x＝＄％名前` と、アクション行のインライン参照である。
- プロパティ変数は式の中（演算・関数の引数・Call ターゲット）には書けず、トランスパイルエラーになる。式で使うときは、いったんローカル変数に代入してから使う。

### シーン引数

`＄０`・`＄１`…（数字だけの変数名）は、Call でシーンに渡された引数を参照する。`＄n` は、そのシーンが受け取った n＋1 番目の引数である。

```pasta
％ぱすた

＊OnTest
    ＞紹介（「ぱすた」、3）

＊紹介
    ぱすた：＄０　は＄１　歳です
```

- 数字は全角でも半角でもよい（`＄０` と `＄0` は同じ）。
- シーン引数には代入できない。`＄０＝1` はパースエラーになる。
- イベントで直接起動されたシーン（Call されていないシーン）では値が無く、参照すると空文字になり、ログに警告が出る。
- 番号は 0〜255 である。256 以上を書くと 0 として扱われ、`＄０` と同じ値になる。
- 引数の渡し方（明示した引数の後ろに呼び出し元の引数が付け足されること）は [Call / Jump](call-jump.md#引数リスト) で扱う。

ベースウェアから届く `Reference0` などは、シーン引数とは別の変数で読む（[リクエスト変数（Reference）](#リクエスト変数reference)）。

## 変数参照の空白ルール

アクション行の中で変数を展開するには、`＄変数名` の直後に**1 文字以上の空白**を置く。この空白は区切りとして消え、出力されない。

```pasta
％ぱすた

＊表示
    ＄ユーザー＝「太郎」
    ぱすた：＄ユーザー　さん、こんにちは！
```

> **重要**: 空白がないと最長一致で変数名を解釈し、後続の文字まで変数名に取り込んでしまう。意図しない動作を避けるため、変数参照の直後には必ず空白（または識別子に含まれない記号）を置く。

> **補足**: 値を代入していない変数を参照すると空文字として展開され、ログに警告（`act:talk - undefined variable`）が出る。存在しない単語（`＠未定義`）や、見つからないローカル関数（`＠未定義（）`）を参照したときも空文字になり、ログに警告が出る。動的参照（`＠＄名前`・`＠＄名前（…）`）では、変数が未代入・空文字列・文字列と数値以外のときに空文字（関数呼び出しは値の無い呼び出し）になり、それぞれ `undefined variable`・`empty variable`・`unsupported value type` の警告が出る（[値が使えないとき・見つからないとき](words.md#値が使えないとき見つからないとき)）。

## 式（Expression）のサポート

変数代入の右辺には式を書ける。書けるものは次のとおり。

| 値の種類 | 構文例 | 説明 |
| -------- | ------ | ---- |
| リテラル値 | `＄score＝100`・`＄name＝「太郎」` | 数値・文字列（[リテラル型](literals.md)） |
| 単語参照 | `＄value＝＠word_name` | 単語を 1 つ選んだ結果（[単語定義](words.md)） |
| 動的単語参照 | `＄value＝＠＄種類` | 変数 `＄種類` の値を単語キーとして単語を 1 つ選んだ結果（[動的単語参照](words.md#動的単語参照)） |
| 変数参照 | `＄new＝＄old`・`＄n＝＄０` | 他の変数・シーン引数の値をコピー |
| 算術式 | `＄result＝＄a＋＄b＊2` | [算術の評価](#算術の評価) |
| ローカル関数呼び出し | `＄r＝＠calculate（）` | 5 段の検索で見つけた関数の戻り値 |
| グローバル関数呼び出し | `＄r＝＠＊calculate（）` | `GLOBAL.calculate` の戻り値 |
| 関数呼び出し（引数付き） | `＄sum＝＠add（10、20）` | 引数は読点・カンマで区切り、位置で渡す |
| 動的関数呼び出し | `＄r＝＠＄計算（10、20）` | 変数 `＄計算` の値を関数名として探した関数の戻り値（[動的関数呼び出し](words.md#動的関数呼び出し)） |

関数呼び出しの引数の書き方は Call の引数リストと同じである（[Call / Jump](call-jump.md#引数リスト)）。演算子の一覧は [キーワード・マーカー](markers.md#算術演算子) を参照。

計算や条件判定を関数にまとめたいときは、Lua ブロックでシーンテーブルに関数を定義し、`＠名前（引数）` で呼び出す。関数は第 1 引数に act を受け取り、その後ろに DSL で書いた引数を受け取る。

````pasta
％ぱすた

＊計算
    ＄result＝＠add（10、20）
    ぱすた：合計は＄result　です

```lua
function SCENE.add(act, x, y)
    return x + y
end
```
````

### 算術の評価

式は Lua の算術としてそのまま評価される。

- `＊`・`／`・`％` が `＋`・`－` より先に計算される（優先順位）。同じ優先順位の演算子は左から順に計算される。`1＋2＊3` は 7、`10－4－3` は 3 になる。
- `／` は整数どうしでも小数の結果になる。`7／2` は 3.5 になる。
- 負の符号は数値リテラルにだけ付けられる（`－5`）。変数に付ける `-＄x` はパースエラーになる。
- 文字列を連結する演算子は無い。`＋` などはすべて数値の演算である。
- 数字だけの文字列は数値に変換されて計算される。`「1」＋2` は 3 になる。

### 関数スコープの展開先

| DSL 構文 | Lua 展開先 | 説明 |
| -------- | ---------- | ---- |
| `＠func（…）` | `act:expr_fn("func", …)` | 実行中のシーンから 5 段の順に探して呼ぶ |
| `＠＊func（…）` | `GLOBAL.func(act, …)` | `GLOBAL` テーブルの関数を直接呼ぶ |
| `＠＄名前（…）` | `act:expr_fn_var(var.名前, "var.名前", …)` | 変数の値を関数名として、`＠func（…）` と同じ段から探して呼ぶ（act のメソッドの段は探さない） |

`＠func（…）` の 5 段の検索は Call と同じである（シーンテーブル → ローカルシーン → act のメソッド → `GLOBAL` → グローバルシーン。[スコープ解決アルゴリズム](call-jump.md#スコープ解決アルゴリズム)）。最初に見つかった関数を `(act, 引数…)` で呼び、その戻り値を使う。ただしアクション行の中（`アクター：＠func（…）`）で呼んだ場合は `act.アクター:expr_fn("func", …)` を経由し、関数の第 1 引数は act ではなくそのアクターのプロキシになる。プロキシは act のメソッド（`init_scene` など）を持たないため、act が必要なときはプロキシの `act` フィールドから取る。`＠＊` のグローバル関数は、変数の `＄＊` → `save.` と対称の書き方である。

`＠＄名前（…）` は、変数の値と、警告に使う変数の場所（`"var.名前"`）を渡す。`＠＄＊名前（…）` は `save.名前`、`＠＄０（…）` は `args[1]` を渡す。アクション行の中では `act.アクター:expr_fn_var(…)` を経由し、`＠func（…）` と同じく関数の第 1 引数はそのアクターのプロキシになる。静的な `＠func（…）` と検索が異なる点は [動的関数呼び出し](words.md#動的関数呼び出し) で扱う。

## 式文（ExprStmt）

代入を伴わず、式の評価（副作用）だけを行うには `＄＝式` と書く。変数名を省略し、結果を捨てる。

```pasta
＊OnTest
    ＄＝＠副作用関数（）
    ＄＝＠＊グローバル副作用（）
```

1 行目は `act:expr_fn("副作用関数")`、2 行目は `GLOBAL.グローバル副作用(act)` を呼び、戻り値を使わない。変数代入行（ローカル・グローバル・プロパティ・式文）はすべて `＄` で始まる。

## DSL と Lua の対応表

変数と関数呼び出しは、次の Lua に変換される。Lua ブロックの関数からは、`local save, var = act:init_scene(SCENE)` で同じ `save`・`var` を取り出して読み書きできる。

| DSL 構文 | Lua 変換後 | 値の寿命 |
| -------- | ---------- | -------- |
| `＄名前` | `var.名前` | 1 回のイベント処理 |
| `＄＊名前` | `save.名前` | 永続（終了時に保存） |
| `＄％prop＝値` | `act:set_property("prop", 値)` | ベースウェアが管理 |
| `＄x＝＄％prop` | `var.x = act:get_property("prop")` | ベースウェアが管理 |
| `＄０`・`＄１` | `args[1]`・`args[2]` | そのシーンの呼び出し 1 回 |
| `＄x＝＠単語` | `var.x = act:word("単語")` | — |
| `＄x＝＠＄y` | `var.x = act:word(var.y, "var.y")` | — |
| `＠関数（…）` | `act:expr_fn("関数", …)` | — |
| `＠＊関数（…）` | `GLOBAL.関数(act, …)` | — |
| `＠＄y（…）` | `act:expr_fn_var(var.y, "var.y", …)` | — |

## グローバル変数の保存先

グローバル変数（`＄＊名前`、Lua の `save.名前`）は、`save` テーブルごと JSON ファイルに保存される。

- 既定の保存先は、ゴーストのフォルダからの相対パス `profile/pasta/save/save.json` である。
- 保存は Lua ランタイムの終了時（ゴーストの終了・辞書の再読込）に自動で行われ、起動時に読み込まれる。
- 保存先のパスと難読化（gzip 圧縮した `.dat` での保存）は、pasta.toml の `[persistence]` で変えられる。
- Lua から明示的に保存・読み込みする方法は `@pasta_persistence` モジュールで扱う（[@pasta_persistence](../lua/modules/pasta-persistence.md)）。

## Lua 予約語の制約

変数名は Lua の識別子としてそのまま `var.名前`・`save.名前` に出力される。そのため、Lua の予約語を変数名にすると、パースとトランスパイルは通るが、生成された Lua が構文エラーになり、辞書の読み込み全体が失敗する。

使えない名前は次の 22 語である（大文字・小文字を区別する。`End` は使える）。

```text
and break do else elseif end false for function goto if
in local nil not or repeat return then true until while
```

`＄end＝1`・`＄＊local＝1`・アクション行の `＄end` のいずれも同じ失敗になる。単語名・シーン名・`＠関数（）` の関数名は文字列として扱われるため、この制約を受けない。

## エンジンが値を入れる変数

ここまでの変数はすべて辞書側で代入するものだった。これとは別に、pasta.dll（実行時エンジン）が値を入れる変数がある。文法上は普通のローカル変数・グローバル変数と同じで、`＄変数名` で参照する。

| 種類 | 変数 | 値が入る条件 |
| ---- | ---- | ------------ |
| 日時変数 | `＄年`・`＄時１２` など（[下表](#日時変数)） | 時報シーンでは自動。それ以外は `＞transfer_date_to_var` を呼ぶ |
| リクエスト変数 | `＄ｒ０`〜`＄ｒ９`・`＄req_id` など（[下表](#リクエスト変数reference)） | 自動では入らない。`＞transfer_req_to_var` を呼ぶ |
| 予約グローバル変数 | `＄＊pasta_` で始まる名前（[下表](#予約グローバル変数pasta_-で始まる名前)） | 辞書側で代入すると、エンジンの動作が変わる |

> **注意**: 転記を呼ばずに日時変数やリクエスト変数を参照すると、値が入っていないため空文字として展開され、ログに警告が出る。また、転記すると同じ名前のローカル変数は上書きされる。`＄日` や `＄時` といった名前を自分の変数に使わないこと。

### 日時変数

時報シーン（`＊時報14`・`＊時報その他`・`＊OnHour14`・`＊OnHourOther`。数字は半角 2 桁）には、発火した時点の日時が自動で入る。ランダムトークやクリック反応など、それ以外のシーンで使うときは、シーンの先頭で `＞transfer_date_to_var` を呼んでから参照する。

| 変数 | 内容 | 例 |
| ---- | ---- | -- |
| `＄年` `＄月` `＄日` | 年・月・日（単位付きの文字列） | `2026年` `9月` `26日` |
| `＄時` `＄分` `＄秒` | 時（24 時間制）・分・秒（単位付きの文字列） | `14時` `5分` `0秒` |
| `＄時１２` | 12 時間制の時刻 | `午後2時` |
| `＄曜日` | 曜日 | `土曜日` |
| `＄year` `＄month` `＄day` | 年・月・日（数値） | `2026` `9` `26` |
| `＄hour` `＄min` `＄sec` | 時（0〜23）・分・秒（数値） | `14` `5` `0` |
| `＄wday` | 曜日番号（0=日曜〜6=土曜） | `6` |
| `＄week` | 曜日（英語） | `Saturday` |

`＄時１２` は、0 時が `深夜0時`、1〜11 時が `午前N時`、12 時が `正午`、13〜23 時が `午後N時` になる。`１２` は全角数字で書く。

日本語名の変数はアクション行での表示向けである。英語名の変数（`＄year`〜`＄wday`）は数値のまま入るため、Lua ブロックの関数で `var.hour` を比べるなど、条件分岐に使える。

```pasta
＊OnMouseDoubleClick
　＞transfer_date_to_var
　女の子：＠通常　今日は　＄曜日　、いまは　＄時１２　だよ。
```

### リクエスト変数（Reference）

ベースウェアはイベントごとに `Reference0`、`Reference1`… という付加情報を送ってくる（ダブルクリックされた部位、選択肢の ID など）。これらは自動では変数に入らない。シーンの先頭で `＞transfer_req_to_var` を呼ぶと、次の変数に値が入る。

| 変数 | 内容 |
| ---- | ---- |
| `＄ｒ０`〜`＄ｒ９` | `Reference0`〜`Reference9` の値（文字列）。`ｒ` と数字は全角 |
| `＄r0`〜`＄r9` | 同じ値の半角名 |
| `＄req_id` | イベント名（例: `OnMouseDoubleClick`） |
| `＄req_base_id` | リクエストの `BaseID` ヘッダの値（送られてきた場合のみ） |

```pasta
＊OnMouseDoubleClick
　＞transfer_req_to_var
　女の子：＠通常　＄ｒ４　を触ったね？
```

各 `Reference` に何が入るかはイベントごとに異なる。[UKADOC の SHIORI Event 一覧](https://ssp.shillest.net/ukadoc/manual/list_shiori_event.html)で確認できる。たとえば `OnMouseDoubleClick` では `Reference4` がダブルクリックされた部位の名前になる。`Reference10` 以降は変数に入らないため、Lua から `act.req.reference[10]` で読む（[scripts/ の記述パターン](../lua/patterns.md)を参照）。

`＄ｒ０`（`Reference0`）と `＄０`（[シーン引数](#シーン引数)）は別物である。イベントで直接起動されたシーンの `＄０` には値が入らない。

### 予約グローバル変数（pasta_ で始まる名前）

`＄＊pasta_` で始まるグローバル変数はエンジンが予約している。辞書側で代入すると、エンジンの動作が変わる。自分の変数に `pasta_` で始まる名前を使わないこと。

| 変数 | 用途 | 既定値 |
| ---- | ---- | ------ |
| `＄＊pasta_talk_interval_min` | ランダムトークの最小間隔（秒） | `180` |
| `＄＊pasta_talk_interval_max` | ランダムトークの最大間隔（秒） | `300` |

```pasta
＊OnBoot
    ＄＊pasta_talk_interval_min＝60
    ＄＊pasta_talk_interval_max＝120
```

間隔は、この変数 → `pasta.toml` の `[ghost]` にある `talk_interval_min` / `talk_interval_max` → 既定値、の順に決まる。値は数値で代入すること（数値以外は無視される）。10 秒未満を指定したときは 10 秒になり、最小間隔が最大間隔を上回ったときは最大間隔が最小間隔にそろえられる。代入した値は、次にトーク間隔を計算するときから反映される。
