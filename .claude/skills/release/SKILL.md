# release — pasta のリリース

<instructions>

## 中心の仕事

リリースを 1 回だけ行う。同じフォルダの `procedure.md` を、メインの文脈で上から順に実行する。`0.4.0` や `v0.4.0` のような引数は、版を決める段への開発者の版の指示である。

段・コマンド・合否の基準・判定表の正本は `procedure.md` だけである。このファイルは約束と段の要約だけを持つ。この手順は、常駐 spec `release-workflow` の実装をスキルへ移したもので（2026-10-11）、経緯は `.kiro/specs/completed/release-workflow/` にある。実行には使わない。

## 段の要約（詳しくは procedure.md）

1. 開始の確認 — ブランチ、GitHub の権限、版の表記のファイルを触る開いた PR、作業ツリー（`git merge-tree` で何も変えずに確かめる）、main の取り込み。
2. 状態の判定 — 定型コマンド A の出力を判定表 S0〜S9 に当て、始める段を決める。
3. 版の決定 — 次のリリースへの申し送りを読み、版を決めて重ならないことを確かめる。
4. 版の更新 — 版の表記の 6 ファイルと見どころのファイル `doc/release-notes/v{V}.md` を 1 つのコミットにする。
5. main への統合 — PR を作り、main が動いていれば見どころを確かめ直して、squash で統合する。承認で止まらない。
6. リリースタグ — 統合のコミットに注釈付きのタグを付け、その 1 本だけを push する。承認で止まらない。
7. リリース CI の結果の確認 — 実行を裏の `gh run watch` で待ち、7 つの公開先の結果を読む。
8. 失敗への対応 — 判定表 F0〜F7 に当てる（未完了のときだけ）。
9. 完了の報告 — 見どころの全文を含む報告。開発者が直しを頼んだら「公開の後に見どころの直しを頼まれたら」を行う。

## 進め方

1. `procedure.md` を 1 回通して読む。サブエージェントを起こさない（開発者への確認があり、値を次の段へ渡すため）。レビュー・デバッグのサブエージェントも使わない。進み具合をファイルに書かない。
2. 頼みが、公開済みの版の見どころの直しなら、段を行わず、`procedure.md` の「公開の後に見どころの直しを頼まれたら」だけを行って終える。
3. それ以外は、毎回段 1 から始める。再開の位置は、前回の会話の記録でなく、段 2 の判定表で決める。
4. 段 N を始める前に、`procedure.md` の「段 N」を読み直す。コマンドは、そこに書いてあるものを、波かっこ（`{V}` など）だけ置き換えて実行する。記憶で書かない。足さない。定型コマンド A〜D は「定型コマンドの呼び出し方」の 1 行で呼び、スクリプトの中身を写して実行しない。
5. 順調な経路では承認を求めない。止まるのは `procedure.md` の「止まり方」に書いた所だけで、そのときは同節の報告の形で終える。
6. 段 9 の報告で終える。

## 約束

- テストを書かない。段の完了は、段が定める確認のコマンドの結果で判定する。
- コミットしてよいのは、段 4 の版の更新（7 ファイル）と、段 5 と「公開の後に見どころの直しを頼まれたら」の見どころのファイル 1 つの直しだけである。`git add` には必ずファイルのパスを並べる（`git add -A`・`git add .` を使わない）。
- main へ直接 push しない。push するのは、作業ブランチ（PR のため）とリリースタグだけである。
- 手元で `cargo build`・`cargo test`・`release.ps1`・`npm run package` を実行しない。main の CI の結果を見ない。
- 手元から `cargo publish`・`vsce publish`・`gh release create`・`gh release upload` を実行しない。公開済みのものに `cargo yank`・`vsce unpublish`・`gh release delete` を実行しない。
- 押したタグを消さない。動かすのは「タグの付け直し」（どこにも公開していない・開発者がその 1 回を明示して承認した）だけである。
- 外へ出るコマンド（`git push`・`gh pr create`・`gh pr merge`・`gh run rerun`・`gh release edit`）は、1 回のツールの呼び出しに単独の 1 行で実行する。`;`・`&&` でつながない。`cd` を前に付けない。終了コードを見るための `echo` などを足さない。つなぐと許可の規則（`Bash(gh pr merge:*)` など）に合わなくなり、許可の判定に拒否される。
- 許可の判定に拒否されたら、言い直して実行し直さず、別の道具へ回さず、「止まり方」に従って止まる（足す許可の規則は `procedure.md` の「開発者の設定」）。
- 判定表・手順に無い状態に当たったら、推測で進めず、「止まり方」に従って止まる。
- `bash` のブロックは Bash ツールで、`powershell` のブロックと定型コマンドは PowerShell ツールで実行する。

</instructions>
