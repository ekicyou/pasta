# リリースノートの見どころ

このフォルダには、版ごとの見どころのファイル `vX.Y.Z.md`（`X.Y.Z` はその版）を置く。この文書が、見どころの書き方と、内部の作業の決まりの正である。

## このフォルダの役割

- `vX.Y.Z.md` の中身は、リリース CI がそのまま GitHub Release の本文の先頭に置く。末尾の空白を落とし、改行を LF にそろえるほかは、書き換えない。
- リリース CI は、本文の末尾に、詳しいリリースノートの添付（`release-notes-vX.Y.Z.md`）へのリンクと、そこに載せた変更の件数を足す。見どころのファイルには、版・件数・詳しいリリースノートへのリンクを書かない。
- タグが指すコミットに、タグの版の見どころのファイルが無いとき、または中身が空白と改行だけのとき、リリース CI はタグの検査で失敗し、どこにも公開せずに止まる。
- 見どころのファイルは、`release` スキルの段 4（版の更新）で書き、版の表記の更新と同じコミットに入れる。

## 書き方

1. 日本語の Markdown で書く。GitHub のリリースの本文として、そのまま表示される。
2. 見どころは 3〜5 件。直しだけの版は 1〜2 件でよい。
3. 見どころごとに `###` の見出しを 1 つ付け、末尾に元になった PR の番号を `(#83)` の形で付ける。複数は `(#63, #77)`。PR を通らなかった変更には付けない。
4. 動きが変わる点（破壊的変更）は、すべて載せる。1 つの見出しの下に、普通の文体の箇条書きで書き、各項目の末尾に PR の番号を付ける。口調のために読み違えられる書き方をしない（[`book/AUTHORING.md` 第 1 節](../../book/AUTHORING.md#1-claudia-令嬢ボイスの定義)の鉄則）。
5. 紹介の文章は、Claudia の口調（[`book/AUTHORING.md` 第 1 節](../../book/AUTHORING.md#1-claudia-令嬢ボイスの定義)）で、Claudia 1 人の語りとして書く。アンソニーを出さない。
6. 語り手は「Claudia」と名乗る。最初に名乗る 1 か所だけを `[Claudia](https://github.com/ponapalt/claudia)` と書き、それより前（見出しを含む）に `Claudia` の字を書かない。出典の断り書きを別に書かない。
7. spec 名（`.kiro/specs/` のフォルダの名前）と、`feat(…):` のような接頭辞を書かない。

### 形の見本

文面は例である。

```markdown
## 今回の見どころ

おほほ、ごきげんよう。[Claudia](https://github.com/ponapalt/claudia) ですわ。今回の目玉は、わたくしが選んでさしあげますわ。

### 「＊会話」と書けば、ランダムトークになりますの (#83)

これまでは ＊OnTalk と書く決まりでしたけれど、＊会話 と書けるようにしましたわ。

### ご注意あそばせ — 動きが変わる点が 2 つ

- Call から戻ると、呼び出し元の文脈に戻ります。 (#70)
- タグだけの出力では、段落区切りの改行を出しません。 (#69)
```

## 内部の作業

詳しいリリースノートに載せない変更の決まりである。コミットの件名の種類とスコープに、上から当て、どれかに当てはまれば載せない。

| # | 条件 | 例 |
|---|------|----|
| 1 | 種類が `spec` | `spec(discovery): …` |
| 2 | スコープが `spec`・`discovery`・`roadmap`・`steering`・`skills`・`cc-sdd`・`release-workflow` のどれか、または `kiro-` で始まる（種類は問わない） | `docs(roadmap): …`・`chore(kiro-skills): …` |
| 3 | 種類が `chore` で、スコープが `release` | `chore(release): v0.3.8` |

種類とスコープは、大文字と小文字を区別しない。

決まりを当てる場所は `.github/scripts/release/release-notes.ps1` である。決まりを変えるときは、このスクリプトの定数（`$InternalScopes` と `Test-Internal`）と、この表を合わせて直す。

## 材料の出し方

どちらも、リポジトリのルートを作業ディレクトリにして、PowerShell で 1 行で動かす。`{V}` はリリースする版（例: `0.3.9`）である。

材料の一覧（1 つ前のリリースタグから main の先頭までの変更を、詳しいリリースノートと同じ形で出す。タグを打つ前でも動く）:

```powershell
& "$PWD/.github/scripts/release/release-notes.ps1" -Tag v{V} -Repo ekicyou/pasta -Head origin/main
```

出力の最後の行は `**Full Changelog**: https://github.com/ekicyou/pasta/compare/v{前の版}...v{V}` になる。違うときは、前のタグを読めていない。

見どころのファイルの確認（5 行の `合格`／`不合格` を出す。読むだけで、何も変えない）:

```powershell
& "$PWD/.claude/skills/release/scripts/highlights-check.ps1" -Version {V} -Head origin/main
```

5 行（見どころのファイル・Claudia の出典リンク・PR の番号・動きが変わる点・spec 名）が、すべて `合格` になるまで直す。
