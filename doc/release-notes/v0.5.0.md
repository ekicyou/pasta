## 今回の見どころ

おほほ、ごきげんよう。[Claudia](https://github.com/ponapalt/claudia) ですわ。0.5.0 は、同じ名前のシーンの「どれを選ぶか」を、辞書だけで思いのままに決められるようになった版ですの。Lua の if など、もう要りませんわよ。

### ＆重み・＆順番 で、同名シーンの選び方を決められますの (#238)

`＆重み` を付けたシーンは、その数だけ選ばれやすくなりますわ。`＆順番` を候補の全部に付ければ、番号の順に 1 つずつ選んで、最後まで行けば最初へ戻りますの。単語の値にも、後ろに `＠３` のように書けば重みが付きますのよ。書き間違い（重みと順番の両方書き、番号の重なりなど）は、読み込みのときにきちんと止めてさしあげますわ。

### シーンの条件と ＆優先 で、そのときの変数に合う場面だけを選べますの (#234, #237)

`＊雑談　＆＄＊経験値≧500` のように宣言の行へ条件を書けば、満たさない場面は候補から外れますわ。`＆＄＊初回待ち` のようなフラグも書けますし、`＆優先` を付ければ、満たした中でいちばん高い段だけから選びますの。段階的な開示も、一度だけのお話も、イベントの振り分けも、辞書だけで書けますわね。イベントでは Reference と日時が先に変数へ入りますから、`＊OnUpdateComplete　＆＄ｒ０＝「changed」` もそのまま書けますのよ。場面に入った後は、`SCENE.attrs` で属性を書いた順・型のまま読めますわ。

### シーンの数を、辞書から数えられますの (#230)

`シーン数` と `シーン数完全一致` で、ある名前にぶら下がるシーンがいくつあるかを読めますわ。数えても、次に選ばれるシーンは変わりませんから、ご安心なさいまし。

### VSCode の開発の道具が、SSP・areka の MCP へお引っ越ししましたの (#231, #233)

「▶ シーンを実行」「SHIORI をリロード」「保存変数を表示」の 3 つを、エディタの右クリックから、動いているゴーストへ直接お届けしますわ。保存変数は `OnPastaDumpVariables` で `profile/pasta/debug/variables.toml` に書き出しますの。

### 大きな辞書でも、読み込みが速くなりましたの (#223)

行の数に比例して解析するようにいたしましたわ。8,000 行の辞書でも、1 秒かかりませんのよ。

### ご注意あそばせ — 動きが変わる点

- 「」で囲まない単語の値の最後にある `＠数` は、重みとして読みます。文字として出すときは「」で囲んでください。最後が `＠０` の囲まない値と、`＠数` だけの囲まない値は、パースエラーになります。 (#238)
- ファイル属性を 2 行続けて書いた辞書は、パースエラーになります。1 行にまとめてください。 (#234)
- イベントのシーンでは、選ぶ前に Reference と日時がローカル変数に入ります。同じ名前の変数に本文で入れている場合は、本文の代入が後から勝つので、今までどおり動きます。 (#237)
- `pasta_core` の `SceneTable::resolve_*` の引数（`filters` から述語へ）と、`SceneTableError::NoMatchingScene` の形が変わりました。 (#237)
- i64 に収まらない数は近い小数として読み、小数でも表せない数は構文の誤りになります。アクターの番号（0〜4294967295）とシーン引数の番号（0〜255）の範囲外、1 行で 64 段を超える括弧、1 つの式で 256 個を超える演算子も、構文の誤りになります。 (#223)
- pasta.dll から DAP とキックを取り除きました。`[debug]` で読むのは `enabled` だけで、`port`・`present_as`・`source_map_sidecar` は読み飛ばします。`.lua.map` は書き出しません。 (#233)
- VSCode 拡張から DAP のデバッグ構成とブレークポイントを取り除きました。開発の道具は、SSP・areka の MCP を使うコマンドに置き換わりました。 (#231)
- `pasta_core` のシーン表・単語表の使われていない API と誤りの型、`pasta_dsl` の作られない誤りの型（`PestError`・`MultipleErrors`・`ParseErrorInfo`・`ParseResult`）を取り除きました。 (#223, #227)
